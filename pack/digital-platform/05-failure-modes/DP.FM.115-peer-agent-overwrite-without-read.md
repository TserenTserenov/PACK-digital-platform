# DP.FM.115 — Peer-agent overwrite без чтения shared-файла

## Симптом

Peer-агент получает задачу «добавь запись в файл X», выполняет Write без предварительного Read → затирает заголовок (H1) и предшествующий контент. Дополнительный сигнал: неправильный год/дата в добавленном контенте (агент не видит существующий контекст).

## Корневая причина

Агент не читает файл перед записью. Формулировка задачи «добавь в конец» воспринимается как «создай содержимое с нуля».

## Последствия

- Потеря исторических записей в shared-файле.
- Некорректные метаданные (год, ссылки на контекст).
- Ручное восстановление через `git revert` / `git diff`.

## Canonical Fix

**Pre-write gate:** перед любым Write/Edit shared-файла — Read весь файл в текущей сессии. Проверка: «прочитан ли файл в этой сессии?» Если нет → Read first, затем Write.

## Mitigation для протокола агента

Инструкция в системном промпте: «При любом Write или Edit существующего файла — Read обязателен перед записью, даже если задача формулируется как "добавь"».
