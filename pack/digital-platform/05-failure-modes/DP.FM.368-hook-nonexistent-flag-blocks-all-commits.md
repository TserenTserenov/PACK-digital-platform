# DP.FM.368 — несуществующий флаг в хуке блокирует все коммиты

## Паттерн

Pre-commit хук вызывает вспомогательный скрипт с флагом, которого на самом деле не существует в его CLI (`--mode=staged`) — скрипт завершается ошибкой аргумента при каждом вызове, что в fail-closed конфигурации хука блокирует абсолютно все коммиты в репозитории, независимо от их содержимого.

## Механизм

1. Хук был написан/обновлён со ссылкой на флаг, который либо никогда не существовал, либо был удалён/переименован в целевом скрипте
2. Хук не проверяет корректность своего вызова заранее (например, `--help` дизайн-тестом), полагаясь на то, что вызов сработает
3. Ошибка аргумента в fail-closed хуке трактуется как «проверка не пройдена» → блокировка каждого коммита

## Почему опасен

Один опечатанный флаг в хуке — это не локальная поломка одной функции, а полная остановка всей работы через git для всех, кто использует этот хук, пока не будет исправлено.

## Лечение

При изменении CLI скрипта, вызываемого из хука — синхронно обновлять сам хук; периодическая smoke-проверка хуков (реальный тестовый вызов, не только наличие файла) перед их публикацией/обновлением.
