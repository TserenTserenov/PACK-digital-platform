# DP.FM.360 — Прод-сервис в обход LLM-прокси

## Паттерн

Продакшн-сервис (в найденном случае — бот `aist_bot_newarchitecture`) вызывает LLM-провайдера (Anthropic) напрямую, минуя обязательный платформенный прокси-шлюз. Расходы и трафик такого вызова невидимы для централизованной наблюдаемости и биллинга платформы.

## Механизм

1. Часть кода прод-сервиса написана до внедрения обязательного прокси-инварианта (или добавлена позже без прохождения через ревью прокси-политики)
2. Прямой вызов работает функционально корректно — сервис не падает, ответ приходит
3. Расход токенов/деньги за эти вызовы не отражаются в централизованной системе учёта, где прокси — единственная точка входа
4. Обнаружено 3 файла с таким обходом в конкретной фазе (Ф-Bot-Anthropic-Bypass)

## Почему опасен

- Финансовые расходы платформы становятся непрозрачными — часть трафика LLM невидима для аналитики
- Нарушает уже существующий инвариант «LLM-прокси — обязательный ingress» (`AR.218`), но обнаруживается только целевым аудитом, не автоматически

## Лечение

1. Периодический аудит кодовой базы прод-сервисов на прямые вызовы LLM-провайдеров (grep по доменам API-провайдеров, минуя домен прокси)
2. Перенаправить обнаруженные вызовы через прокси
3. Рассмотреть сетевой уровень блокировки прямых вызовов к доменам провайдеров из прод-окружения (defense in depth)

## Связи
