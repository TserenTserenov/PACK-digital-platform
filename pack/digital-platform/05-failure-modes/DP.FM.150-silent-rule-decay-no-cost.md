# DP.FM.150 — Silent rule decay

## Краткое описание

Failure mode системы соблюдения правил: detect → write log → агрегатор → reminder с порогом N/неделю. Если порог > 1 и нарушения редкие — reminder никогда не генерируется → нарушитель не видит свою ошибку → правило перестаёт действовать.

## Симптомы

- Правило технически «работает» (детектор ловит), но поведение не меняется.
- Лог пишется, но никто его не видит в реальном времени.
- Fault-reminder с порогом N>1 молчит при единичных нарушениях критических правил.

## Контекст

WP-388: fault-reminder порог = 3/неделю, но A1 (путь как подлежащее) зафиксировано 1 раз — напоминание не генерируется. A2 (английский без перевода) — 14 нарушений в ручном аудите, детектор не замечает совсем.

## Формула

Ценность контроля = (видимость нарушителю) × (стоимость для нарушителя). Невидимый лог = ноль ценности независимо от точности детектора.

## Решение

(а) Видимый канал — inject reminder в начало следующей сессии при ≥1 нарушении критического правила (порог 1, не 3).
(б) Изменить агрегатор: для CRITICAL-tagged правил порог = 1.
(в) Speed-camera принцип: детектор без обратной связи = декоративный знак.
