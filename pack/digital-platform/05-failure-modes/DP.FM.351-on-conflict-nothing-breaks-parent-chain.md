# DP.FM.351 — ON CONFLICT DO NOTHING молча обрывает цепочку parent-chunk

## Паттерн

Вставка чанка использует `ON CONFLICT DO NOTHING` для игнорирования конфликта уникальности. При конфликте новая строка не вставляется — но если эта строка должна была стать родителем для последующих чанков, цепочка `parent_id` обрывается молча: последующие чанки ссылаются на несуществующий parent или на устаревшую версию.

## Механизм

1. Индексатор вставляет чанк с `ON CONFLICT (doc_id, chunk_index) DO NOTHING`
2. Конфликт возникает (повторный прогон, гонка, retry) → INSERT не происходит, id существующей строки не возвращается
3. Код-вызывающая сторона ожидает `id` новой строки для использования как `parent_id` следующего чанка
4. Без `RETURNING id` или обработки конфликта — parent_id следующих чанков указывает в никуда или на неверную строку

## Почему опасен

- Ошибки не возникает — INSERT просто «ничего не делает», без исключения
- Цепочка parent-chunk используется для графового обхода — обрыв обнаруживается только при попытке пройти по цепочке, не в момент записи
- Симптом проявляется в другом месте кода (там, где строится граф), не там, где произошёл сбой (индексатор)

## Лечение

1. Заменить `DO NOTHING` на `DO UPDATE ... RETURNING id`, чтобы всегда получать актуальный id строки (новой или существующей)
2. Явно обрабатывать случай конфликта в коде вызывающей стороны — не полагаться на побочный эффект отсутствующего INSERT
3. Тест: вставить чанк дважды подряд → проверить, что parent_id следующего чанка указывает на реально существующую строку в обоих случаях
