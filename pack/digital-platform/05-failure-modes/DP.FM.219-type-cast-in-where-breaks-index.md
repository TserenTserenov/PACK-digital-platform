# DP.FM.219 — Приведение типа в WHERE на большой таблице → seq scan вместо index scan

## Описание

Перенос примера SQL-условия с маленькой таблицы на большую без учёта приведения типа (`::text`, `CAST(x AS text)`) убивает использование индекса — планировщик переходит к полному просмотру таблицы при каждом запросе.

## Механизм

Индекс PostgreSQL создаётся для конкретного типа данных колонки (например, `uuid`). Если условие в WHERE приводит значение к другому типу (`col::text = 'value'`), планировщик не может применить индекс на исходном типе — он вынужден вычислить приведение для каждой строки таблицы, что равнозначно seq scan.

## Пример

```sql
-- Маленькая таблица (работало): индекс на uuid, пример из документации
WHERE user_id::text = current_setting('app.user_id')

-- Большая таблица (провал): domain_event, миллионы строк → seq scan
-- Фикс: сравнивать в совместимых типах
WHERE user_id = current_setting('app.user_id')::uuid
```

## Признаки

- SQL-условие скопировано с маленькой или учебной таблицы
- В WHERE есть `::text` или `CAST(col AS text)` при наличии индекса на колонке
- EXPLAIN ANALYZE показывает Seq Scan вместо Index Scan

## Тест

«Сохранит ли условие тип колонки, совместимый с индексом?» Нет → seq scan.

## Контрмера

Переписать условие так, чтобы приведение типа применялось к параметру, а не к индексируемой колонке.
