# DP.FM.390 — Блайнд `git stash pop` орфанного автостэша теряет чужие незакоммиченные удаления

## Симптом

Карточка рабочего продукта и три файла уже применённой на проде миграции пропали из репозитория. Первичный диагноз указывал на логику скрипта закрытия дня (гипотеза «снимок/перезапись» — не подтвердилась). Настоящая причина: `git pull --rebase --autostash` внутри защитного шага упал на несвязанном конфликте checkout и оставил орфанный автостэш. Интерактивный агент нашёл этот стэш, посмотрел диф одного файла (`git stash show -p --stat`), увидел неконфликтное авто-слияние и заключил, что весь стэш — легитимная работа текущей сессии. Выполнил `git stash pop` целиком, не проверив построчно записи `deleted:` — часть из них была чужим незакоммиченным удалением, возникшим до начала этой сессии и просто подхваченным автостэшем. Плановый прогон в ту ночь не запускался автономно ни разу — перенёс уже испорченное рабочее дерево в свой коммит, но не был причиной порчи.

## Почему это ошибка

Один благополучный пример из выборки (один файл без конфликта) экстраполирован на весь стэш без проверки. Орфанный стэш может содержать смесь: реальную работу текущей сессии и чужое, более старое незакоммиченное состояние (включая удаления файлов), случайно попавшее в тот же автостэш через `--autostash`. Оба выглядят одинаково в `--stat`-сводке.

## Антипаттерн → Паттерн

- Антипаттерн: `git stash show -p --stat` на одном примере → «выглядит нормально» → `git stash pop` без дальнейшей проверки.
- Паттерн: перед `pop`/`apply` неизвестного (не только что своего) стэша — смотреть полный `git stash show -p` (не `--stat`), по каждой строке `deleted:` отдельно решать «это моё в этой сессии или чужое незакоммиченное состояние», не восстанавливать автоматически удаления файлов, похожих на боевые артефакты (миграции, исполняемый код).

## Тест обнаружения

Стэш, который вы собираетесь `pop`/`apply`, создан не вами лично в текущей сессии (орфанный/чужой)? Если да — полный `git stash show -p`, построчная проверка каждого `deleted:`, обязательна перед `pop`.
