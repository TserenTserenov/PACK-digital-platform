# DP.FM.421 — Регэксп извлекает аргумент до раскрытия shell — значение через переменную невидимо

## Паттерн

Хук угадывает значение флага (`--slug`) регэкспом по сырому тексту вызова команды — до того, как shell раскрыл переменные. Когда значение передано через `$VAR`, а не литералом, регэксп синтаксически не может его увидеть: символ `$` рвёт символьный класс. Результат молча трактуется как «значение отсутствует», хотя вызов был полностью валиден.

## Механизм

1. Guard/парсер читает ТЕКСТ команды, а не результат её реального исполнения shell'ом.
2. Автор вызова использует легитимную форму — значение через переменную, а не литерал.
3. Регэксп, написанный и проверенный на литеральных примерах, синтаксически не покрывает форму `$VAR`.
4. Даунстрим-логика получает «не найдено» и обращается с этим как с «значение отсутствует», а не как с «не удалось распознать».

## Почему опасен

Не проявляется на литеральных вызовах (стандартный путь тестирования) — только на форме с переменной, которая для автора вызова выглядит полностью нормальной. Симптом на выходе («билет не выдавался ВООБЩЕ») не указывает на регэксп как причину.

## Антипаттерн → Паттерн

- Антипаттерн: единственный источник истины для параметра — regex-разбор сырого текста вызова; при несовпадении шаг просто не выполняется.
- Паттерн, два слоя:
  1. **Точечный:** там, где уже есть независимый резервный источник истины (например, `CLAUDE_CODE_SESSION_ID` в окружении) — читать его как fallback, не полагаться только на результат регэкспа.
  2. **Системный:** нераспознанное значение параметра заменяется явным видимым sentinel, а нижестоящая логика гейтится на сам sentinel — пропускает СТРОГО ту одну проверку, которой честно нужен разобранный параметр, оставляя остальные (сильные) инварианты без изменений. Дополнительно (находка холодного ревью, WP-484): guard на приёмке билета обязан отдельно проверять, что буквальное значение параметра не совпадает с самим sentinel-значением — иначе реальный (хоть и странный) ввод притворяется нераспознанным.

## Тест обнаружения

«Может ли этот параметр быть передан не литералом, а через shell-переменную/подстановку — и если да, что случится с ВСЕЙ нижестоящей логикой, если regex его не увидит?» Если ответ — «весь шаг тихо пропускается» → дефект этого класса.
