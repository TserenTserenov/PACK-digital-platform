# DP.FM.148 — Regex-detector semantic blindspot

## Краткое описание

Failure mode при попытке закрыть качество текстов одним regex-детектором: regex видит только морфологию (символы, паттерны), не семантику (что такое «английский термин», «голый маркер успеха»).

## Симптомы

- 98% нарушений в логе = одно тривиальное орфографическое правило (длинное тире).
- Семантические нарушения (A2 английский без перевода, A10 маркеры статуса) = false-negative, детектор не замечает.
- Создаёт видимость работы детектора при отсутствии coverage.

## Контекст

Из 56 нарушений за 3 дня (WP-388 аудит): 55 — длинное тире (BASE5), 1 — путь как подлежащее (A1). A2 — 14 случаев в ручном аудите, детектор их не заметил. Coverage по правилам: 1 из 11 = 9%.

## Диагностика

Тест: «сколько разных правил сработали хотя бы раз за неделю?» — если 1 из N → coverage = 1/N → детектор не покрывает большинство правил.

## Решение

Либо добавить словарь+model для семантики, либо явно задокументировать ограничение: regex закрывает орфографические правила (~10-20%), семантические — нет.
