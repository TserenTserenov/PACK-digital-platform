# DP.FM.366 — vacuous ok при нулевых гейтах в проверке протокола

## Паттерн

`check-trace-satisfaction`, запущенная против `day-close/SKILL.md`, находила 0 гейтов в файле и на этом основании возвращала «всё в порядке» — формально верно (все 0 гейтов удовлетворены), но фактически такой результат ничего не гарантирует, если сама проверка не должна была найти 0.

## Механизм

1. Скрипт ищет разметку гейтов ([[gate]]) в целевом файле по определённому паттерну
2. Если файл использует другой формат разметки/структуру, скрипт находит 0 совпадений
3. «0 из 0 удовлетворено» логически истинно (vacuous truth), но маскирует то, что сам скрипт не смог распарсить реальные гейты файла

## Почему опасен

Vacuous ok неотличим внешне от «в файле действительно нет гейтов» — единственный способ различить два случая — заранее знать ожидаемое количество гейтов, что снижает автономность проверки.

## Лечение

Проверка на пустой результат (0 найденных гейтов) сопровождается явным warning/failure, если ожидается ненулевое число, вместо тихого прохождения; после фикса `check-trace-satisfaction` реально находит 18 позиционных шагов в целевом файле.
