# [DP.FM.019] L3 Identity Leak

## Суть паттерна

§9 (авторское) CLAUDE.md в FMT-шаблоне содержит конкретные авторские идентификаторы (имя, пути `/Users/<author>/IWE/`, Telegram ID, UUID) вместо `{{PLACEHOLDER}}` или обобщённых примеров. При обновлении шаблона через `update.sh` или при использовании FMT как основы нового IWE эти данные распространяются на всех пользователей.

**Конкретный инцидент:** Имя пилота в §9 S-33 — последний остаток rollback'а 22-23 апр 2026 — попало в FMT и распространилось бы на всех пользователей шаблона.

## Архитектурный контекст

| Секция CLAUDE.md | Источник при update.sh | Требование |
|---|---|---|
| §1-§8 (платформенное) | FMT с `{{PLACEHOLDER}}` substitution | Нейтральные заглушки ✅ |
| §9 (авторское) | FMT напрямую, **без sync из авторского IWE** | Только `{{PLACEHOLDER}}` или обобщённые примеры ⚠️ |

**Ловушка:** template-sync.sh берёт §9 из FMT напрямую, не из авторского IWE (это защита от случайного переноса авторских константы). Поэтому новые §9-правила нужно добавлять в FMT напрямую с заглушками.

## Механизм

1. Автор пишет правило в §9 авторского IWE с конкретным именем
2. При ручном переносе в FMT забывает заменить имя на `{{PILOT_NAME}}`
3. template-sync.sh берёт §9 из FMT как есть
4. `update.sh` у всех пользователей раскладывает FMT → личное имя появляется в IWE каждого пользователя

## Правило предотвращения

**§9 FMT должен содержать только `{{PLACEHOLDER}}` или обобщённые примеры, не конкретные имена/ID/пути.**

**Проверка перед каждым template-sync:**

```bash
# Найти начало §9 и проверить на имена собственные и личные идентификаторы
# grep -n "^## 9\." FMT-exocortex-template/CLAUDE.md
# Затем вручную: нет ли личных имён, UUID, telegram ID, абсолютных путей /Users/<name>/?
```

**При добавлении нового §9-правила:**
1. Добавить в `FMT/CLAUDE.md §9` с заглушками `{{PLACEHOLDER}}`
2. Авторские константы (имя, paths) → `extensions/` или авторский `params.yaml`
3. Запустить `template-sync.sh --check` для верификации
