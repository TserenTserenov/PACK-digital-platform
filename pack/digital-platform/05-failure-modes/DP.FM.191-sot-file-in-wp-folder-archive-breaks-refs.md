# DP.FM.191 Source-of-truth в смертной папке РП: закрытие РП ломает внешние ссылки

## Паттерн

SoT-файл (реестр состояний, каталог типов, схема, реестр осей) создан внутри рабочей папки РП (`inbox/WP-NNN/<file>`). Внешние файлы — платформенные правила, CLAUDE.md, спецификации — ссылаются на него по текущему пути.

При закрытии РП папка переезжает в архив. Внешние ссылки становятся битыми. Сигнала нет: нет явной ошибки при запуске, агент не может найти файл только в момент инцидента.

## Признаки

- Файл создан как временный артефакт РП, но приобрёл внешних потребителей.
- На файл ссылаются ≥2 платформенных документа или правила.
- Lifecycle файла не совпадает с lifecycle рабочей папки.

## Тест

> «Переживёт ли место хранения файла закрытие работы, которая его породила?»

Нет + внешние ссылки → файл требует переезда в стабильное место **до** закрытия РП.

## Стабильные альтернативные места

| Тип файла | Место |
|-----------|-------|
| Доменный реестр / каталог | `PACK-*/pack/domain/02-domain-entities/` |
| Реализационный каталог | `DS-*/docs/` |
| Операционный справочник агентов | `memory/*.md` |
| Lazy-правило агента | `.claude/rules-lazy/*.md` |

## Митигация

При создании нового SoT-файла внутри папки РП:

1. Спросить: «Будет ли этот файл нужен после закрытия РП?»
2. **Да** → разместить сразу в стабильном месте.
3. **Да, место неизвестно** → создать временно + пометить `# TODO: migrate before WP close` + добавить в чеклист закрытия РП.
