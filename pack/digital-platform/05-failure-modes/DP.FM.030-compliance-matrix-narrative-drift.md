# [DP.FM.030] Compliance Matrix Narrative Drift

## Суть паттерна

При заполнении compliance-матрицы по факторам (Ф1 → Ф12 в отдельных коммитах) **нарратив-секция «Заметки по факторам»** обновляется реже, чем ячейки таблицы. Числа в тексте не совпадают с реальными counts — drift проявляется при независимом review.

Пример: `F2 narrative ❌6/N/A 2 vs matrix ❌5/N/A 3` — матрица была корректна, нарратив устарел.

## Механизм

1. **Ячейки заполняются инкрементально** — каждая фаза меняет несколько ячеек в разных факторах.
2. **Нарратив не синхронизируется автоматически** — агент обновляет ячейку, но не видит связанную нарратив-строку как обязательный апдейт.
3. **Числа в нарративе = ручной агрегат** — при изменении ячейки нужно пересчитать `❌N / ⚠️M / ✅K / N/A P`, что трудоёмко и часто пропускается.

## Где проявляется

| Документ | Риск |
|---------|------|
| 12-factor compliance matrix | Нарратив отстаёт от Ф-по-Ф заполнения |
| Security posture audit | Counts в executive summary расходятся с матрицей |
| Architecture review checklist | Текстовые выводы противоречат таблице баллов |

## Тест на провал

`grep -n "❌[0-9]" narrative_section` vs `awk '{count}' matrix_cells` — числа должны совпадать. Если нет — drift произошёл.

## Защита

**Правило:** При каждом изменении ячейки матрицы — обновить соответствующую нарратив-строку в **том же коммите**.

**Альтернатива:** Генерировать нарратив из матрицы скриптом (narrative = derived, не ручной).

**Применимость:** Любой документ со структурой «матрица + нарратив»: security posture, WP compliance, architecture review.

## Пример: WP-307 (12 мая 2026)

Independent reviewer указал расхождения: F2 narrative `❌6/N/A 2` vs matrix `❌5/N/A 3` (A1 → N/A); F12 narrative `N/A 15` vs matrix `N/A 18` (W5/X1/T1 closed). Матрица была корректна; нарратив обновлён для consistency.
