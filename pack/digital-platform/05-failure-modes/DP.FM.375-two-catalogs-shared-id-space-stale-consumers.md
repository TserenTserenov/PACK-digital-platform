# DP.FM.375 — общее ID-пространство двух каталогов маскирует устаревание

## Паттерн

Два каталога данных (учебный каталог и основной справочник, например `SA.CAT.001`) используют пересекающийся диапазон номеров (M-065..M-091), но развиваются независимо. Потребитель, продолжающий читать старый каталог, молча получает записи, семантически устаревшие относительно нового — совпадение номеров создаёт видимость валидности без реального соответствия.

## Механизм

1. Два каталога исторически используют один и тот же диапазон нумерации (общее происхождение)
2. Один каталог обновляется (новые переходы/значения под теми же номерами), другой остаётся как legacy
3. Потребитель, всё ещё привязанный к старому каталогу (например, через устаревший генератор), не получает сигнала об устаревании — номера по-прежнему «валидны» с его точки зрения

## Почему опасен

В отличие от явно удалённого/переименованного ID, коллизия номеров между двумя живыми каталогами не вызывает ошибку — потребитель молча продолжает работать с устаревшими данными неопределённо долго.

## Лечение

При обнаружении коллизии — либо развести номерные пространства (перенумеровать один из каталогов), либо явно вывести устаревший каталог/генератор, привязанный к нему.
