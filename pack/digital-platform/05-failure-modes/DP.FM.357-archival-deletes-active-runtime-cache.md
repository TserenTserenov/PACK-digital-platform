# DP.FM.357 — Массовая архивация удаляет активные runtime-кэши

## Паттерн

Скрипт массовой архивации закрытых рабочих продуктов удаляет содержимое `inbox/WP-N/cache/` вместе с самим РП, если РП формально помечен как архивированный. Проблема: некоторые директории `cache/` внутри архивированных WP-путей воссоздаются и используются активными скриптами независимо от статуса самого РП — их удаление ломает эти скрипты.

## Пример

`inbox/WP-425/cache/` — воссозданный runtime-кэш (WP-425 архивирован, но кэш живёт отдельной жизнью), удалён чужим коммитом при бэкфиле архивации 33 РП разом, хотя по факту используется тремя активными скриптами.

## Механизм

1. Скрипт архивации проверяет статус РП по frontmatter — `archived`
2. Удаляет всю директорию `inbox/WP-N/` включая `cache/` без проверки, использует ли что-то ещё эти файлы
3. Активные скрипты, ссылающиеся на путь кэша по абсолютному пути, начинают падать

## Почему опасен

- Статус РП (архивирован) и статус конкретной поддиректории кэша (используется/не используется) — разные вопросы, смешанные в одной операции удаления
- Массовая архивация (33 РП разом) увеличивает шанс задеть такой edge-case незаметно среди множества затронутых файлов

## Лечение

1. Перед массовым удалением `cache/` внутри архивируемого WP — проверить, ссылается ли на этот путь какой-либо активный скрипт (grep по кодовой базе)
2. Runtime-кэши, переживающие архивацию своего WP-контекста — переносить в отдельное, не привязанное к статусу РП место

## Связи

- Смежный принцип: не удалять на основе одного признака (статус РП), не проверив фактическое использование
