# DP.FM.292 — JWT-single-flag: достаточен для 1 продукта, ломается при N типах

## Паттерн

Архитектура с единственным boolean-флагом в JWT для авторизации — достаточна при бинарной модели (есть подписка / нет подписки), ломается при расширении продуктовой линейки до N типов продуктов.

## Детектор-триггер

В архитектурном документе одновременно присутствуют:
- «JWT-флаг обновляется раз в ~15 минут» (техническое ограничение)
- «Доступ зависит от типа продукта» (бизнес-требование, N типов)

→ Это сигнал явной дискуссии о design trade-off, не молчаливого продолжения.

## Последствие

JWT TTL (~15 мин) несовместим с актуальностью fine-grained доступа по N продуктам: пользователь купил/потерял доступ, но старый флаг ещё действует. Silent wrong permissions.

## Прецедент

WP-467: v1 = бинарная модель, один boolean-флаг в JWT достаточен. v2 = 11 типов продуктов (подписка, группа с наставником, пакет семинаров, записи, сообщество…). Флаг v1 не масштабируется. Пересмотр authorization design не был сделан явно — зафиксирован как FM.

## Fix

При расширении бизнес-модели (1 тип → N типов продуктов):
1. Явно поднять вопрос authorization design trade-off
2. Рассмотреть event-sourced read-model (DP.METHOD.187) вместо JWT-флага
3. Не продолжать с v1-дизайном молча
