# DP.FM.276 — Regex верификатора LLM-вывода: жёсткая пунктуация → ложный негатив

## Паттерн

Чеклист проверяет наличие жирного лейбла (`**Текст.**`) через regex с фиксированным суффиксом точки (`\.?`).
LLM генерирует лейблы с двоеточием (`**Текст:**`), без суффикса (`**Текст**`) или с `!`.
Regex не совпадает → ложный красный на реально присутствующем блоке.

## Пример

```python
# Антипаттерн: только точка
pattern = rf"\*\*{re.escape(label)}\.?\*\*"  # не принимает : или пустое

# Fix: вариативность пунктуации
pattern = rf"\*\*{re.escape(label)}[.:]?\*\*"
```

## Инцидент

WP-149 (`verify_form_content.py`, commit d863951):
чеклист отклонял `**В одном предложении:**` как «missing block».
Блок существовал; regex принимал только `.` или пустое.

## Диагностика

**Тест:** «Запустить верификатор на 10+ реальных примерах из прода, не только на unit-тестах».
Если ложных красных > 0 при корректном контенте → regex слишком строгий.

## Правило

При regex-верификации LLM-вывода закладывать вариативность пунктуации в конце синтаксических маркеров: `[.:]?` покрывает точку, двоеточие и отсутствие суффикса. LLM не строго следует единому стилю пунктуации.

## Применимость

Любой верификатор/чеклист LLM-вывода, использующий regex для структурных маркеров.
