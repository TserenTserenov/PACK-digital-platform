# DP.FM.189 — Hash-chain фикция: хэш без prev_hash

## Описание

Формула хэша события не включает хэш предыдущего события — только содержимое самого события. Результат: видимость цепочки при отсутствии её свойства. Злоумышленник с SQL-доступом подменяет запись двумя UPDATE и пересчитывает хэши — verify-скрипт и внешний анкор проходят чисто.

## Условие возникновения

- Журнал имеет поле `event_hash` / `integrity_hash`
- Формула: `hash(event_id || payload || timestamp)` — без `prev_hash`
- Verify-скрипт проверяет `hash(row) == stored_hash` — тест проходит при подмене + пересчёте двух хэшей
- Потребитель журнала полагается на «цепочку» как свидетельство неизменности

## Тест обнаружения

«Входит ли `prev_hash` в формулу нового хэша?» Нет → это не цепочка, а набор независимых контрольных сумм.

Дополнительный тест: «Подмени любую запись вручную, пересчитай её хэш и хэш следующей записи — обнаруживает ли verify-скрипт подмену?» Нет → failure mode активен.

## Митигация

1. `prev_hash` в формулу: `hash(event_id || prev_hash || payload || timestamp)`
2. Запрет UPDATE/DELETE на уровне хранилища (row-level security или append-only constraint)
3. Для уже записанной истории: открыть новую эпоху цепочки с явной пометкой `chain_epoch = N+1`
