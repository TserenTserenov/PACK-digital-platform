# DP.FM.423 — Обёртка с собственными опциями уводит команду из проверяемой позиции

## Паттерн

Резолвер «где в вызове начинается исполняемая команда» умеет пропускать голые имена типовых обёрток времени выполнения (`env`, `sudo`, `nohup`, `time`, `command`) — но не умеет пропускать саму обёртку ВМЕСТЕ с её собственными опциями и их аргументами (`timeout 5`, `nice`, `sudo -u nobody`, `env -i`, `xargs -n 1`). Первое слово ПОСЛЕ такой опции читается как имя реальной команды — неверно, потому что это ещё одна опция обёртки или её аргумент.

## Механизм

1. Резолвер видит обёртку (`timeout`) и пропускает её как «известное имя-обёртку».
2. Следующее слово (`5` — числовой аргумент опции `timeout`) резолвер трактует как имя реальной команды.
3. Проверочный шаблон (denylist `rm`, `-rf` и т.п.) применяется к неверно определённой «команде» (`5`) — реальная опасная команда (`rm -rf`) стоит на следующей позиции и в разбор не попадает.
4. Одна и та же прореха резолвера открывает обход сразу для всех guard'ов, которые полагаются на общий разбор позиции команды (запрет `rm -rf` И запрет опасных git-команд `add`/`reset`/`clean`/`push`/`stash` — оба разделяют один резолвер).

## Почему опасен

Не локален для одного guard'а: фикс одного потребителя резолвера не закрывает обход для остальных, использующих тот же общий разбор позиции — обе категории (`rm -rf` и опасные git-команды) были открыты одной и той же прорехой одновременно.

## Антипаттерн → Паттерн

- Антипаттерн: список «что пропустить перед именем команды» содержит голые имена обёрток без учёта того, что у обёртки могут быть СОБСТВЕННЫЕ опции с аргументами.
- Паттерн: резолвер пропускает обёртку ВМЕСТЕ со всеми её опциями и аргументами этих опций (по грамматике конкретной обёртки — `timeout <N>`, `sudo -u <user>`, `env -i`, `xargs -n <N>`), прежде чем считать следующее слово именем реальной команды. Список опций-несущих обёрток и их грамматика — общая инфраструктура резолвера, а не свойство отдельного guard'а.

## Тест обнаружения

«Взять любую опцию-несущую обёртку (`timeout N`, `nice`, `sudo -u X`, `env -i`, `xargs -n1`) перед заведомо запрещённой командой — распознаёт ли резолвер реальную команду на правильной позиции?» Нет → обход существует для ВСЕХ guard'ов, использующих этот резолвер, не только для того, на котором обход был впервые замечен.
