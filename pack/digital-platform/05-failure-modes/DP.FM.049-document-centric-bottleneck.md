# DP.FM.049: Document-centric analysis yields false bottleneck

## Описание

Constraint-analysis в системе с формализованными обещаниями (DP.SC.NNN) запускается с чтения governance-документов (план, стратегия, направление-файл, WeekPlan). Результат — «bottleneck = пункт X не закрыт в плане», тогда как реальный constraint — operational gap между обещанием потребителю и фактической поддержкой обещания.

**Симптом:** план-документы обновляются на основе анализа план-документов; реальные потребители не получают обещанный сервис; constraint identified как «надо доделать пункт N плана», а не «обещание Y не подкреплено активной реализацией».

**Пример (WP-250 v8 → v9, 20 мая 2026):** v8 (документо-центричный) → bottleneck = «марафон не запущен». v9 (после SC-first сканирования через DP.ROLE.054) → bottleneck = «operational gap activation» — конкретный gap между DP.SC.NNN и фактической реализацией.

## Корень

Документо-центричный анализ оптимизирует УЖЕ ЗАФИКСИРОВАННЫЕ артефакты:

- План — намерение, не обязательство потребителю.
- Стратегия — направление, не контракт.
- Направление-файл — фокус, не сервис.

Эти артефакты — внутренние для governance. Constraint в системе живёт на границе с потребителем (Service Clause). Анализ внутренних артефактов без проверки границы → false-bottleneck на уровне «не дописали план», а не «не выполнили обещание».

## Детектор

Перед началом constraint-analysis ответить: «начали ли мы с DP.SC.NNN или с current/WeekPlan.md?»

- Начали с WeekPlan/Strategy/направление-файла → высокий риск false-bottleneck. Пересобрать с DP.SC.
- Начали с DP.SC.NNN (что обещано) → проверить, где обещание не подкреплено активной реализацией → там constraint.

## Решение

SC-first сканирование (DP.ROLE.054 Ф2 перед Ф3):

1. Прочитать все активные DP.SC.NNN в scope системы-конвейера.
2. Для каждого SC — проверить, есть ли активная реализация (роль, скрипт, hook, MCP-инструмент), которая выполняет обещание.
3. SC без активной реализации = operational gap. Constraint — здесь, не в плане.

Документ-сканирование (план, стратегия) — только дополнение SC-сканирования, не замена.
