# DP.FM.073 — Protocol Coverage Gap — Mentioned but Not Enforced

## Описание

Протокол или SKILL.md упоминает, что артефакт переходит из состояния A в B «при событии X или Y» (например: «архивация при Day Close или Week Close»), но шаг исполнения формально описан только для одного из событий. Артефакт зависает в состоянии A до срабатывания позднего события — недели лежит «вчерашний» документ в `current/`, недели не закрытый WP в `inbox/`.

«Перечисление точек срабатывания в свободном тексте ≠ реализованный шаг в чек-листе протокола.»

## Условие возникновения

- Документ верхнего уровня (SKILL.md, README, спецификация) описывает lifecycle артефакта в формате «при X или Y»
- Соответствующий протокол нижнего уровня (memory/protocol-close.md, скрипт-сценарий) реализует шаг только для одного из перечисленных событий
- Нет автоматической проверки (Day Open checks, smoke-test) на залежавшийся артефакт
- Зрительно симптом маскируется: один из перечисленных триггеров (Week Close) всё-таки срабатывает раз в неделю → артефакт «как-то архивируется» → ложное ощущение, что система работает

## Fix

1. **Снять рассинхрон между документом и протоколом** — если в SKILL.md/README сказано «при X или Y», то в обоих протоколах X и Y должен быть отдельный шаг с конкретной командой (`git mv`, `move-to-archive.sh`, etc.).
2. **Добавить detector** — Day Open / smoke-test проверяет инвариант: «в `current/` нет артефактов вчерашнего дня». BLOCKING при нарушении.
3. **Альтернатива (если шаг сложен)** — вынести в отдельный скрипт `archive-lifecycle.sh`, который вызывается из всех релевантных протоколов (Day Close, Week Close, ручной /archive). Один шаг — одна реализация.

## Тест (триггер распознавания)

«Документ говорит "при X или Y"? Открой протокол X — есть ли там реальный шаг? Открой протокол Y — есть ли там реальный шаг? Совпадают ли они?» Нет → coverage gap.

Дополнительный тест: «Сделай grep в репо на артефакт, который должен архивироваться — есть ли он в `current/` старше суток?» Да → шаг не исполняется на ранней точке.

## Применимость

- Протоколы ОРЗ-фрактала (Quick Close, Day Close, Week Close, Month Close)
- Lifecycle артефактов в governance-репо (DayPlan, WP-контексты, sessions/)
- Любой документ с фразой «при событии X или Y» в описании lifecycle
- CI-pipelines с условным triggering («запускается при push или PR» — а реально только при PR)
