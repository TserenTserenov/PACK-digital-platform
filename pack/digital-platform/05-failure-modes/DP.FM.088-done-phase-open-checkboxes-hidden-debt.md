# DP.FM.088: Done-фаза с открытыми `[ ]` — hidden technical debt

## Симптом

Фаза WP-контекста помечена `status: done`, но в теле фазы остаются незакрытые `[ ]`. При следующем открытии контекст-файла читатель видит `done` и пропускает тело — открытые задачи остаются невидимыми.

## Механизм

Закрывающий агент/пилот маркирует фазу `done` без явного принятия решения по каждому `[ ]`:
- часть `[ ]` — настоящий defer (scope cut, нет бюджета)
- часть `[ ]` — молчаливая недоделка (агент забыл / решил «само исчезнет»)

Различить их при следующей сессии невозможно — нет метки о намерении.

**Пример:** WP-358 — 5 `[ ]` в done-фазах помечены как «MVP-defer», но 2 из них — §Б Security ArchGate-чеклист и README — не могут быть defer по контрактным причинам.

## Тест (Gate при закрытии фазы)

Сканировать все `[ ]` в теле фазы. Для каждого принять явное решение:
1. `[x]` — реально выполнено (закрыть сейчас)
2. `[OPEN DEBT, peer-session YYYY-MM-DD, ~Nh]` — явный defer с бюджетом
3. Перенести `[ ]` в следующую фазу с datestamp

Молчаливые `[ ]` при `status: done` = ошибка.

## Различение

`[ ]` как «MVP-defer» (явно задокументировано, есть дата/бюджет возврата) ≠ `[ ]` как молчаливая недоделка.

## Применимость

WP-контексты, Sprint-ретро, любые фазовые документы с чек-боксами. Критично для security-чеклистов (§Б ArchGate) — их defer требует явного разрешения пилота.
