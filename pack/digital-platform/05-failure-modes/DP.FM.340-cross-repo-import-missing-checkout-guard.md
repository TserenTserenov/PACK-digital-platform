# DP.FM.340 — Cross-repo импорт на уровне модуля без checkout-guard

## Паттерн

Модуль импортирует зависимость из другого репозитория (checkout) на уровне модуля — при отсутствующем или перемещённом checkout сторонний импорт падает не там, где ожидается, а ломает импорт всего модуля, использующего его для несвязанной функциональности.

## Конкретный случай

Отсутствующий/перемещённый checkout `FMT-exocortex-template` ломал рендеринг персонального руководства для КАЖДОГО пилота уже на этапе импорта модуля — задолго до того, как рендеринг вообще должен был обратиться к этому checkout.

## Почему это происходит

Import-time зависимость от cross-repo пути не имеет явной проверки наличия. Любой сбой инфраструктуры (переезд, ребрендинг репо, временное отсутствие checkout) превращается в блокирующий сбой ВСЕГО модуля, а не деградацию конкретной функции.

## Профилактика

Cross-repo импорт на уровне модуля → явный guard (try/except с осмысленной деградацией, или ленивый импорт внутри функции, которая реально использует зависимость), не голый `import` в заголовке модуля.
