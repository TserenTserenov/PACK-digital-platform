# DP.FM.134 — Раскол словаря между учебными и aux-подразделами

## Симптом

При переписке многоуровневого учебного раздела (5-7 основных глав + 3-5 aux-подразделов: «Понятия», «Упражнения», «Контрольные вопросы», «Выводы») переключение регистра словаря с rules-кодов на учебный язык **не доходит до aux-секций**.

Автор редактирует основной массив (например, 6.01-6.07: ступени, gate, переход), aux-подразделы (6.08-6.11: концепты, упражнения, вопросы, выводы) остаются на исходном rules-словаре:

- технические коды слотов RCS (`bh.*`, `cp.*`)
- имена внутренних ролей (Аттестатор, Диагност)
- термин «gate» в учебных вопросах вместо «переход» / «рубеж»

Дополнительный риск: aux-таблицы понятий и шапочные списки ступеней не синхронизированы с основным текстом — выпадает одна ступень («Дисциплинированный»), добавлена несуществующая («Мастер»).

## Корень

Failure mode **не ловится smoke-проверкой** (структура валидна, lint pass): требует cold-context content-review всего раздела. Автор работает по «главному скелету» (5-7 глав) и считает aux «приложением» — внимание угасает.

## Профилактика

При terminologической миграции guide — обязательный grep по rules-кодам и техническим именам ролей **по ВСЕМ файлам подраздела**, не только по основным главам:

```bash
grep -rE "(bh\.|cp\.|Аттестатор|Диагност|\\bgate\\b)" <guide-section>/
```

При обнаружении несоответствия — повторный проход по aux. Дополнительно — cold-context review (sub-agent) с явной инструкцией «проверь шапки, списки понятий, контрольные вопросы».

## Применимо к

- WRITING-PIPELINE для multi-subsection guides
- Любые многоступенчатые учебные материалы с aux-разделами
- Pack-документы с разделами «Понятия / Примеры / Тесты»
