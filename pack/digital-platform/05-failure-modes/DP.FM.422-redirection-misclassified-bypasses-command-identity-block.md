# DP.FM.422 — Перенаправление, принятое за часть команды/переменную, обходит блокировку по идентичности

## Паттерн

Guard блокирует класс «команда печатает весь секрет/окружение разом» по идентичности команды (denylist `env`/`printenv` без аргумента). Разбор аргументов у потребителей этой проверки не выделяет перенаправление (`>`, `>>`, `2>&1`, слитную цель `>out.txt`, номер дескриптора) в отдельную синтаксическую категорию — оно засчитывается либо как часть оборачиваемой команды, либо как позиционный аргумент/имя переменной. Форма с перенаправлением (`env > out.txt` вместо заблокированного `env | sort`) обходит ровно ту проверку, которая только что была поставлена.

## Механизм

1. Guard распознаёт опасную команду по её «голому» виду (`env`, `printenv` без аргументов = печатает всё).
2. Автор добавляет перенаправление вывода вместо пайпа — семантически эквивалентно для цели «получить содержимое секрета наружу», но синтаксически выглядит иначе для разбора аргументов.
3. Разбор аргументов не содержит отдельной категории «это перенаправление» — токен утекает либо в «часть команды», либо в «позиционный аргумент/имя переменной».
4. Guard не видит признак опасности там, где его разбор аргументов классифицировал токен неправильно.

## Почему опасен

Обходит ИМЕННО ТУ проверку, которая была недавно добавлена специально для этого класса угрозы — создаёт ложное чувство защищённости: проверка формально есть и работает на очевидном случае (`env | sort` блокируется), но не на семантически эквивалентном (`env > out.txt`).

## Антипаттерн → Паттерн

- Антипаттерн: каждый потребитель разбора аргументов (резолвер исполняемого, каждый класс bulk-enumeration проверки) сам решает, что перед ним — перенаправление, часть команды или переменная.
- Паттерн: один разбор перенаправления (`redirection_span`), которым пользуются ВСЕ потребители.

## Тест обнаружения

«Может ли то же самое опасное действие быть выражено через перенаправление вместо пайпа или прямого аргумента — и если да, распознаёт ли разбор аргументов guard'а перенаправление как отдельную синтаксическую категорию?» Нет → обход существует.

## Связи

- `DP.FM.192` (subshell-redirect-silences-exit-code) — сосед по теме «перенаправление ломает разбор», но иной механизм: там перенаправление в subshell скрывает реальный exit-код от вызывающего кода; здесь перенаправление обходит security-guard из-за неверной классификации токена. Не дубликат.
- WP-482 Ф7. Побочно закрыта смежная дыра: `2>&1 cat <секретный_файл>` проходил мимо блокировки чтения, потому что исполняемым объявлялась цифра дескриптора.
