# DP.FM.202 — N>1 файлов-реестров одной сущности: гарантированный drift

## Описание

В одном репозитории существует N>1 файлов, каждый из которых претендует на роль «реестра» одного класса сущностей. Без механизма derivation (generated from SoT + build step) все N файлов расходятся по содержанию: каждый содержит свой subset записей, записи добавляются в разные файлы независимо.

## Пример

WP-73 (IT-платформа Aisystant): при уборке inbox обнаружены 3 файла с пересекающимися заголовками «сервисы платформы». У каждого свой subset: 8 сервисов в первом, 12 во втором, 6 в третьем, пересечение 4. Ни один не являлся полным.

## Тест обнаружения

«Если добавить запись в файл A — нужно ли обновлять файлы B и C?» Да → один из них лишний или derivation сломана.

## Инвариант

Один класс сущностей = один canonical реестр. Дополнительные файлы допустимы только как derived — с явным build-шагом и запретом ручного редактирования.

## Митигация

1. Аудит: найти все файлы с пересекающимися структурами (`grep -r` по общим заголовкам)
2. Выбрать canonical source (один файл — source-of-truth)
3. Остальные: удалить или перевести в generated + добавить guard от ручного редактирования
4. CI test: нет файлов с аналогичной структурой кроме canonical
