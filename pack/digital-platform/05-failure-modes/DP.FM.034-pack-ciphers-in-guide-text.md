# DP.FM.034 — Pack-шифры в теле текста руководства

## Описание

Файлы подразделов руководства содержат Pack-шифры (PD.FORM.NNN, PD.METHOD.NNN, FORM.NNN и т.п.) в читаемом теле текста, а не только во frontmatter. Нарушение ограничения #1 конвейера guide authoring.

## Симптом

В секциях body (особенно «Определение из источника») присутствуют строки вида:
- `(PD.FORM.089)`, `(PD.METHOD.008)` — в скобках внутри текста
- Прямые упоминания шифров в предложениях («согласно FORM.089 §6.1...»)

Системный признак: если нарушение в ≥5 файлах одного раздела → ошибка в LLM-шаблоне генерации, не в отдельных файлах.

## Дополнительный симптом

Присутствие неизвестных рубрик (`cp.cre`) во frontmatter — orphan-reference, ломает линтер Этапа 6.

## Причина

Шаблон LLM-генерации не фильтрует Pack-шифры в теле. Шифры добавляются как «ссылки на источник» внутри текста, тогда как правило требует их только во frontmatter.

## Последствия

- Нарушение ограничения #1 конвейера (Pack-цифры не для читателей)
- Orphan-reference рубрик ломает линтер
- Необходимость ручного прогона grep-фикса по всем файлам раздела

## Тест обнаружения

```bash
grep -rE 'PD\.FORM\.|PD\.METHOD\.|FORM\.[0-9]' <section-dir>/ \
  | grep -v "^[^:]*:---" \
  | grep -v "^[^:]*:cp_check:\|^[^:]*:bh_check:\|^[^:]*:subsection_id:"
```

Если вывод непустой → FM присутствует.

## Профилактика

При pipeline-review guide-подразделов обязательно прогонять тест обнаружения до коммита. При массовом обнаружении (≥5 файлов) — пересмотреть LLM-шаблон генерации, а не исправлять файлы поодиночке.
