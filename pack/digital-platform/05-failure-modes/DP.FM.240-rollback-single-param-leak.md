# DP.FM.240 — Откат одного параметра без связанного: риск перетекает

## Паттерн

При откате плана (переход A→B) изменяется только один видимый параметр (например, дата), но связанный с ним параметр (например, порядок действий) остаётся прежним. Риск ветки A в неизменном виде переносится в ветку B.

## Механизм

1. Ветка A несёт риск через сцепку двух параметров (P1: дата; P2: порядок — набор до прогона)
2. Обнаруживается проблема → откат A→B
3. Откат меняет только P1 (сдвигает дату)
4. P2 (порядок набор-до-прогона) не трогается → сцепка риска сохраняется
5. Ветка B несёт тот же риск, что ветка A

## Почему опасен

Откат кажется исправлением, но косметический: исходный риск жив, только под другой меткой версии плана.

## Пример — WP-437

Ветка A: дата 16 июля + набор открыт. Риск: набрали участников до прогона механики.
Откат A→B: сдвинули дату. Набор остаётся открытым.
Итог: риск ветки A перетёк в B без изменений.
Корректный откат: сдвинуть дату И заморозить набор до завершения прогона.

## Тест отката

«Снимает ли откат именно тот риск, ради которого делается — или только видимый параметр?»
- Только видимый → откат косметический → найти и адресовать все связанные параметры.

## Профилактика

При проектировании отката:
1. Явно выписать сцепки: «какие ещё параметры связаны с P1?»
2. Для каждой сцепки решить: «меняется P2 вместе с P1?»
3. Откат = изменение всего сцепленного набора, не только одного параметра.
