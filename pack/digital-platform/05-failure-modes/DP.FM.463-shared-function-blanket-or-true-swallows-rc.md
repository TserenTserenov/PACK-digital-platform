# DP.FM.463 — `|| true` внутри общей функции глотает код возврата для всех вызывающих

## Тезис и механизм ошибки

Общая (переиспользуемая) функция завершает свой вызов внешнего действия безусловным подавлением ошибки — `telegram_send "$msg" || true` — «чтобы не ронять скрипт из-за уведомления». Тем самым она возвращает 0 при любом исходе ВСЕМ вызывающим. У одного из вызывающих ниже по коду стояла собственная ветка на случай неудачи (`primary_alert … || log "primary alert delivery failed"`) — она стала мёртвым кодом: условие никогда не наступает, сбой доставки первичного алерта не логируется и не эскалируется.

Прецедент: новая обёртка дедупа уведомлений `tg_notify_dedup` в `scripts/day-open-alert.sh` (DS-my-strategy). Найдено холодным ревью субагента до деплоя, не живым инцидентом.

Решение «важен ли этот сбой» зависит от контекста вызова: для вторичного уведомления доставка может быть best-effort, для первичного алерта — обязательной с fallback. Общая функция этого контекста не знает; подавляя код возврата у себя, она принимает ценностное решение за все места вызова разом и лишает их возможности решить иначе. Ошибка молчалива вдвойне: скрипт «работает» (код 0), а мёртвая ветка `|| log` выглядит в коде как действующая защита.

## Диагностический принцип

Общая функция ПРОПУСКАЕТ статус наружу (код возврата последней команды или явный `return $rc`), а политику выбирает место вызова — `|| log`, `|| true`, `|| exit 1` — по своей асимметрии риска.

- **Антипаттерн:**
  ```bash
  tg_notify_dedup() {            # общая функция
    …
    telegram_send "$msg" || true # решает за всех: «не критично»
  }
  tg_notify_dedup "$primary" || log "primary alert delivery failed"   # ветка мертва
  ```
- **Паттерн:**
  ```bash
  tg_notify_dedup() {
    …
    telegram_send "$msg"         # статус — наружу
  }
  tg_notify_dedup "$primary"   || log "primary alert delivery failed"  # обязательное
  tg_notify_dedup "$secondary" || true                                  # best-effort, решено здесь
  ```

## Границы

Если общая функция обязана быть «никогда не роняющей» (например, вызывается из ловушек), она возвращает статус структурно (код возврата, переменная, stdout-маркер), а не глушит его: «не ронять» ≠ «не сообщать».

## Проверка

«Внутри общей/переиспользуемой функции стоит безусловное подавление кода возврата (`|| true`, `2>/dev/null || true`, `return 0` после сбоя)? Хотя бы одно место вызова этой функции имеет собственную ветку `|| …`?» Оба «да» → воспроизведён DP.FM.463: ветка вызывающего никогда не выполнится. Механическая проверка: `grep -n '|| true' lib/*.sh` внутри тел функций + `grep -n '<имя_функции> .* ||' callers` — пересечение множеств.
