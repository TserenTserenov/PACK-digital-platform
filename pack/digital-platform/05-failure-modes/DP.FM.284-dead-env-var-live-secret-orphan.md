# [DP.FM.284] Dead Env Var with Live Secret

## Суть паттерна

При переходе с одного LLM-провайдера (или ключа) на другой команда меняет код и env-vars локально, но **забывает убрать старую env-переменную из деплой-платформы** (Railway, Render, Fly.io и т.д.). Код её уже не читает — потребителя нет — но ключ живёт в сервисе, имеет права и занимает квоту.

## Инцидент

WP-399 аудит расходов Anthropic API: сервис `iwe-llm-proxy` в Railway содержал `ANTHROPIC_API_KEY` как env var. Код прокси использует только `OPENROUTER_API_KEY`; Anthropic-ключ не читается ни одним файлом. Ключ — живой, с теми же правами, но без потребителя.

## Механизм

1. Провайдер A → провайдер B: разработчик меняет код (`OPENROUTER_API_KEY`), добавляет новую env-var.
2. Старая env-var (`ANTHROPIC_API_KEY`) остаётся — «не мешает», delete не нажали.
3. Периодический аудит кода (grep по использованию) ключ не найдёт: ключ в платформе, не в коде.
4. Риски: ротация не проводится (зачем? — «не используется»), при утечке платформы ключ действующий.

## Тест на провал

`grep -r ANTHROPIC_API_KEY <codebase>` — ни одного результата, но Railway Console показывает env var — FM.284.

## Детектор

```bash
# Для каждого env var в деплой-платформе:
# 1. Получить список env vars сервиса
# 2. Для каждой: grep -r "ENV_VAR_NAME" <codebase>
# 3. Если grep пустой → dead var → кандидат на удаление
```

При аудите: `grep ANTHROPIC_API_KEY` по env-vars всех сервисов + сверить, читает ли его код.

## Защита

1. **Аудит orphan env vars при смене провайдера:** после любого переключения — проверить все env vars платформы на предмет отсутствия grep-результатов в коде.
2. **Принцип минимальных прав в env:** если ключ не читается — удалить немедленно.
3. **Ротация как аудит:** при ротации секретов — список всех мест использования. Место без кода-потребителя → удалить var, а не ротировать.
