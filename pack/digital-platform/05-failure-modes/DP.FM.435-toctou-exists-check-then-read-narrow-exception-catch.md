# DP.FM.435 — Гонка проверки и чтения файла; неполная обработка ошибок чтения

## Тезис

Предварительная проверка существования файла не гарантирует успешного последующего открытия. Ошибка чтения также не доказывает физического отсутствия источника. При обработке набора файлов необходимо сохранять различие между отсутствием, недоступностью чтения и некорректным содержимым.

## Механизм 1: состояние меняется между проверкой и чтением

Между isfile()/exists() и open() файл может исчезнуть, сменить тип или стать недоступным. Результат предварительной проверки не описывает состояние последующей операции. В описанном случае ошибка чтения дневного журнала могла включить запасной поиск по git log, предназначенный для иного условия — отсутствия самого источника.

Решение о запасном пути должно опираться на фактическую классификацию отказа согласно контракту источника, а не на предположение, что состояние после exists() неизменно.

## Механизм 2: обработчик покрывает только ошибки парсера

Перехват только yaml.YAMLError не покрывает ошибки открытия, прав доступа или декодирования. Эти ошибки возникают до разбора либо вне библиотеки парсера; исправление окна гонки само по себе не расширяет их обработку.

Набор ожидаемых отказов определяется всем путём чтения. Разные причины не следует сворачивать в один успешный запасной результат.

## Границы

Пропуск повреждённого элемента допустим только по контракту обработки, с явной отметкой неполноты результата. Если обязательный вывод требует всех источников, недоступность одного не превращается в «всё проверено». Этот документ не рекомендует безусловно перехватывать любые исключения или продолжать после каждого отказа.

## Проверка

Для первого механизма отдельно внедряется удаление между проверкой и открытием; проверяется классификация и допустимость запасного пути. Для второго независимо внедряются отказ доступа, неверная кодировка и ошибка разбора.

Ожидаемые исходы задаются до прогона: состояние источника и итоговый вывод остаются честными, другие элементы обрабатываются только там, где это разрешено контрактом. Прохождение одного набора сценариев не засчитывает второй механизм.
