# [DP.FM.286] Silent Semantic Loss on Hot-File Compression

## Суть паттерна

При сжатии (compaction) hot-файлов контекста (CLAUDE.md, distinctions.md, MEMORY.md) LLM-агент может **удалить или деградировать семантику правил** — без ошибки, без warning, без явного симптома в момент сжатия. Детектор противоречий базы знаний срабатывает только на downstream-симптом: агент начинает путать термины или нарушать правила в последующих ходах. Разрыв: потеря произошла в ходе N (сжатие), обнаружение — в ходе N+1 или N+2 (неправильное действие).

## Инцидент

WP-429 (детектор непротиворечивости базы знаний) Ф4-Ф5: детектор проверяет семантическую согласованность после хода агента. Найден структурный пробел: при сжатии hot-файла детектор не срабатывает на сам факт сжатия, только на ошибку агента в следующем ходу. Тихая потеря (semantic loss) не обнаруживается до момента проявления в действии.

## Механизм

1. LLM-сжатие hot-файла (например, Kimi уплотняет CLAUDE.md).
2. Из hot-файла удаляется «косметическая» строка, несущая смысловой инвариант.
3. В момент сжатия — нет ошибки, нет warning.
4. В ходе N+1 агент действует по деградированному контексту → нарушение правила.
5. Детектор срабатывает на нарушение (downstream), не на сжатие (upstream).

## Принцип диагностики

**Тест детектора:** «Детектор срабатывает до или после ущерба?»
- До (upstream-детектор) — верно.
- После (запаздывающий детектор) — FM.286.

## Детектор

Контур A: триггер на момент **сжатия** (commit с изменением hot-файла), а не на ошибку агента.
Алгоритм: при коммите, затрагивающем `CLAUDE.md`/`distinctions.md`/`MEMORY.md` → автоматическая проверка семантической целостности удалённых строк (против эталона или контрольных утверждений).

## Защита

1. **Upstream-триггер:** hook на commit hot-файла → слой-1 семантическая проверка удалённых строк.
2. **Freeze-зоны:** блоки hot-файлов, несущие критические инварианты, маркировать `# do not compress` (аналог `# attribution: do not remove` для shell-снипетов).
3. **Порядок move-then-trim:** при slim-е — сначала перенести содержимое в lazy, потом срезать из hot (необратим обратный порядок — см. DP.M.384).
