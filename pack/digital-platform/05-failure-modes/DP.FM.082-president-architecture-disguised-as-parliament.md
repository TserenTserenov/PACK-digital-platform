# DP.FM.082: «4 кирпича = Президент» — Парламент-антипаттерн с единым посредником

## Симптом

Дизайн называется «Парламент», но использует единый посредник (дворецкий, butler, proxy, gateway) с видением содержимого всех доменов памяти.

## Паттерн ошибки

Поэтапная архитектура (4 кирпича: дворецкий → рабочий стол → допуски → команды) внешне выглядит как Парламент, но дворецкий — единый посредник с полным доступом → провал Парламент-теста.

## Тест-детектор

> «Знает ли посредник содержимое всех доменов?»

- **Да** → Президент-архитектура (антипаттерн), независимо от именования
- **Нет** → может быть Парламентом

## Триггеры

- Единый «координирующий агент» с read/write ко всем доменам
- Butler / proxy / gateway с кешем от нескольких доменов
- Архитектура с «единой точкой доступа» без domain isolation

## Решение

Применить DP.M.091 (Scope Guard) + разделить доступ по доменам. Координатор должен знать ТОЛЬКО имена доменных агентов, не содержимое.
