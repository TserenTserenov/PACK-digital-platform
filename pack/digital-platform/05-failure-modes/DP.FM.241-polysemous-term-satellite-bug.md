# DP.FM.241 — Полисемия термина-источника: баг-спутник при формализации

## Паттерн

При формализации нового различения «A ≠ B» оба термина (A, B) заимствуются из существующего корпуса. Если один из терминов полисемичен (имеет два+ значения), новое различение наследует двойственность и порождает «баг-спутник»: читатель может подставить любое из значений, и различение становится бессмысленным или противоречивым.

## Механизм

1. Термин T имеет значения T1 и T2 в разных контекстах.
2. Формализуется различение «T ≠ X».
3. При чтении подставляется T2 вместо T1.
4. Возникает «T1 — это не T2» (тавтология или нонсенс вместо различения).

## Пример

**Термин «SPF»** значит две разные вещи:
- SPF как **форма доменного пространства** (структурный шаблон в Base, платформенный)
- SPF как **заполненный домен** (конкретный Pack)

При формализации различения «уровень принципов (TPF) ≠ слой репозиториев (DS)» использовали «SPF» в обоих смыслах без явного разведения. Результат: баг-спутник «SPF — это не SPF», который блокировал понимание основного различения.

## Диагностика

«Читает ли фраза различения одинаково при подстановке каждого значения полисемичного термина?»
- Если нет → термин полисемичен → требует разведения перед построением различения.

## Профилактика

Перед фиксацией нового различения:
1. Выписать все ключевые термины различения.
2. Для каждого: есть ли у него второй смысл в этом же корпусе знаний?
3. Если да → построить таблицу соответствия «термин → значение в данном контексте» и закоммитить её первой.
4. Только после разведения — строить новое различение поверх.
