# DP.FM.245 — Inline-комментарий не обходит валидатор присутствия литерала

## Паттерн

Разработчик пытается «обойти» pre-commit-валидатор, который проверяет наличие запрещённого литерала в файле, добавив inline-комментарий (`... # ok`) в конце строки. Валидатор всё равно блокирует: он сканирует наличие подстроки (или фильтрует строки по **первому** символу `#`), а не понимает inline-комментарий как исключение. Литерал физически остаётся в файле → проверка срабатывает.

## Пример

```bash
# FMT issue #215: валидатор запрещает литерал имени governance-репо в update.sh
GOVERNANCE="DS-strategy"        # ok   ← НЕ помогает: литерал "DS-strategy" всё ещё в файле

# Валидатор (упрощённо): блокирует, если строка-НЕ-комментарий содержит литерал
#   фильтр пропускает только строки, начинающиеся с '#'
#   inline '# ok' не делает строку комментарием → проверка проходит по литералу

# Правильный фикс — убрать сам литерал:
GOVERNANCE="${IWE_GOVERNANCE_REPO:-DS-strategy}"   # env-var с дефолтом
```

## Механизм

1. Валидатор проверяет **присутствие** запрещённого литерала (substring / regex), либо исключает строки по признаку «начинается с `#`».
2. Разработчик мыслит «комментирование = отключение строки» и дописывает `# ...` в конце.
3. Строка не начинается с `#` → не считается комментарием; литерал на месте → блок остаётся.
4. Симптом: «я же закомментировал, почему всё ещё падает?»

## Почему опасен

- Ложная ментальная модель тратит итерации (несколько коммитов «обхода» подряд).
- Подталкивает к настоящему обходу хука (`--no-verify`) — нарушение Hooks Bypass Gate (S-33).
- Скрывает реальную причину: валидатор проверяет **что есть в файле**, а не **как это помечено**.

## Лечение

1. **Убрать/заменить сам литерал**, а не комментировать его: env-переменная с дефолтом (`${VAR:-default}`), плейсхолдер, вынос в конфиг.
2. Если строка легитимна и должна быть исключена — добавить её в **явный allowlist валидатора**, а не маскировать комментарием.
3. Принцип: «закомментировал строку» ≠ «обошёл проверку на присутствие литерала». Валидатор присутствия видит содержимое, не разметку.

## Связи

- Смежный: DP.FM.038 (validator-silent-pass) — обратная сторона: валидатор молча пропускает.
- Смежный: DP.FM.136 (неякорный grep → false-positive) — про точность матчинга самого валидатора.
- Смежный: DP.FM.077 (overstated-validator-coverage) — расхождение «что валидатор реально проверяет» vs «как его понимают».
- Правило-щит: Hooks/Scripts Bypass Gate (S-33) — не обходить хук, выполнять как задумано.
