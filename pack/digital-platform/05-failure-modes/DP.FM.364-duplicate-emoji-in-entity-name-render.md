# DP.FM.364 — дублирование эмодзи в имени сущности при рендере

## Паттерн

Имя сущности (например, тира/уровня) хранится с уже встроенным эмодзи в исходном поле; отдельная точка рендера (презентационный слой) добавляет тот же или другой эмодзи повторно при отображении — результат содержит два эмодзи там, где ожидался один.

## Механизм

1. Поле имени в данных уже включает эмодзи как часть строки
2. Код рендера, не знающий об этом, добавляет собственный эмодзи-префикс/суффикс при построении отображаемой строки
3. Две независимые точки формирования визуального представления одного и того же смысла не синхронизированы

## Почему опасен

Внешне мелкий визуальный баг, но указывает на более общую проблему: представление сущности собирается в нескольких разных местах кода вместо одной точки истины.

## Лечение

Хранить имена без эмодзи в исходных данных; собирать финальное отображаемое представление (включая эмодзи) в одной выделенной функции (`tier_display_name` и подобные), вызываемой из всех точек рендера.
