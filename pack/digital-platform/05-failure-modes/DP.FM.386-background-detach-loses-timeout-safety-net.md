# DP.FM.386: Переход на фоновый детач тихо теряет таймаут-подстраховку синхронного ожидания

## Симптом

Раннер перешёл с синхронного ожидания шага (с собственным потолком 180с) на фоновый детач — теперь раннер этот шаг вообще не ждёт. Новую защиту от зависания возложили на внешний watchdog поверх бинарника `timeout`, который не гарантированно доступен в PATH (типичный случай — macOS без coreutils). Итог: при отсутствии `timeout` фоновый процесс стал полностью неограниченным по времени, а старая синхронная защита исчезла вместе с переходом на детач.

## Корневая причина

При замене одного safety-механизма (синхронное ожидание с потолком) другим (детач + watchdog на внешнем бинарнике) не была явно проверена работоспособность нового механизма в целевом окружении — предположение «watchdog сработает» не было верифицировано против конкретного PATH деплой-среды.

## Антипаттерн → Паттерн

- **Антипаттерн:** убрать проверенный safety-механизм (синхронный таймаут) при переходе на новую архитектуру (асинхронный детач), положившись на замену, которая зависит от внешнего окружения (`timeout` в PATH) без проверки этой зависимости.
- **Паттерн:** при замене одного safety-механизма другим — явно подтвердить в целевом окружении деплоя, что новый механизм реально сработает (например, `command -v timeout` перед деплоем), либо использовать встроенный в сам скрипт таймаут вместо внешнего бинарника.

## Тест обнаружения

На целевой машине деплоя: `command -v timeout`. Если пусто — watchdog, полагающийся на этот бинарник, не сработает; фоновый процесс без `timeout` в PATH ничем не ограничен по времени.
