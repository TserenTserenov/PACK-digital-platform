# DP.FM.369 — template-sync откатывает фиксы приёмника

## Паттерн

Скрипт синхронизации шаблона с приёмными репозиториями (`validate-template`/`template-sync`), работающий в одностороннем режиме (source → destination), при некорректном режиме (например, потеря staged-режима, статическая вместо динамической `TEMPLATE_DIR`) может перезаписать локальные исправления, сделанные в приёмнике после последней синхронизации, откатывая их к устаревшей версии источника.

## Механизм

1. Синхронизация задумана как «source has authority» для общих файлов
2. Регрессия в самом sync-скрипте (потеря режима staged, статичный путь вместо динамического) заставляет его перезаписывать файлы, которые приёмник уже поправил локально после предыдущей синхронизации
3. Фикс приёмника теряется без явного предупреждения — выглядит как «синхронизация прошла успешно»

## Почему опасен

Односторонний sync изначально несёт риск потери локальных изменений приёмника; регрессия в самом механизме защиты (staged mode) делает этот риск реализующимся молча.

## Лечение

Восстановлен staged-режим + динамическое разрешение `TEMPLATE_DIR` — sync применяет изменения через промежуточный staged-diff, который можно проверить перед применением, вместо прямой перезаписи.
