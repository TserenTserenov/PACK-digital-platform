# DP.FM.207 — grep без якорного паттерна → false-positive на ключевом слове в теле раздела

## Описание

Проверка «присутствует ли раздел X в файле» через `grep -q "X"` ищет слово во всём файле — и находит его в теле других разделов. Результат: секция отсутствует как заголовок, но grep возвращает `0` (found). Детектор молча отчитывается успехом 4 дня подряд.

## Пример

`fix(day-open.checks)`, IWE `e510f76`: проверка DayPlan на наличие раздела «Мир»:

```bash
# Было (FM.207):
grep -q "Мир" dayplan.md  # совпадает со словом "Мир" в теле раздела "Требует внимания"

# Стало (fix):
grep -q "<summary><b>Мир" dayplan.md  # точный паттерн HTML-тега заголовка
```

4 дня (30 июня — 3 июля) раздел «Мир» отсутствовал в DayPlan, проверка каждый раз давала ✅.

## Диагностика

Тест: «Может ли ключевое слово X встречаться в теле других разделов?»
- Да → `grep -q "X"` ненадёжен; нужен якорный паттерн

## Исправление

Для проверки структуры файла использовать маркер-заголовок:
- Markdown H2/H3: `grep -q "^## X"` или `grep -q "^### X"`
- HTML collapsible: `grep -q "<summary><b>X"`
- Любой уникальный маркер начала секции, не встречающийся в теле

Общее правило: «Присутствует ли раздел X?» — искать маркер-заголовок X, не слово X.
