# DP.FM.365 — молчаливый отказ session-guard при переименовании семафора

## Паттерн

Скрипт `session-guard` при закрытии сессии пытается прочитать семафор-файл по старому имени после того, как тот был переименован в другом месте кода — попытка чтения падает в warn-блок, который не сигнализирует об ошибке достаточно явно, чтобы её сразу заметили.

## Механизм

1. Семафор-файл переименован в одной части кодовой базы (например, при рефакторинге WP-487)
2. Проверяющий скрипт (`session-guard`) продолжает искать старое имя
3. Отсутствие файла обрабатывается как «нормальный» случай внутри `warn`-логики, а не как явная ошибка рассинхрона имени

## Почему опасен

Переименование одной стороны контракта (имя семафора) без синхронного обновления всех читателей создаёт тихий разрыв — guard формально не падает с ошибкой, а просто ничего не проверяет.

## Лечение

При переименовании файла-семафора/контрактного артефакта — grep по всей кодовой базе на прежнее имя, чтобы найти всех потребителей до завершения переименования; warn-блоки для отсутствующих файлов проверять на предмет того, не маскируют ли они на самом деле рассинхрон контракта.
