# DP.FM.102: Boolean flag с hardcoded константой — silent underpayment

## Описание

В формуле вычисления значения добавляется boolean-флаг (`is_marker`), который меняет code path, но в ветке for-marker используется hardcoded константа (`v_base=1.0`) вместо параметрического чтения из event-record (`v_amount`). Результат: все маркерные события дают фиксированное значение независимо от конфигурации правил.

## Симптомы

- Маркерные события всегда возвращают одно и то же значение
- Unit-тесты проходят (если не покрывают случай `is_marker=true` с `v_amount ≠ 1.0`)
- Проявляется только после заполнения таблицы правил и сравнения ожидаемых vs фактических значений

## Условие возникновения

Ветка «специального случая» для флага скрывает необходимость пробрасывать параметр из конфигурации. Разработчик заменяет lookup магическим числом.

## Детектор

«Есть ли unit-тест с `is_marker=true` И `v_amount ≠ default_constant`?» Нет → баг invisible.

## Решение

При добавлении флага-мутатора в формулу:
1. Явно документировать источник каждого параметра в каждой ветке
2. Запрет магических чисел в branch conditions — только именованные константы или lookup
3. Тест-кейс: специальный режим с нестандартным значением параметра

## Применимость

Любое вычисление с ветвлением по типу: бонусы, скидки, весовые коэффициенты, gamification points, pricing engine.
