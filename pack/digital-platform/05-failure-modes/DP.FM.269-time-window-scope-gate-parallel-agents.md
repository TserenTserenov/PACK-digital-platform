# DP.FM.269 — Temporal scope gate пропускает чужие файлы при параллельных долгих сессиях

## Симптом

Scope-gate определяет «файлы текущей сессии» как «всё, изменённое с момента открытия сессии». При параллельной долгой сессии (42+ часа) в том же репозитории — gate включает файлы, изменённые другим агентом в этот же период. Ложное «разрешение» фиксирует чужую работу как «свою».

## Корень

Время модификации — плохой прокси для принадлежности файла сессии при:
- Нескольких агентах в одном репо
- Длинных сессиях (мобильный агент, headless, overnight)

Временное окно безопасно только когда `max_session_length << время между модификациями несвязанных файлов`.

## Профилактика

**Правило:** не использовать mtime как единственный критерий scope-gate в multi-agent репозиториях.

Правильный scope-критерий (одно или оба):
1. **Session-ID в имени файла** — файл содержит session-ID как часть имени или frontmatter (как housekeeping-семафор без даты)
2. **Явный manifset сессии** — агент при открытии сессии создаёт файл-манифест с перечнем санкционированных файлов; scope-gate сверяется с манифестом

**Тест:** «Могла ли другая сессия модифицировать этот файл за тот же период?» Да → time-window gate недостаточен.

## Применимо к

- Session guards (session-guard.sh, аналоги) в репозиториях с несколькими агентами
- Headless операциях с длинными временными окнами
- CI/CD commit hooks, проверяющих принадлежность файлов по mtime
