# DP.FM.428 — tail -N в алерте теряет причину провала при успехе после провала в том же тике

## Симптом
Алерт-скрипт использовал `tail -5` по общему GATE_LOG для pilot-facing уведомления. При нескольких тестах за один тик `tail -5` почти всегда показывал PASS-строки последнего (прошедшего) теста, а строка `GATE FAIL: <file>` более раннего провалившегося теста тонула выше среза. Живой случай 09.09: алерт пришёл с одними PASS/WARN, вообще без причины провала. Третий случай за сессию — независимо обнаружен в двух репозиториях в один день (iwe-server-config и DS-my-strategy/day-open-run.sh: RUN-карточка хранила только `tail -5` вывода пайплайна).

## Механизм
`tail -N` как способ показать «последнее из лога» систематически теряет причину провала, если после провалившегося шага в том же логе успел отработать ещё один шаг — не единичная ошибка одного скрипта, а системный паттерн. Отдельно тот же скрипт дампил сырой английский лог прямо в текст Telegram-сообщения вместо короткой человекочитаемой фразы.

## Фикс
Явный grep по маркеру `GATE FAIL:` вместо слепого хвоста для выбора того, что показать в алерте; деталь остаётся в файле лога launchd, в чат уходит только короткая фраза.

## Тест обнаружения
«Pilot-facing алерт формируется через `tail -N` (или аналог — последние M строк/событий) общего лога?» Да → проверить сценарий «провал, затем успех в том же цикле/тике»: если хвост показывает только успех, причина провала теряется. Нужен явный поиск маркера ошибки (grep по сигнатуре FAIL) или полный вывод в отдельном файле, не хвост фиксированной длины.

## Применимость
Любой pilot/human-facing алерт или сводка, собираемая усечением (`tail`, `head`, «последние N записей») общего лога с несколькими шагами за один цикл.
