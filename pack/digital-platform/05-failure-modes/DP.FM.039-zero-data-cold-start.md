# [DP.FM.039] Zero-Data Phase Cold Start

## Суть паттерна

При запуске нового metric pipeline (или переключении источника данных) все пользователи оказываются в **zero-data фазе**: новый формат данных ещё не накоплен, исторические данные несовместимы.

## Механизм

1. Старый pipeline снят / источник изменён
2. Новый pipeline смотрит на пустые таблицы / несовместимые поля
3. Все пользователи = 0 по всем показателям
4. Downstream: неверные ступени, нулевые streak'и, заниженные рекомендации

## Пример (WP-310)

После введения `bh.inv = slot_logged + lesson_completed` вместо `coding_time` — dry-run на 7 пилотов wave-1: все показали `bh.inv = 0`. Ни один не имел записей в новом формате.

## Правило

**Перед запуском нового metric pipeline — обязательный dry-run на zero-data кейс:**

1. Запустить pipeline на реальных пользователях
2. Проверить: есть ли zero-значения там, где ожидается ненулевое?
3. Если да → реализовать **human-override** до launch

## Паттерны защиты

| Паттерн | Когда применять |
|---------|-----------------|
| **Human-override** | Декларация начального значения пользователем через UI/бот |
| **Migration script** | Конвертация исторических данных в новый формат |
| **Grace period** | Первые N дней = baseline по умолчанию |
| **Backward compat** | Параллельное чтение старого и нового источника с fallback |

## Применимость

Любой pipeline метрик, переключающий источник данных или вводящий новый обязательный показатель.
