# DP.FM.350 — Нетранзакционный DELETE+INSERT в индексаторе чанков

## Паттерн

Индексатор чанков удаляет старые строки и вставляет новые двумя отдельными запросами, не обёрнутыми в одну транзакцию. Если процесс прерывается между DELETE и INSERT — старые данные уже удалены, новые ещё не вставлены — контент теряется.

## Механизм

1. Индексация запускает `DELETE FROM chunks WHERE doc_id = X`
2. Между DELETE и последующим `INSERT` процесс прерывается (обрыв соединения, краш, kill)
3. Транзакция отсутствует → DELETE уже закоммичен, INSERT не выполнен
4. Документ X остаётся без чанков — контент физически потерян до следующего полного переиндексирования

## Почему опасен

- Второй риск того же участка кода: разрыв связи parent-chunk возможен при параллельной индексации (два процесса переиндексируют один документ одновременно)
- Оба риска были отмечены в прошлом ревью и на момент повторной проверки оставались неисправленными
- Потеря данных не вызывает ошибки выполнения — обнаруживается только при последующем поиске по документу

## Лечение

1. Обернуть DELETE+INSERT в одну транзакцию (BEGIN...COMMIT), чтобы прерывание откатывало обе операции
2. Для параллельной индексации — блокировка на уровне документа (advisory lock или аналог), чтобы исключить гонку parent-chunk
3. Регрессионный тест: убить процесс между DELETE и INSERT → проверить, что документ не остался без чанков после отката
