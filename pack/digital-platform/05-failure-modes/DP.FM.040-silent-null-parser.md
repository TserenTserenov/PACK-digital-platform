# [DP.FM.040] Silent-Null Parser on Unknown Syntax

## Суть паттерна

Парсер ad-hoc форматов (minimal-YAML, regex frontmatter, custom DSL) принимает «не распознал → вернул пустое» как defensible default. Если поле в текущих файлах ещё не заполнено, тест на пустых значениях зелёный. Слепая зона активируется ровно в момент, когда поле начинают использовать — все будущие записи проходят валидацию пустыми, потому что парсер не умеет их прочитать.

## Механизм

1. Парсер написан под текущие данные.
2. Тестовые фикстуры содержат только поля, фактически заполненные на момент написания.
3. Поле X пока пустое во всех файлах → парсер X либо отсутствует, либо возвращает `''` на неизвестный синтаксис.
4. Тесты зелёные (пустые входы дают пустые выходы — «верно»).
5. Через месяц авторы начинают заполнять поле X в формате, который парсер не распознаёт.
6. Парсер тихо возвращает `''` → валидатор пропускает.

## Защита

Парсер обязан различать три состояния:

| Состояние | Поведение |
|-----------|-----------|
| Поле отсутствует | Legit — вернуть `None` / opt |
| Поле есть, синтаксис не распознан | **Fail loud** — exception / exit-with-error |
| Поле есть, синтаксис пустой | Edge case — явно решить (legit empty / error) |

**Дополнительно:** тестовая фикстура должна содержать **заполненное значение в каждом синтаксическом варианте**, который парсер обещает поддерживать. Smoke на пустых данных недостаточно.

## Применимость

- Custom YAML / TOML парсеры в shell-скриптах.
- Regex-парсеры markdown frontmatter.
- DSL-парсеры в curriculum, configuration, ADR templates.
- Любой `parse(s) -> dict` с partial coverage синтаксиса.

## Симптом

Парсер «работает» в CI и smoke-тестах, но никто не видел его выход на полностью заполненных данных. Тестовые фикстуры написаны под текущее состояние, не под full schema.
