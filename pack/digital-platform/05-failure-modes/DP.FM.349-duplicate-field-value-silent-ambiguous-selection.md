# DP.FM.349 — Lookup по значению поля YAML: молчаливый выбор при count > 1

## Паттерн

Скрипт ищет файл по значению поля (`wp: 251`) — находит несколько файлов с одинаковым значением, выбирает первый по sort/glob без ошибки. Пользователь получает контекст не того РП.

## Пример

```bash
# В inbox/ два файла с wp: 251 (дубль, ошибка ввода):
# inbox/WP-251/WP-251.md  → wp: 251 (правильный)
# inbox/WP-000/WP-000.md  → wp: 251 (дублированное значение — ошибка)

# wp-sync-bundle.sh:
FILES=$(grep -rl "^wp: 251" inbox/)
# Находит оба → берёт первый по sort → возвращает контекст WP-000 вместо WP-251
```

## Механизм

1. Lookup ищет `wp: N` по grep — находит N файлов (N > 1)
2. Нет явной проверки уникальности результата
3. Скрипт берёт `head -1` или первый элемент массива → молчаливый выбор
4. Пользователь получает bundle чужого РП без сообщения об ошибке

## Почему опасен

- Ошибка дублирования `wp:` поля обнаруживается поздно (при использовании bundle, не при вводе)
- Результат выглядит нормально — bundle сформирован, просто содержимое неверно
- Дебаггинг нетривиален: grep по wp: N вернёт один правильный файл, если смотреть по одному

## Лечение

1. После lookup: если `count(FILES) > 1` → exit с ошибкой: «Обнаружены N файлов с wp: 251, ожидается 1»
2. Не использовать frontmatter-поле как единственный идентификатор: путь `inbox/WP-251/` надёжнее
3. Тест: два файла с `wp: 251` → bundle → проверить, что выводится ошибка, не случайный контекст

## Связи

- DP.FM.346 (тот же скрипт, другой паттерн: зачёркивание не парсится) — смежный FM в wp-sync-bundle
- Общий принцип: lookup по неуникальному ключу = потенциальная тихая ошибка выбора
