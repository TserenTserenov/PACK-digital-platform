# DP.FM.050 — Lazy regex для markdown bold не матчит bold с пунктуацией перед **

## Симптом

Ingest-пайплайн пропускает bold-секции вида `**Основные понятия:**` или `**Вывод:**` — они не включаются в результат без каких-либо ошибок. Silent fail.

## Причина

Стандартный lazy regex `\*\*(.*?)\*\*` при парсинге `**Основные понятия:**` останавливается на двоеточии внутри match и не завершает match корректно. Реализации regex-движков по-разному обрабатывают пунктуацию в lazy-режиме, но общий эффект: bold-блок с завершающей пунктуацией (`:`, `.`, `!`) перед `**` не матчится.

## Диагностика

Нет ошибок в логах. Просто меньше результатов, чем ожидается. Обнаруживается только при dry-run с подсчётом (`.length` до и после фикса). WP-242 Ф9.1: обнаружено +126 missed concepts после применения фикса.

## Fix

Заменить lazy `.*?` на character-class exclusion:

```
# Было:
\*\*(.*?)\*\*

# Стало:
\*\*([^*]+)\*\*
```

Альтернатива: lookbehind assertion `\*\*(.+?)(?<!\*)\*\*` (поддерживается не во всех движках).

## Применимо к

Любой ingest/extract pipeline, работающий с markdown bold-разметкой, где bold-секции могут заканчиваться пунктуацией непосредственно перед закрывающим `**` (заголовки-секции в учебных материалах, Pack-документах, гайдах).
