# DP.FM.387 — Опциональный шаг без явного else определяет итоговый exit-код обязательной операции

## Паттерн

Обязательная операция скрипта (например, publish) завершилась успешно, но опциональный пост-шаг без явной ветки `else` оказался последней командой success-пути — итоговый exit-код скрипта стал кодом этого опционального шага, а не индикатором успеха обязательной операции.

## Почему это ошибка

Shell возвращает код последней выполненной команды. Конструкция `if [ -x "$OPTIONAL" ] && do_thing; then ...; fi` (без `else`) как последняя команда success-ветки — при «false»-условии (бинарник отсутствует) её код становится итоговым кодом всей ветки/скрипта. Успешная обязательная операция маскируется под провал.

## Антипаттерн → Паттерн

- Антипаттерн: `if [ -x "$OPTIONAL" ] && do_optional_thing; then ...; fi` как последняя команда success-пути, без переустановки кода возврата.
- Паттерн: опциональные пост-шаги не должны влиять на итоговый код возврата обязательной операции — явно зафиксировать код после обязательного шага (`exit 0` после обязательной части, либо `|| true` на опциональном шаге, либо явный `else :`).

## Тест обнаружения

Последняя команда success-ветки скрипта — опциональная (может не выполниться) или явно возвращает код обязательной операции? Если опциональная без `else`/финального `exit` — риск маскировки.
