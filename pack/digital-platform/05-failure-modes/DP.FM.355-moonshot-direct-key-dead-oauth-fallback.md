# DP.FM.355 — Moonshot прямой ключ умер, OAuth-подписка как fallback

## Паттерн

Прямой API-ключ провайдера Moonshot перестал работать (401 Unauthorized на `api.moonshot.cn` и `.ai`). Рабочий обход — переключение на OAuth-подписку (`kimi login`, тариф Allegro, модель K2.7 Code) вместо прямого ключа.

## Механизм

1. Прямой API-ключ, ранее работавший, начинает возвращать 401 на обоих доменах провайдера
2. Причина на стороне провайдера (истечение, отзыв, смена схемы аутентификации) — не в клиентском коде
3. OAuth-based подписочный вход (`kimi login`) остаётся рабочим независимо от состояния прямого ключа

## Почему опасен

- 401 на прямом ключе легко спутать с локальной ошибкой конфигурации (неверный ключ в env, опечатка) — требуется проверка на обоих доменах, чтобы исключить локальную причину
- Если единственный настроенный метод аутентификации — прямой ключ, отказ провайдера полностью останавливает работу без явного fallback

## Лечение

1. При 401 от AI-провайдера — не чинить сразу ключ, а проверить статус самого провайдера / альтернативный метод входа
2. Иметь настроенный OAuth-путь (`kimi login`) как резервный канал аутентификации, не только прямой ключ
3. Задокументировать: тариф Allegro + модель K2.7 Code как проверенная рабочая комбинация fallback
