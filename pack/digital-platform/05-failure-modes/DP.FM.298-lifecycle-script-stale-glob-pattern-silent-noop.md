# DP.FM.298 — Lifecycle-скрипт молча игнорирует объекты при смене конвенции путей

## Паттерн

После смены конвенции хранения (glob-паттерн, имена, структура директорий) lifecycle-скрипт продолжает искать по старому паттерну → «ничего не нашёл» → `exit 0` → **операция молча не работает**.

## Инцидент

WP-5: после смены конвенции (плоский файл `inbox/WP-N-*.md` → папка `inbox/WP-N/WP-N.md`, WP-434, 20.06) скрипт `archive-done-wp.sh` искал по старому glob → 3 недели молча не архивировал, накопив 41 висящую папку.

## Диагностика

**Ключевое различение:** «нашёл 0 объектов» — два смысла:

| Интерпретация | Когда |
|---------------|-------|
| «Нечего делать» (легитимно) | Нет закрытых РП |
| «Ищу не там» (ложный успех) | Паттерн не совпадает с реальными путями |

**Тест:** явный лог количества найденных объектов при каждом запуске lifecycle-скрипта.

## Превентивный метод

**При смене конвенции путей/имён:**

1. `grep` по glob-паттерну старой конвенции во **всех** lifecycle/maintenance скриптах
2. Обновить все найденные скрипты в одном коммите вместе с документацией смены конвенции
3. Добавить smoke-тест: скрипт после смены должен найти N > 0 объектов

**Перед архивацией контейнера:** прогнать чек полноты переноса (режим warn-not-block).

## Правило

Успешный exit 0 lifecycle-скрипта с 0 найденных объектов = подозрительный результат, требует различения.
