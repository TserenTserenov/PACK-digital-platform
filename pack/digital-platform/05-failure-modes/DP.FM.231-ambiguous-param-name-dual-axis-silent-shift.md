# DP.FM.231 — Обобщённое имя параметра с двумя семантическими осями → молчащее смещение

## Описание

Функция принимает параметр с обобщённым именем (например, `stage`), который де-факто может содержать значения **двух разных** семантических осей — не взаимозаменяемых. Вызывающий код передаёт значения одной оси; функция ищет по другой. Ошибки нет — результат просто неверный (молчащее смещение).

## Пример

```python
# До фикса: параметр stage несёт обе оси
def get_program_seed_context(stage: int) -> dict:
    # вызывающие передавали cp_stage (1-5)
    # но RR/IR программы используют degree_level (1-7)
    return db.fetch(level=stage)  # для cp_stage=5, ищет degree_level=5 (Практик)
    # правильно: degree_level=6 (Реформатор) через _MSH_TO_DEGREE_LEVEL[stage]
```

| cp_stage (ступень ученика) | degree_level (степень квалификации) |
|---------------------------|--------------------------------------|
| 5 = Проактивный | 6 = Реформатор |
| Шкала 1-5 | Шкала 1-7 |

Для Реформатора (cp_stage=5, degree_level=6): функция искала по уровню 5 (Практик) вместо 6 (Реформатор).

## Симптомы

- Функция выполняется без исключений, код тестируется зелёно.
- Результат сдвинут на один уровень или категорию, не соответствует реальности.
- Расхождение обнаруживается только при ревью вывода (контентный аудит), а не при технических тестах.

## Причина

Обобщённое имя `stage`/`level`/`id` скрывает несколько онтологически разных осей. Вызывающий код видит имя, выбирает «подходящую» ось, передаёт значение — функция молча трактует иначе.

## Фикс-паттерн

1. **Переименовать параметр в точную ось:** `stage → degree_level`.
2. **Единый SoT-словарь маппинга:** `_MSH_TO_DEGREE_LEVEL`, `_RUNG_TO_DEGREE_LEVEL` — явные таблицы конвертации, не магические числа.
3. **Типизация:** Python `TypeAlias` или `Enum` с разными типами для разных осей — ловится при type-check.

## Как обнаружить

- Тест «функция вернула неожиданный уровень/запись» при граничном значении шкалы (ст.5 для cp_stage, ст.6 для degree_level).
- Аудит вызовов функции: все вызывающие передают одну и ту же «подходящую» ось без явного маппинга?
