# DP.FM.367 — same-code sweep оставляет протухшие cross-ref

## Паттерн

Массовая одинаковая правка (sweep), применённая по одному и тому же паттерну сразу ко многим файлам (например, переименование/перенумерация ID), корректно меняет прямое вхождение в каждом файле, но не отслеживает перекрёстные ссылки (cross-ref) на изменённые элементы из файлов, не входивших в область самого sweep.

## Механизм

1. Sweep-скрипт находит и правит целевой паттерн (например, идентификатор) во всех файлах, где он определён как «основное вхождение»
2. Ссылки на этот идентификатор из других, не затронутых sweep'ом файлов, остаются со старым значением
3. Результат: часть базы ссылается на новый ID, часть — на устаревший, без явного индикатора расхождения

## Почему опасен

Sweep создаёт иллюзию полной консистентности (все «основные» места исправлены), маскируя частичность результата — cross-ref, не входившие в scope, остаются битыми до отдельной проверки.

## Лечение

После любого same-code sweep — отдельный проход `grep`/linkcheck по всей кодовой базе на предмет оставшихся ссылок на старое значение, не ограничиваясь файлами, которые редактировал сам sweep.
