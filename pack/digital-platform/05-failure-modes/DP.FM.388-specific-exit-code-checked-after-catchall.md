# DP.FM.388 — Специфичный exit-код проверяется после общей ветки «любой ненулевой = fail»

## Паттерн

Добавлен новый специфичный код возврата (например, 7 = «отложено»), но существующая catch-all проверка «любой ненулевой код = авария» стоит по порядку раньше специфичной проверки — новая ветка обработки становится физически недостижимой.

## Почему это ошибка

Порядок условных проверок определяет достижимость веток. Catch-all условие, идущее раньше специфичного, перехватывает управление первым — специфичная ветка не выполняется никогда, хотя код синтаксически корректен и проходит статический просмотр.

## Антипаттерн → Паттерн

- Антипаттерн: `if [ $code -ne 0 ]; then ...aborted...; elif [ $code -eq 7 ]; then ...deferred...; fi` — ветка `deferred` недостижима.
- Паттерн: специфичные коды проверять раньше общей catch-all ветки: `if [ $code -eq 7 ]; then ...deferred...; elif [ $code -ne 0 ]; then ...aborted...; fi`.

## Тест обнаружения

При добавлении нового специфичного кода возврата — его проверка стоит раньше существующего catch-all «код≠0»? Если нет — ветка мертва.
