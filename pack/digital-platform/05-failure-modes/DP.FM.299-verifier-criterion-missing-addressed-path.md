# DP.FM.299 — Критерий верификатора без описанного addressed-пути делает механический PASS недостижимым

## Паттерн

Верификатор/чеклист определяет условия `partial` и `missing`, но **не определяет**, что считается `addressed`. При агрегатной формуле «хоть один `partial` → CONDITIONAL» — **любой артефакт, даже идеально заполненный, не может получить PASS механически**.

Дефект унаследован из фазы раскладки критериев, а не регрессия реализации.

## Диагностика

**Тест:** «Существует ли реальный артефакт, который механически проходит этот критерий как PASS?» Нет → missing addressed path.

**Как обнаружить:** попробовать применить критерий к эталонному (идеально заполненному) артефакту вручную → если результат не PASS → структурный дефект.

## Инцидент

WP-474: два критерия (D9 и D1) чеклиста verify-pack имели одинаковый структурный дефект. Найден независимой проверкой (не автором чеклиста), что подтверждает системность: дефект невидим изнутри потока разработки.

## Fix / Линт

Переносимый линт для любого верификатора/рубрики перед релизом:

1. Каждый критерий должен явно определять, что считается `addressed`.
2. Проверка: «существует ли артефакт, проходящий PASS механически?» — до публикации инструмента.
3. При агрегации: проверить формулу — «хоть один partial → CONDITIONAL» должна иметь путь выхода к PASS.

## Применимость

- Чеклисты качества (verify-pack, code-review, ArchGate)
- Любая рубрика с состояниями addressed/partial/missing + агрегацией
