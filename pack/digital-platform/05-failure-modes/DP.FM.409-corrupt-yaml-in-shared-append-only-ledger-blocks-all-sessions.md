# DP.FM.409: Общий append-only файл — единая точка отказа даже при частичной порче

## Симптом
Один частично оборванный YAML-блок (вложенная мапа без родительского ключа) заблокировал запуск ВСЕХ сессий, а не только той, чья запись оказалась повреждённой.

## Причина
`process-runner.py` читает общий дневной ledger-файл при старте любой сессии — блокирующий эффект общего файла шире, чем ущерб от исходной ошибки записи.

## Антипаттерн → Паттерн
- **Антипаттерн:** ручное восстановление повреждённых данных без достоверного способа угадать потерянную структуру — реконструкция наугад.
- **Паттерн:** при невозможности достоверно восстановить фрагмент — консервировать в неисполняемом виде (комментарий), не удалять и не переименовывать наугад; имя пропавшего родительского ключа искать по всему файлу, восстанавливать только если совпадение однозначно.

## Тест обнаружения
«Общий append-only файл (ledger, lock-реестр, семафор) читается на каждом старте процесса и допускает частичную порчу без атомарности записи?» Да → один невалидный фрагмент даёт блокировку по всем потребителям, а не только по автору повреждения.

## Применимость
Любой общий append-only файл (ledger, lock-реестр, семафор), читаемый на каждом старте, при конкурентной записи без атомарности.

## Смежный вариант — рассинхрон схемы между хуком и разделяемой библиотекой

Тот же принцип «общий ресурс = единая точка отказа для всех» проявляется и без порчи данных: если хук и разделяемая библиотека, которую он вызывает, обновляются не синхронно (например, хук развёрнут раньше новой версии библиотеки, ожидающей другую форму записи), строгая проверка схемы между ними ломает КАЖДЫЙ вызов до момента, пока версии не совпадут — тот же blast radius «для всех», только причина — рассинхрон версий, не повреждённые байты.
