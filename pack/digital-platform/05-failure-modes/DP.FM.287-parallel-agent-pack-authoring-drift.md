# DP.FM.287 — Параллельное авторство Pack-файла двумя агентами: тихий дрейф

## Паттерн

Два агента (например, Claude + Kimi) работают в разных сессиях над одним Pack-файлом.
Каждый видит снапшот файла на момент открытия своей сессии. Изменения одного агента
недоступны другому до merge — дрейф копится молча, без conflict-маркеров.

## Диагностика

**Тест:** «Более одного агента редактировало один Pack-файл в разных сессиях за последние N часов?»
- Да → reconcile обязателен перед коммитом
- Нет → proceed

## Симптом

Два варианта одного Pack-типа (определения, примеры, related) с незначительными расхождениями.
В отличие от git merge-конфликта — нет явного conflict-маркера; расхождение обнаруживается
только при ручном сравнении HEAD перед коммитом.

## Предотвращение

1. **Назначить write-агента:** один агент = единственный writer на Pack-файл в период работы
2. **Explicit reconcile перед коммитом:** читать HEAD Pack-файл ещё раз непосредственно перед коммитом
3. **Append-only операции:** при возможности добавлять новый тип/запись, не редактировать существующую → merge позже
