# DP.FM.415: Параллельный rebase в общем чекауте опустошает коммит в окне между postcondition-проверкой и записью

## Симптом

Закрытие дня потеряло раздел «Итоги дня» и поле `results_not_captured`: агент прошёл postcondition-проверку (содержимое файла подтверждено корректным), но к моменту `git commit` содержимое исчезло — итоговый коммит приземлился как переименование файла с нулевым diff по обоим затронутым файлам.

## Корневая причина

Между моментом, когда агент прочитал и подтвердил состояние файла (postcondition passed), и моментом его `git commit` в ОБЩЕМ чекауте, параллельная сессия того же чекаута (независимый агент, здесь — WP-7 pid 90816) выполнила свой `git pull --rebase --autostash`. Rebase подставил новую базу для ещё не закоммиченных изменений первого агента: коммит состоялся без ошибки и без конфликта, но относительно другого родителя, где содержательные правки первого агента были потеряны, а зафиксировалось только переименование файла.

Общий принцип: в общем git-чекауте с несколькими одновременными писателями последовательность «проверил postcondition → закоммитил» не атомарна сама по себе. Конкурирующий rebase, случившийся строго внутри этого окна, может незаметно подменить базу коммита без единого сигнала об ошибке.

## Антипаттерн → Паттерн

- **Антипаттерн:** check-затем-commit как две независимые команды в общем чекауте, без взаимного исключения с другими писателями того же чекаута между ними.
- **Паттерн:** lock-protected commit-push handler — взаимоисключающая блокировка на запись, охватывающая ОБА шага (проверка состояния + коммит) как одну атомарную секцию, а не только сам вызов `git commit`.

## Тест обнаружения

После закрытия сессии в общем чекауте, если отчёт об изменении расходится с фактическим содержимым коммита: сравнить diffstat зафиксированного коммита с ожидаемым (чистое переименование/нулевой content-diff при том, что предполагалась содержательная правка — признак этого класса) и проверить git-рефлог/историю чекаута на `pull --rebase` от другой сессии, попавший в интервал между временем последней проверки и временем коммита первого агента.
