# DP.FM.359 — Headless-скаффолд игнорирует PENDING-инструкции

## Паттерн

Шаблон/скаффолд содержит текстовые placeholder-инструкции вида «PENDING: вызови такой-то MCP-инструмент», рассчитанные на то, что агент их прочитает и исполнит. В headless-прогоне, где заполнение делает голый вызов LLM-прокси (не полноценный агент с доступом к инструментам), такие инструкции физически не могут быть выполнены — LLM-fill не имеет инструментов, только генерирует текст.

## Механизм

1. Шаблон содержит текстовые PENDING-маркеры, предполагающие последующее действие агента (вызов MCP-инструмента)
2. Headless-прогон использует «голый» LLM-вызов (LLM-прокси без агентского инструментария) для заполнения шаблона
3. LLM не может вызвать инструмент — PENDING-маркер остаётся нетронутым в финальном артефакте или заполняется текстом-заглушкой

## Пример

Минимум два обнаруженных мёртвых указания (сигналы оргразвития) — PENDING-инструкции остались невыполненными в headless-прогоне заполнения.

## Почему опасен

- Итоговый артефакт выглядит завершённым (шаблон заполнен текстом), но конкретное действие, которое инструкция предполагала, никогда не произошло
- Обнаруживается только при явной проверке артефакта на предмет невыполненных PENDING-маркеров

## Лечение

1. Не полагаться на то, что LLM-fill headless-прогона выполнит инструментальные действия — только код может это гарантированно сделать
2. Заменить текстовые PENDING-инструкции детерминированным скриптом, который явно вызывает нужный MCP-инструмент до или после LLM-fill
3. Проверка на невыполненные PENDING-маркеры — часть валидации результата headless-прогона

## Связи

- Различение «LLM-в-центре ≠ ядро-в-центре»: детерминированный код должен вести инструментальные действия, не полагаться на текстовые инструкции для LLM без инструментов
