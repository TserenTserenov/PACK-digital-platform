# DP.FM.376 — демотирование в lazy без linkcheck ломает ссылки

## Паттерн

При переносе полного текста из hot-файла в отдельный lazy-файл (демотирование) путь целевого файла может отличаться от того, где эти данные лежали раньше — если сам процесс демотирования не сопровождается обязательным отдельным шагом проверки ссылок (linkcheck), внешние указатели на старый путь остаются битыми. В зафиксированном случае найдено 3 унаследованных битых указателя после такого переноса.

## Механизм

1. Контент переносится из hot-файла в новый lazy-файл с другим путём/именем
2. Операция демотирования сфокусирована на самом переносе содержимого, не на поиске всех входящих ссылок на старое расположение
3. Внешние файлы, ссылавшиеся на прежний путь, остаются с указателем на несуществующий/устаревший адрес

## Почему опасен

Битые ссылки не вызывают ошибку исполнения большинства систем (markdown-ссылка просто не резолвится молча) — обнаруживаются только явной проверкой или случайным переходом по ссылке.

## Лечение

Демотирование контента в lazy-слой всегда сопровождается отдельным обязательным шагом linkcheck — поиском всех ссылок на прежний путь по всей кодовой базе и их обновлением.
