# DP.FM.140 — Неполный cutover: основной путь отключён, side-channel активен

**Описание:** При переходе на новую систему (cutover) отключается только основной путь доставки, но side-channel (напоминания, резервная очередь, webhook) продолжает работать по старой логике.

**Симптом:** Пользователи продолжают получать нежелательные уведомления после миграции, хотя основной поток отключён.

**Причина:** Система имеет два независимых пути доставки с разными точками входа. Предикат перехода применён только к основному пути.

**Пример:** Cutover отключил `get_all_scheduled_interns` (основная доставка), но `check_reminders→send_reminder` (напоминания +1h/+3h) не проверяла флаг перехода — legacy-напоминания продолжали приходить.

**Аналог:** Отключить HTTP-сервер, забыть WebSocket — данные продолжают поступать через второй канал.

**Фикс:** Единый предикат перехода (`is_migrated(user_id)`) применяется симметрично во ВСЕХ путях доставки.

**Тест:** «Сколько точек входа в систему доставки? Применён ли предикат к каждой?» Если нет — неполный cutover.
