# DP.FM.141 — Shared queue без tenant-ключа: cross-instance dedup contamination

**Описание:** Очередь без поля `tenant_id`/`bot_id`/`instance_id` становится общей для всех экземпляров на одной БД. Dedup-окно, рассчитанное под один инстанс, не изолирует записи между инстансами.

**Симптом:** При запуске двух инстансов (pilot + prod) один обрабатывает строки, созданные другим → дублирующая доставка или ложное dedup-блокирование.

**Пример:** `marathon_queue` без `bot_id`: pilot-бот создаёт строки → prod-бот читает их как «уже обработано» → дублирование или пропуск доставки.

**Тест применимости:** «Могут ли записи двух инстансов быть неотличимы по содержимому строки (без JOIN на meta-таблицу)?» Да → обязателен tenant-ключ ИЛИ отдельная БД.

**Фикс:** Добавить `bot_id`/`env_id` в схему очереди — ЛИБО использовать физически изолированную БД для каждого инстанса.

**Выявляется только при:** запуске >1 инстанса одновременно на одной БД.

**Связи:** DP.D.028 (user-data tiers), DP.FM.140 (неполный cutover).
