# DP.FM.380 — гонка часовых поясов на границе суток

## Паттерн

Логгер, пишущий метки времени в UTC, и проверка в другой части системы (например, скрипт SKILL.md), сравнивающая с локальным временем, дают рассинхрон вблизи полуночи по локальному времени: момент, который для одной стороны уже «следующий день», для другой ещё «текущий» — race по временной зоне. Смежный баг: ключ имени state-файла, содержавший дату, ломался при пересечении полуночи в середине операции (кросс-полуночный баг), исправлено удалением даты из ключа.

## Механизм

1. Один компонент фиксирует время в UTC
2. Другой компонент сравнивает с локальной датой/временем
3. Возле границы суток (в зависимости от смещения TZ) один компонент уже видит «новый день», другой — ещё «старый»
4. Логика, ожидающая согласованности между ними, ломается именно на этой узкой временной границе

## Почему опасен

Проявляется редко (только вблизи полуночи по конкретной TZ) — трудно воспроизвести и продиагностировать вне точного окна времени, легко списать на случайный сбой.

## Лечение

Единая временная база (UTC) для всех сравнений внутри одной логической операции; не включать дату в ключи состояния, которые должны быть стабильны в пределах операции, пересекающей полночь.
