# DP.FM.198 — Crypto-shredding не является GDPR-удалением: регуляторы не признают удаление ключа эквивалентом удаления данных

## Описание

Архитектурное решение: зашифровать PII пользовательским ключом; реализация права на забвение = удаление ключа. Failure mode: шифрованный текст остаётся в immutable-журнале навсегда. Ключ потенциально скопирован в backup/audit-log/скомпрометированный процесс → данные восстановимы → регуляторы квалифицируют это как «отзыв доступа», не «удаление данных».

## Пример

WP-457 Ф12 К5: crypto-shredding предложен как решение конфликта immutable-журнала с GDPR. Отклонён: (1) ключ потенциально скопирован → данные восстановимы при утечке; (2) управление N ключами — новый операционный риск. Принятая альтернатива: user_id отдельно от хешируемого содержимого + санкционированные разрывы цепочки с отметкой причины.

## Тест обнаружения

«Если ключ пользователя утечёт из backup — будут ли данные восстановимы?» Да → crypto-shredding не удовлетворяет требованию забвения.

## Инвариант

Crypto-shredding = отзыв доступа при живом ключе. GDPR erasure = данные физически невосстановимы. Равенство не выполняется.

## Митигация

1. Хранить user_id отдельно от хешируемого содержимого событий.
2. Реализовать санкционированные разрывы цепочки с явной отметкой причины (GDPR-request) и без фальсификации истории.
3. Не применять crypto-shredding к регулируемым данным без юридического подтверждения эквивалентности в конкретной юрисдикции.
