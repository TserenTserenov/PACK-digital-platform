# [DP.FM.281] Iterative Edit Regression in Untouched Parts

## Суть паттерна

При многораундовой правке текста (писатель + ревьюер) каждый раунд проверяется только **дельта** — что изменено. Нетронутые фрагменты предполагаются валидными. Но правка одного блока (например, замена метафоры) может «восстановить» абстрактные формулировки в соседнем блоке, которые в предыдущем раунде были исправлены на конкретные.

## Инцидент

Telegram-пост telegram-19-07 прошёл 8 итераций правки. Правки метафорического слоя (кухня → блюдо) в одном месте восстанавливали абстрактные фразы («новая культура работы с информацией», «правильно структурировать разного типа информацию») в других местах, которые ранее были конкретными.

## Механизм

1. Раунд N: ревьюер исправляет блок A (был абстрактным — стал конкретным).
2. Раунд N+1: автор редактирует блок B (соседний). При переформулировке B изменяет часть A, возвращая абстрактность.
3. Ревьюер в раунде N+1 проверяет только дельту раунда N+1 (блок B). Блок A не перечитывается — «он уже был исправлен».

## Тест на провал

Последний раунд правки: проверить весь текст по чеклисту конкретности (каждое утверждение — с примером?), **не только изменённые фрагменты**. Если нашлись абстрактные формулировки в «нетронутых» блоках — FM.281 проявился.

## Детектор

Финальная проверка = чтение всего текста по чеклисту, не только изменённых фрагментов. Применимо к любым итеративным редакционным конвейерам «писатель + ревьюер».

## Защита

1. **Финальный full-pass (не delta-check):** перед публикацией — прочесть весь текст целиком, не только правки последнего раунда.
2. **Checklint по всему тексту:** каждое утверждение — с примером? Проверять все утверждения, не только новые.
3. **Freeze-memo:** после исправления блока зафиксировать «блок проверен в раунде N»; следующий раунд явно перечитывает freeze-блоки.
