# DP.FM.486 — Общий обработчик состояний перехватывает чужие префиксы колбэков

## Тезис и механизм ошибки

Общий обработчик состояний (SM) в профильном и настроечном состоянии перехватывал все входящие `callback_data`, включая префикс `github_*`, раньше, чем их успевал увидеть более специализированный `github_router`. Одно событие обрабатывали два обработчика с расходящимся побочным эффектом: при уже подключённом GitHub пользователь получал неверную подсказку «Подключите GitHub» вместо «Репозиторий не выбран». Исправление: `callbacks_router` больше не перехватывает `github_*` в состоянии профиля и настроек, выбор и отключение репозитория обрабатывает `github_router` (`handlers/github.py`), дублирующая обработка между SM и `github_router` убрана.

## Диагностический принцип

В системах с несколькими уровнями диспетчеризации по префиксу или шаблону (state-machine плюс именованные роутеры) общий уровень должен явно исключать зарезервированные префиксы специализированных обработчиков. Иначе порядок регистрации молча решает исход, без ошибки.

## Границы

Ошибка относится к многоуровневой диспетчеризации событий, где несколько обработчиков претендуют на одно пространство идентификаторов (боты, event-driven UI). Противоположный дефект описан в `DP.FM.074`: обработчик состояний не подключён к роутеру, и колбэк не обрабатывается вовсе. `DP.FM.098` — соседний дефект SM-слоя бота с другим механизмом.

## Проверка

«У общего обработчика есть явный список зарезервированных префиксов специализированных роутеров, которые он не перехватывает? Колбэк с префиксом специализированного роутера, отправленный в состоянии профиля или настроек, обрабатывается ровно один раз и именно этим роутером?» Нет → воспроизведён DP.FM.486: исход определяется порядком регистрации, а не назначением обработчиков.
