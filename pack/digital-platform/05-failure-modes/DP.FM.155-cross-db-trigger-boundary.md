# DP.FM.155 — Разработка кросс-БД Postgres-триггера

## Паттерн ошибки

Проектируется Postgres-триггер для логики, затрагивающей таблицы из нескольких баз данных (напр., payment/rewards/learning в Neon), без проверки что все таблицы в одной БД.

## Контекст

Postgres-триггер ограничен одной базой данных:
- Не может читать таблицы другой БД через JOIN
- Не может вызывать функции другой БД
- Не реагирует на события другой БД

В архитектурах с изолированными БД (Neon с разными проектами, PlanetScale, Supabase разные проекты) триггер физически привязан к одной из них.

## Почему незаметен

- Dev-окружение часто одна схема/одна БД — ошибка не проявляется при разработке
- Нет compile-time предупреждения: проблема архитектурная, не синтаксическая
- Обнаруживается только при реализации или деплое в multi-DB среду

## Последствия

Переработка архитектуры: вместо триггера — отдельный компонент (projection-worker) с пулами соединений ко всем нужным БД.

## Тест

«Все таблицы, участвующие в логике, — в одной БД?»
- Да → триггер возможен
- Нет → триггер невозможен, локус = сервис/воркер с multi-DB пулами

## Применимость

Любая архитектура с изолированными БД одного вендора: Neon (разные проекты), PlanetScale, Supabase (разные проекты), RDS (разные кластеры).
