# DP.FM.358 — git worktree не открывает одну ветку дважды

## Паттерн

Попытка использовать `git worktree` для изоляции нескольких параллельных агентских сессий на одной и той же ветке не работает «само по себе»: git отказывается создавать два worktree на одну и ту же ветку одновременно. Для параллельной изоляции требуется отдельная ветка на каждую сессию.

## Механизм

1. Два параллельных агента пытаются работать через `git worktree add` с одинаковой целевой веткой
2. Git-инвариант: одна ветка не может быть checkout'нута в двух worktree одновременно
3. Второй `worktree add` завершается ошибкой, если явно не создать per-session ветку заранее

## Почему опасен

- Идея «просто добавить worktree для изоляции» выглядит достаточной, но не покрывает случай нескольких параллельных агентов на одной задаче/ветке без дополнительной подготовки
- Ошибка обнаруживается только в момент попытки запуска второго параллельного агента, не при проектировании

## Лечение

1. Для параллельных агентских сессий — генерировать уникальную per-session ветку перед созданием worktree (например `agent-session-<id>`)
2. Не полагаться на один и тот же `main`/рабочая ветка для нескольких одновременных worktree

## Связи

- Применимо к любой инфраструктуре параллельных агентских сессий, использующей git worktree для изоляции
