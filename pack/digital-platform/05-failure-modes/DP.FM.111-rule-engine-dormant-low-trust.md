# DP.FM.111 — Спящее правило в session-memory: trust < cut-off → не попадает в reminders

## Описание

Failure mode session-memory rule-engines (Hermes / R31 / любой проксирующий правила к агенту): правило существует и формально известно системе, но из-за низкого trust_score (или relevance, или recency) не попадает в top-N reminders, выдаваемых агенту на старте сессии — агент совершает то же нарушение, ради которого правило заведено.

## Симптом

Recurring-косяк агента в нескольких сессиях подряд. При разборе обнаруживается: правило **уже есть** в БД, но в активные reminders не попало. Пример (WP-364): правило id=2011 «WP naming: процесс ≠ артефакт» с trust=0.60 → не в top-3 → агент создал РП с именем-процессом.

## Диагноз

1. Проверить наличие правила в БД для нарушенного класса косяков.
2. Если правило есть → проверить trust_score → ниже cut-off top-N reminders.
3. Если правило отсутствует → отдельный FM (no-rule-coverage), не этот.

## Фикс

- **Конфигурация под доменное знание:** ручной boost `trust_score >= 0.85` для critical-правил (нарушение которых блокирует протокольный шаг).
- **Экзоскелет (DP.D.046):** изменить ranking — повторяющиеся нарушения автоматически поднимают trust (но это help to thinking, не замена review-цикла).

## Тест

«Есть ли правило в БД для этого класса косяков, и почему оно не сработало?» — обязательный шаг при разборе recurring-косяка.

## Связи

- DP.D.046 (Экзоскелет ≠ Автопилот) — автоматический ranking = экзоскелет, фиксированный boost = конфигурация.
