# DP.FM.279: Day Open hook не транзитивно вызывает дочерние скрипты

## Описание

Extension hook запускает day-plan.md, но day-plan.md не вызывает дочерние скрипты (checks.md) явно — ожидание транзитивного вызова не выполняется, приводя к пропуску проверок.

## Паттерн отказа

Рецидив четвёртого поколения (DOE4–DOE7 в WP-7): при многоуровневом протоколе со скриптами, организующими цепочку вызовов, разработчик предполагает автоматический транзитивный вызов. Результат: дочерние скрипты молчаливо пропускаются, когда их вызов отсутствует в коде родителя.

## Критерий выявления

При отладке multi-script protocol в .claude/hooks/ или .iwe-runtime/:
1. Проверить цепочку явных вызовов: `grep -r "checks" .claude/`
2. Убедиться, что каждое звено **явно** вызывает следующее
3. Не предполагать транзитивный вызов без проверки кода

## Когда срабатывает

- Архитектор протокола и разработчик — разные люди или разные моменты времени
- Описание протокола говорит «day-plan вызывает проверки», но код день не реализует
- Отладка идёт по внешнему интерфейсу («я запустил day-plan») без трассировки вложенных вызовов

## Примеры

**WP-7 Ф-DayOpen-Enforcement:** Extension hook → day-plan.md (вызывается явно) → checks.md (не вызывается в коде day-plan.md) → проверки пропускаются, День Open не завершается.

## Применимость

Любой многоуровневый скриптовый протокол: CI/CD pipelines, event-processing chains, multi-phase automation.

## Связанные сущности

- WP-7 Ф-DayOpen-Enforcement (контекст первоначального обнаружения)

## Метод обнаружения

- **Автоматизированный:** static call-graph lint (grep или AST-анализ для обнаружения missing calls)
- **Ручной:** проверка архитектурного описания против git diff при изменении скриптов
