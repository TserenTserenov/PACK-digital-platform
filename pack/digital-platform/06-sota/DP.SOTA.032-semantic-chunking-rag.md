# DP.SOTA.032 — Семантическая нарезка чанков обученной моделью (RAG)

## Феномен

Нарезка текста на чанки специально обученной нейросетью (semantic chunking) даёт заметно
более релевантный поиск, чем фиксированная нарезка по символам / предложениям / абзацам —
на тех же запросах. Модель небольшая, запускается локально. Подтверждено внешним
исследованием (Андрей, Оперативка ИТ 25 июня 2026).

## Значение для IWE

Качество любого retrieval-процесса ограничено качеством чанков на входе
(«garbage chunks → garbage retrieval»). Затрагивает knowledge_search, граф понятий (ingest),
персональный поиск. Дополняет приоритетную тройку SOTA (Context Engineering, DP.SOTA.002):
хороший контекст начинается с хорошей сегментации источника.

## Инструменты-кандидаты

- chonkie
- semantic-chunker
- llm-chunker

(локальный запуск, небольшая модель — приватность сохраняется)

## Ограничения

- Конкретный выигрыш зависит от домена и типа документов — требует A/B-замера на нашем
  корпусе перед внедрением
- «Обученная модель сегментации» — общий класс, не один стандарт; выбор инструмента —
  отдельное решение

## Оспаривается (2026-09-21, РП-170)

Тезис карточки («нарезка обученной моделью даёт заметно более релевантный поиск, чем фиксированная») оспаривается результатами сессии `MC-sessions:2026-09/18/2026-09-18-06-wp579-chunking-research` (WP-579 Ф1, Claude + Kimi + Codex, консенсус; отчёт `report.md`). По четырём независимым измерениям 2024-2026 годов разница между «умным» и простым чанкером составила 0,5-2 процентных пункта при кратно более высокой стоимости; источники сессии включают T2-RAGBench, HiChunk, RusBEIR, ruMTEB и Anthropic contextual retrieval (всего 47 фоновых). Больший измеренный эффект даёт гибридный поиск с объединением через Reciprocal Rank Fusion, ранжирование результатов (reranking) и контекстные заголовки.

Оговорки сессии: текущий чанк-потолок конвейера (10 000 символов) лежит вне диапазона этих измерений (200-1000 токенов на чанк), поэтому переносить «±2 п.п.» на него некорректно; нейро-чанкер (chonkie) отклонён как приоритет, потому что нет опубликованных измерений качества поиска, только внутренняя метрика границ секций. Проверка пилотом ожидается; до неё не цитировать тезис карточки как установленный. Статус `draft` и основной текст карточки не менялись.
