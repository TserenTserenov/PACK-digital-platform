## Проблема, которую закрывает

Мобильное взаимодействие с ботом = печатать на ходу. Высокая фрикция: на бегу, за рулём, в движении мысль теряется, пока набираешь. Голосовой ввод снимает фрикцию захвата. Но наивная реализация «голос → ассистент» ломается о факт: у бота **нет общего LLM-pipeline** — он handler/FSM/prefix-маршрутизируемый, свободный текст без команды/префикса падает в `fallback.py` (подсказка). Поэтому естественная речь «на бегу» (поток сознания, не команда «Гермес, ...») в чистом «голос → ассистент» получила бы fallback «не понял» → пользователь бросает фичу.

## Правило (инварианты — что гарантируется)

- **Голос = чистый edge-канал.** Распознавание (транскрипция) происходит в aiogram-handler на границе; дальше — обычный текстовый путь. Никакой voice-специфичной ветки внутри ядра ассистента (инвариант thin-client / [[суть ≠ интерфейс]]).
- **Always-capture (мысль не теряется).** Расшифровка голосового **безусловно** сохраняется как заметка, независимо от того, смог ли ассистент ответить. Целевой flow — существующий путь рефлексии (`reflect.py` → `history/YYYY-MM-DD-*.md` в personal-guide), не отдельный безымянный инбокс.
- **Best-effort ответ.** Параллельно расшифровка прогоняется по hermes-пути (DP.SC.169: hermes_chat для T≥3 / Проводник на Haiku для T<3). Ответ = эхо расшифровки + содержательный ответ ассистента, либо (если ответ = дефолтный fallback-шаблон) «Сохранил заметку: <эхо>. Нужно действие — уточните текстом.» Проверка «содержательный ответ» = «ответ ≠ дефолтный fallback-шаблон», НЕ новый intent-классификатор.
- **Эхо расшифровки обязательно.** Ответ всегда показывает, что распозналось — доверие + проверка точности Whisper.
- **Аудио не хранится (transcribe-and-discard).** После распознавания аудиофайл удаляется; в покое аудио не лежит.
- **Egress раскрыт явно.** Аудио уходит в OpenAI Whisper (третья сторона) — пользователь уведомлён до первого использования.
- **Отдельное согласие.** Голос требует explicit consent-gate, **не** reuse generic `tracking_consent` (иной класс данных: тембр-биометрия, фон, посторонние, возможный PII). Без согласия голос не обрабатывается.
- **Текстовый fallback.** Сбой распознавания → внятное сообщение + предложение повторить текстом, не молчание.
- **Без tier-gate.** Голос доступен на всех тирах (фрикция выше у новичков). Для T1/T2 — honest scope-месседж о границах ответа, не запрет.
- **Маркировка voice-заметок.** Заметка помечается источником (`source: voice` / тег `voice-log`) для будущей batch-чистки (Ф3) — защита от захламления inbox.

## Триггер · Входы · Выходы · Отклик · Режим отказа

- **Триггер:** пользователь шлёт голосовое сообщение (content_type voice) в бот.
- **Входы:** аудио OGG/Opus из Telegram (≤60 сек — hard cap; длиннее → reject с предложением разбить или текстом), telegram_user_id, тир.
- **Выходы:** (1) сохранённая заметка-расшифровка; (2) текстовый ответ = эхо + ответ ассистента/предложение уточнить.
- **Время отклика (SLA, MVP):** голосовое → ответ ≤15 сек для аудио ≤60 сек (Whisper ~3-8с + LLM). Длинное аудио, chunking, мульти-спикер — вне MVP.
- **Режим отказа:** ошибка Whisper / сети → текст-fallback («Не смог распознать, повторите текстом»); заметка не теряется только если транскрипция прошла (без транскрипции захватывать нечего — это честная граница).

## Сценарии использования (≥3)

1. **Пилот — идея на бегу.** Идёт по улице, голосом: «идея для статьи про экзоскелет мышления, проверить связь с WP-392». → расшифровка сохранена как заметка, бот эхом подтверждает. Мысль не потеряна.
2. **Стажёр — hands-free вопрос ассистенту.** За рулём (на светофоре): «как мне начать с программой личного развития?». → расшифровка сохранена + hermes-путь (для стажёра T1/T2 — Проводник) отвечает по существу онбординга или честно очерчивает scope.
3. **Оператор — быстрая фиксация задачи.** Между делами: «напоминание: проверить деплой воркера вечером». → заметка сохранена; ассистент best-effort (на MVP без TTS — текстовый ответ).

## Out-of-scope (MVP / Ф2)

Явно НЕ входит в MVP (защита от scope creep): TTS / голосовые ответы (Ф3), bidirectional voice, автоопределение языка, chunking длинных аудио (>60с), multi-speaker, голосовые команды без эха, кастомный голос (ElevenLabs — путь 3 roadmap), телефония (Google Agent Builder — путь 2 roadmap).

## ArchGate-оценка (профиль ЭМОГССБ + Security §Б)

> Решение системного уровня: новый внешний egress (аудио → OpenAI) + новый класс согласия (PII). Per Security Gate B7.3 — обязательна оценка ДО кода Ф2.

| Характеристика | Оценка | Комментарий |
|----------------|:------:|-------------|
| **Э**кономичность | ✅ | Whisper API дёшев (~$0.006/мин); ≤60с cap ограничивает COGS. Один вызов на сообщение. |
| **М**асштабируемость | ✅ | Stateless edge-транскрипция; нагрузка линейна; cap 60с защищает от тяжёлых запросов. |
| **О**тказоустойчивость | ✅ | Текст-fallback при сбое Whisper; always-capture делает заметку независимой от ответа ассистента. |
| **Г**ибкость | ✅ | Edge-инвариант: смена провайдера транскрипции (OpenAI→локальный) не трогает ядро. |
| **С**овместимость | ✅ | Reuse hermes-пути (DP.SC.169) + reflect-flow; новых контрактов в ядре нет. |
| **С**тоимость владения | ⚠️ | Шум voice-заметок (always-capture) → нужна маркировка + batch-чистка (Ф3), иначе захламление inbox. Известный риск, не блокер. |
| **Б**езопасность | ⚠️ | Audio egress к третьей стороне + PII в речи. Митигировано: transcribe-and-discard, egress-раскрытие, отдельный consent-gate, без хранения аудио. **Блокер снят только при выполнении всех 4 privacy-инвариантов.** |

**Security §Б (B7.3):** PII в голосе (имена, контакты, возможные чувствительные данные). Логирование расшифровки = только в существующий notes-flow с согласием пользователя; сырое аудио НЕ логируется и НЕ хранится. Передача в OpenAI — под explicit consent.

**Conjunctive screening:** ни одного ❌. Два ⚠️ (стоимость владения = шум заметок; безопасность = egress) имеют явные митигаторы и критерии приёмки. → решение проходит экран при условии реализации всех privacy-инвариантов и маркировки заметок.

## Roadmap (после Ф1)

- **Ф2 (~6-8h, после ArchGate-pass):** voice-handler в боте, Whisper-интеграция (с нуля — reusable клиента нет, вопреки исходному контексту РП), always-capture через reflect-flow, best-effort hermes-ответ, consent-gate, cap 60с. Smoke: голосовое ≤60с → эхо + ответ/подтверждение заметки ≤15с.
- **Ф3 (~8h):** TTS (выбор провайдера: OpenAI TTS / ElevenLabs / Google), bidirectional voice, маркировка + batch-чистка voice-заметок.
