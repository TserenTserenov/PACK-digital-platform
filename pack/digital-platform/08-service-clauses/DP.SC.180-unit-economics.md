# DP.SC.180 — Юнит-экономика IWE

> **Одной фразой:** для направления или продукта IWE сервис даёт расчёт юнит-экономики (выручка, отток, расходы, маржа) с разбивкой по когортам, **с явным указанием допущений и границ применимости** — и честно отвечает «нет данных» вместо экстраполяции, когда выборки не хватает.

---

## §1. Обещание

| Потребитель | Что получает |
|---|---|
| Стратег (Strategy Session) | Окупаемость направления, маржа, snapshot выручки/расходов по когорте |
| Портной (продуктовые решения) | Точка безубыточности, потолок привлечения для целевой маржи, рекомендация «запускать / дорабатывать / не запускать» |
| Оператор (еженедельный контроль) | Тренд выручки, отток за неделю, доля маркетинга в выручке, флаги порогов |
| Продуктовая команда | Стандартный SaaS-отчёт (формат Bessemer/Skok) без ручного сбора |

## §2. Триггер

Batch: еженедельно при закрытии недели ИЛИ ad-hoc по запросу потребителя.

## §3. Входы / Выходы

- **Читает:** платежи (выручка, возвраты), гранты подписок (отток, удержание), стоимость инфраструктуры и LLM (расходы), UTM-разметку (привлечение). Точные таблицы и поля — в контракте данных (см. frontmatter `data_contract`).
- **Пишет:** дашборды (когда активированы), отчёты для Strategy Session, артефакты продуктовых решений.

## §4. Инвариант

1. Сервис **не делает прогнозов без указания доверительного интервала / допущений**.
2. При отсутствии данных — честный «нет данных» вместо экстраполяции.
3. Один источник стоимости (cost-callback), без параллельного учёта (OwnerIntegrity).

## §5. Границы применимости (режим отказа)

> **Текущий рунг: 1 (ассоциация).** Помечается `N < min_sample`, пока платящих < 30 и нет полной когорты 3 мес.

| Режим | Что входит |
|---|---|
| **supportedUse** | Описательный snapshot: выручка (MRR), переменные расходы на пользователя, маржа вклада, активные пользователи; продуктовый шаблон расчёта (3 сценария) |
| **unsupportedUse** | Когортный отток, LTV, окупаемость привлечения (CAC payback), любые прогнозы и интервенционные утверждения — **до триггера** ≥30 платящих И ≥1 полная когорта (3 мес.) |

**Режим отказа:** при недостатке данных → описательная статистика по наблюдениям; прогнозирование и каузальные утверждения отключены.

## §6. Время отклика

Batch (не real-time). Snapshot строится из daily-кэша, чтобы не нагружать прод-БД (ЭМОГССБ: эффективность).

## §7. Статус реализации (WP-390)

- **Готово (design + ready-to-run):** шаблон расчёта (Ф2), контракт данных (Ф3), SQL-прототипы snapshot + synthetic smoke (Ф4).
- **Отложено с триггером:** дашборд (Ф5 — ≥30 платящих И когорта); проекция в командное табло (Ф6 — реопен WP-302 + появление команды-аудитории).
- **Открытый шаг:** прогон SQL на проде под доступом + DLP → живые числа.
