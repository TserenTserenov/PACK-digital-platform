# [DP.SC.155] Маршрут оснащения — Setup Journey

> # see DP.SC.155 (WP-349 Ф8-пре)

## Правило (инвариант)

- **Свежесть данных:** tier_detector (кэш 5 мин), cp_assessments (live из Neon), onboarding_state (first_use_* флаги, допустимо stale до 8h).
- **Единый источник тира:** только tier_detector — не onboarding_state.
- **asyncio.gather():** Railway pool (resolve ory_uuid) и Neon pool (cp_assessments + onboarding_state) читаются параллельно.
- **Double-tap protection:** callback.answer() + edit_reply_markup(None) немедленно при нажатии CTA — до выполнения бизнес-логики.
- **Cooldown-sync:** любой CTA-клик пишет `last_nudge_at = now` в `learning.onboarding_state` — исключает дубль от onboarding_controller в течение 24h.
- **Идемпотентность:** повторный /setup показывает актуальный дашборд без побочных эффектов.

## Обещание

**Кому:** Пилот R2 (T1+, привязан к Aisystant-аккаунту).

**Зачем:** Без маршрута оснащения пилот не знает, что делать после согласия: нет индикатора прогресса, нет следующего шага, нет понимания «где я». /setup устраняет навигационный пробел между T1 и T4.

**Что получит:**

| Потребитель | Канал | Что получает |
|-------------|-------|-------------|
| Пилот (T1) | Telegram /setup | Дашборд: шкала T1→T4, ступень (если есть диагноз), чекбоксы подключённых инструментов, CTA «следующий шаг» |
| Пилот | Guided flow (callbacks) | Пошаговые инструкции: пройти диагностику → привязать браузер → оформить подписку → подключить репозиторий |
| Onboarding controller | Cooldown sync | `last_nudge_at` обновлён — нет дубля в течение 24h |

**Триггер:** команда `/setup` в Telegram (R2-пилот) или callback кнопки guided flow.

**Время отклика:** дашборд отображается ≤3 сек (parallel gather двух DB пулов).

**Режим отказа:**
- Neon недоступен → отображается базовый дашборд с данными из Railway (tier_detector) + сообщение «Данные диагностики временно недоступны».
- Railway недоступен → команда не работает (критическое — нет ory_uuid).
- Частичный gather fail → degraded mode: заполнить что доступно, пропустить отсутствующее.

## Что НЕ делает маршрут оснащения

- **Не выполняет диагностику** — только показывает результат из cp_assessments.
- **Не управляет подпиской** — только отображает статус из tier_detector.
- **Не создаёт GitHub-репозиторий** — только показывает, подключён ли.
- **Не отправляет nudge по расписанию** — это DP.SC.151 (onboarding_controller).

## Сценарии использования

### СС.1 — Первый заход (T1, нет диагноза)

Пилот только прошёл онбординг. Открывает /setup.

Дашборд:
```
📍 Ваш путь: T1 → T4

✅ Аккаунт привязан
⬜ Диагностика ступени
⬜ Подписка БР
⬜ Браузер-расширение (T3)
⬜ Репозиторий GitHub (T4)

👉 Следующий шаг: пройти диагностику
[🧪 Пройти диагностику]
```

### СС.2 — Диагноз есть, нет подписки (T1, cp_stage=2)

```
📍 Ваш путь: T1 → T4

✅ Аккаунт привязан
✅ Ступень: 2 (Практикующий)
⬜ Подписка БР
⬜ Браузер-расширение (T3)
⬜ Репозиторий GitHub (T4)

👉 Следующий шаг: оформить подписку
[💳 Оформить подписку]
```

### СС.3 — Повторный заход (T2, браузер не подключён)

```
📍 Ваш путь: T2 → T4

✅ Аккаунт привязан
✅ Ступень: 3 (Систематический)
✅ Подписка БР активна
⬜ Браузер-расширение (T3)
⬜ Репозиторий GitHub (T4)

👉 Следующий шаг: установить расширение
[🔌 Инструкция по установке]
```

### СС.4 — Полный T4

```
📍 Ваш путь: T4 (полное оснащение)

✅ Аккаунт привязан
✅ Ступень: 4 (Дисциплинированный)
✅ Подписка БР активна
✅ Браузер-расширение подключено
✅ Репозиторий GitHub подключён

🎉 Вы полностью оснащены!
```

## Свидетельства (критерий приёмки)

| Критерий | Как проверить |
|----------|--------------|
| Дашборд показывает актуальный тир | tier_detector возвращает T1/T2/T3/T4 — совпадает с подпиской Aisystant |
| cp_stage из cp_assessments, не из onboarding_state | `SELECT stage FROM learning.cp_assessments WHERE account_id='...' ORDER BY created_at DESC LIMIT 1` — совпадает с отображаемой ступенью |
| double-tap не вызывает двойного действия | Быстрое двойное нажатие CTA → только одно действие выполнено |
| last_nudge_at обновлён после CTA | `SELECT last_nudge_at FROM learning.onboarding_state WHERE account_id='...'` — timestamp обновлён |
| Дашборд ≤3 сек | Railway logs: `/setup` response time |

## Реализующие сервисы (MAP.002)

| Сервис | Роль | Триггер |
|--------|------|---------|
| `handlers/setup.py` (aist_bot) | Команда /setup + guided flow callbacks | /setup, callback data |
| `tier_detector.py` | Определение тира (кэш 5 мин) | вызов из setup.py |
| `learning.cp_assessments` (Neon) | Ступень мастерства | SELECT при gather |
| `learning.onboarding_state` (Neon) | first_use_* флаги + cooldown sync | SELECT + UPDATE при gather / CTA |
