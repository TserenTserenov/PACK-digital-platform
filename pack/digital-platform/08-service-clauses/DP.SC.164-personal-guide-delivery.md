# DP.SC.164 «Доставка персонального руководства пилоту»

> **Статус:** перенесено из draft `inbox/WP-371/peer-session-2026-05-30/DP.SC-personal-guide-delivery.md` в Pack (peer-session 2026-05-30-45). Provider role `DP.ROLE.NNN Портной` — handoff в отдельный РП (не существует на момент создания).

## Краткая формула обещания

Каждое утро (по расписанию пилота, дефолт 7:00 локали) — `daily/<YYYY-MM-DD>.md` в репо `personal-guide/<пилот>/`. Каждый понедельник 8:00 локали — `weekly/<YYYY-Www>.md`. Supporting-файлы (`profile.md`, `concerns.md`, `iwe-changes.md`, `README.md`, опц. `worldview.md`/`methods.md`) — при изменении входов (dirty-check). Файлы отражают **контекст пилота** (его РП, captures, посты, рефлексии, cp-профиль), не оглавление универсального руководства.

## Элемент 1 — Триггер

| Режим | Когда | Источник расписания |
|-------|-------|---------------------|
| Daily | Расписание пилота, по дефолту **07:00 локали пилота** (предложение peer-сессии 2026-05-30-35; конкретное значение утверждается пилотом; мотив: «утром голова свежая») | `personal-guide/<пилот>/config.yaml` поле `daily_time`, при отсутствии — default 07:00 |
| Weekly | **Понедельник 08:00 локали пилота** (тот же статус: предложение peer-сессии, утверждение пилотом) | `config.yaml` поле `weekly_time`, при отсутствии — default Пн 08:00 |

Триггер инициирует внешний планировщик (календарный конвейер WP-357 или эквивалент). **Никакой skill ОРЗ не инициирует рендер** (инвариант R, см. ниже).

## Элемент 2 — Входы

### Daily
- cp-профиль пилота (по PD.FORM.089 §6.1): `cp.rhy`, `cp.wld`, `cp.skl`, `cp.iwe`, `cp.int`, `cp.agt`.
- Активные РП пилота (статус `in_progress` или `pending`) из `DS-my-strategy/inbox/WP-*.md`.
- Captures за последние 24h (`personal_search` API по сорсам клуб/LMS/captures).
- Последний выпущенный `daily/<вчера>.md` (для непрерывности нарратива).
- **Явный запрос пилота** из `personal-guide/<пилот>/requests.md` (если есть; срок жизни — 1 день).
- **Метки чтения и полезности** последних N дней (для определения unread_streak и feedback-цикла).
- Индекс тегов универсального руководства программы пилота: `docs/ru/<program>/index.tags.json`.

### Weekly
- cp-профиль пилота.
- `WeekPlan W{N}.md` и/или `WeekReport W{N-1}.md` (если присутствуют).
- Captures за последние 7 дней.
- Последний выпущенный `weekly/<YYYY-Www-1>.md`.
- **Явный запрос пилота** из `requests.md` (если есть; срок жизни — 1 неделя).
- **Агрегированные feedback-метрики** за прошлую неделю (read_ratio, useful_ratio, capture_rate по тегам).
- Индекс тегов универсального руководства.

### Общие входы (настройки пилота из `personal-guide/<пилот>/profile.md`)
- **Квалификация пилота** (Ученик/Работник/Стратег/Специалист/Практик) — самодекларация / последний тест Диагноста / RCS-fallback.
- **`primary_program`** (ЛР/РР/ИР) — основная программа развития пилота; постоянная, меняется редко.
- **`current_request`** (свободный текст, опционально) — кратковременный запрос пилота, активирует временное усиление веса соответствующих фрагментов.
- **`daily_session_minutes`** (15 / 30 / 45 / 60, default 15) — настраиваемая длительность ежедневного занятия. Управляет L-инвариантом.
- **`weekly_session_minutes`** (15 / 30 / 45 / 60, default 30) — настраиваемая длительность недельной сессии.
- **`source_weights_override`** (опционально, формат `{<источник>: <delta>}`) — корректировка весов источников относительно базовой таблицы (например, `{honcho: -2, personal_search: +1}`). Финальный вес ≥ 0.
- **`pause_until`** (опционально, ISO-дата) — пауза рендера до указанной даты (для отпуска / болезни).

## Элемент 3 — Выходы

### Daily
- **Обязательно:** `daily/<YYYY-MM-DD>.md` (5 секций, см. контракт ниже).
- **По dirty-check:** обновление `profile.md`, `concerns.md`, `iwe-changes.md` (если входы изменились).

### Weekly
- **Обязательно:** `weekly/<YYYY-Www>.md` (6 секций) + `README.md` (обложка репо, при смене квалификации/программы).
- **По dirty-check:** те же supporting + опц. `worldview.md`, `methods.md` (только Ученик).

## Элемент 4 — Время отклика (SLA)

- **Daily:** P95 ≤ 30 сек от триггера до успешного `git push`.
- **Weekly:** P95 ≤ 60 сек.
- Превышение SLA = инцидент (событие `personal_guide.render.slow` для R46 или мониторинга).

## Элемент 5 — Инварианты

### K (контекст превыше плана) — главный инвариант обещания
В каждом выпущенном файле:
- **§1 (daily) / §1 (weekly):** обязан содержать явный якорь `Refs: <WP-NNN | capture-... | проект-...>` на актуальный элемент S3.
- **§2, §4 (daily); §2, §3, §4 (weekly):** обязаны иметь tag-пересечение с активным множеством сигналов S3 (теги фрагмента ∩ теги S3 ≠ ∅).
- **§3, §5 (daily); §5, §6 (weekly):** не проверяются по K, имеют собственные критерии (`is_actionable`, `target_repo`).
Нарушение → `degraded: content`.

### R (курьер — рендер независим от ритуалов)
- Ни один skill ОРЗ (`/day-open`, `/day-close`, `/week-open`, `/week-close`, `/lesson`) не вызывает Портного.
- Все вызовы Портного — только от внешнего планировщика по расписанию.
- Skill'ы ОРЗ читают готовые файлы daily/weekly как input. Если файла нет — отрабатывают на пустом руководстве с пометкой «руководство не пришло».

### L (окно длины) — параметризовано по настройке пилота

Длина зависит от `daily_session_minutes` (default 15) и `weekly_session_minutes` (default 30) из `profile.md`:

| Длительность | Daily окно | Weekly окно |
|--------------|-----------|-------------|
| 15 мин       | 350-450 слов | 600-800 слов  |
| 30 мин       | 700-900 слов | 1100-1500 слов |
| 45 мин       | 1050-1350 слов | 1700-2200 слов |
| 60 мин       | 1400-1800 слов | 2300-2900 слов |

- Соотношение секций сохраняется (см. DP.M.241 S5); все окна секций масштабируются пропорционально.
- Превышение/недобор → жёсткое усечение/расширение в S5/S7 с пометкой источника.

### D (детерминированный self-check)
- S6 self-check выполняется через **пересечение множеств тегов**, не семантическую близость.
- Tagging — предусловие сервиса (см. ниже).

### T (transparency — прозрачность выбора)
- §1 daily обязан содержать **обоснование «Почему сегодня это»** — 1-2 предложения с конкретикой источников выбора («на основании capture от <дата> + активного <WP-NNN> + явного запроса <X>»).
- §1 weekly аналогично — обоснование выбора фокуса недели.
- Без обоснования пилот не может корректировать процесс через `requests.md` и `source_weights_override` (не понимает, что повлияло). Без T главное правило «от контекста пилота» становится непрозрачной чёрной коробкой.

### F (feedback loop — управляемая обратная связь)
- Сервис обязан публиковать метрики чтения/пользы/captures для каждого выпущенного файла (события `personal_guide.feedback.*`).
- Метрики агрегируются в Honcho и используются для еженедельной автокорректировки весов (предложения для пилота, не автоприменение).
- Пилот видит агрегаты в weekly §6 «Что отслеживать».
- Подробности — DP.M.241 S8 «Feedback Loop».

### N (непрерывность нарратива)
- **Daily** обязан учитывать **вчерашний выпуск** и captures за последние 24h. В §1 daily обязан явно указать одно из:
  - «**Продолжаем** работу над <фокус вчера>» — если фокус не сменился.
  - «**Вчера** занимались <Y>, **сегодня** смещаемся на <X>, **потому что** <причина из S3>» — если фокус сменился.
  - «**Первый день** в персональном руководстве» — только при welcome-mode (нет вчерашнего файла).
- **Weekly** обязан учитывать **прошлый weekly** + ход недели по daily-цепочке. В §1 weekly обязан явно указать:
  - «**На прошлой неделе** фокус был на <Z>; **на этой** — <текущий фокус> на основании <причина>».
- **Если вчерашний daily был degraded** → этот факт явно отражается в новом daily («вчера руководство не пришло полностью; восстанавливаем связь с твоим контекстом»).
- **Источник проверки:** наличие в §1 одной из 3 формул («продолжаем», «вчера/сегодня смещаемся», «первый день») — проверяется grep'ом в S6.

Инвариант N — производный от главного принципа «от контекста пилота», но именно про **временной** контекст (вчерашнее + свежие captures). Без N сервис превращается в ежедневный «случайный урок», нарратив рвётся.

## Элемент 6 — Режим отказа

| Режим | Условие | Поведение | Событие |
|-------|---------|-----------|---------|
| `degraded: content` | Нарушен K-инвариант хотя бы в одной обязательной секции | Файл создан, плашка «руководство неполное», retry на следующее окно | `personal_guide.render.degraded` (reason=content, consecutive=N) |
| `degraded: no-tag-index` | Индекс `index.tags.json` отсутствует или невалиден | Рендер по последовательности оглавления универсального руководства, K-инвариант не применяется | `personal_guide.render.degraded` (reason=no-tag-index) |
| `degraded: no-context` | Cold-start: нет cp-профиля И нет РП И нет captures 14d И нет универсального руководства — после истечения welcome-mode | Минимальный onboarding-файл с плашкой «нам нужны твои сигналы — подключи репо/делай captures» | `personal_guide.render.degraded` (reason=no-context) |
| `welcome` | Cold-start, первый цикл | 5 фиксированных файлов (Дни 1-5: онбординг + базовая практика капчуры + первый фрагмент ступени 1 + первый weekly review) | `personal_guide.render.welcome` (day=N) |
| `failed` | Push в репо не удался (GitHub недоступен, права отозваны) | Рендер не выпущен, локальная очередь повторов | `personal_guide.render.failed` (error=...) → 3 retry с интервалом 5 мин |
| `suspended` | После 14 дней `no-context` контекст не появился | Полная остановка рендера до восстановления сигнала | `personal_guide.render.suspended` |
| `digest-mode` | `unread_streak >= 3` (пилот не открывал daily 3+ дня подряд) | Рендер выпускается как «дайджест за пропуски»: суть пропущенных дней + сегодняшний фокус; N-формулы заменяются на «вы пропустили N дней» | `personal_guide.render.digest` (skipped_days=N) |
| `paused` | `pause_until` в `profile.md` > сегодня | Рендер не выпускается, ожидается до `pause_until` | `personal_guide.render.paused` (until=...) |

Управление эскалациями на основе событий — **вне сервиса**. Подписчики (R46 Контролёр развития, TG-бот, мониторинг) решают по своим правилам.

## Элемент 7 — Потребители и каналы

### Consumers (потребители обещания)

- **Пилот** (DP.ROLE.001, IWE Creator) — через личный репо `personal-guide/<пилот>/`. Primary потребитель.
- **Skill `/day-open`** — читает daily как input.
- **Skill `/lesson`** — открывает daily в чате IDE.
- **R46 Контролёр развития** (TBD DP.ROLE) — подписан на события рендера для управления эскалациями.
- **TG-бот пилота** — best-effort нотификация со ссылкой на push.

### Каналы доставки

| Канал | Тип гарантии | Где живёт |
|-------|--------------|-----------|
| Push в репо `personal-guide/<пилот>/` | **Primary (обязательный)** — без успешного push рендер = failed | GitHub (App-installation у пилота) |
| `/lesson` skill в IDE | Pull (best-effort) — зависит от того, открыт ли IDE | Локально у пилота |
| Web-доступ к репо | Pull (best-effort) — зависит от GitHub Pages / web UI | GitHub |
| Telegram-нотификация со ссылкой на push | Notification (best-effort) — зависит от подключённого TG | TG-бот пилота |

### События для подписчиков

Публикуются после каждого рендера независимо от исхода.

**Основные:**
- `personal_guide.render.completed` (нормальный выпуск, для R46 и Day Open). TG-бот подписан на это событие как триггер нотификации со ссылкой на push.
- `personal_guide.render.degraded` (reason: `content` | `no-tag-index` | `no-context`, счётчик consecutive).
- `personal_guide.render.failed` (с ошибкой push, retry-counter).

**Производные от режимов** (extension, нужны R46 для управления эскалациями):
- `personal_guide.render.welcome` (day: 1-5) — производное от welcome-mode (Элемент 6).
- `personal_guide.render.suspended` (final) — производное от suspended-режима после 14 дней no-context.
- `personal_guide.render.digest` (skipped_days=N) — производное от digest-режима.
- `personal_guide.render.paused` (until=...) — производное от paused-режима.
- `personal_guide.render.slow` (SLA превышен) — производное от SLA-инварианта (Элемент 4).

**События feedback-цикла** (для self-correcting service, см. DP.M.241 S8):
- `personal_guide.feedback.read` (file=daily/weekly, source=`/lesson` | tg-click | repo-commit) — отметка чтения.
- `personal_guide.feedback.useful` (file, value=+1|-1) — пилотская оценка пользы.
- `personal_guide.feedback.capture_accepted` (file, section=§N, target_repo=Pack|feedback) — capture из §5 принят.

**TG-нотификация** — производный канал, не отдельное событие: бот подписан на `render.completed` и при получении публикует ссылку на push в чат пилота (best-effort).

## Предусловия (вне обещания, но фиксируются)

1. **Индекс тегов универсального руководства** `docs/ru/<program>/index.tags.json` существует и поддерживается актуальным (handoff в WP-364 Ф6 — разметка склада по графу понятий).

4. **Источники контекста** (DS-my-strategy / personal_search / Honcho) — необязательны, но без них работает в degraded.
