# DP.SC.067 — Секретарь: обязательства и вопрос по требованию

> **Статус: черновик.** Текст обещания зафиксирован по итогам архитектурной оценки и пир-сессии с Кодексом 15.08.2026 (WP-389). Реализация не начата — консенсус пир-сессии зафиксирован без запуска implementation pipeline (решение пилота: сначала зафиксировать).

## Обещание

**Кому:** пилоту (сейчас), любому пользователю шаблона IWE со своим репозиторием (после доставки, критерий готовности WP-389).

**Зачем:** обязательства и созревшие сроки (гипотезы с истёкшей датой сверки, застрявшие решения по РП) сейчас фиксируются в разных местах и ничем не оповещаются — пилот узнаёт о просрочке только если сам вспомнил заглянуть. Секретарь закрывает разрыв между «где-то записано» и «дошло вовремя», не создавая нового хранилища поверх уже существующих.

**Что получит:**
- Обязательство с истёкшим сроком доставляется без запроса пилота, не реже раза в 6-12 часов.
- У доставленного обязательства есть отмена — до отправки снимается тихо, после отправки отмена фиксируется отдельным событием (не удаление записи).
- На прямой вопрос («что просрочено», «что зависло», «на чём стоим») секретарь отвечает синтезом по существующим источникам (журнал гипотез, журнал событий, портфель РП), без нового хранилища и без обязательного вызова языковой модели на первом шаге — ответ идёт по фиксированному шаблону (просроченное → зависшее → конфликты, по возрасту).
- Если сам секретарь замолкает дольше полутора суток — отдельный сигнал об этом (защита от повторения находки 15.08: диспетчер, на котором стоит секретарь, простаивал три месяца незамеченным).

## Триггер

- Автоматический: обязательство пересекает срок (событие «созрело»), не реже раза в 6-12 часов.
- По требованию: пилот прямо спрашивает секретаря о состоянии дел.

## Входы

- Журнал гипотез (`current/hypotheses-log.md`, поле `due`/`status`), журнал событий (`machine/ledger/day/*.yaml`), портфель РП (`WP-REGISTRY.md` через `wp-list.py`).
- Прямой вопрос пилота (текст).

## Выходы

- Сообщение с созревшим обязательством, содержащее идентификатор для отмены.
- Ответ на прямой вопрос — синтезированный текст по фиксированному шаблону.
- Событие «отменено» / «доставлено» / «замолчал» в журнале.

## Время отклика

Созревшее обязательство доставляется в течение цикла обхода (6-12 часов), не мгновенно. Ответ на прямой вопрос — секунды (без вызова модели на MVP).

## Инвариант

1. Секретарь не становится новым источником истины — только читает уже существующие источники и синтезирует ответ (принцип платформы №6, отчуждаемость; снимает противоречие «единый vs распределённый календарь», зафиксированное в карточке WP-389 03.07.2026).
2. Любое доставленное обязательство отменяемо (принцип платформы №29, отменяемость автоматического действия) — на момент написания этой клаузы нигде в системе такого инструмента не было.
3. Не удалять записи при отмене — добавлять событие, чтобы сохранить след для разбора гонок «отменено до/после доставки».
4. Ответ на прямой вопрос без вызова модели строится по фиксированному шаблону, не сырой склейкой источников (находка пир-сессии 15.08 — иначе плохой пользовательский опыт).

## Режим отказа

- Источник (журнал гипотез/событий/РП) недоступен или повреждён → секретарь сообщает об этом явно, не выдаёт частичный ответ молча.
- Диспетчер, на котором держится доставка, не запускался дольше полутора суток → отдельный сигнал (см. «Что получит»), не тихое молчание.
- Канал доставки недоступен (нет ключа бота и т.п.) → обязательство остаётся непогашенным до восстановления канала, повторная отправка без нового вызова модели (переиспользуется уже принятый паттерн повторной отправки без нового суждения, WP-503).

## Границы с сопутствующими обещаниями

- Не путать с ночной актуализацией РП и очередью решений пилота ([DP.SC.064](DP.SC.064-wp-nightly-actualization-decision-queue.md), WP-503) — та работает только с портфелем РП пилота на одной машине, эта — с обязательствами и вопросами шире портфеля РП, и рассчитана на доставку многим пользователям.
- Использует существующий канал доставки ([DP.SC.192](DP.SC.192-scheduled-wp-launch.md) — отложенный запуск по расписанию, тот же принцип предохранителей и одноразовых задач).
