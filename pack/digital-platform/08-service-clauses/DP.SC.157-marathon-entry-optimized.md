# [DP.SC.157] Оптимизированный вход в марафон

<!--
  ПРАВИЛО — инвариант
  ОБЕЩАНИЕ — что получит потребитель
  СВИДЕТЕЛЬСТВА — как проверить

## Правило (инвариант)

- [ ] Путь от /start до первого занятия марафона требует не более 4 действий пользователя
- [ ] После принятия consent пользователь видит tier-экран с кнопкой марафона напрямую — без необходимости вводить /setup вручную
- [ ] Нажатие кнопки «📚 Начать марафон» запускает марафон напрямую — без необходимости вводить /marathon_start вручную
- [ ] `MARATHON_SAME_DAY_CUTOFF_HOUR = 18` (МСК): если старт до 18:00 МСК — первое занятие отправляется немедленно (day_num=1); если после — первое занятие завтра в 04:00 МСК (day_num=1)
- [ ] Инвариант day-counter: queue[0].day_num=1, queue[1].day_num=2; нумерация непрерывна независимо от режима старта
- [ ] Для T2+ пользователей: post-consent экран показывает их tier-экран, не T1-марафон
- [ ] Daily reminder включается автоматически при старте марафона

## Обещание

**Кому:** T1-пользователь (R16 Ученик, уровень «Старт»)

**Зачем:** Снизить friction при входе в марафон — новый пользователь не должен знать команды. Первое занятие как можно быстрее после регистрации.

**Что получит:**
- Кнопку «📚 Начать марафон» сразу после consent (не через /setup)
- Первое занятие марафона: сегодня (если <18:00 МСК) или завтра 04:00 МСК
- Pre-text «14 дней × 20 мин/день, можно ставить паузу» перед кнопкой старта
- Автоматически включённый daily reminder
- Кнопку «Пропустить → Поток S{N}» при cp_stage ≥ 2

**Критерий приёмки:** T1-пользователь с нуля проходит /start → consent → кнопка марафона → первое занятие за ≤4 клика/команды, без ввода /setup или /marathon_start.

## Режим отказа

- **Neon недоступен при consent accept** → показать tier-экран без cp_stage (кнопка марафона всегда видна для T1)
- **cp_stage недоступен** → не показывать skip-кнопку; показывать стандартный марафон-экран
- **Старт в 18:00–23:59 МСК** → первое занятие завтра 04:00 МСК (стандартный path)
- **Rollback** → git revert кода; материалы, отправленные немедленно, не отзываются (данные не повреждены, пользователь получил день 1 раньше)

## Свидетельства

- `test_marathon_day1_immediate`: старт <18:00, queue[0].day_num=1, queue[0].scheduled_at ≈ now
- `test_marathon_day1_tomorrow`: старт >18:00, queue[0].day_num=1, queue[0].scheduled_at = tomorrow 04:00
- `test_consent_accept_tier_check`: T1 → кнопка марафона; T2 → T2-экран (не T1-марафон)
- `test_marathon_integration_full`: consent accept → tier-экран → кнопка → marathon_start → немедленная отправка
- Smoke в @aist_pilot_bot: новый T1-пользователь, 4 действия, первое занятие получено
