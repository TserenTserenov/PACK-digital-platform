# DP.SC.060 «Живой доступ guide-kit к курируемым материалам платформы»

<!-- carrier-specific расширение обещания R27 (guide-kit); см. WP-483 Ф9 -->

## Обещание

**Кому:** пользователю guide-kit, собирающему руководство по фундаментальной теме (режим А) — независимо от того, подключён он к платформе или нет.

**Зачем:** демо-каталог (Ф4, WP-483) — маленький статичный пример для холодного старта без сети, не источник свежего контента. Универсальные руководства платформы многочисленны и часто меняются (решение пилота 14.07) — статичная копия в личном репозитории каждого пользователя устаревала бы. Обещание разводит два способа получить актуальный материал по подключению, не по содержанию (тот же корпус, разный транспорт).

**Что получит потребитель:**
1. **Подключённый пользователь — живой доступ.** Портной при сборке порции обращается к публичному MCP-слою платформы (`guides-mcp`: `get_guides_list`/`get_guide_sections`/`get_section_content`/`semantic_search`; `knowledge-mcp` публичный слой: `knowledge_search`/`knowledge_get_document`) без токена — тот же корпус, что видит любой пользователь платформы, всегда актуальный на момент запроса.
2. **Автономный пользователь — снимок.** Человек без платформы вообще получает статичный архив курируемых материалов через отдельный сервис скачивания (новый, наш сервер) при установке/явном обновлении — не при каждой сборке порции.

## Инвариант

- [ ] **И1 (no-stale-copy).** guide-kit никогда не хранит устаревающую статичную копию курируемых материалов для подключённого пользователя — живой запрос каждый раз, когда материал нужен для сборки. Демо-каталог (Ф4) не заменяет это обещание — он остаётся отдельным, маленьким, не обновляемым.
- [ ] **И2 (honest degradation).** MCP платформы недоступен / пустой ответ / автономный снимок отсутствует и не скачан → сборка порции продолжается без свежего материала (демо-каталог или честный пробел в decision_log), не крэш всего прогона. Тот же принцип, что hard-fail policy Ф1 (DP.SC.056 И3): диагностика вместо имитации, но здесь — деградация, не полный отказ (свежий платформенный материал не входит в required-слоты).
- [ ] **И3 (zero new server for live path).** Живой канал не создаёт нового серверного компонента — переиспользует существующие `guides-mcp`/`knowledge-mcp` как есть. Решение пилота 19.07: не строить `guides_fetch`.
- [ ] **И4 (snapshot service is new, scoped separately).** Сервис скачивания снимка (валидация — если нужна — + хранение + версионирование архива) — реализуется отдельно от живого канала, собственная оценка бюджета при старте (Элемент «Открытые задачи» ниже), не смешивается с клиентской частью в одной цифре.

## Режим отказа

- **MCP платформы недоступен во время сборки порции** → Портной использует демо-каталог/существующий локальный материал, помечает пробел в decision_log; порция не падает целиком.
- **Автономный пользователь не скачал снимок** → фундаментальный материал ограничен демо-каталогом (Ф4), честно; не выдаётся за полный корпус.
- **Снимок устарел** (сервис скачивания появится позже) → не входит в этот SC; поведение специфицируется при реализации сервиса.

## Сценарии использования

1. **Подключённый пользователь, ежедневная сборка (главный).** Портной внутри `adapter.py` собирает утреннюю порцию → нужного мема CAT.00X нет в демо-каталоге → живой запрос `knowledge_search`/`get_section_content` → decision_log фиксирует источник (`platform-mcp`, timestamp) → порция собрана с актуальным материалом.
2. **Автономный пользователь, разовая установка без платформы.** git clone guide-kit, сети к платформе нет или пользователь сознательно офлайн → команда скачивания снимка обращается к сервису №16 → архив курируемых материалов кладётся в `baseline/` (путь уже используется демо-каталогом, CONCEPT §10) → дальнейшие сборки идут по снимку до следующего явного обновления.

**Forward-pointer (не входит в это обещание сейчас):** будущие генераторы Ф6-Ф8 (прикладные темы, карта фронтира) — тот же транспорт, если/когда эти фазы откроются; не заявляется потребителем, пока Ф6-Ф8 остаются downstream и заблокированы основаниями РП495/РП493 (WP-483.md, «Осталось» 19.07).
