# DP.SC.166 — Сторож новых задач (issue watcher)

## Обещание

| Поле | Значение |
|------|----------|
| **Триггер** | launchd `com.iwe.issue-watcher`, ежедневно 06:30 (до 09:00 — правило календарных событий) |
| **Входы** | Все каталоги `~/IWE/*/` с github-remote; задачи `--state open`, `created:>=сегодня−2д`; state-файл `current/.issue-watcher-seen` |
| **Выходы** | Telegram-сообщение пилоту: 🔴 срочное (данные/безопасность/регрессия) + остальное; append новых ключей `slug#num` в state |
| **Время отклика** | ≤2 мин на прогон |
| **Инвариант** | Каждая новая задача показывается ровно один раз (дедуп по `slug#num`); критичные — в отдельной секции вверху; state обновляется только при успешной отправке |
| **Режим отказа** | нет gh / не авторизован / нет сети / iwe-tg fail → log-only, exit 0, state НЕ обновляется (повтор при следующем прогоне). Не спамит, не падает. |

## Сценарии использования

1. **Критичная регрессия от участника** — волонтёр заводит задачу «потеря данных при обновлении» в 14:00. Утром 06:30 пилот получает в Telegram дайджест с этой задачей в секции 🔴 «Срочное» → реагирует с телефона, не дожидаясь, пока откроет редактор.
2. **Обычный поток замечаний** — за ночь 3 задачи-улучшения. Дайджест в «Остальном» → пилот видит на телефоне, планирует разбор без захода в GitHub.
3. **Тихий день** — новых задач нет → сообщение не отправляется (нет шума).

## Связь с соседними каналами

- **Day Open digest** (`render_repo_issues` в day-open-scaffold.sh) — тот же обзор задач, но в редакторе и только когда пилот открывает сводку. Сторож DP.SC.166 — мобильный слой поверх: догоняет на телефоне независимо от того, открыта ли сессия.
- **Agent Inbox (DP.SC.135)** — другой класс: отложенный исполняемый task, не сигнал-уведомление.

## Реализация

`DS-my-strategy/scripts/iwe-issue-watcher.sh` + `exocortex/launchd/com.iwe.issue-watcher.plist` (зарегистрирован в `install-launchd.sh`). Роль-исполнитель — DP.ROLE.064.
