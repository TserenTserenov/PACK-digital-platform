# [DP.SC.051] Совместный недельный ритуал Стратега и Плановика

> **Обе роли — явные участники обещания:** R1 Стратег (DP.ROLE.012) и Плановик
> (DP.ROLE.066). Ритуал НЕ принадлежит одной роли — это точка их совместной работы.

## Правило (инвариант)

- [x] **Ведущий по умолчанию — Плановик** (DP.ROLE.066). Он упаковывает «контекст
  приоритетов» (от Стратега) в РП-неделя с бюджетами, распределяет по дням, держит WIP.
- [x] **Стратег подключается условно** — только если сработал один из триггеров
  пересмотра: (а) приоритеты месяца устарели (прошёл месяц / закрыт приоритет);
  (б) состояние пилота изменилось (Хаос/Потолок/Поворот/Развитие сдвинулось);
  (в) пилот явно просит пересмотр приоритетов. Иначе Плановик ведёт неделю один.
- [x] **Объект передачи Стратег → Плановик — «контекст приоритетов»**, не голый
  `monthly-priorities.md`: приоритеты + состояние пилота + системные уровни НЭП.
  Плановик имеет право интерпретировать при упаковке.
- [x] **Граница решений сохраняется в ритуале:** Стратег решает WHAT/WHY (дропнуть/
  добавить приоритет — стратегическая корректировка); Плановик решает HOW MUCH/WHEN
  (переставить РП между днями — тактическая корректировка). Ритуал не смешивает оси.

## Обещание

**Кому:** Пилот (R01).

**Зачем:** Без разделения недельный ритуал сшивает две разные операции — пересмотр
приоритетов (дорогой, по запросу) и упаковку в дни (рутинный, каждую неделю). Сшивка
заставляет каждую неделю «перестратегировать» с нуля. Разделение даёт лёгкую неделю
(Плановик один), когда стратегия стабильна, и подключает Стратега, только когда надо.

**Что получит:** План недели (РП с бюджетами, распределение по дням, WIP-лимит),
собранный Плановиком из актуального контекста приоритетов; при необходимости —
пересмотренные приоритеты от Стратега перед упаковкой.

**Триггер:** Старт недели (понедельник / strategy_day) — Плановик инициирует. Стратег
подключается по триггерам пересмотра выше.

**Время отклика:** В пределах сессии планирования недели.

**Режим отказа:** Если контекст приоритетов отсутствует (стратегирование месяца не
проводилось) — Плановик не выдумывает приоритеты, а инициирует discovery (DP.SC.030)
у Стратега перед упаковкой.

**Данные:**

| Критерий | Как проверить |
|----------|--------------|
| Паспорт Плановика описывает ведущую роль в ритуале | `grep -A3 "ritual\|ритуал" DP.ROLE.066-planner.md` |
| Паспорт Стратега описывает условное подключение | `grep "cooperative\|ритуал\|DP.SC.051" DP.ROLE.012-strategist/00-role-passport.md` |
| Обе роли названы в этой клаузе явно | данный файл, заголовок + инвариант |

**Контекст:**

| Условие | Проверка |
|---------|---------|
| Контекст приоритетов передан от Стратега | handoff DP.ROLE.012 → DP.ROLE.066 произошёл |
| Триггер пересмотра определён | один из (а)/(б)/(в) сработал или нет |

**Полномочия:**

| Роль | Что подтверждает |
|------|-----------------|
| Пилот (R01) | Что план недели отражает его приоритеты |
| Стратег (R1) | Актуальность приоритетов (нужен пересмотр или нет) |
| Плановик (DP.ROLE.066) | Корректность упаковки (бюджеты, WIP, дни) |

**Свидетельства:**

| Свидетельство | Источник |
|--------------|---------|
| WeekPlan собран с распределением по дням | `current/WeekPlan W{N}.md` |
| Стратег подключался только при триггере | журнал сессии планирования |
