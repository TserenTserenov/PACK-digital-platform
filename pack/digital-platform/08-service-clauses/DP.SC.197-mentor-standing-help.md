# [DP.SC.197] Наставник (Режим 2) — оперативная помощь в чате

> **Терминология (2026-07-20):** сущность называется «Наставник», реализуя **Режим 2** уже существующей роли `MIM.R.001` (Pack MIM) — зонтичной роли с двумя режимами: Режим 1 (плановый групповой разбор через фасилитацию, исходное содержание MIM.R.001) и Режим 2 (always-on 1:1 диагноз+рекомендация в чате, описанный здесь). Полная запись роли и обоих режимов: `PACK-MIM/pack/mim/02-domain-entities/MIM.R.001-mentor.md`.

## Обещание

**Кому:** Пилот IWE, проходящий персональное руководство (доставляется по расписанию, РП149).

**Зачем:** Между сеансами доставки руководства (ночная генерация) пилот не имеет точки опоры «прямо сейчас» — если состояние изменилось (застрял, потерял мотивацию, не понимает, что делать дальше, нужно объяснение по предмету), помощь приходит только на следующем плановом рубеже. Наставник (Режим 2) закрывает этот разрыв: постоянная доступность, не привязанная к расписанию доставки.

**Что получит пилот:**
- Возможность в любой момент написать в чат свободным текстом, что происходит («застрял», «не понимаю, зачем это», «нет времени», «объясни этот метод», и т.п.).
- В ответ — диагноз состояния, рекомендацию, при необходимости — постановку в саму роль ученика (если человек сейчас её не играет) и предметное объяснение по методам личного развития.
- Честный сигнал, когда знаний о пилоте недостаточно для персонального ответа: явное «не хватает контекста» либо универсальная рекомендация без ложной персонализации.

**Триггер:** Свободное сообщение пилота о своём состоянии в чат-канале (бот), вне явной команды `/diagnose` или `/lesson` и вне расписания доставки руководства.

**Время отклика:** Синхронный чат-ответ (секунды-десятки секунд, не сессия в несколько дней).

**Режим отказа:**
- Недостаточно данных о пилоте → явное «не хватает контекста» + либо запрос уточнения, либо универсальный (неперсонализированный) ответ — без выдумывания фактов о пилоте.
- Диагностический слой (роль-компонент Диагност) не может определить cp-состояние → рекомендация всё равно даётся (роль-компонент Навигатор отвечает и без свежего cp-среза, деградация мягкая).
- Предметный вопрос без надёжного grounding-источника → явное «не уверен, вот общий принцип» вместо уверенного, но непроверенного предметного ответа (см. Инварианты, риск личного грамотного).
- Технический сбой → честная деградация: «сейчас не отвечу, попробуй позже» вместо притворной доступности.

## Состав связки (RoleRelationStructure, FPF A.2.7)

> Закрытый, поимённо обоснованный список четырёх ролей-компонентов — не открытый набор «по требованию» (АрхГейт РП-498 явно отклонил вариант с расширяемым списком как анти-паттерн F.14 Hybrid/Prestige Role Shortcut). Маршрутизация между ролями видна в трейсе одного ответа.

| Роль-компонент | Источник | Метод | Даёт в ответе |
|---|---|---|---|
| Диагност | `DP.ROLE.042` / `MIM.R.009` | Формальная диагностика cp-состояния | Диагноз: что сейчас происходит с человеком |
| Навигатор | `MIM.R.007` | Адаптация + смысловая навигация + калибровка мотивации ВНУТРИ роли ученика | Рекомендация: что делать дальше и зачем, место на карте развития |
| Преподаватель-лидер | `MIM.R.011` | Системное лидерство (курс «Системное мышление») | Постановка в саму роль ученика — когда человек её сейчас не играет |
| Преподаватель-предметник | Курс «Инженерия личности» (методическая основа, роль формально не заведена отдельным ID — работает как функция внутри связки) | Предметная экспертиза, поиск ошибки мышления | Предметное объяснение — **grounding-инвариант обязателен**, см. ниже |

## Инварианты (Правила)

| Правило | Смысл |
|---------|-------|
| **Составная роль, не новая сущность** | Наставник (Режим 2) = `RoleRelationStructure` из 4 ролей. Не заводится пятая независимая роль. Список закрыт — расширение состава требует нового прохода АрхГейта, не молчаливого добавления. |
| **Grounding-инвариант для предметника (критично, риск принят с обязательной митигацией)** | Любой ответ от роли-компонента Преподаватель-предметник обязан ссылаться на конкретный метод из PACK-personal (`PD.METHOD.*`), никогда не генерироваться из общих знаний модели о личном развитии. Без grounding-источника — явное «не уверен» вместо уверенного предметного ответа. Механизм grounding-гейта — отдельная задача фаз реализации (Ф4+), не спроектирован на момент написания этого SC. |
| **Расширение допуска только внутри связки** | Вне связки базовые контракты компонентов не меняются — Диагност по-прежнему не читает свободный текст и не ведёт диалог в фоне вне Режима 2 (`DP.ROLE.042` §5-6). |
| **TTL + маскирование raw-текста** | Свободный текст пользователя не хранится дольше сессии одного ответа; перед любым логом — маскирование. Паттерн идентичен трейсам РП149. |
| **Честная деградация вместо ложной персонализации** | Нет cp-профиля / нет grounding-источника → явно сказать об этом или дать универсальный ответ. Запрещено выдавать универсальный совет за персонализированный, и непроверенный предметный тезис — за grounded. |
| **Always-on без ложного SLA** | Обещание постоянной доступности не подразумевает гарантированный SLA отклика — при сбое системы явный отказ («попробуй позже»), не молчание и не притворство. |
| **Маршрутизация видна в трейсе** | Каждый ответ фиксирует, какая часть от какого из 4 компонентов — предотвращает «протекание» связки в отдельную сущность явочным порядком. |

## Сценарии использования

1. **Пилот застрял на задании.** «Не понимаю, что делать с этим упражнением, второй день топчусь». → Диагност: bottleneck из cp-профиля. Навигатор: конкретный следующий шаг.

2. **Потеря мотивации.** «Не вижу смысла продолжать практикум». → Навигатор объясняет «зачем» через связь с целями пилота.

3. **Человек не в роли ученика.** Пилот пишет с явным раздражением/усталостью не по теме практикума, отвечает односложно на учебные вопросы. → Преподаватель-лидер: системное лидерство — помогает добровольно вернуться в роль ученика, не осуждая и не принуждая.

4. **Предметный вопрос.** «Объясни, как работает метод X из руководства». → Преподаватель-предметник отвечает со ссылкой на конкретный `PD.METHOD.*`; если источника нет — честно: «нет точного метода на это, вот общий принцип».

5. **Недостаточно данных.** Новый пилот без cp-профиля: «что мне делать сейчас?». → «Пока мало знаю о твоём уровне — либо пройди диагностику, либо вот универсальный совет для старта».

6. **Между сессиями руководства.** Руководство доставлено ночью, пилот утром хочет обсудить пункт до вечернего занятия. → Отвечает сразу, не дожидаясь планового рубежа.

7. **Технический сбой.** Диагностический слой недоступен. → «Сейчас не вижу твой профиль, отвечу по общей рекомендации» либо «попробуй чуть позже» — не молчание, не фиктивная персонализация.

8. **Пограничный случай — запрос вне домена.** Бытовой вопрос, не связанный с практикумом. → Явная граница применимости, не попытка ответить на всё.

## Out-of-scope (Ф2a/текущая спецификация)

- Канал реализации (бот / браузер / self-host) — Ф4.
- Конкретный технический алгоритм маршрутизации и grounding-гейта — Ф3/Ф4 (паковая спецификация + реализация).
- SLA-цифры отклика — не фиксируются на уровне обещания, только качественное «синхронно, не сессия».
- Полная методическая формализация Преподавателя-предметника как отдельной паковой сущности (сейчас — функция внутри связки, не отдельный ID).
