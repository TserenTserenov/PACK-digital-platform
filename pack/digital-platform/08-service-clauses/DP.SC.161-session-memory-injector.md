# [DP.SC.161] Инжектор сессионной памяти

## Правило (инвариант)

> Нарушение любого = провал SC.

- **Graceful degradation.** Если инжектор не может прочитать БД, найти записи или отформатировать контекст — сессия продолжается с пустым контекстом. Никогда не блокирует выполнение задачи.
- **0–3 записи.** Инжектор возвращает не более 3 напоминаний. Приоритет: fault_last_7d > w_reflection_last_30d > distinction_relevant.
- **Не модифицирует БД.** Только чтение (`SELECT`). Запись в `fault_log` при ошибке — через отдельный `INSERT` в таблицу `learning.fault_log`.
- **Синхронный вызов.** Время отклика < 500 мс (локальная SQLite). При превышении — таймаут → пустой контекст.

---

## Обещание

**Кому:**
- **Opening-агент** — «перед началом сессии получаю релевантный контекст из памяти пилота, не спрашивая его лишний раз»
- **Пилот IWE** — «система помнит, что я делал вчера, и подсказывает на основе этого»

**Зачем:**
- Без инжектора каждая сессия начинается с нуля — контекст теряется, пилот повторяет объяснения.
- Session Memory Injector замыкает кольцо «действие → запись → напоминание → действие».

**Что получит исполнитель:**

```
[Sessional Context — injected by DP.SC.161]
- Fault (3d ago): «consent SLA нарушен — проверить WP-253»
- W-reflection (12d ago): «глубина рефлексии 2/5 — нужно больше конкретики»
- Distinction: «Маршрутизатор ≠ Диспетчер» (релевантно текущей задаче)
[/Sessional Context]
```

**Время отклика:** < 500 мс (SQLite локально; нет сетевых вызовов).

## Основной flow

```
protocol-open начинается
  │
  ├─ Вызвать session-memory-load.sh <user_id> <session_type>
  │   │
  │   ├─ SELECT * FROM iwe_memory WHERE user_id = ? ORDER BY relevance DESC LIMIT 3
  │   │
  │   ├─ Форматировать в markdown-блок «Sessional Context»
  │   │
  │   └─ Вернуть строку (или пустую строку при отсутствии записей)
  │
  ├─ Инжектировать результат в системный промпт исполнителя
  │
  └─ Продолжить Opening-протокол (Router Gate, WP Gate, ...)
```

## Режим отказа

| Сценарий | Поведение | Логирование |
|---------|-----------|-------------|
| `iwe_memory.db` не найдена | Пустой контекст, сессия продолжается | `FAULT: SC.161 DB_NOT_FOUND` → `fault_log` |
| `user_id` отсутствует в БД | Пустой контекст (не ошибка) | Не логируется |
| SELECT таймаут (> 500 мс) | Пустой контекст | `FAULT: SC.161 TIMEOUT` → `fault_log` |
| Ошибка форматирования | Пустой контекст | `FAULT: SC.161 FORMAT_ERROR` → `fault_log` |
| Запись в `fault_log` не удалась | Игнорировать (двойной сбой — не блокировать) | stderr только |

## Границы (что НЕ входит в SC)

- **Не роль.** Нет DP.ROLE.NNN. Owner = Opening-агент, который вызывает скрипт.
- **Не принятие решений.** Инжектор не решает, «важно ли напоминание» — он ранжирует по времени и релевантности, финальный выбор за пилотом/исполнителем.
- **Не замена памяти агента.** LLM-контекст агента ограничен; инжектор — «подсказка извне», не полное состояние.
