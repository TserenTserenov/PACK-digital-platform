# DP.SC.036 — Knowledge Routing Gate

> **Контекст:** инцидент 12 мая 2026 — повестка встречи с архитектором записана без проверки DP.KR.001.
> Цель SC: сделать маршрутизацию явной, быстрой и верифицируемой. WP-216 Ф4.

## Правило (инвариант)

- Ни один новый файл не записывается по пути, не выведенному из routing-vocab.md ИЛИ DP.KR.001 §5 ИЛИ явного указания пользователя.
- Routing Gate всегда предшествует Write нового артефакта.
- При miss в vocab → обязательный lookup в DP.KR.001 §5; аналогия с соседним файлом не допускается.
- Нарушение гейта фиксируется в `inbox/bugs/` целевого репо (паттерн P5).

## Обещание

**Кому:** R6 Кодировщик (агент, выполняющий Write) и R14 Заказчик (получает корректно размещённый артефакт).

**Зачем:** Без явного routing-решения агент кладёт файлы «по аналогии» с соседними — это паттерн P5 (нарушение Routing Gate). Следствие: drift между источниками истины, дубликаты, потерянные артефакты.

**Что получит:**

- **Канонический путь** — конкретный путь `~/IWE/<repo>/<subdir>/<filename>` с обоснованием (ссылка на правило).
- **Naming-паттерн** — как именовать файл (формат, slug, дата).
- **Время отклика < 5 сек** на vocab-пути (fast-path), < 60 сек на map-lookup (slow-path).

**Триггер:** любое из условий:
1. Агент собирается выполнить Write нового файла (не редактирование существующего).
2. Пользователь произносит фразу из vocab: «повестка», «пост», «ADR», «инцидент», «feedback», «lesson» и т.д.
3. Capture-to-Pack на рубеже: агент обнаружил знание и определяет маршрут.

**Не-триггер:** редактирование существующего файла, перемещение в рамках одной папки, явное указание пути пользователем.

**Режим отказа:**

| Ситуация | Поведение |
|----------|-----------|
| Фраза не в vocab И аналогичного файла нет | Один уточняющий вопрос пользователю; не угадывать |
| DP.KR.001 недоступен (нет репо) | Работать по последнему известному правилу + пометить «potentially stale» |
| Путь в vocab устарел (файл перемещён) | Сообщить + обновить vocab |

## Каскад маршрутизации (4 уровня)

```
L0  routing-vocab.md  (memory/, warm)
    ├─ match → canonical path + naming → Write
    └─ miss/doubt
        ↓
L1  DP.KR.001 §5.2    (PACK-digital-platform, slow-path)
    ├─ правило найдено → canonical path → Write + обновить vocab
    └─ правило не покрывает → L2
        ↓
L2  <target-repo>/CLAUDE.md  (Repo-Touch Gate DP.SC.027)
    ├─ локальная структура + naming → Write
    └─ не решено → L3
        ↓
L3  Один вопрос пользователю → ответ → Write + обновить vocab
```

**Принцип L0:** vocab — это проекция L1+L2 в горячую короткую таблицу (~25-40 строк). Source of truth — L1 (Pack). Vocab обновляется при: (а) инциденте неверного размещения, (б) появлении нового типа артефакта, (в) Ф4 ревизии WP-216.

## Свидетельства (критерий приёмки)

**Данные:**

| Критерий | Как проверить |
|----------|--------------|
| Новый файл размещён по пути из vocab или DP.KR.001 §5 | Сравнить путь файла с таблицей §5.2 |
| В ответе агента есть обоснование пути | grep «→» в ответе агента перед Write |
| Vocab покрывает фразу пользователя | Открыть routing-vocab.md, найти строку |

**Контекст:**

| Условие | Проверка |
|---------|---------|
| Write нового файла (не edit) | `git status` — файл untracked |
| Артефакт создан в текущей сессии | Временная метка файла = время сессии |

**Полномочия:**

| Роль | Что подтверждает |
|------|-----------------|
| R14 Заказчик | Путь соответствует ожиданиям |
| R6 Кодировщик (агент) | Путь выведен из vocab или DP.KR.001, не «по аналогии» |

**Свидетельства:**

| Свидетельство | Источник |
|--------------|---------|
| routing-vocab.md покрывает фразу | `grep <фраза> memory/routing-vocab.md` |
| Нет P5-инцидентов за неделю | `ls inbox/bugs/bug-*routing*` пусто |

## Сценарии использования

### S1 — Пользователь инициирует («повестка встречи с Андреем»)

**Кто:** R14 Заказчик  
**Когда:** «Сделай повестку встречи с Андреем по WP-150»  
**Контекст:** Инцидент 12 мая — агент записал повестку без routing-проверки.

**С гейтом:** агент ищет «повестка» в vocab → hit → путь `DS-my-strategy/inbox/meetings/YYYY-MM-DD-<slug>.md` → Write с первого раза.

**Без гейта (что произошло):** агент записывает «по аналогии» с соседним файлом → неверный репо → P5-инцидент.

**Потребитель результата:** Пользователь получает файл в правильном месте без повторной работы.

---

### S2 — Capture-to-Pack на рубеже (агент-инициатор)

**Кто:** R6 Кодировщик (агент)  
**Когда:** Обнаружено различение в ходе работы → «Capture: различение X ≠ Y → куда?»  
**Контекст:** Различение может идти в distinctions.md, hard-distinctions.md или Pack 01B-distinctions.md в зависимости от длины и типа.

**С гейтом:** vocab → «различение 1-2 строки → distinctions.md, >3 строк + тест → hard-distinctions.md, доменное → Pack 01B» → правильный файл.

**Потребитель результата:** Pack остаётся source-of-truth, нет дублирования между distinctions-файлами.

---

### S3 — Субагент headless пишет отчёт (ночной аудитор)

**Кто:** subagent VR.R.002 (Аудитор, headless)  
**Когда:** tsekh-1 overnight — аудит завершён, нужно записать отчёт  
**Контекст:** Subagent не имеет интерактивного контекста, не может спросить пользователя.

**С гейтом:** vocab передаётся в prompt субагента → «security-audit-report → DS-ecosystem-development/C.IT-Platform/C2.2.Architecture/Incidents/audit-YYYY-MM-DD/» → Write без вопросов.

**Потребитель результата:** R14 видит отчёт в правильном месте при Day Open.

---

### S4 — Новый тип артефакта (miss в vocab)

**Кто:** R6 Кодировщик  
**Когда:** Пользователь говорит «запиши протокол встречи с инвестором»  
**Контекст:** «протокол встречи с инвестором» не в vocab (новый тип).

**С гейтом:** vocab miss → DP.KR.001 §5.2 lookup → не покрывает → один вопрос пользователю → ответ → Write → vocab обновляется новой строкой.

**Без гейта:** агент угадывает → 50% вероятность неверного репо.

**Потребитель результата:** после одного уточнения — правильное размещение + vocab улучшается.
