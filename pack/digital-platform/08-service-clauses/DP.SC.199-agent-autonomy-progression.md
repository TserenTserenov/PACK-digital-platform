# DP.SC.199 — Прогрессирующая автономность агента с откатом

> **Статус: скелет, не проектный документ.** Реализует принцип #34 (DP.ARCH.001 §7), но сам принцип был сформулирован сегодня (27.07) в брейншторме направлений развития IWE — механизм ниже НЕ откалиброван и НЕ проверен практикой. Открытые вопросы явно перечислены и требуют решения пилота до перевода в `status: active`.

## Правило (инвариант)

> Что ВСЕГДА должно выполняться для данного сервиса. Нарушение = провал SC.

- [ ] Уровень автономии агента (сколько шагов/решений без подтверждения) присваивается **по классу задачи**, не глобально — рост в одном классе не переносится на другой.
- [ ] Рост уровня — только по накопленному track record (N успешных закрытых циклов подряд без отката пилотом) для данного класса.
- [ ] Провал/откат пилотом на текущем уровне — немедленное сужение scope до предыдущего проверенного уровня, не «попробовать ещё раз на том же уровне».
- [ ] История изменения уровня (когда повышен/понижен, из-за чего) трассируется, не теряется.

## Обещание

**Кому:** R01 Пилот

**Зачем:** расширение автономии агента («пилот как начальник команды агентов» — направление развития IWE от 27.07) не должно быть актом веры один раз — оно должно расти вместе с фактическим доверием и откатываться при сбое без ручного пересмотра всей политики.

**Что получит:** видимый, объяснимый уровень автономии на класс задачи + автоматическую защиту от продолжения на уровне, переставшем быть надёжным.

**Триггер:** агент завершает цикл задачи данного класса (успешно или с откатом пилотом).

**Время отклика:** обновление уровня — на закрытии цикла, не отложенно.

**Режим отказа:** нет данных по классу задачи → минимальный уровень автономии (максимум подтверждений) по умолчанию, не оптимистичный.

## Сценарии использования (≥3, иллюстративные — механизм не спроектирован)

1. Агент 10 раз подряд успешно закрывает тривиальные (`verification_class: trivial`) РП без отката пилотом → получает право пропускать явное подтверждение для этого класса.
2. Агент ошибается в open-loop задаче (пилот откатывает решение) → уровень автономии для open-loop сужается до предыдущего, требует больше подтверждений на следующих попытках.
3. Новый класс задачи (например, работа с payment-registry) стартует с нулевого уровня автономии независимо от track record в других классах.
