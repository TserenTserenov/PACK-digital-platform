# [DP.SC.046] Runtime-цикл IWE (open → work → close)

> **Различение с DP.SC.013:** DP.SC.013 описывает рабочую сессию в Claude Code (конкретный хост, слой 3). DP.SC.046 описывает инвариантный контракт runtime-цикла на уровне IWE (слой 4) — не зависит от того, какой хост исполняет цикл.
>
> **Архитектурная связь:** IWE = дистрибутив (слой 4). Цикл open→work→close — ключевой контракт дистрибутива. Хост (слой 3) обязан поддержать три фазы или предоставить адаптер. WP-348 разрабатывает этот адаптер для Hermes runtime (слой 1).

## Правило (инвариант)

> Что ВСЕГДА должно выполняться независимо от хоста. Нарушение = провал SC.

- Любая сессия IWE начинается с фазы **open**: WP Gate проверен, репо touched (git pull), контекст загружен.
- Любая работа в сессии проходит через фазу **work**: Capture-to-Pack на рубежах, Pre-action Gates соблюдены.
- Любая сессия завершается фазой **close**: `git status` по всем репо сессии, незафиксированные изменения → commit + push, MEMORY.md обновлён, отчёт сформирован.
- Пропуск любой фазы = незавершённый цикл. Незафиксированный результат = потерянный результат.
- Хост (Claude Code, Hermes, бот, CLI-скрипт) обязан: либо поддержать три фазы нативно, либо предоставить адаптер, вызывающий DP.SC.046-артефакты.

## Обещание

**Кому:** Пилот (T4, TD1) — пользователь, работающий в IWE через любой runtime-хост.

**Зачем:** Без обязательного цикла open→work→close:
- Работа начинается без контекста (stale репо, пропущенный WP Gate)
- Знания не фиксируются (нет Capture на рубежах)
- Результат теряется или остаётся не зафиксированным в git

**Что получит:**

| Фаза | Гарантия | Артефакт |
|------|----------|---------|
| **open** | WP Gate пройден, репо актуален, приоритеты загружены | Day Open отчёт или Session Open запись |
| **work** | Знания захвачены на рубежах, Pre-action Gates не пропущены | Captures в Pack / DS |
| **close** | Все изменения зафиксированы, MEMORY.md обновлён | Commit + push во всех репо сессии; Session Close запись |

## Триггер

**Кто:** Пилот (инициатор) или хост-агент (автоматически при старте сессии).

**Когда:** При каждом открытии рабочей сессии IWE.

**Входы:**
- Намерение (задача / тема сессии) — опционально для open
- Список активных репо сессии — для close

**Выходы:**
- Фаза open: контекст загружен, WP Gate пройден
- Фаза close: git push во всех репо + MEMORY.md + Session Close запись

**Время отклика:** Синхронный. Фаза open: ≤5 мин. Фаза close: ≤3 мин.

## Режим отказа

| Ситуация | Поведение |
|----------|-----------|
| Хост не поддерживает фазу open | Пилот выполняет протокол вручную по memory/protocol-open.md |
| git push failed | Зафиксировать локально, пометить «potentially stale», сообщить пилоту |
| WP Gate: задача без РП | Остановиться, предложить создать РП через Ритуал согласования |
| Сессия прервана без close | При следующем open проверить git status — незафиксированные изменения → commit с меткой «recovered from interrupted session» |

## Связь с хостами

| Хост | Статус поддержки DP.SC.046 | Примечание |
|------|---------------------------|------------|
| Claude Code (текущий) | ✅ Нативно | Через CLAUDE.md + memory/protocol-*.md |
| Hermes runtime (WP-348) | 📋 Проектируется | Адаптер open/work/close для layer 1↔4 boundary |
| Telegram-бот (T1-T3) | ⚠️ Частично | Только фаза work (бот выполняет задачи); open/close не поддержаны для T0-T3 |
| Headless CLI (tsekh-1) | ⚠️ Частично | Автономные агенты: open/close через scheduler.sh |
