# DP.SC.065 «Декомпозиция прикладных источников»

## Обещание

**Кому:** пользователю guide-kit, который хочет учиться по собственному источнику (учебник, курс, методика) и встраивать порции в своё руководство.

**Зачем:** фундаментальный трек (режим А) покрывает нашу тему; прикладные темы требуют работы с чужим материалом. Без декомпозитора пользователь вынужден сам превращать учебник в план, что ломает единый процесс сборки руководства.

**Что получит потребитель:**
1. **Режим Б (источник назван):** guide-kit читает `topic.yaml` (пользователь сам заполняет структуру секций), разбирает источник на карточки с якорями на оригинал, строит топологический порядок подачи от известного к цели.
2. **Режим В (источник неизвестен):** отдельный подборщик (Ф7) предлагает кандидатов; после выбора — режим Б. Не входит в это обещание.

**Формат входа:** `topic.yaml` (см. `FORMAT-topic.yaml.md`).

**Формат выхода:** `topic_sections.yaml` (граф тем с якорями) + `decision_log` (источник каждого факта).

## Инвариант

- [ ] **И1 (source anchor).** Каждый факт в guide привязан к оригинальному якорю источника (глава, URL, временная метка).
- [ ] **И2 (topological order).** Порядок подачи — топологический обход графа зависимостей, не выдуманный порядок.
- [ ] **И3 (own axis).** У темы собственная ось областей, не навязывается общая пятиобластная.
- [ ] **И4 (honest degradation).** Неразбираемый источник → диагностика, не пустое руководство.
- [ ] **И5 (zero-upload decomposition).** Разложение не вывозит ИИ (это работа Разметчика локально); LLM только для финального текстирования (BYOK пользователя).
- [ ] **И6 (library reuse).** Декомпозитор не получает отдельного доступа к файлам пользователя; вызывает готовую функцию приёма источника у Разметчика как библиотечную функцию.

## Режим отказа

- **Отсутствует `topic.yaml`** → фундаментальный трек (режим А), прикладная часть не добавляется.
- **`topic.yaml` битый/неполный** → честная деградация: diagnostic, не крэш.
- **Пустой `sections`** → decomposition с нулём секций, логируется, руководство продолжается без прикладной части.
- **Цикл в зависимостях** → логируется, обход продолжается без зацикливания.

## Сценарии использования

1. **Учебник (режим Б, главный).** Пользователь указывает источник в `topic.yaml`, guide-kit разбирает на карточки, порядок подачи = топологический обход от известного к цели. Пример: «Я нашёл учебник по паттернам Python, хочу пройти его последовательно, но встроить в мою работу».
2. **Смешанное руководство.** Фундаментальная часть (Ученик) + прикладная часть из источника (Интеллектуал) + рабочая часть (Профессионал) в одном руководстве. Модель совмещения — РП495 Ф3.
3. **Открытый поиск (режим В).** Пользователь не знает источник → подборщик Ф7 предлагает кандидатов → выбор → режим Б. Не входит в этот SC.
