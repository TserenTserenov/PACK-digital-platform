# [DP.SC.175] Выбор стиля пользователем

## Правило (инвариант)
- [x] **Каскад платформа→канал→пользователь**, верх приоритета у пользователя (пользовательский оверрайд перекрывает дефолты платформы и канала).
- [x] Выбор пишется как `user_override_hash` (часть полного ключа реестра), **не** меняет общий счётчик (нет гонки на инкременте).
- [x] Текст-пример конвертируется в **значения осей** на write-path выбора; в каскад пишутся оси, не embedding. Read-path реестра (DP.SC.173) остаётся детерминированным (нечёткая extraction не попадает в детерминированный путь).
- [x] Хэш считается от нормализованных/отсортированных значений осей.

## Обещание
- **Кому:** пилот / пользователь IWE.
- **Зачем:** пользователь управляет своим стилем, не редактируя хуки или код.
- **Что получит:** персональный оверрайд в каскаде, который реестр учитывает при следующих ответах.
- **Триггер:** пользователь настраивает стиль (двигает оси / выбирает пресет / даёт текст-пример).
- **Вход:** значения осей (формальность/тон/интенция, модель Grammarly из теории Ф2) ИЛИ имя пресета ИЛИ текст-пример (→ конвертируется в оси).
- **Выход:** новый `user_override_hash` в каскаде.
- **Время отклика:** **асинхронно, применяется со следующего хода** (не середина текущего; новый хэш → следующий вызов реестра видит новый ключ).
- **Режим отказа:** конфликт оверрайдов → последний выигрывает + лог конфликта.

## Свидетельства (4 компонента семиозиса)
- **Данные:** значения осей каскада (пользовательский слой); пресеты; правила конвертации пример→оси.
- **Контекст:** пользователь открыл настройку стиля.
- **Полномочия:** пользователь (пишет свой слой); владелец механизма каскада — DP.ROLE.073 Хранитель реестра.
- **Свидетельства:** лог изменений оверрайда (старый/новый хэш); лог конфликтов «последний выигрывает».

## Сценарии использования (≥3)
1. **Пилот двигает ось формальности** — снижает формальность для чата → новый `user_override_hash` → со следующего хода ответы менее формальные.
2. **Пользователь выбирает пресет «онбординг»** — пресет = набор значений осей → каскад применяет бытовой регистр с заменами терминов.
3. **Пользователь даёт текст-пример «пиши вот так»** — пример конвертируется в значения осей (формальность/тон) на write-path → оси пишутся в каскад; сам текст-пример в каскаде не хранится.
