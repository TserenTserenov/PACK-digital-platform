# [DP.SC.179] Семантический ревью соответствия инженерному стилю кода

> # see DP.SC.179, DP.ROLE.076 (WP-420 Ф1, peer-сессии 2026-06-14-23 + -35 + -38)

Закрывает дыру энфорсмента: **впрыск правил ≠ их соблюдение**. Механический детектор (`code-style-hook.sh`) ловит 3 правила из 9 дешёвыми регэкспами (P1/P2/P4-прокси); семантические — реальная копипаста (P2), мёртвый код/ветка (P3), смешение обязанностей (P5), наблюдаемость (P6), неидиоматичность (P8), ручной парсинг (P9) — требуют суждения LLM. Этот SC = обещание ревью-агента (v2 дорожной карты базы).

## Правило (инвариант)

- **Природа роли — контрольная (DP.D.080).** Ревьюер НИКОГДА не мутирует аудитуемый код. Только вердикт. Тест: «изменились ли аудитуемые артефакты?» — нет → control.
- **Gating ≠ роль.** Сам агент не блокирует. «Блокировать ли коммит на Critical» — политика потребителя. Сценарии 1-2 (чужие/командные артефакты) — advisory. Сценарий 3 (Kimi сам перед своим коммитом) — допустим self-gate, но только узкий high-precision класс **P1+P4**, override = явная аннотация автора (НЕ `--no-verify`).
- **Граница масштаба:** self-gate сценария 3 = личный замок, не командный enforcement (различение «Серверный замок ≠ Локальный хук»). Командная проверка крафта = серверная CI/pre-receive — вне WP-420.
- **Режим отказа = честный sentinel.** LLM недоступен → запись «review skipped: LLM unavailable», НИКОГДА не пустой результат, читаемый как «чисто» (различение «настоящий ноль ≠ нет ответа»; «HTTP 200 + 0 байт = false-green»).
- **Трактовка sentinel метрикой:** «не оценено» исключается из знаменателя code-compliance (не штраф, не зачёт), логируется как покрытийная дыра (счётчик `reviews_skipped`).
- **Идемпотентность:** повторный прогон на том же diff даёт тот же класс вердикта (без побочных эффектов на код).

## Обещание

**Кому:** агенту/пилоту, инициировавшему ревью (Claude, Kimi, пилот).

**Зачем:** правила стиля впрыскиваются в промпт, но соблюдение не проверяется по семантике. Без агента крафт-качество не наблюдаемо → метрика code-compliance покрывает только 3 механических правила.

**Что получит (3 сценария = WP-420 Ф2):**

| Потребитель | Триггер | Вход | Что получает | Политика |
|-------------|---------|------|--------------|----------|
| Claude Code | Stop-хук, gated async (diff>порога + код-файлы) | diff сессии | запись в лог + пометка Day Open «Требует внимания» при Critical | advisory |
| Пилот-ревьюер | on-demand (вызов на ветке) | diff ветка-vs-база | отчёт-чеклист P1-P9 перед merge | advisory |
| Kimi headless | граница коммита (pre-commit) | staged diff | вердикт; при Critical (P1/P4) self-correct или эскалация | self-gate (узкий) |

**Триггер:** per-scenario (не глобальный дефолт).

**Вход:** `git diff` (область по триггеру) + расширенный unified-контекст (`-U20–30`). Двухуровневый анализ: diff-строк достаточно для P1, P4; контекст функции/модуля нужен для P2 (другие повторения), P3 (достижима ли ветка), P5 (вся функция), P6 (логируется ли операция). Не читать весь файл.

**Выход:** advisory-вердикт по P1-P9: `rule → file:line-range → severity → почему`.
- **Целевая схема:** расширить контракт лога WP-388 двумя append-only полями (`file:line`, `severity`) — координация с WP-408 (владелец метрики Ф6).
- **Interim (реализовано Ф4):** packing `file:line+severity` внутрь поля `description` существующего 5-польного формата; метрика `code-compliance` считает без изменений.

**Время отклика:** async (Sonnet на нескольких сотнях строк ~10-60с). Не блокирует завершение хода/сессии.

**Режим отказа:** LLM недоступен/таймаут → пропуск семантического прохода + sentinel «не оценено» (не ложный зелёный). Механический детектор работает независимо.

## Калибр и стоимость

- Модель: Sonnet (closed-loop по чек-листу), cold-context.
- Cost-гейт: порог размера diff + фильтр код-файлов (как в `code-style-hook.sh`).
- Калибровка false-positives — на контр-критериях P5 (глубокий модуль), P8 (осмысленный цикл), P7 (модульный маркер).

## Сценарии использования (детально — WP-420 Ф2)

1. **Claude после своей сессии (Stop-хук, gated async).** diff затронул код + размер > порога → ревью → запись в лог; Critical → пометка в Day Open. Advisory (свою сессию не блокируем).
2. **Пилот-ревьюер PR (on-demand).** Явный вызов на ветке → отчёт P1-P9 как чеклист перед merge. Advisory.
3. **Kimi headless перед коммитом (pre-commit self-gate).** staged diff → при Critical (только P1+P4) self-correct/эскалация. Self-gate узкий; override = аннотация автора, не `--no-verify`.

## Связи

- **Потребляет:** контент правил P0-P9 — DP.SC.172 (владелец WP-408).
- **Питает:** единый лог стиля → метрика `code_compliance_from_hook_log` (WP-408 Ф6).
- **Сосед:** механический детектор `code-style-hook.sh` (дёшево, регэксп, P1/P2/P4-прокси) — агент берёт семантику. Встроенный `/code-review` (баги корректности ≠ крафт) — standalone, не обёртка. VR.R.002 Аудитор (безопасность ≠ стиль).

## Реализация (WP-420 Ф4)
- Тонкая обёртка `code-craft-review.sh`: `git diff` → cold-context промпт с чек-листом P1-P9 → агент (Sonnet headless) → парсинг JSON-вердикта → запись в единый лог (interim-формат). Переиспользует существующий вызов агента, не строит свой LLM-pipeline.
- Smoke: синтетический diff с заведомыми запахами P3/P5/P8 → агент находит; чистый diff → молчит.
