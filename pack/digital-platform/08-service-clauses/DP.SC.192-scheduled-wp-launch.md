# DP.SC.192 — Отложенный запуск РП по расписанию с жёсткими предохранителями

## Обещание

Пилот ставит РП в очередь на конкретное время (один или серией с шагом 1 час) — указанный агент (kimi/claude) запустится автоматически, даже если Мак спит, проработает не дольше лимита и оставит отчёт. Падение одного запуска не останавливает очередь.

## Триггер

Фраза пилота «запусти WP-NNN во столько-то» / «поставь очередь из N РП с 11:00».

## Входы

- Время старта (локальное время машины), WP-NNN, агент (kimi|claude)
- Опционально: таймаут (default 50 мин), max-turns (claude, default 40), кастомный промпт

## Выходы

- Запущенная headless-сессия агента по WP-NNN (session-guard open→close, ORZ)
- Лог прогона `.iwe-runtime/logs/wp-queue/<id>.log`
- Строка результата в `.iwe-runtime/logs/wp-queue/report.md` (утренний отчёт)
- Самоудалившаяся одноразовая задача launchd

## Время отклика

Старт в заданную минуту ±2 мин (точность launchd StartCalendarInterval).

## Инвариант

1. Каждый запуск ограничен wall-clock таймаутом (предохранитель токенов) — превышение = принудительное завершение + статус `timeout`.
2. WP Gate: в очередь ставятся только РП, уже согласованные пилотом (есть в WeekPlan/реестре).
3. Задачи launchd одноразовые — после отработки выгружаются и удаляются; очередь не накапливает мусор.

## Режим отказа

- РП упал/завис → статус `failed`/`timeout` в отчёте, очередь идёт дальше по расписанию.
- Мак выключен (не спит) → запуск пропущен, launchd выполнит задачу при ближайшем включении (RunAtLoad не ставится — пропуск фиксируется как `missed` при следующем `list`).
- Два прогона kimi одновременно → сериализация через OAuth-refresh lockf (как в kimi-peer-adapter.sh).

## Сценарии использования

1. **Утренняя серия.** Пилот вечером ставит 8 РП с 11:00 шагом 1 час → утром читает `report.md`: 7 done, 1 timeout (WP с blocker-записью).
2. **Разовый отложенный запуск.** «Запусти WP-417 завтра в 08:00» — к приёму кофе табло уже проверено, результат в ORZ.
3. **Делегирование разным агентам.** WP-487 → kimi, WP-458 → claude: пилот выбирает исполнителя под класс задачи, предохранитель одинаковый.

## Ограничения

- Будит Мак только из сна (не из выключенного состояния); FileVault после холодной перезагрузки требует разблокировки.
- Headless-прогон без живого пилота: решения, требующие пилота, оформляются как blocker, не как остановка очереди.
