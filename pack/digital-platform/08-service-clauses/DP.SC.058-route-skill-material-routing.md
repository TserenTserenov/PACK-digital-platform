# DP.SC.058 «Маршрутизация материала через скилл /route»

## Обещание

**Кому:** пользователю IWE, агенту, интегратору.

**Когда (триггер):**
- Пользователь пишет `/route <описание-материала>`
- Агент обнаруживает новый материал при capture/extract и спрашивает `/route`
- Интегратор помогает разобраться: `/route [--batch] [--validate]`

**Что получит потребитель:**
```
Материал: <имя>
Класс: <1|2|3|4> — <имя класса>
Дом: <путь-или-название>
Режим: index | pointer | external
Тест сработал: <какой-именно-тест-из-DP.KR.002>
Уверенность: <high|medium|low>
Альтернатива: <если есть граничный случай>
```

Или: `Вне карты (причина)` — легитимный ответ.

## Инвариант

- **И1 (OwnerIntegrity):** Один материал → один дом. Нет дублей, нет «запасных копий».
- **И2 (Словарь режимов):** Режим ∈ {index | pointer | external}, ничего больше.
- **И3 (Нет выдумки):** Если класс неясен → «вне карты», не угадывание.
- **И4 (Обоснование):** Каждый ответ несёт обоснование (тест класса), пользователь может оспорить.
- **И5 (Карантин fail-closed):** Материал похож на PII/секрет/платёж → карантин (вне оси).

## Время отклика

- Интерактивный запрос: ≤5 сек (LLM-классификация по кратной информации).
- Batch-режим (файловая база): O(N) за полный проход.
- Validate-режим (сверка существующего): ≤2 сек на файл.

## Режим отказа

- Материал вне классов 1–4 → честное «вне карты» с диагностикой.
- Граничный случай (например, юридический факт, но нужна оценка) → И4 (обоснование) + И5 (fail-closed).
- API timeout / LLM-отказ → возвращает cached-результат или сообщает о недоступности.
