# DP.SC.057 «Маршрутизация знаний пользователя»

## Обещание

**Кому:** пользователю IWE, у которого есть разнотипный материал (репо с кодом, горнолыжный ресёрч, налоговая декларация, инвентарь гаража, рабочая архитектура, таски).

**Зачем:** пользователь не знает, куда класть разнотипный материал. Действующая таксономия Base/Pack/DS обслуживает методологию, не организацию жизни. Карта агентской маршрутизации (DP.KR.001) покрывает только платформенные артефакты. Без пользовательской карты вопросы «куда положить» летят пилоту-автору, а не IWE.

**Что получит потребитель:** на вопрос «куда положить X» — дом + режим (`index`/`pointer`/`external`) + обоснование (какой тест класса из DP.KR.002 §2 сработал). Или честное «вне карты» — не выдуманный дом.

**Триггер:** пользователь спрашивает «куда положить [материал]» или агент обнаруживает новый материал при захвате.

## Инвариант

- [x] **И1 (OwnerIntegrity).** Один материал — один дом. Дубль = ошибка синхронизации, не «запасная копия».
- [x] **И2 (словарь режимов).** Режим — только из `index | pointer | external` (совместимость с FORMAT.md §4). Выдуманный режим — нарушение.
- [x] **И3 (no-invented-home).** «Не знаю / вне карты» — легитимный ответ. Выдуманный дом — нарушение (тот же инвариант «не выдумывать», что у guide-kit).
- [x] **И4 (обоснование).** Routing-ответ несёт обоснование (какой тест класса сработал) — пользователь может оспорить класс, не переписывая карту.
- [x] **И5 (карантин fail-closed).** Неуверенность «не карантин ли это» → карантин (наследует И1 DP.SC.055).

## Режим отказа

- **Материал не подходит ни под один класс** → «вне карты» + предложение обсудить новый класс (ArchGate при 2–3 экземплярах, правило 5.1.4).
- **Неоднозначность класса** → предъявить тест обоих кандидатов, пользователь решает (И4).
- **Карантин-детектор не уверен** → fail-closed: материал блокируется до явного решения пользователя (И5).
