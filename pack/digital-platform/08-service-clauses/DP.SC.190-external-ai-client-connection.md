## Обещание

**Кому:** пользователю с оплаченной подпиской уровня T3 или T4, который хочет получать знания платформы не только в Telegram-боте, но и в claude.ai (через Connector) или в VS Code (через расширение).

**Зачем:** сейчас внешний ИИ-клиент получает отказ авторизации при обращении к шлюзу знаний, потому что ни один пользователь не прошёл процесс выдачи пропуска. Разбор показал: сам процесс существует (`/connect_external` в боте), но никто им не воспользовался — либо не знает о нём, либо барьер входа слишком высокий.

**Что получит потребитель:**
- Проактивное предложение подключения от бота (кнопка), когда человек достиг T3/T4 — не нужно самому искать команду.
- Альтернативный путь по собственной инициативе (`/connect_external`) для тех, кто узнал о возможности сам — оба пути работают параллельно, не взаимоисключают.
- Для VS Code — настройка в один клик из бота (без ручной вставки пропуска в конфигурационный файл).
- Явный сигнал при сбое выдачи пропуска, не тихий отказ.

**Триггер:**
- Push: пользователь пересекает порог T3/T4 (событие смены тира) → бот предлагает подключение.
- Pull: пользователь вызывает `/connect_external` вручную.

**Время отклика:** пропуск выдаётся синхронно в рамках одного взаимодействия с ботом (без ожидания фоновых задач).

**Режим отказа:**
- Тир человека ниже T3 на момент выдачи → пропуск не выдаётся, явное объяснение почему (fail-secure, не тихая заглушка).
- Сбой записи в таблицу пропусков (`ory_client_tokens`) → сигнал об ошибке пользователю + запись в capture-bus, повторная попытка доступна сразу.
- Просроченный или невалидный пропуск на стороне шлюза (401) → шлюз не подбирает случайный другой пропуск пользователя без проверки срока годности (см. находку WP-5 07.07 — `list_tools()` брал первый попавшийся токен без retry; тот же класс риска здесь, инвариант ниже закрывает его явно).

## Инвариант

- [ ] Пропуск выдаётся **только** пользователю с фактическим тиром T3 или T4 на момент выдачи (проверка на стороне выдающего, не только на стороне UI кнопки).
- [ ] Массовая рассылка предложения всем существующим пользователям **не входит** в это обещание — сначала ограниченная тестовая группа, решение о расширении на весь контингент (539 человек) принимается отдельно, после проверки на тестовой группе.
- [ ] Push-путь и pull-путь ведут к одному и тому же механизму выдачи пропуска — не два независимых конкурирующих кода.
- [ ] Просроченный пропуск не используется молча — обращение к шлюзу с истёкшим пропуском получает явный отказ, не пустой список знаний.

## Сценарии использования

### Сценарий 1: Push — бот предлагает подключение при достижении T3/T4

**Кто:** пользователь, только что оплативший подписку до уровня T3 или выше.
**Когда:** сразу после смены тира (событие апгрейда).
**Что делает:**
1. Бот показывает сообщение с кнопкой «Подключить claude.ai / VS Code».
2. Пользователь нажимает кнопку → бот выдаёт пропуск, пишет в `ory_client_tokens`.
3. Пользователь получает готовую инструкцию (для claude.ai — ссылку OAuth, для VS Code — автонастройку по сценарию 3).

### Сценарий 2: Pull — пользователь сам инициирует подключение

**Кто:** пользователь T3/T4, узнавший о возможности не через push-предложение (из документации, от друга).
**Когда:** в любой момент после достижения нужного тира.
**Что делает:**
1. Вызывает `/connect_external`.
2. Получает тот же результат, что и в сценарии 1 (тот же механизм выдачи, другая точка входа).

### Сценарий 3: Подключение VS Code одним действием

**Кто:** пользователь T3/T4 с установленным расширением VS Code.
**Когда:** после получения пропуска (из сценария 1 или 2).
**Что делает:**
1. Нажимает кнопку «Подключить VS Code» в боте.
2. Бот сам передаёт конфигурацию расширению (без просьбы вручную вставить пропуск в файл настроек).
3. Расширение сразу видит знания пользователя при следующем обращении.

**Тест приёмки:** тестовый пользователь из ограниченной группы (не из полных 539) проходит любой из путей 1 или 2, затем сценарий 3 — и получает рабочий доступ в VS Code без единого ручного редактирования конфигурационных файлов.

## Не гарантирует

- Массовую рассылку предложения всем 539 существующим пользователям T3/T4 — это отдельное решение пилота после проверки на тестовой группе, не часть текущего обещания.
- Полную замену Telegram-бота как основного канала — внешний ИИ-клиент дополняет бот, не заменяет.
- Защиту от компрометации самого claude.ai/VS Code окружения на устройстве пользователя — обещание касается только выдачи и валидности пропуска на стороне платформы.

## Антипаттерны

- ❌ **Тихая заглушка вместо явного отказа** при недостаточном тире — пользователь должен понимать, почему не получил доступ, не видеть пустой список знаний без объяснения.
- ❌ **Выбор случайного пропуска из нескольких без проверки срока годности** — тот же класс бага, что уже нашли в обнаружении MCP-инструментов (WP-5, 07.07): при нескольких пропусках шлюз обязан проверять валидность выбранного, не брать первый попавшийся.
- ❌ **Массовая рассылка без проверки на малой группе** — 539 одновременных новых подключений при непроверенном процессе создают риск нагрузки и путаницы в поддержке.
- ❌ **Два независимых кода для push и pull путей** — расхождение в поведении между «бот предложил» и «пользователь запросил сам» создаёт два источника истины для одного и того же пропуска.
