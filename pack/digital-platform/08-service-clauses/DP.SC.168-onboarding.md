# DP.SC.168 — Онбординг IWE: зонтичное обещание

> **Одной фразой:** онбординг ведёт нового пилота по **двум ортогональным осям** — технологической (оснащение T0→T4) и содержательной (развитие: ступень + программа) — до трёх конечных состояний: **персональное руководство · работа по своим РП · стратегирование**.
>
> Логика «где пилот и какой следующий шаг» живёт в MCP как **pull-механизм**. Бот, браузер, Claude Code — каналы, исполняющие общее обещание.

---

## §1. Обещание (что получает пилот)

| Момент | Что платформа делает |
|--------|---------------------|
| Первый контакт (T0) | Сразу доступны знания МИМ, онбординг-контекст, согласие — без регистрации |
| Регистрация (T0→T1) | UUID создан, кросс-системная идентичность, диагностика ступени открыта |
| Диагностика | Платформа знает ступень (1-5) и bottleneck — предлагает конкретный поток (S1/S2/…) |
| 7+ дней активности (T1) | Предложение персонализации (T2) — когда пилот готов, не раньше |
| Подписка (T2+) | Персональное руководство, ЦД-адаптация, замкнутый цикл действие→баллы→обновление |
| T3/T4 | Managed-репо или свой GitHub — собственная среда IWE |

**Инвариант:** в любой момент пилот может узнать своё положение по обеим осям через `get_journey_state`. Следующий шаг — всегда один конкретный (`get_next_onboarding_step`).

---

## §2. Две оси (инвариант модели)

> Подробнее: DP.ARCH.002 §2б.

| Ось | Единица измерения | Источник | Гейт |
|-----|------------------|----------|------|
| **Технологическая** | Тир T0-T4 (Ory + подписка + репо) | `onboarding_state` + `tier_detector` | доступ |
| **Содержательная** | Ступень 1-5 (Ученик) или степень квалификации (другие роли) + программа | `learning.cp_assessments` (Диагност R28) | персонализация |

**Граница free/paid:** универсальные руководства (любая программа) — бесплатно T1. Персонализация — платно T2+.

---

## §3. MCP-инструменты (четыре)

| Инструмент | Доступен с | Что делает |
|-----------|-----------|-----------|
| `get_journey_state` | T0 (частичный), T1 (полный) | Где пилот по обеим осям: тир + ступень + bottleneck + программа + флаги |
| `get_next_onboarding_step` | T0 | Один приоритетный шаг + опциональный + альтернатива пропуска. Pull-механизм |
| `grant_consent` | T0 | Согласие из любого канала (снимает бот-only зависимость) |
| `request_equipment_upgrade` | T1 (требует Ory) | Апгрейд оснащения из любого канала: T1→T2 (подписка), T2→T3 (managed-репо), T3→T4 (github_connect). **Не доступен T0** — требует ory_id для записи состояния |

> **Координация T0 в gateway:** `tool-tiers.ts` KNOWN_T1_TOOLS / T0-whitelist — реализует **WP-392 Б1**. Контракт зафиксирован в DP.ARCH.002 §2б. Не трогать `tool-tiers.ts` до merge DP.ARCH.002 v2 в WP-392.

## §5. Конечные состояния (три)

1. **Персональное руководство** — пилот имеет `cp_profile` + персональное руководство под ступень + bottleneck (T2+).
2. **Работа по своим РП** — пилот имеет managed-репо или свой GitHub, работает с DS-my-strategy (T3/T4).
3. **Стратегирование** — пилот использует `/discovery-session` + `/strategy-session` + Плановик DP.ROLE.066 (T4, программа РР/ИР).
