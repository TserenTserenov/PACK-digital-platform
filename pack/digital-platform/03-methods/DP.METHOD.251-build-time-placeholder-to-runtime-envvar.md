# DP.METHOD.251 — build-time placeholder → runtime env var

## Суть метода

Плейсхолдеры путей, зашитые на этапе сборки (`{{WORKSPACE_DIR}}` и подобные, подставляемые один раз при генерации артефакта), заменяются паттерном разрешения через переменную окружения в момент фактического выполнения — раннер читает путь из env-переменной каждый раз при запуске, а не из значения, зафиксированного при сборке.

## Обоснование

Build-time плейсхолдер фиксирует путь окружения сборки — при переносе готового артефакта в другое окружение выполнения (Docker-контейнер, WSL2, другая машина) зафиксированный путь становится неверным. Runtime env var разрешается заново в каждом окружении, где артефакт реально запускается, что делает его переносимым по конструкции.

## Применение

Дизайн раннеров/скриптов, готовый артефакт которых может выполняться в окружении, отличном от того, где он был собран/сгенерирован.
