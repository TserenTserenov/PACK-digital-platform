# DP.METHOD.151: Классификация-до-счёта при миграции

## Контекст

При планировании миграции N объектов часто берут весь пул не учитывая, что целевой атрибут применяется только к подмножеству.

**Пример (WP-418):** «65 проактивных отправителей», но cap-ограничение применяется только к `capped`-классу (nudge, реанимация). Реальный объём capped = 8-12 из 65. Прогресс «4/65» = 6%, хотя реально 33%+.

## Метод

**До объявления объёма и старта:**

```sql
SELECT count(*)
FROM objects
WHERE target_attr = 'target_class'
```

| Этап | Действие |
|------|---------|
| 1. Mapping | Определить целевой атрибут (capped / transactional / ops) |
| 2. Count | `SELECT count(*) WHERE target_attr` → реальный N' |
| 3. Progress | Прогресс = done / N', не done / total_pool |
| 4. Announce | «Осталось N' объектов класса X из Y в пуле» |

## Антипаттерн

«4/65 мигрировано» → ложный прогресс 6%; выгорание команды, неверное планирование.

## Применимость

- DB-миграции по типу
- Рефакторинг с фильтром по атрибуту
- Batch processing с целевым классом
- Тест: «применяется ли изменение ко ВСЕМ N объектам пула?» Нет → classifiy first
