# DP.M.093 — CI Artifact in Create-Flow

> **Merged 2026-07-12 с DP.M.092** (тот же метод, записан дважды в соседних KE-коммитах 18 мая — `7a89d39` затем `a5096fd`). DP.M.092 → superseded, эта запись — каноническая.

## Описание

Обязательный инфраструктурный артефакт (CI-конфиг, security scan, lint, issue-template) встраивается как обязательный шаг create-flow нового репо определённого типа, а не ставится вручную отдельной задачей.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Автоматическая гарантия артефакта ↔ стоимость поддержки установщика | Обязательный шаг create-flow устраняет ошибку забвения системно, но переносит стоимость на идемпотентный `pack-ci-install.sh`, который нужно держать актуальным под проверки R1-R4 и эволюцию типа репо |
| Единообразие каждого нового экземпляра ↔ гибкость исключений | Шаг обязателен для КАЖДОГО репо данного типа, иначе снова возникает рассинхрон; критерий «создаётся несколько раз в год и забывается» ограничивает набор встраиваемых артефактов, чтобы create-flow не раздувался |

## Принцип

**Инфраструктурный артефакт = часть create-flow, не отдельная задача.**

Если артефакт обязателен для каждого экземпляра типа репо, его отсутствие — человеческая ошибка при создании. Автоматизация на уровне create-flow устраняет ошибку системно.

## Шаги

1. Определить: какой артефакт обязателен для КАЖДОГО экземпляра репо данного типа?
2. Написать идемпотентный установочный скрипт (например, `pack-ci-install.sh`).
3. Встроить вызов скрипта в create-skill (например, `/pack-new`) как обязательный шаг ПОСЛЕ `git init + initial commit`.
4. Ретроспективно покрыть все существующие экземпляры.

## Критерий применимости

«Новый репо-тип создаётся несколько раз в год, и важный артефакт регулярно забывается?» Да → встроить в create-flow.

## Пример применения

`/pack-new` skill → `pack-ci-install.sh` → `.github/workflows/pack-lint.yml` автоматически в каждом новом Pack-репо. После WP-5: 8/8 Pack-репо покрыты без ручной работы.

## Применимость

Любой scaffolding-инструмент (create-skill, CLI, скрипт инициализации), порождающий типовые репозитории: Pack-репо, DS-governance, DS-instrument.

## Тест применимости (для FM-каталога)

«Артефакт X обязателен для каждого экземпляра типа репо T, но отсутствует более чем в одном существующем экземпляре?» Да → P10, решение — встроить X в create-flow T.
