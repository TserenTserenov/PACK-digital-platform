# Семантика-сначала / Производительность-после (DP.M.147)

## 1. Проблема

При интеграции с внешним runtime, который готовится дольше нашей итерации, возникает дилемма:
- Ждать готовности нижнего слоя — блокировка пользователя и простой команды.
- Делать в два захода с разной семантикой — двойная работа, миграция данных, переучивание пользователя.

## 2. Метод

**Принцип разделения:** семантика реализуется на нашем стеке доступными примитивами, производительность апгрейдится подменой транспорта (внешний runtime) без изменения семантики.

**Двухфазная декомпозиция:**

| Фаза | Слой | Содержание | Бюджет | Pacing |
|------|------|------------|--------|--------|
| Ф-A (MVP) | Наш | Полная семантика на доступных примитивах (sequential loop, file-based bus, polling) | основной | худший (десятки секунд) |
| Ф-B (апгрейд) | Внешний runtime | Подмена транспорта (real-time bus, push-канал) без изменения семантики | минимальный на нашей стороне | целевой (миллисекунды) |

**Контракт между фазами:** одно и то же поведение снаружи (multi-turn, эскалация, итоговый отчёт) — изменяется только канал доставки. Внешний наблюдатель не различает Ф-A и Ф-B по семантике, только по pacing.

## 3. Применимость

- Внешний runtime в работе у другой команды, релиз через недели.
- Полная семантика выразима через примитивы текущего стека даже с худшим pacing.
- Пользователь получает рабочий MVP до готовности внешнего слоя.
- Финальный апгрейд минимальный — только транспорт, не логика.

## 4. Антипаттерны

- **«Дождаться готовности и потом начать»** — зависимость от внешнего стека, простой команды, риск отмены внешнего проекта.
- **«Сделать в два захода с разной семантикой»** — двойная работа, миграция данных, переучивание пользователя.
- **«Сразу real-time, но с упрощённой семантикой»** — пользователь привыкает к ограниченной модели; при апгрейде переучивание + UX-долг.

## 5. Условия неприменимости

- Семантика принципиально требует pacing внешнего runtime (real-time co-edit невозможен через polling).
- Внешний runtime ломает контракт при подмене транспорта (несовместимая модель данных).
