# DP.M.188 — Маппинг N backend ступеней в M UI грейдов

## Проблема

Backend нуждается в тонкой шкале мастерства / ранжирования / уровня для:
- точных расчётов (qual_mult ×0.2 → ×5.0 = 12 ступеней),
- EMA-скользящих,
- диагностики bottleneck.

Пользователь в UI нуждается в крупной шкале для:
- узнаваемой иерархии (Bronze/Silver/Gold/Platinum/Diamond),
- мотивации (заметные события перехода),
- понимания «где я» без анализа цифр.

Конфликт: одна шкала не подходит обоим.

## Метод

1. **Backend** использует тонкую шкалу N (например, 12 ступеней с шагом 0.4).
2. **UI** использует крупную шкалу M (5 грейдов: Случайный / Практикующий / Систематический / Дисциплинированный / Мастер+).
3. **Маппинг** фиксирован таблицей `backend_stage → ui_grade`, хранится в Pack как часть SC.
4. Маппинг **не пересчитывается** при изменении backend шкалы — только обновляется явным решением.

## Преимущества

- (а) **Стабильность UI** при изменении backend (можно добавить промежуточные ступени без перерисовки UI).
- (б) **Когнитивная экономия** пользователя (5 грейдов ≪ 12 ступеней по нагрузке).
- (в) **Заметность переходов** (переход между UI-грейдами — событие, мотивирует; backend-ступени — фон).

## Тест применимости

Гранулярность нужна **расчётам**, но не **показу**? Используй маппинг.
Если расчёты и UI должны видеть одну шкалу — маппинг лишний.

## Прецеденты

- **Sephora**: 3 UI-tier'а (Insider/VIB/Rouge) при тонкой внутренней динамике покупок.
- **Chess Elo**: точная числовая шкала (rating) + крупные UI-категории (Beginner/Intermediate/Advanced/Master/GM).
- **WP-327 v4.3**: 12 backend ступеней → 5 UI грейдов.

## Анти-аналог

UI показывает все 12 backend ступеней → пользователь не различает шаги «×0.2 vs ×0.6», переходы теряют значимость, обозреватель UX сообщает «слишком сложно».

## Связи

- Применяется в связке с DP.D.104 «Прогресс к награде ≠ баланс».
- Реализует принцип `internal model granularity ≠ external presentation granularity`.

## Ограничения

- В expert-инструментах (chess engine UI для GM, trader dashboards) допустимо показывать полную шкалу.
- Маппинг должен сохранять монотонность: backend_stage(a) < backend_stage(b) ⇒ ui_grade(a) ≤ ui_grade(b).
