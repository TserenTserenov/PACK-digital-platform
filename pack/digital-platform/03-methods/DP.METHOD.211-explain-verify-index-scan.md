# DP.METHOD.211 — верификация плана запроса через EXPLAIN после создания vector-индекса

## Суть метода

После создания или изменения векторного индекса выполняется `EXPLAIN` на целевом запросе, чтобы подтвердить, что планировщик Postgres реально выбирает Index Scan (использует индекс), а не Sequential/VectorScan-обход. Наличие индекса в схеме само по себе не гарантирует его использования планировщиком.

## Обоснование

Планировщик может игнорировать существующий индекс по множеству причин (статистика таблицы, тип условия, cost-эстимейт) — единственный надёжный способ проверить фактическое использование индекса — прочитать план выполнения, а не полагаться на факт его создания.

## Применение

Любое изменение индексной структуры на таблице с векторным поиском — обязательная пост-проверка `EXPLAIN` перед закрытием задачи.

## Связи
