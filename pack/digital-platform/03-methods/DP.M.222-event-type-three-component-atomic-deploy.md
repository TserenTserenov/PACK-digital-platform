# DP.M.222: Event-тип = 3-компонентная атомарная единица деплоя

## Суть

Новый event-тип требует 3 компонента, которые должны быть задеплоены атомарно. Частичный деплой (1 или 2 из 3) создаёт невидимые failure mode.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Атомарность деплоя ↔ независимость компонентов | Три точки живут в разных системах (Worker, БД, projection worker) с разными циклами выкатки; принуждение к одному PR даёт атомарность ревью, но физическая выкатка всё равно неодновременна — окно частичного деплоя лишь сужается, не исчезает |
| Видимость отказа ↔ стоимость проверки | Schema-rejection виден в DLQ бесплатно, а silent drop из-за отсутствующей записи в projection_rules обнаруживается только smoke-тестом по target-таблице — самый дешёвый для проверки gap самый заметный, самый дорогой — невидимый |

## Три компонента

| # | Компонент | Где | Gap-эффект |
|---|-----------|-----|-----------|
| 1 | JSON Schema | event-gateway Worker | Видимый rejection (DLQ) |
| 2 | Запись в `reference.projection_rules` | БД (которой projection_worker) | Невидимый silent drop |
| 3 | Хендлер | projection_worker | Невидимый unprocessed |

## Чеклист деплоя

```
[ ] JSON Schema добавлена в event-gateway Worker и задеплоена
[ ] Запись в reference.projection_rules добавлена (event_type → projection_worker)
[ ] Хендлер в projection_worker реализован
[ ] Smoke-test: тестовое событие → проверить target table (reward_transactions или аналог)
```

## Применение

PR на добавление нового event-типа должен содержать изменения во всех трёх точках. Code review: grep по event-type-имени в трёх местах.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Внимание тянется к хендлеру | Компонент 3 — содержательная работа с кодом; запись в projection_rules — одна строка в БД — пропускается чаще всего, и это ровно тот компонент, чей пропуск даёт невидимый silent drop, а не видимый reject |
| Smoke проверяет хендлер, не таблицу | Тест гоняет обработчик изолированно и видит «обработано» в логах; последний пункт чеклиста — проверить target-таблицу после сквозного прохода — опускается, и событие «обработано» без строки в таблице остаётся незамеченным |
