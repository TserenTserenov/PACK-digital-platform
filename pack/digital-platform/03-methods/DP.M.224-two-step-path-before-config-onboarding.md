# DP.M.224 — Двухшаговый онбординг бота: путь → конфигурация

## Суть

Разделить онбординг на два последовательных шага: (1) выбор маршрута (что делать), (2) конфигурация параметров выбранного маршрута (как именно). Объединение в один экран лишает пользователя контекста — непонятно зачем вводить данные.

## Механизм

1. Экран 1: выбор пути (Марафон / Аккаунт / …)
2. Экран 2: конфигурация, специфичная для выбранного пути (время, периодичность, ...)
   — Контекст уже установлен: «вы выбрали Марафон → скажите когда удобно»
3. Default-значение (например, 04:00) снижает friction — пользователь может пропустить шаг 2 и получить рабочее поведение

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Пошаговая ясность ↔ дополнительный экран | Два шага дают контекст, но увеличивают количество экранов и friction; один экран экономит шаги, но лишает пользователя понимания, зачем вводить данные |
| Контекст выбора ↔ скорость прохождения | Пользователь должен сначала выбрать маршрут, чтобы осознанно отвечать на вопросы, но это требует времени; объединение шагов ускоряет прохождение за счёт неосознанных ответов |
| Default-значение ↔ осознанность конфигурации | Default снижает friction, но пользователь может пропустить настройку и не понять, что именно настроено; без default шаг 2 становится блокером |

## Применимость

Любой TG-бот с несколькими маршрутами + конфигурируемыми параметрами.

## Инварианты

- Шаг 1 всегда предшествует шагу 2
- Default-значение обязательно — иначе шаг 2 становится блокером
- Каждый экран содержит ТОЛЬКО вопросы, относящиеся к его шагу

## Примеры

- WP-330 Этап 8: Марафон-бот — сначала маршрут, потом время уроков

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Объединение шагов в один экран | Практикующий стремится сократить путь «до клика» и объединяет выбор маршрута с вводом параметров — пользователь не понимает, зачем вводит данные, и бросает онбординг |
| Default-значение воспринимается как «небрежность» | Практикующий считает, что default снижает «качество» ответа, и оставляет шаг 2 без default — шаг становится блокером, и пользователь не доходит до ценности |
| Вопросы разных шагов смешиваются | На шаге 1 появляются уточняющие параметры, а на шаге 2 — повторный выбор маршрута; граница «путь → конфигурация» размывается, и пользователь теряет контекст |
