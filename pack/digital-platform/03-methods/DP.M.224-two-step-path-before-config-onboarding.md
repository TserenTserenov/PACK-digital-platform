# DP.M.224 — Двухшаговый онбординг бота: путь → конфигурация

## Суть

Разделить онбординг на два последовательных шага: (1) выбор маршрута (что делать), (2) конфигурация параметров выбранного маршрута (как именно). Объединение в один экран лишает пользователя контекста — непонятно зачем вводить данные.

## Механизм

1. Экран 1: выбор пути (Марафон / Аккаунт / …)
2. Экран 2: конфигурация, специфичная для выбранного пути (время, периодичность, ...)
   — Контекст уже установлен: «вы выбрали Марафон → скажите когда удобно»
3. Default-значение (например, 04:00) снижает friction — пользователь может пропустить шаг 2 и получить рабочее поведение

## Применимость

Любой TG-бот с несколькими маршрутами + конфигурируемыми параметрами.

## Инварианты

- Шаг 1 всегда предшествует шагу 2
- Default-значение обязательно — иначе шаг 2 становится блокером
- Каждый экран содержит ТОЛЬКО вопросы, относящиеся к его шагу

## Примеры

- WP-330 Этап 8: Марафон-бот — сначала маршрут, потом время уроков
