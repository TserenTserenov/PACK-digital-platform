# DP.M.190 — 3-уровневый fallback для технического риска в live-демо

## Применимость

Live-демонстрация рискованного компонента: MCP gateway, прод-сервис, новый функционал, beta-feature. Бинарный fallback («работает / не работает») недостаточен — нужен сценарий «упало посреди».

## 3 уровня fallback

### Уровень 1 — Pre-decision (Т-30мин до старта)

- Smoke-test всех зависимостей.
- Если хоть что-то даёт WARN → переключиться на резервную ветку **до** аудитории.
- Решение фиксированное, не пересматривается во время демо.

### Уровень 2 — Plan-B (подготовленная альтернатива)

- Заранее записанное демо (видео) с тем же сценарием.
- Статический разбор 2-3 кейсов (скриншоты + анализ).
- Чёткая точка перехода («Если технический риск — смотрим вместе видео»).
- Plan-B репетируется наравне с основной демонстрацией.

### Уровень 3 — Mid-failure (упало во время демо)

4-шаговый алгоритм:
1. **Acknowledge** — назвать сбой прямо, без оправданий («Сервис не отвечает»).
2. **Switch** — перейти на Plan-B без задержки («Покажу записанную версию»).
3. **Continue** — донести запланированный смысл/инсайт.
4. **Debrief** — после демо: post-mortem + явный план действий для аудитории.

## Анти-паттерн

«Попробую починить во время демо» — теряем темп, аудитория видит панику, фокус смещается с предмета на инцидент.

## Применимо

- Конференционные доклады с live-демо
- Демо инвесторам (особенно прод-сервисы)
- Обучающие семинары
- Релиз-демо для customer success / sales
- Public webinar с интеграциями
