# DP.METHOD.152: Time-window эвристика для ротации трудоёмких типов контента

## Контекст

В системах с несколькими типами контента (по сложности) агент систематически предлагает более лёгкие типы: выгода просчитываемее, риск меньше. Без регулятора трудоёмкие типы (видео-скрипт, лонгрид) вытесняются.

## Метод

```
if days_since_last_accepted(type=T_heavy) > WINDOW_DAYS:
    offer T_heavy instead of fallback_topic
```

**Алгоритм:**
1. Читать `topic-log.yaml` — трекер тем с полями `type`, `status`, `date`
2. Проверить: есть ли `type: T_heavy, status: accepted` за последние `WINDOW_DAYS` дней?
3. Нет → предложить T_heavy вместо резервной темы в DayPlan

| Параметр | Значение по умолчанию | Смысл |
|---------|----------------------|-------|
| `WINDOW_DAYS` | 14 | окно проверки |
| `T_heavy` | зависит от системы (T3 = видео-скрипт) | тип с наибольшей трудоёмкостью |
| `source` | `topic-log.yaml` | трекер с status accepted/rejected |

## Применимость

Любая система с типами задач разной трудоёмкости, где лёгкие вытесняют трудоёмкие:
- Контент-конвейеры (посты / цепочки / видео / лонгриды)
- Feature backlog (quick wins vs complex features)
- Обучение (короткие упражнения vs глубокие проекты)
- Тест: «есть ли тип задач, который систематически не берётся?» Да → добавить time-window триггер
