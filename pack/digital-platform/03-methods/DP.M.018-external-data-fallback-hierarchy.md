# DP.M.018 — Иерархия fallback для внешних данных

## Назначение

Паттерн для получения данных от внешнего источника, который может быть недоступен.
Трёхуровневая стратегия: прямой CLI → событийная БД → отложенная синхронизация.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Свежесть данных (уровень 1: прямой CLI/API) ↔ надёжность при недоступности сервиса | Прямой запрос к внешнему CLI даёт самые актуальные данные, но зависит от доступности стороннего сервиса в моменте — переход на уровень 2 жертвует свежестью ради гарантированного ответа |
| Обход недоступности CLI (уровень 2: событийная БД) ↔ задержка ночной синхронизации | Запрос к `domain_event` работает независимо от текущей доступности внешнего сервиса, но данные там появляются только после ночной синхронизации — за день до неё их там ещё нет |
| Единообразие ответа («pending sync») ↔ явность для пользователя | Финальный уровень 3 сводит любой отказ к одной пометке «pending sync», что упрощает обработку на стороне вызывающего кода, но скрывает разницу между «данных никогда не будет» и «данные появятся после следующей синхронизации» |

## Алгоритм (IPO)

**Вход:** запрос на данные X за дату D от пользователя U
**Процесс:**
1. Попытка через прямой CLI/API внешнего сервиса
2. При недоступности CLI: запрос к событийной БД (`domain_event`), где данные хранятся
   после ночной синхронизации
3. При отсутствии в БД: пометить «pending sync» до следующей синхронизации
**Выход:** данные X или явная пометка о временном отсутствии

## Пример: WakaTime в Day Close

```sql
SELECT payload->>'human_readable', payload->>'total_seconds'
FROM public.domain_event
WHERE event_type = 'coding_time'
  AND account_id = '{DT_USER_ID}'
  AND external_id = 'wakatime:{DT_USER_ID}:{YYYY-MM-DD}'
```

Источник: `learning` БД (Neon). Поле `human_readable` = «9 hrs», `total_seconds` для мультипликатора.

## Применимость

Любой внешний data source с ночной синхронизацией в событийную БД:
WakaTime, Linear, GitHub activity, Calendar.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Пример WakaTime вытесняет общий IPO-паттерн | При реализации для нового источника (Linear, GitHub activity, Calendar) внимание фиксируется на конкретном SQL-запросе из примера, а не на трёхуровневой иерархии из §Алгоритм — под «данные X» неявно подставляется структура WakaTime-события вместо собственной схемы источника |
| Недооценка уровня 3 (явная пометка отсутствия) | Реализация фокусируется на уровнях 1-2 (CLI + БД), а обработка выхода «явная пометка о временном отсутствии» на практике опускается как редкий краевой случай, хотя IPO явно включает его в Output |
