# DP.M.387 Row Digest без mutable-полей для GDPR-совместимого ретро-якорения

## Определение

`row_digest` (хеш-якорь строки для ретроспективного обнаружения изменений в event-chain) вычисляется только по неизменяемым полям записи — без `payload` и без `account_id`. Изменяемые через право на забвение (`forget_account`) поля не входят в дайджест.

## Причина

Если дайджест включает mutable-поля, реализация права на забвение (стирание `payload`/`account_id` по запросу) меняет хеш ранее замороженных записей — заморозка (immutability anchor) ломается ровно тем механизмом, который обязан её уважать (GDPR-совместимость).

## Правило

При проектировании ретро-якоря (row digest, content hash, integrity anchor) над таблицей с полями, подлежащими стиранию по GDPR — явно исключать эти поля из вычисления хеша.
