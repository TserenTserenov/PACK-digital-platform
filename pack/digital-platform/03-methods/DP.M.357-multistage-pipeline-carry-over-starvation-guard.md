# DP.M.357 — Многостадийный конвейер с накопителями (carry-over как защита от голодания)

## Описание

В многостадийном конвейере (контент, обработка данных, любой batch-процесс) накопители между стадиями обеспечивают carry-over: неизрасходованные единицы переходят в следующую итерацию.

**Синхронный конвейер (без накопителей):** каждая стадия зависит от предыдущей прямо сейчас → «голодание» при сбое любой стадии.

**Асинхронный конвейер с накопителями:** голодание только при полном опустошении буфера стадии.

## Algorithm

### Шаг 1: Определить стадии и накопители

Для каждой стадии определить:
- Накопитель на входе (буфер из предыдущей стадии)
- Скорость производства (сколько единиц в единицу времени)

### Шаг 2: Найти узкое место

Узкое место = стадия, производящая медленнее всех последующих. Именно она определяет throughput всего конвейера.

### Шаг 3: Приоритизировать автоматизацию

Автоматизировать первой именно узкое место, не последнюю стадию (delivery).

### Шаг 4: Обеспечить carry-over

В конце каждой итерации: неизрасходованные единицы не удалять, переносить в следующий прогон накопителя.

## When to use

- Контент-конвейер (банк тем → очередь к производству → готовые материалы)
- Dev-pipeline с разной скоростью стадий (feature backlog → in-progress → review)
- Любой batch-процесс, где стадии работают с разной скоростью

## Тест применимости

«При сбое стадии N — останавливается ли стадия N+1?»
- Да → нет накопителя между стадиями, конвейер синхронный
- Нет → накопитель работает, carry-over обеспечен
