# DP.M.309 — Маршрутизация правил языка по осям Холлидея

## Обещание

Однозначно определяет хранилище для правила языкового стиля агента, предотвращая копирование правил между Паками и drift при обновлении.

## Три оси (Systemic Functional Linguistics, M.A.K. Халлидей)

| Ось | Вопрос | Маршрут в IWE |
|-----|--------|---------------|
| **Поле (Field)** | ЧТО говорим? (тема, домен, лексика) | → Pack домена (DP, PP, MIM, …) |
| **Отношение (Tenor)** | КТО автор/читатель? (регистр, формальность) | → Pack стилей / риторики |
| **Канал (Mode)** | ЧЕРЕЗ ЧТО? (Telegram, IDE, браузер) | → Слой интерфейса IWE |

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость добавления правила ↔ корректность маршрута | Проще дописать правило туда, где уже правишь файл (локальность правки), чем остановиться и определить его ось — но неверный маршрут создаёт drift при следующем обновлении |
| Единое место для «всего про язык» ↔ разделение по трём осям | Интуитивно тянет собрать все языковые правила в одном файле для удобства поиска, но Field/Tenor/Mode живут в разных Pack'ах/слоях по разным причинам изменения |
| Атомарность правила ↔ естественная многосоставность формулировки | Правило, сформулированное одним предложением, часто неявно смешивает 2+ оси (что говорим + как говорим) — разбить на атомарные части занимает больше времени, чем оставить как есть |
| Копирование между Pack'ами ↔ единственный источник истины | Скопировать готовое правило в новый Pack — быстрее, чем найти его текущий маршрут и сослаться; но копия создаёт вторую точку правки, которая рано или поздно разойдётся с оригиналом |

## Алгоритм

1. Взять правило языка
2. Определить ось: «ЧТО говорим / КТО говорит / ЧЕРЕЗ ЧТО?»
3. Маршрутизировать в соответствующее хранилище
4. Если правило покрывает 2+ оси → разбить на атомарные части, маршрутизировать раздельно

## Тест

«Если перенести правило в другой Pack/слой — оно будет иметь смысл без изменений?»
- Да → ось определена правильно, правило атомарно
- Нет → разбить или переопределить ось

## Применение в IWE

- Предметная лексика МИМ-домена → PACK-MIM distinctions (field)
- Правила регистра и формальности → Pack стилей (tenor)
- Канальная адаптация Telegram vs claude.ai → config интерфейса (mode)

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Это правило про язык — значит оно в Pack стилей» | Практикующий видит слово «язык» в формулировке и рефлекторно маршрутизирует в Tenor, не проверяя, не является ли это на самом деле доменной лексикой (Field) |
| «Канал сейчас один (Telegram), ось Mode не актуальна» | При работе в единственном интерфейсе ось Mode кажется избыточной абстракцией; правило зашивается как будто оно универсально, хотя на деле привязано к каналу |
| «Я знаю, где это должно жить — тест применимости для очевидных случаев необязателен» | Уверенность в интуитивном ответе пропускает шаг «перенести в другой Pack — сохранит ли смысл?», который и вскрывает смешение осей |
| «Три оси Холлидея — это лингвистическая теория, для IWE это избыточная строгость» | Модель воспринимается как академическая надстройка, а не как работающий тест маршрутизации — в результате правила распределяются по интуиции, а не по осям |
