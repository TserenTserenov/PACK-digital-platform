# DP.M.023 — Chaining nightly tasks через фиксированный offset

> **Контекст:** Планирование зависимых ночных задач, где задача-потребитель обрабатывает данные,
> подготовленные задачей-поставщиком за цикл до.

## §1 Паттерн

Задача-потребитель стартует через **фиксированный N минут** после задачи-поставщика.

```
producer: OnCalendar=*-*-* 04:30:00 UTC
consumer: OnCalendar=*-*-* 04:35:00 UTC   # +5 мин
```

Альтернативы: `After=` / `ExecStartPost=` в systemd (жёсткая зависимость).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Простота эксплуатации (два независимых .timer файла) ↔ отсутствие гарантии свежести данных | Независимость timer'ов упрощает конфигурацию и позволяет запускать consumer вручную (§3), но именно эта независимость — источник риска §3: «если producer задержится > N мин → consumer читает данные предыдущего цикла» |
| Величина offset N ↔ выбор между риском устаревших данных и излишним ожиданием | Правило §3 «offset ≥ P95 времени выполнения producer + buffer»: увеличение offset снижает риск stale data, но увеличивает задержку доставки данных потребителю; малый offset — обратный компромисс |
| Устойчивость к разовой задержке producer (§3) ↔ отказ от строгой корректности при системной деградации | Паттерн принимает возможность stale data как приемлемую цену за отказ от жёсткой зависимости `After=`/`ExecStartPost`, что подходит только для случая §2 «задержка данных допустима» |

## §2 Когда применять

| Ситуация | Паттерн |
|----------|---------|
| Consumer читает данные producer'а, задержка данных допустима (несколько минут) | Фиксированный offset ✅ |
| Consumer ДОЛЖЕН дождаться завершения producer'а | `After=` / `ExecStartPost` |
| Producer может занимать переменное время (>N мин) | Увеличить offset или использовать `After=` |

## §3 Преимущества и риски

**Преимущества:**
- Простота конфигурации: два независимых .timer файла
- Устойчив к задержкам producer'а: если producer задержался на < N мин, consumer получит свежие данные
- Нет жёсткой зависимости: можно запускать consumer вручную без запуска producer'а

**Риск:** Если producer задержится > N мин → consumer читает данные предыдущего цикла (stale data).
Правило: offset должен быть ≥ P95 времени выполнения producer'а + buffer.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Offset выбирается по наблюдаемому среднему, а не по P95 | §3 явно требует «offset ≥ P95 времени выполнения producer + buffer», но внимание при настройке смещается на типичное/среднее время выполнения producer'а — хвостовые задержки, которые и делают consumer stale, недооцениваются |
| §2-таблица перепроверяется только один раз, при внедрении | Практик останавливается на первой строке («задержка допустима → offset ✅») и не возвращается к третьей строке («producer может занимать переменное время > N мин») при изменении характера producer'а со временем |
