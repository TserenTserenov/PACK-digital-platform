# DP.M.029 — Cross-verify перед действием по CRITICAL из аудита

## Проблема

Автоматический аудит генерирует CRITICAL/🔴-флаги на основе эвристик и ограниченного контекста. Цена ложного CRITICAL выше, чем задержка: немедленное действие по ложной тревоге наносит вред (ненужная ротация секретов, лишний git revert, паника).

## Правило

**CRITICAL-флаг из автоматического аудита ≠ «действуй немедленно».**

Перед любым необратимым действием (ротация, revert, деплой rollback) — cross-verify в изолированном контексте.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость реакции на CRITICAL-флаг ↔ цена ложного действия | Метод постулирует, что цена ложного CRITICAL выше, чем задержка, поэтому вставляет обязательную изолированную сессию (шаг 1) перед необратимым действием — это добавляет время к реакции на реальный инцидент, но именно эту цену метод считает оправданной |
| Изоляция контекста верификатора (шаг 1: subagent без контекста исходного аудита) ↔ скорость воспроизведения диагноза | «Чистая» сессия без предзнания диагноза даёт независимую проверку, но требует заново находить и запускать нужную команду (шаг 2) с нуля, без ускоряющих подсказок исходного аудита |

## Процедура

### Шаг 1 — Изолированная сессия

Открыть новую сессию (другой Claude Code, subagent с `context_isolation: true`) без контекста исходного аудита.

### Шаг 2 — Воспроизвести диагноз независимо

Выполнить ту же проверку командой напрямую:

```bash
# Пример: проверить .env в git history
git log --all --full-history -- .env
# Пример: проверить PII в коде
grep -r "email\|telegram_id" src/ --include="*.py"
```

### Шаг 3 — Сравнить результаты

| Результат изолированной сессии | Действие |
|-------------------------------|---------|
| Подтверждено | Выполнять план устранения |
| Ложная тревога | Пересмотреть вердикт аудита (🔴→❌ или ⚠️) |
| Неоднозначно | Эскалировать к пользователю |

### Шаг 4 — Обновить posture

Пересмотренный вердикт зафиксировать в security-posture.md с пометкой `cross-verified: true` и датой.

## Инвариант

Снижение severity (🔴→❌) после cross-verify не теряет информативность отчёта — аудит фиксирует найденное, верификация фиксирует фактический уровень риска.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Подтверждение вместо независимого воспроизведения | Внимание съезжает на подтверждение исходного диагноза (шаг 2 — «воспроизвести диагноз независимо»), а не на реальную независимость: зная про какой CRITICAL идёт речь, практикующий невольно ищет именно то, что искал исходный аудит, вместо того чтобы дать изолированной сессии команду с чистого листа — это подрывает саму цель шага 1 |
| «Неоднозначно» смещается в сторону «ложная тревога» | При результате «Неоднозначно» (таблица шага 3) внимание смещается в сторону трактовки как ложной тревоги, а не эскалации к пользователю — задержка неприятна, а понижение severity выглядит как завершение задачи, хотя предписанное действие для неоднозначного случая — эскалация, не самостоятельное решение |
