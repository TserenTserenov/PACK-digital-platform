# DP.M.049: Lean Frontmatter — расширение по запросу, не upfront

## Назначение

Когда структура контента ещё движется (первый автор пишет, формат не доказан), frontmatter / DSL поля надо вводить **по факту использования**, не upfront «потом не придётся переделывать». На практике переделок больше, потому что каждая правка структуры тянет за собой 5 полей.

## Двухфазная схема

| Фаза | Когда | Frontmatter |
|------|-------|-------------|
| **1. Пилот** | Первый автор пишет, формат проверяется | Минимум: id, title, базовые навигационные поля (subsection_id, order, prerequisites) |
| **2. Стабилизация** | После фиксации структуры всех артефактов | Расширение: введение/миграция полей через концепт-граф / schema-registry / `v4-concept-graph.yaml` |

## Анти-паттерн

«Давайте сразу проставим parent_concepts, U.*-типы, mastery_node, prerequisites — потом всё формально».

**Реальность:**
- Структура ещё движется → каждое поле фиксируется на месте, где автор ещё не уверен.
- Переделки 2-3 раза за пилот.
- Двойная ответственность (валидатор + автор-человек) усиливает стоимость каждой правки.

## Правило (фаза 1)

Frontmatter содержит только то, что используется **немедленно**:
- `id`, `title` — идентификация.
- `can_do` — навыковая цель (если применимо).
- Базовые навигационные поля (`subsection_id`, `order`, `prerequisites`).

**Не добавлять** в фазе 1:
- `parent_concepts`, `U.*` типы.
- `mastery_node`, `cp_check`, `bh_check` — расширенные cross-ref.
- Дублирующие поля, которые потом всё равно поедут в concept-graph.

## Правило (переход к фазе 2)

После фиксации структуры всех артефактов в области:

1. Введение `v4-concept-graph.yaml` (или аналог) — отдельный artifact для cross-ref.
2. Frontmatter остаётся минимальным; ссылки на концепт-граф через `id`.
3. Миграция через автоскрипт (без ручного редактирования каждого файла).

## Применимо

- Curriculum design (учебные программы, руководства).
- Документация API на ранней фазе.
- Schema-design эволюционирующих систем (Pack, ADR templates).
- Любой контент с двойной ответственностью валидатора и автора-человека.

## Близко к

**YAGNI** (You Aren't Gonna Need It) — но специфично для frontmatter / DSL, где поле = и инвариант валидатора, и обязательство автора.
