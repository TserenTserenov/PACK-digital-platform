# DP.M.356 — Routing Gate: расширение существующей конвенции вместо параллельной структуры

## Описание

При проектировании нового класса контента или артефакта возникает соблазн создать новую структуру (папку, шаблон, тип файла). Routing Gate говорит: сначала проверь, не решает ли задачу расширение существующей конвенции дополнительным полем.

Нарушение создаёт дрейф (OwnerIntegrity): два слота с одним смыслом → артефакты расходятся, один устаревает.

## Algorithm

### Шаг 1: Grep по SoT

Перед созданием новой структуры выполнить `grep` по шаблонам и source-of-truth текущего типа артефакта.

### Шаг 2: Тест применимости

Задать вопрос: «Если добавить поле к существующему типу — получу тот же результат?»
- Да → расширить поле, не создавать параллельную структуру
- Нет → создание новой структуры обосновано

### Шаг 3: Применить минимальное расширение

Добавить поле в frontmatter существующего типа. Не менять форматирование остального файла.

## When to use

- При проектировании нового «банка», «базы», «индекса» для нового класса контента
- При появлении нового канала публикации (video, telegram, blog)
- При расширении типологии артефактов в IWE (новый тип РП, новый тип поста)

## Тест применимости

«Слот с похожим назначением уже есть в SoT?»
- Да → наполнять поле, не создавать структуру
- Нет → создание новой структуры обосновано
