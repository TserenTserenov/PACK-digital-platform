# DP.METHOD.212 — отдельный grep-проход по user-facing строкам после смены терминологии

## Суть метода

После переименования термина (например «Обучение» → «Развитие/Работа») grep-guard, проверяющий отсутствие старого термина, запускается двумя проходами: (1) по коду/идентификаторам/путям и (2) отдельно по user-facing строкам — текстам, которые видит пилот (сообщения, заголовки, подсказки интерфейса).

## Обоснование

User-facing строки часто живут в шаблонах, конфигах локализации или строковых литералах, которые обычный grep по коду формально находит, но обычная проверка на «остался ли идентификатор» может пропустить текстовые вариации того же термина (склонения, синонимы, разные регистры) — они требуют отдельного семантического прохода, не идентичного техническому grep-guard.

## Применение

Любая массовая замена терминологии, затрагивающая пользовательский текст, а не только внутренние имена/коды.
