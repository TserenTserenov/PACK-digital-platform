# Приоритет Derived-значения над пересчётом из примитивов при чтении цифрового двойника

## Суть

При чтении цифрового двойника через Aisystant MCP: если `path:3_derived → 3_4_qualification.stage` содержит непустое значение ≥ 2 — оно авторитетнее, чем пересчёт из отдельных RCS-срезов (W/M1/M2/M4).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Доверие к кэшу ↔ желание перепроверить | Derived — агрегат с гарантиями платформы; но у агента есть искушение «на всякий случай» пересчитать из примитивов, чтобы убедиться самому |
| Скорость ответа ↔ полнота проверки | Чтение готового Derived — один MCP-вызов; пересчёт из W/M1/M2/M4 требует нескольких чтений и агрегирующей логики на стороне агента |
| Единый источник агрегата ↔ дублирование логики агрегации | Derived уже содержит агрегацию платформы; если агент параллельно пересчитывает то же самое своим алгоритмом — два места считают одно и то же с риском разойтись |
| Нулевые поля как валидные данные ↔ нулевые поля как сигнал отсутствия | `marathon_steps_total=0` выглядит как «данных нет», но по методу это реальный ноль; давление — трактовать пустоту как повод для fallback-пересчёта |

## Алгоритм

1. Читать `3_derived`, не `2_collected` — только Derived-путь содержит агрегированные значения.
2. Если `stage` заполнен и ≥ 2 → записать как `stage_confirmed`, пропустить диалог уточнения.
3. Нулевые поля `marathon_steps_total=0`, `training_passed_total=0` — реальные нули, не признак отсутствия профиля. Не снижать ступень на их основании.
4. Пересчёт из примитивов — только когда Derived отсутствует.

## Обобщение

Когда Derived-значение уже существует в хранилище — не пересчитывать из примитивов. Derived — кэш с гарантиями платформы. Аналогия: если в реестре есть итоговая оценка, не суммировать её компоненты заново.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Пересчитаю сам — так надёжнее» | Внимание смещается на самостоятельную верификацию через примитивы, хотя Derived уже гарантирован платформой; лишний пересчёт создаёт риск разойтись с источником, а не устраняет его |
| «Ноль в поле — значит, данных не было» | Нулевые агрегаты (`marathon_steps_total=0`) читаются как признак пустого профиля, а не как реальное значение; это тянет к ошибочному fallback на примитивы там, где Derived уже корректен |
| «2_collected ближе к \"сырым\" данным — надёжнее» | Практикующий склонен доверять более «первичному» слою данных интуитивно больше, чем агрегату; фактически именно агрегат несёт гарантию согласованности, а `2_collected` — нет |
| «Если Derived не заполнен полностью — читаем примитивы на всякий случай» | Частичная заполненность Derived трактуется как повод перепроверить всё целиком, а не только отсутствующую часть; лишняя работа там, где нужен только точечный fallback |
