# [DP.M.035] Явные триггеры извлечения модуля в сервис

## Суть метода

При принятии решения «оставить как модуль внутри X» вместо «вынести в отдельный сервис» — **немедленно зафиксировать измеримые триггеры**, при которых решение пересматривается. Триггеры пишутся в момент принятия решения, не ретроспективно.

## Четыре типа триггеров

| Тип | Пример триггера | Когда применять |
|-----|----------------|----------------|
| **Нагрузочный** | `>100 OAuth setup/день в течение 2+ недель` | Когда модуль может стать узким местом при росте |
| **Безопасный** | `Security incident в родительском сервисе` | Когда изоляция критична для blast radius |
| **Tenant-граница** | `Второй tenant/client_id OAuth` | Когда появляются разные security domains |
| **Размерный** | `src/module/ > 5000 LOC` | Когда когнитивная нагрузка превышает разумный порог |

## Почему это важно

**Без явных триггеров** решение «оставить как модуль» становится вечным — команда теряет moment for review. Никто не следит за метриками, решение принято «навсегда».

**С явными триггерами** — кто угодно может проверить: «сработал ли триггер?» без необходимости переоткрывать архитектурную дискуссию с нуля.

## Шаблон в ADR

```markdown
## Триггеры обратного extraction в отдельный сервис

- [ ] >{{N}} {{operation}}/день в течение {{period}}
- [ ] Security incident в {{parent_service}}
- [ ] Появляется {{second_boundary_condition}}
- [ ] {{module_path}}/ > {{LOC}} строк кода
```

## Пример: ADR-IWE-016 (WP-305, 12 мая 2026)

Решение: OAuth логика как модуль `gateway-mcp/src/oauth/` (не отдельный CF Worker).

Зафиксированные триггеры extraction:
- `>100 OAuth setup/день в течение 2+ недель` (нагрузочный)
- `Security incident в gateway-mcp` (безопасный)
- `Второй tenant OAuth` (tenant-граница)
- `gateway-mcp/src/index.ts > 5000 LOC` (размерный)
