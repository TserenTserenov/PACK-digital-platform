# DP.M.282 — Function-First Onboarding

## Описание

Паттерн онбординга сложной инструментальной системы: сначала показывать что система делает (функции для пользователя), откладывать объяснение механизма (термины и архитектура).

Ключевая метафора: «ты уже носишь костюм, просто он разобран» — снимает страх «я ещё не готов», потому что человек уже в процессе использования.

## Три элемента паттерна

1. **Метафора снятия барьера** — переформулировать «ещё не готов» в «уже начал». Конкретная метафора под систему (костюм, велосипед, …).
2. **Function-First presentation** — называть что делает для пользователя, не как устроена. Примеры для IWE: «помнит», «знает стиль», «читает заметки» вместо «MCP», «скрипты», «агенты».
3. **Practice-then-Explain** — сначала 2 минуты делаем (практика), потом объясняем структуру. Глубокая архитектура (MCP/скрипты/агенты) → видео-модуль или третий семинар.

## Алгоритм применения

1. Определить 3-5 ключевых функций системы с позиции пользователя (глаголы: «запоминает», «напоминает», «предлагает»)
2. Подобрать несущую метафору (аналогия из физического мира), снимающую барьер «не готов"
3. Открыть онбординг с практикой (2-5 минут работы в системе)
4. Объяснить структуру после того, как пользователь почувствовал ценность
5. Вынести механизмы (архитектура, конфигурация) в отдельный модуль для желающих

## Тест применимости

Применимо, если: (1) система имеет ≥5 технических терминов в документации; (2) пользователь может получить ценность без понимания архитектуры.
