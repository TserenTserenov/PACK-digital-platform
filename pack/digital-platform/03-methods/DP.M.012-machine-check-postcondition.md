# DP.M.012: Machine-Check Postcondition

## Определение

Паттерн обеспечения качества чеклиста: любой шаг, записывающий артефакт (файл, запись, коммит), обязан содержать машинную проверку (grep/test) как postcondition.

**Инвариант:** postcondition FAIL → шаг НЕ помечается выполненным; исполнитель возвращается к шагу записи.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Строгость postcondition (шаг 3: FAIL → вернуться, не помечать ✓) ↔ скорость прохождения чеклиста | Каждый шаг записи получает дополнительную обязательную проверку, что замедляет линейное прохождение чеклиста, но исключает целый класс silent-skip ошибок («Почему важно») |
| Простота grep-проверки (шаг 2: по имени файла или ключевому содержимому) ↔ точность проверки | Дешёвая текстовая проверка доступна для любого шага без специальной инфраструктуры, но ловит только факт наличия артефакта/фразы, не корректность содержимого |

## Алгоритм применения

1. Шаг чеклиста содержит действие записи (Write / Edit / commit / архивация)
2. Немедленно после — grep-postcondition по имени файла или ключевому содержимому
3. FAIL (grep ничего не находит) → вернуться к записи, не помечать ✓
4. PASS → помечать шаг выполненным

## Примеры

- **Day Close 9a** (архивация DayPlan): grep проверяет наличие файла в archive/
- **Day Close 9b** (запись итогов в WeekPlan): grep проверяет ключевую фразу в WeekPlan
- **KE-применение**: после создания Pack-файла — grep по имени файла в целевой директории

## Почему важно

Silent skip: шаг помечается выполненным, но файл не создан / не обновлён → накопленный drift (WeekPlan без итогов, DayPlan не архивирован). Машинная проверка исключает этот класс ошибок.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Существование файла принимается за корректность содержимого | Практик пишет grep-postcondition, проверяющий сам факт существования файла (пример «Day Close 9a»: «grep проверяет наличие файла»), но недооценивает проверку содержимого — файл может быть создан, но не тем, что требовалось (пустой, старая версия), хотя алгоритм (шаг 2) прямо допускает проверку «по ключевому содержимому» |
| Новые шаги получают постконтроль, старые — нет | Внимание смещается на добавление postcondition к новым шагам чеклиста; шаги, написанные до внедрения паттерна, остаются без machine-check, хотя определение относит паттерн к «любому шагу, записывающему артефакт» без исключения по дате |
