# DP.M.425 — Явный non-fatal sync-шаг перед чтением опциональной cross-repo зависимости

## Определение

Перед чтением данных из ДРУГОГО репозитория, который является опциональной (не гарантированно склонированной/актуальной на этом хосте) зависимостью, нужен явный шаг синхронизации прямо перед чтением: клонировать при первом запуске (репозиторий отсутствует), иначе подтянуть изменения без слияния (fast-forward-only). Ошибка синхронизации уходит в лог, не фатальна — вызывающий процесс (например, открытие дня) продолжается, а не падает из-за недоступности опциональной зависимости.

## Когда применять

- Компонент читает опциональные данные (тайл, конфигурацию, значение) из репозитория, не являющегося основным репозиторием процесса
- Целевой хост может не иметь этот репозиторий склонированным (первый запуск на новом хосте/сервере)
- Читающая функция и так умеет мягко деградировать при отсутствии данных (не падает, просто не показывает тайл/значение)

## Структура

```bash
if [ ! -d "$DEP_REPO_PATH" ]; then
  git clone "$DEP_REPO_URL" "$DEP_REPO_PATH" 2>/tmp/sync.log || echo "sync failed: clone, см. /tmp/sync.log"
else
  git -C "$DEP_REPO_PATH" pull --ff-only 2>/tmp/sync.log || echo "sync failed: pull, см. /tmp/sync.log"
fi
# далее — штатное чтение данных, независимо от результата sync
```

## Ключевые свойства

1. **Явный шаг, не побочный эффект другого процесса.** Периодический таймер синхронизации ОСНОВНЫХ репозиториев (`DP.M.375`) не гарантирует, что опциональная cross-repo зависимость тоже туда попадает — если её не добавили в список таймера, она никогда не клонируется на новый хост.
2. **Non-fatal по конструкции.** Ошибка sync (клонирование или подтягивание изменений) логируется, но не останавливает вызывающий процесс — та же дисциплина разделения кодов, что в `DP.M.020` (мягкий пропуск при недоступности опциональной зависимости), но здесь разделяется не код возврата скрипта, а sync-шаг от шага чтения.
3. **Различает «источник не подключён» от «данных нет».** Без явного sync-шага мягкая деградация читающей функции выглядит как «данных нет» (тайл просто пуст) — фактическая причина («репозиторий никогда не клонировался на этот хост») не видна без чтения логов воркера.

## Отличие от смежного

- **DP.M.020 (опциональная зависимость скрипта через параметры конфигурации):** там — статический config-guard на входе скрипта (использовать ли заданный путь вообще); здесь путь всегда используется, но перед чтением его нужно явно актуализировать через git.
- **DP.M.375 (двунаправленная git-синхронизация через раздельные таймеры):** там — периодическая фоновая синхронизация ОСНОВНЫХ репозиториев сервера через systemd timer; здесь — точечный sync-шаг перед конкретным чтением опциональной зависимости, не обязательно входящей в периодический таймер.

## Применимо к

Любой компонент, читающий опциональные данные из репозитория, не гарантированно присутствующего/актуального на исполняющем хосте — не только открытие дня/тайлы, любое опциональное cross-repo чтение.

## Связи
- DP.M.020 — паттерн опциональной зависимости через параметры конфигурации (config-guard, не sync-guard)
- DP.M.375 — периодическая двунаправленная git-синхронизация (фоновый таймер, не point-in-time guard)
