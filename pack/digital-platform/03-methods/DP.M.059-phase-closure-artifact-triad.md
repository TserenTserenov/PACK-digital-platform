# Триада артефактов закрытия фазы РП (DP.M.059)

## 1. Контекст и разграничение

Закрытие фазы РП — отдельная операция в ОРЗ-фрактале, ортогональная закрытию сессии и закрытию РП.

| Операция | Триггер | Что закрывает |
|----------|---------|----------------|
| Закрытие сессии (Quick Close) | Конец работы за раз | Контекст текущей сессии |
| **Закрытие фазы** (этот метод) | Критерии фазы выполнены, остальные фазы РП открыты | Подзадача внутри РП |
| Закрытие РП (Archive) | Все фазы РП выполнены, DoD достигнут | Весь РП |
| Spawn из фазы (DP.M.051) | Фаза доросла до независимо релизуемого продукта | Фаза выносится в дочерний РП |

## 2. Правило: триада артефактов

Коммит закрытия фазы ДОЛЖЕН содержать три компонента:

1. **Inbox-context update** — обновление `DS-my-strategy/inbox/WP-{N}-{slug}.md`: добавлена секция «Ф{X} done» со списком artifacts (commit-хеши, файлы, ссылки).
2. **Cross-link при триггерах** — в commit-сообщении явные ссылки на смежные РП, если фаза создала триггер для другого РП (новые файлы под покрытие, изменение контракта).
3. **Side-artifact при extraction** — если в фазе была extraction-работа: `inbox/extraction-reports/<date>-<source>.md` со списком кандидатов + verdict. Без него кандидаты исчезают из audit-trail.

## 3. Тест полноты

«Можно ли по этому коммиту через 6 месяцев восстановить, что было сделано в фазе и какие хвосты остались?»

Если нет — коммит неполный, добавить недостающий артефакт триады.

## 4. Анти-паттерны

| Анти-паттерн | Симптом | Лечение |
|--------------|---------|---------|
| **Создать отдельный РП на каждую фазу** | Раздувание WP-REGISTRY, фрагментация бюджета | Применить DP.M.048 (scope discipline) |
| **Закрыть весь РП когда закрыта одна из N фаз** | Потеря carry-over бюджета на остальные фазы | Закрыть фазу триадой §2, оставить РП `in_progress` |
| **Не создавать extraction-report при extraction** | Кандидаты исчезают из audit-trail | Side-artifact §2.3 обязателен |
| **Cross-link только в чате/слаке** | Через месяц связь между РП потеряна | Cross-link в commit-сообщении §2.2 |

## 5. Признаки явного применения триады

В commit-сообщении закрытия фазы видны все три компонента:

```
WP-{N}: закрыта Ф{X} {название}

- {inbox-context}: добавлен раздел «Ф{X} done» с 4 commit-ссылками
- Триггер для WP-{M} Ф{Y}: покрыть 9 новых файлов
- Side-artifact: inbox/extraction-reports/{date}-{source}.md (N кандидатов, verdict: defer)
```

## 6. Пример (WP-242 Ф-Семинар-Агроскина, 17 мая 2026)

Закрытие фазы commit `df7a46ce`:

1. **Inbox-update:** `inbox/WP-242-concept-graph.md` дополнен секцией «Ф-A done» со списком 8 объектов и 4 commit-хешами (PACK-personal + aisystant/docs).
2. **Cross-link:** commit-message ссылается на WP-300 и фиксирует триггер для Ф3 двуязычности — «покрыть 9 новых файлов в общем проходе».
3. **Side-artifact:** `inbox/extraction-reports/2026-05-17-agroskin-seminar.md` создан с 13 deferred-кандидатами для последующего решения PACK-finance (см. DP.M.058).

## 7. Связь с другими методами

- **DP.M.010** — описывает 5 операций lifecycle РП; этот метод расширяет «Закрытие сессии» дополнительной операцией «Закрытие фазы».
- **DP.M.048** — отвечает на вопрос «новая работа = фаза или новый РП?»; этот метод отвечает «как именно оформить коммит закрытия фазы».
- **DP.M.051** — обратное направление: вынесение фазы в дочерний РП, когда фаза доросла. Если выносим — не закрываем триадой.
