# DP.METHOD.165: Публичная витрина подключает только директорию финальных артефактов

## Назначение

Паттерн интеграции личного репо пользователя с публичной витриной (public showcase, сайт,
открытый профиль).

## Правило

**Область подключения** к публичной витрине = только директория с финальными артефактами
(например, `guide/`).

**Запрещено** подключать:

- Корень репо целиком
- Сырые данные: `inbox/`, `memory/`, `profile/`, `exocortex/`
- Любые файлы с PII или незавершённым персональным контекстом

## Почему

Подключая весь репо к витрине, пользователь публикует в открытый доступ:

- Inbox: незавершённые мысли, черновики задач
- Memory: личные предпочтения, история сессий с агентами
- Profile: RCS-данные, уровни, прогресс, диагностические результаты

Даже если сам пользователь не считает эти данные критичными — публикация
незавершённых данных нарушает принцип суверенитета данных (DP.D.234).

## Применение (ADR-2026-06-30)

Топология персональных руководств IWE (WP-149):

- Репо пользователя: `personal-guide/` содержит `guide/`, `profile/`, `inbox/`
- Витрина подключает: **только** `guide/` → публикует скомпилированное руководство
- Всё остальное: остаётся в суверенной зоне пользователя (его машина / private repo)

## Тест

«Если пользователь подключит весь репо к витрине — что попадёт на неё?»

- Только `guide/` → правильно (только финальный артефакт)
- Корень репо → неправильно (сырые данные + возможный PII)
