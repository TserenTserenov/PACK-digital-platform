# DP.METHOD.159: Авто-детект состояния через минимальные сигналы с одним вопросом при неоднозначности

## Назначение

Определить бинарное состояние системы (развёрнута/не развёрнута) с минимальным числом вопросов пользователю, используя прямые сигналы.

## Алгоритм

1. Собрать N прямых сигналов состояния (не proxy-сигналы).
2. Все положительны → `state = true`, вопросов нет.
3. Один положительный, остальные отрицательные → состояние неоднозначно → один уточняющий вопрос.
4. Все отрицательны → `state = false`, вопросов нет.

## Ключевые принципы

- Использовать прямые сигналы, не косвенные proxy.
- Типовая ошибка: «ступень мастерства ≠ развёрнутость IWE» — proxy, не факт.
- Число вопросов пользователю ≤ 1 при любом сценарии.

## Пример применения

Скилл `personal-guide-render`: определить, развёрнут ли IWE-инструментарий у пилота.
- Сигнал A: `github_status` — подключён ли репо `personal-guide`.
- Сигнал B: `personal_list_sources` — подключён ли личный источник.
- A=true, B=true → `iwe_deployed = true`.
- A≠B → один вопрос: «Подключён ли ваш personal-guide?».
- A=false, B=false → `iwe_deployed = false`.

## Применимость

Любой агентный UX, где нужно определить наличие инструмента/интеграции перед выбором пути рендеринга или генерации.
