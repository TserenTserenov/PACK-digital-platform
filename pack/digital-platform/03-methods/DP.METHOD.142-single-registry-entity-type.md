# DP.METHOD.142 — Единый реестр для одного типа сущности

**Суть:** Один тип сущности (темы, задачи, статусы, реестры) хранится ровно в одном месте. Два и более параллельных списков одного типа данных — сигнал к консолидации.

## Проблема

Несколько параллельных списков одного типа сущностей неизбежно расходятся — drift накапливается с каждым обновлением.

**Инвариант OwnerIntegrity:** один факт — одно место.

## Метод

1. **Детектировать:** N ≥ 2 файлов одного типа данных — сигнал к консолидации
2. **Консолидировать:** выбрать один canonical файл, мигрировать записи из остальных
3. **Удалить источники дрейфа:** после миграции удалить параллельные файлы
4. **Мониторить:** появление второго реестра того же типа — немедленная консолидация

## Пример

Три параллельных реестра тем (draft-list.md + posts-README + content-plan.md, 62 записи) → один topic-log.yaml.

## Применимость

Любая система: задачи, темы, статусы, реестры сущностей — везде, где один тип данных ведётся в N файлах одновременно.
