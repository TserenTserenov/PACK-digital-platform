# DP.M.461 — Портируемый in-place патч: temp-файл в той же директории + `mv` под удерживаемой блокировкой

## Проблема

`sed -i` без аргумента-суффикса — GNU-синтаксис. BSD sed (macOS) требует пустую строку сразу после `-i` (`sed -i ''`), без неё падает с невнятной ошибкой парсинга (`invalid command code f`, exit 1), файл остаётся нетронутым. Развилка `if sed --version …` громоздка и сама по себе источник ошибок (DP.FM.201 — второй известный BSD/GNU-разрыв в `&`). В прецеденте вызывающий код не проверял код возврата — патч семафора молча не применялся (экземпляр DP.FM.400: платформенный примитив принят за общий; и DP.M.415: подавленный код возврата). Живой баг воспроизведён и починка подтверждена на реальном хосте до деплоя.

## Метод

Правка файла «на месте» в скрипте, обязанном работать и на macOS (BSD userland), и на Linux (GNU), выполняется не через `sed -i`, а через генерацию нового содержимого во временный файл в той же директории, что и целевой, с последующим атомарным `mv` — внутри уже удерживаемой блокировки (`flock`/mkdir-замок), которая защищает файл от параллельных писателей.

**Вход:** целевой файл; преобразование содержимого (sed без `-i`, awk, python — любой фильтр stdin→stdout); уже удерживаемая блокировка. **Выход:** целевой файл в новом состоянии целиком (читатели видят либо старое, либо новое содержимое, никогда частичное); ненулевой код и нетронутый файл при любом сбое.

1. **Блокировка уже взята** вызывающим кодом (`flock`-блок или mkdir-замок — DP.M.434). Метод не берёт вторую блокировку и не выходит из первой до завершения `mv`.
2. **Temp — рядом с целью:** `tmp=$(mktemp "${target}.XXXXXX")`. Та же директория ⇒ та же файловая система ⇒ `mv` — атомарный `rename(2)`, а не копирование с окном частичного содержимого. `${TMPDIR}` для этого не подходит.
3. **Генерация без `-i`:** `sed 's/…/…/' "$target" > "$tmp"` (или awk/python). Код возврата генератора проверяется явно: `|| { rm -f "$tmp"; return 1; }` — именно его отсутствие сделало исходный сбой молчаливым.
4. **Права и владелец:** `mv` подменяет inode — у файла будут права temp-файла (`mktemp` даёт 0600). Если файл читают другие процессы/пользователи — выставить нужный режим явно (`chmod 644 "$tmp"`) до `mv`; `chmod --reference` не портируем.
5. **Атомарная подмена:** `mv -f "$tmp" "$target"`.
6. **Проверка результата,** а не только кода возврата: `grep -q "$expected" "$target"` — критерий «патч применился», проверяемый на обеих платформах.
7. **Уборка на путях сбоя:** temp удаляется во всех ветках ошибки (ловушка `trap … RETURN` внутри функции — с учётом DP.FM.460: область действия ловушки).

## Тест метода

«Скрипт обязан работать и на macOS, и на Linux? Он правит файл на месте через `sed -i` (с развилкой или без)? Код возврата и результат правки проверяются?» Первые два «да» → заменить на temp-в-той-же-директории + `mv`; третье «нет» → добавить шаги 3 и 6. Проверка на живом хосте с BSD sed обязательна до деплоя — CI на GNU/Linux этот класс не ловит (DP.FM.201).

## Forces

| Force | Tension |
|-------|---------|
| Портируемость (macOS BSD ↔ Linux GNU) ↔ краткость записи | `sed -i` — одна команда, но GNU-синтаксис; портируемая замена требует temp-файла, проверки кода возврата, прав и уборки — семь шагов вместо одного |
| Атомарность подмены ↔ сохранение прав и владельца | `mv` даёт читателям либо старое, либо новое содержимое, но подменяет inode: у файла оказываются права temp-файла (0600), их нужно выставить явно, а `chmod --reference` не портируем |
| Сохранить `sed -i` с развилкой по диалекту ↔ единый путь без развилки | Развилка `if sed --version` оставляет привычную команду, но сама источник ошибок; единый путь через temp + `mv` снимает зависимость от диалекта ценой более длинного кода |

## Bias-Annotation

| Bias | Direction of distortion |
|------|--------------------------|
| Зелёный CI на GNU/Linux принимается за портируемость | Класс BSD-разрывов CI не ловит (DP.FM.201): уверенность завышается; поэтому проверка на живом хосте с BSD sed обязательна до деплоя |
| Непроверенный код возврата читается как успех | В прецеденте `exit 1` не проверялся, и патч молча не применялся (DP.M.415): молчаливый сбой смещает оценку в сторону «работает» |
| Прецеденты — файлы состояния одной подсистемы (семафор сессии, `meta.yaml` пир-сессий) | Общность метода завышается: за пределами этой подсистемы применимость остаётся предположением; для Python-слоя приём уже реализуется средствами языка (AS.M.043) |

## Применимо

Любой скрипт с обязательством кроссплатформенности, который правит файлы состояния (семафоры сессий, `meta.yaml`, реестры, конфиги) под блокировкой. Не нужен, если правка идёт из Python/другого языка с собственным атомарным write-then-rename — там тот же приём реализуется средствами языка (AS.M.043 относит atomic write к Python-слою).
