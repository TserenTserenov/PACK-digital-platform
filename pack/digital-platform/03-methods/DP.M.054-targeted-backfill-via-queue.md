# DP.M.054 — Точечный бэкфилл через выделенную очередь (cursor-воркер)

## Назначение

Добавить N пользователей в downstream-функцию когда cursor projection-воркера уже продвинулся мимо соответствующих событий. Альтернатива cursor reset (side effects на весь поток) и полного replay событий (дорого, нарушает идемпотентность).

## Когда применять

1. Cursor воркера уже прошёл мимо событий (нет возможности переобработать)
2. Новая downstream-функция нужна только для subset пользователей (не для всего потока)
3. Replay нарушил бы идемпотентность других проекций, работающих с тем же потоком

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Хирургичность вставки (только subset пользователей, Инвариант) ↔ скорость покрытия всех пострадавших | Ограничение вставки строго нужным подмножеством предотвращает нагрузку full-replay, но требует точно вычислить, кто именно «прошёл мимо курсора» — если subset определён неточно, часть пользователей останется необработанной и потребует повторного точечного бэкфилла |
| Идемпотентность через `ON CONFLICT DO NOTHING` ↔ гибкость повторной обработки при исправлении данных | Жёсткий idempotency guard защищает от дублирования при повторном запуске, но также блокирует намеренное повторное обновление той же строки, если `context` в очереди нужно изменить после первой вставки — `DO NOTHING` молча игнорирует апдейт вместо сигнала о конфликте |

## Механизм

Вместо cursor reset или replay — хирургическая вставка N строк в специализированную очередь обработки:

```sql
-- Пример: вставка задач для 5 wave-1 пилотов в guide_render_queue
INSERT INTO guide_render_queue (queue_id, user_id, context, created_at)
VALUES
  (4, '<uuid-1>', '{"trigger": "backfill", "source": "wave1"}', NOW()),
  (5, '<uuid-2>', '{"trigger": "backfill", "source": "wave1"}', NOW()),
  ...
ON CONFLICT (user_id) DO NOTHING;  -- идемпотентность
```

Воркер обрабатывает строки очереди как обычные задачи — изменения в коде не требуется.

## Инварианты

- **Идемпотентность:** ON CONFLICT DO NOTHING или UPSERT — повторный запуск не дублирует задачи
- **Хирургичность:** вставляются только строки для нужного subset, не перезаписывается cursor
- **Совместимость:** воркер-код не меняется — только данные в очереди

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Внимание на SQL, не на предпосылке | При составлении точечного INSERT внимание сосредотачивается на корректности запроса (правильные user_id, ON CONFLICT) и не доходит до повторной проверки условия «курсор уже прошёл мимо» непосредственно перед вставкой — применимость метода (п.1) проверяется один раз в начале рассуждения, а не в момент фактического запуска |
| Недооценка содержательности `context` | Внимание сосредотачивается на корректности `user_id`/`queue_id` и недооценивает содержательность поля `context` — пример из карточки копируется дословно (`{"trigger": "backfill", "source": "wave1"}`), не адаптируя trigger/source к фактической причине конкретного бэкфилла, что обедняет аудиторский след очереди |

## Failure modes

- Вставка строк без idempotency guard → дублирование обработки
- Вставка для ALL users вместо subset → нарушение "хирургичности", нагрузка как при full replay
- Использование при отсутствии специализированной очереди → cursor reset как fallback (см. DP.M.028)
