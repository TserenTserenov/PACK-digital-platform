# DP.METHOD.222 — execution_mode: constraint-satisfaction

## Суть метода

Выполнение протокола (например, Open/Close ОРЗ-фрактала) моделируется не как последовательность обязательных шагов в фиксированном порядке, а как набор ограничений (constraints), которые должны быть удовлетворены к моменту завершения. Каждый шаг размечается как `[[gate]]` (предусловие — блокирует продолжение, пока не выполнено) или `[[narrative]]` (демонстрационный порядок внимания — пропустим без вреда). Вход «с середины» (не с первого шага) допустим, если все гейты в итоге соблюдены — порядок их удовлетворения не имеет значения.

## Обоснование

Линейная скриптовая модель протокола вынуждает искусственно проходить шаги по порядку даже там, где реальный рабочий процесс начинается «с середины» (например, продолжение прерванной сессии). Разделение на gate/narrative формализует то, что реально обязательно (constraint), отделяя это от порядка изложения, полезного только для человека, читающего протокол первый раз. Легализует mid-entry ≤15 мин без штрафа.

## Применение

Дизайн любого многошагового протокола (Open/Close, ритуалы согласования), где часть шагов действительно обязательна, а часть — просто удобный порядок повествования.
