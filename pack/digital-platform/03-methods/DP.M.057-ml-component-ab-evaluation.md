# DP.M.057 — A/B-оценка альтернативного ML-компонента

## Описание

Метод замены встраивающей или retrieval-модели (embedding, reranker, BM25) на основе двухшагового критерия: feasibility (cost/leak) → quality gate (recall@N). Применим к любой паре компонентов с одинаковым интерфейсом.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Строгость Entry criterion (Этап 1: нулевой leak И нулевой cost) ↔ размер пула кандидатов, доходящих до quality gate | Оба feasibility-условия должны быть истинны одновременно — это отсекает кандидатов с ненулевой, но приемлемой стоимостью ещё до того, как их качество вообще измерено (Этап 2), экономя цикл прогона на заведомо неподходящих вариантах ценой потери потенциально хороших |
| Минимальный размер корпуса (Входы: «минимум 50 пар») ↔ статистическая надёжность решения | Порог в 50 запросов дёшево прогнать за один проход Этапа 2, но при граничном результате (±0.01, таблица «Критерий принятия решения») метод сам требует расширения корпуса до 200+ — минимальный порог экономит время, но покупает эту экономию ценой ненадёжного решения именно в спорных случаях |
| Допуск -0.05 в критерии приёмки (`recall@5(challenger) ≥ baseline - 0.05`) ↔ требование нулевой стоимости на входе (Этап 1) | Метод разрешает challenger'у быть немного хуже baseline по качеству, если он бесплатнее/быстрее — Этап 1 уже отфильтровал кандидатов по cost, поэтому допуск -0.05 на Этапе 2 фактически монетизирует экономию, обменивая измеримую долю recall на стоимость |

## Входы

- Текущий компонент (baseline)
- Кандидат-компонент (challenger)
- Реальный корпус prod-запросов (минимум 50 пар)

## Выходы

- A/B evaluation report: recall@5 baseline vs challenger с парными примерами
- Решение: принять / отклонить / defer (при сомнительных результатах)

## Алгоритм

### Этап 1 — Entry criterion (feasibility)

Проверить оба условия. Оба должны быть истина для перехода к Этапу 2:

1. **Нулевой data leak**: challenger не обучен на данных из prod-корпуса (или open-weights без fine-tuning)
2. **Нулевой cost**: challenger бесплатен или дешевле baseline

Если хотя бы одно ложно → не рассматривать, закрыть как infeasible.

### Этап 2 — Quality gate

1. Выбрать ≥50 реальных prod-запросов (случайная выборка)
2. Прогнать оба компонента на одном корпусе документов
3. Вычислить recall@5 для baseline и challenger
4. **Критерий приёмки:** `recall@5(challenger) ≥ recall@5(baseline) - 0.05`
   - Не требуется улучшение, достаточно «не хуже -5%»
5. Для каждого запроса с расхождением подготовить парный пример (baseline top-5 vs challenger top-5)

### Этап 3 — Отчёт

A/B evaluation report содержит:
- Сводная таблица: recall@5 baseline / challenger / delta
- Парные примеры расхождений (≥10 штук)
- Решение и обоснование

## Критерий принятия решения

| Результат | Решение |
|-----------|---------|
| recall@5 ≥ baseline - 0.05 | Принять challenger |
| recall@5 < baseline - 0.05 | Отклонить |
| Граничное значение (±0.01) | Defer: расширить корпус до 200+ запросов |

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Количественный порог как самоцель | После прохождения Этапа 1 внимание смещается на числовой порог «≥50 запросов» (Входы) как формальную галочку, а не на репрезентативность выборки — метод требует «случайную выборку», но не проверяет расслоение по типам запросов, и практикующий не доходит до этой проверки, раз минимум по количеству уже набран |
| Тяга к «принять» при граничном результате | На пограничном значении (±0.01) внимание тянется к решению «принять challenger», потому что defer предписывает дополнительную работу (расширение корпуса до 200+) — предписанный протоколом путь наименьшего сопротивления не совпадает с путём метода, и решение округляется в пользу более лёгкого варианта |

## Контекст применения

WP-323 (Granite Embedding R2 vs текущий, 2026-05-17). Паттерн выявлен как недостающий: без формального entry criterion команды принимают компоненты без проверки feasibility, а без quality gate — без метрики сравнения.
