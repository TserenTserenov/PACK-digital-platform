# Living Pack-to-Guides Pipeline (DP.M.115)

## 1. Контекст

Традиционный документооборот: авторы вручную создают и обновляют гайды. Если меняется Pack (source of truth), гайды устаревают. Порядок изучения фиксируется оглавлением, не путём пользователя.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Единственный источник истины ↔ многообразие аудиторий | Pack один, а тематических поверхностей N (G1–G4 плюс персонализация по ступени, bottleneck и домену) — конвейер «триггер → валидация → оценка → сборка» удерживает синхронность всех руководств с Pack, а bounded context не даёт guide'ам знать про cp-слоты друг друга |
| Автоматизация сборки ↔ ручная гибкость правок | Ручное редактирование гайда даёт быстрый локальный результат, но объявлено anti-pattern: drift неизбежен — метод жертвует этой гибкостью ради гарантии, что любое изменение в Pack доезжает до всех N поверхностей через CI, а не по памяти авторов |

## 2. Метод

**Принцип:** Pack = single source of truth для N тематических поверхностей (руководств). Конвейер похож на CI/CD для кода.

**Этапы конвейера:**
1. **Триггер:** изменение секции в Pack (коммит в Pack-репо)
2. **Валидация структуры:** автоматическая проверка схемы (frontmatter, cp-индикаторы, bounds)
3. **Оценка качества:** проверка связности, полноты, bounded-context соответствия
4. **Сборка:** формирование (или обновление) тематического руководства по шаблону
5. **Персонализация (опционально):** выбор разделов по ступени + bottleneck + домен

**4 руководства (пример экземпляра):**
- G1: Мировоззрение (cp.wld-ориентированные разделы)
- G2: Практики (cp.rhy/cp.skl)
- G3: ИИ-среда (cp.iwe)
- G4: Системное мышление (cp.int/cp.agt)

**Персонализация:** порядок изучения ≠ порядок глав в книге. Определяется вектором S1→S5 от текущей ступени к целевой.

## 3. Инвариант

- Руководства не являются источниками истины — только Pack
- Изменение руководства вручную = anti-pattern (drift неизбежен)
- Bounded context: каждый guide «не знает» про cp-слоты других guides

## 4. Применимость

Любая knowledge-intensive платформа с несколькими аудиториями:
- Единый Pack → N тематических поверхностей → одна персонализированная под конкретного читателя

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Работающий конвейер затмевает инвариант единого источника | Практик сосредотачивается на этапах (триггер, валидация, сборка) и перестаёт замечать ручные правки в самих руководствах — drift возникает не от сбоя CI, а от тихого обхода его, и зелёный pipeline этот обход не показывает |
| Персонализация воспринимается как главная ценность | Внимание тянется к слою выбора разделов по ступени, bottleneck и домену, хотя он объявлен опциональным, — и база метода (Pack как единственный SoT с валидацией структуры и оценкой качества) недополучает усилий при запуске |
