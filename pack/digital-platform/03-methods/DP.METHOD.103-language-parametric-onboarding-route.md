# DP.METHOD.103 — Language-parametric onboarding route

## Описание

При добавлении нового языка в продукт — не создавать отдельный онбордер-артефакт на каждый язык. Вместо этого: один backend, язык = параметр маршрута. Результат: матрица **интерфейс × язык** как единый артефакт принятия решений.

## IPO

**Input:** запрос на поддержку нового языка / интерфейса в продукте

**Process:**
1. Составить матрицу интерфейс × язык (пример: Claude Code×RU, Claude Code×EN, Web×EN, Telegram×RU)
2. Для каждой ячейки определить статус (основной / первая заливка / будущий / не планируется)
3. Реализовать единый backend с language-параметром; frontend-маршруты ссылаются на ячейки матрицы
4. Приёмка нового языка = отдельный smoke по ячейке (не отдельный онбордер-тест)

**Output:** матрица интерфейс × язык (артефакт принятия решений) + реализация с единым backend

## Условия применения

- Продукт имеет >1 целевой язык или планирует расширение
- Backend не зависит от языка (бизнес-логика языко-нейтральна)

## Антипаттерн

Дублирование онбордера под каждый язык (отдельный файл, отдельный маршрут, отдельные тесты) → рост maintenance при каждом добавлении ячейки матрицы.

## Источник

WP-456 Ф1 (продукт-определение EN-онбордера). Ключевое решение: вместо EN-онбордера как отдельного артефакта — language-parametric route через тот же backend.
