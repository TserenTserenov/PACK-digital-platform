# DP.M.325 — Радар: поиск аналогов перед строительством нового компонента

## Описание

**Радар** — метод активного поиска существующих аналогичных решений перед проектированием нового компонента. Применяется на старте любого нового инструмента, агента или метода: «знаем ли мы уже более общий паттерн, покрывающий этот случай?»

Функция: anti-premature-crystallization. Прежде чем зафиксировать новый паттерн — проверить, не изобретаем ли велосипед.

## IPO

| Вход | Обработка | Выход |
|------|-----------|-------|
| Описание задачи нового компонента | Структурированный поиск: (1) аналоги в IWE/Pack (DP.M.*, DP.SOTA.*); (2) внешние решения («что делают другие с той же задачей?»); (3) оценка применимости | Решение: адаптировать готовое / строить новое |

## Критерий применения

Метод обязателен при:
- Добавлении нового рефлекса в каталог (WP-436 Ф2-Ф4)
- Проектировании нового агента / инструмента (IntegrationGate)
- Первом упоминании архитектурного паттерна в команде

Не применяется к: правкам существующих компонентов, bugfix без изменения поведения.

## Признак провала метода

Команда строит компонент → через N недель обнаруживает точный аналог в OSS/Pack. Симптом: «это уже есть, просто под другим именем».
