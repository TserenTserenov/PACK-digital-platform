# DP.M.217: Glue требует исполнителя — расщепление pipeline-фазы на новый артефакт + расширение существующего skill

## Анти-паттерн

При проектировании «как добавить новый периодический процесс между существующими skills» формулировать его как «glue layer / pipeline-фаза / связующее звено» без выделения исполнителя. Результат — фантомный артефакт (есть в плане, нет в коде), процесс не запускается, через 2 недели — «забыли».

## Корректный паттерн

«Glue требует исполнителя» — два явных артефакта:

1. **Новый исполнитель** (script / scheduled-job) с собственным контрактом и ответственной ролью. Минимум: один script + один config.
2. **Расширение существующего skill** на N строк (5-20), которое читает результат исполнителя как обогащённый input.

Не один комбинированный артефакт (смесь осей «когда» и «кто»).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Разложение ответственности (явный исполнитель) ↔ простота плана | Glue-задача выглядит как одна строчка в плане, но без именованного исполнителя она не запускается — метод платит дополнительным артефактом за реальность выполнения |
| Повторное использование существующего skill ↔ чистота нового артефакта | Добавление 5-20 строк в знакомый skill дешевле и снижает фрагментацию, но смешивает оси «когда» и «кто», делая скрытую зависимость |
| Видимость в плане ↔ реальность запуска | Фантомный артефакт есть в плане, но не в коде; метод заставляет платить либо удалением, либо материализацией, не оставляя промежуточного состояния |

## Тест границы

«Если убрать исполнителя, нарушится ли периодичность?»
«Если убрать расширение skill, нарушится ли потребление?»

Оба «да» → корректное расщепление. Один «нет» → нужен либо отдельный исполнитель, либо отдельное расширение.

## Прецедент

WP-364 Ф2.2 Loop C: исходно одна задача «glue weekly-digest». После применения принципа распалась на:
- C.1 — digest-сборщик (новый скрипт, носитель Аналитик, расписание).
- C.2 — +1 строка в существующем skill стратегирования (consumer).

## Применимо

- weekly-digest / daily-report между знающими skills
- pre-commit-pipeline integration
- CI/CD integration новой проверки в существующий pipeline
- любая «новая регулярность» между существующими workflow

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Слово «glue» звучит как решение, а не как проблема | Практикующий записывает «сделать glue layer» и считает задачу спроектированной, не задаваясь вопросом «кто исполняет» — ответственность остаётся размытой |
| Склонность к минимизации новых артефактов | Расширение существующего skill кажется более «легковесным», поэтому новый периодический процесс протаскивается как +N строк, хотя по оси «когда» это отдельный исполнитель |
| Забывание о триггере/расписании | Внимание концентрируется на обработке данных и потребителе, а периодичность остаётся неявной — через 2 недели выясняется, что процесс никто не запускал |
