# DP.METHOD.060 — Skill promotion: L2 (авторское) → L1 (платформенное)

## Назначение

Процедура переноса скилла из авторского IWE (L2, `/Users/tserentserenov/IWE/.claude/skills/<skill-name>/`) в шаблон платформы (L1, `FMT-exocortex-template/.claude/skills/<skill-name>/`). Делает скилл доступным для всех новых пользователей IWE через `update.sh`.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Полнота обобщения (шаг 1: удалить авторские константы) ↔ скорость промоции | Поиск и замена личных путей/repo-имён/email на плейсхолдеры (`{{IWE_ROOT}}`, `{{HOME_DIR}}`, `{{IWE_GOVERNANCE_REPO}}`, `{{AUTHOR_EMAIL}}`) требует построчного прохода по SKILL.md, что медленнее прямого copy-paste, но неполная замена — единственный способ, которым авторская логика просачивается в шаблон для всех пользователей |
| Машинная проверка (шаг 2 `validate-fmt-scripts.sh`, шаг 4 `diff`) ↔ доверие к ручному чеклисту | Метод не полагается на то, что автор аккуратно прошёл шаги 1 и 3 — обязывает прогнать валидатор синтаксиса и сравнить diff между L2 и L1 копиями, дублируя проверку машиной поверх человеческого чеклиста ценой двух дополнительных шагов перед коммитом |

## Чеклист промоции

1. **Удалить авторские константы** из SKILL.md:
   - Личные пути (`~/IWE/`, `tserentserenov`) → `{{IWE_ROOT}}`, `{{HOME_DIR}}`
   - Репо-имена → `{{IWE_GOVERNANCE_REPO}}`
   - Личные email/id → убрать или `{{AUTHOR_EMAIL}}`

2. **Прогнать валидатор синтаксиса:**
   ```bash
   bash $IWE_SCRIPTS/validate-fmt-scripts.sh $IWE_SCRIPTS/
   ```

3. **Запустить skill-promote:**
   ```bash
   bash $IWE_SCRIPTS/skill-promote.sh <skill-name>/ [--dry-run]
   ```

4. **Проверить copy в FMT:**
   ```bash
   diff ~/IWE/.claude/skills/<skill-name>/SKILL.md \
        ~/IWE/FMT-exocortex-template/.claude/skills/<skill-name>/SKILL.md
   ```

5. **Коммит в FMT:**
   ```bash
   cd ~/IWE/FMT-exocortex-template && git add .claude/skills/<skill-name>/ && \
   git commit -m "feat: promote skill <name> from L2 to L1"
   ```

## Тест применимости

«Скилл запускается у нового пользователя после `update.sh` без дополнительных настроек?» Да → промоция выполнена корректно.

## Когда НЕ применять

Скилл содержит авторскую логику (личные репо, личные workflow), которую нельзя обобщить → оставить в L2, не промотировать.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего. Статус карточки — `draft`: пометка `tentative`._

| Bias | Direction of distortion |
|------|--------------------------|
| _(tentative)_ Фокус на explicit-примерах вместо исчерпывающего поиска | На шаге 1 чеклиста внимание практикующего фокусируется на explicit-примерах из инструкции (`~/IWE/`, `tserentserenov`, репо-имена, email) и не доходит до менее очевидных форм авторской привязки — захардкоженных чисел/порогов, ссылок на другие L2-скиллы, упоминаний инструментов, доступных только в авторской среде — потому что чеклист называет категории, а не даёт исчерпывающий grep-паттерн |
| _(tentative)_ Diff подменяет собой тест применимости | После успешного шага 4 (diff между L2 и L1 копиями пуст или ожидаем) внимание переключается на коммит (шаг 5), считая промоцию технически завершённой — но diff проверяет только идентичность файлов, а не то, что промотированный скилл реально работает у пользователя без доступа к личным путям/секретам автора; «Тест применимости» по факту не прогоняется, потому что кажется покрытым предыдущим шагом |
