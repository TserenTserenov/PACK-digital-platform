# DP.METHOD.120: Multi-session reconcile gate

## Описание

Когда за один день ожидается N>2 параллельных сессий на одном артефакте (WP-context, спецификация, FSM), в план дня закладывается явный reconcile-ход как завершающая сессия: один агент берёт все N версий и сводит к единственной.

## IPO

- **Input:** N session reports или context-файлы, изменённые за один день на одном артефакте
- **Process:** один агент читает все N, выявляет расхождения, применяет логику слияния (приоритет по явным аргументам, а не хронологии)
- **Output:** единственный согласованный артефакт + reconcile-запись в session-файле дня

## Когда применять

- N>2 сессий за день на одном `inbox/WP-NNN/WP-NNN.md` или смежном артефакте
- Сессии ведут разные агенты (Claude / Kimi) независимо
- Sync Gate не видит session-файлы текущего дня (только контекст-файл РП)

## Чего не делать

- Не считать последнюю сессию «правильной» только по времени — хронология не = приоритет
- Не откладывать reconcile: неслитые версии на следующий день создают каскад расхождений

## Пример

WP-457 Ф10: сессии -02, -07, -09 дали три разных ответа по RLS-условиям за 05.07. Сессия -16 (reconcile) свела к единственной версии.

## Связи

- DP.ARCH.008 (Enforcement требует наблюдателя вне субъекта) — общий принцип: reconcile = внешний наблюдатель для параллельных агентов
