# DP.M.348 — Content-first audit phase ordering

## Описание

При многопроходном аудите документа порядок фаз должен идти от нестабильного (содержание) к стабильному (формат), чтобы работа более ранних фаз не выбрасывалась при изменении более поздних.

## Принцип

**Наивный порядок (анти-паттерн):** A (формат) → B (стиль) → C (содержание)

Проблема: если в фазе C текст переписывается, работа A и B теряется → Inventory, не Progress.

**Content-first порядок (правильно):**

| Фаза | Работа | Стоимость | Стабилизирует |
|------|--------|-----------|---------------|
| Pre-flight | Regex-расчистка, механические замены | Низкая (~30 мин, скрипт) | Читабельность для аудита |
| C — Содержание | Логика, Pack-ссылки, примеры | Высокая, нестабильная | Смысловой скелет |
| B — Стиль | Тон, язык, правила стиля | Средняя | Поверхность |
| A — Формат | Заголовки, отступы, markdown | Низкая | Вёрстка |
| D — Сверка | Diff с эталоном/чеклистом | Низкая | Соответствие |

## Применение

При любом многопроходном аудите документов:
1. Идентифицировать фазы по стабильности их output
2. Расставить в порядке возрастания стабильности (нестабильное — первым)
3. Pre-flight = единственное исключение: делается до содержания, потому что дёшево и убирает шум для остальных фаз

## Диагностика нарушения

«Я переделал стиль, но потом переписал текст» — Inventory. Ход работы нарушает content-first.
