# DP.M.348 — Content-first audit phase ordering

## Описание

При многопроходном аудите документа порядок фаз должен идти от нестабильного (содержание) к стабильному (формат), чтобы работа более ранних фаз не выбрасывалась при изменении более поздних.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Интуитивный порядок ↔ порядок по стабильности | Естественно начать с формата (видно сразу, легко проверить), но содержание чаще всего меняется позже всех и перезаписывает уже сделанную работу над формой |
| Скорость первой фазы ↔ выживаемость последующих | Формат/стиль быстрее исправить, но если начать с них — их результат чаще всего теряется при последующей правке содержания |
| Один проход ↔ многопроходность | Слияние всех правок в один проход экономит переключения контекста, но не даёт зафиксировать смысловой скелет до косметики |
| Экономия на pre-flight ↔ читаемость для C-фазы | Пропуск дешёвой regex-расчистки экономит минуты, но добавляет шум, который замедляет самую дорогую фазу (содержание) |

## Принцип

**Наивный порядок (анти-паттерн):** A (формат) → B (стиль) → C (содержание)

Проблема: если в фазе C текст переписывается, работа A и B теряется → Inventory, не Progress.

**Content-first порядок (правильно):**

| Фаза | Работа | Стоимость | Стабилизирует |
|------|--------|-----------|---------------|
| Pre-flight | Regex-расчистка, механические замены | Низкая (~30 мин, скрипт) | Читабельность для аудита |
| C — Содержание | Логика, Pack-ссылки, примеры | Высокая, нестабильная | Смысловой скелет |
| B — Стиль | Тон, язык, правила стиля | Средняя | Поверхность |
| A — Формат | Заголовки, отступы, markdown | Низкая | Вёрстка |
| D — Сверка | Diff с эталоном/чеклистом | Низкая | Соответствие |

## Применение

При любом многопроходном аудите документов:
1. Идентифицировать фазы по стабильности их output
2. Расставить в порядке возрастания стабильности (нестабильное — первым)
3. Pre-flight = единственное исключение: делается до содержания, потому что дёшево и убирает шум для остальных фаз

## Диагностика нарушения

«Я переделал стиль, но потом переписал текст» — Inventory. Ход работы нарушает content-first.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Начну с того, что вижу первым — с оформления» | Внимание тянется к визуально заметному (заголовки, отступы) раньше смыслового ядра, потому что формат легче оценить на глаз |
| «Уже причесал стиль — жалко переписывать» | Sunk cost на промежуточную фазу создаёт сопротивление изменению содержания, которое эту фазу обесценивает |
| «Pre-flight — это тоже часть содержания, можно совместить» | Механическая расчистка смешивается со смысловой правкой, дешёвый шаг перестаёт быть дешёвым фильтром для дорогого |
| «Аудит почти закончен, формат — последний штрих» | Ощущение близости к завершению после формата маскирует то, что содержание ещё не зафиксировано и может обрушить всю проделанную работу |
