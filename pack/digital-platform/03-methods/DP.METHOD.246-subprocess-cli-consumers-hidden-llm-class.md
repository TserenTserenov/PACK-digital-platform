# DP.METHOD.246 — subprocess/CLI как скрытый класс LLM-consumers

## Суть метода

Аудит потребителей LLM-провайдера перед миграцией на другого провайдера включает не только прямые вызовы SDK в коде, но и вызовы через `subprocess`/`exec` внешних CLI-инструментов, которые сами внутри себя обращаются к LLM (например, сторонние CLI-агенты, вызываемые как чёрный ящик). Такие потребители невидимы для грепа по SDK-импортам.

## Обоснование

SDK-аудит ищет прямые вызовы известного API — subprocess-вызов внешнего бинарника выглядит как обычный вызов процесса, не как LLM-потребитель, хотя внутри этого процесса может скрываться зависимость от конкретного провайдера/прокси.

## Применение

Планирование миграции LLM-провайдера или изменения маршрутизации LLM-трафика (например, обязательный переход через прокси) — аудит потребителей должен включать subprocess/CLI-вызовы, не только прямые SDK-импорты.
