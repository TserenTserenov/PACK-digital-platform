# [DP.M.038] Идемпотентное распределение скиллов при рендере

## Суть метода

При каждом рендере персонального руководства (personal-guide-render) агент идемпотентно копирует набор скиллов в `.claude/skills/` репо пилота.

**Идемпотентность:** копирование выполняется только если:
1. Файл скилла отсутствует в целевом репо, или
2. Checksum изменился относительно эталона в шаблоне

## Цель

Скиллы становятся доступны в browser-канале (`claude.ai/code`) без необходимости VS Code. Решает проблему **channel-parity**: пилот в браузере получает тот же набор инструментов, что в VS Code.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость идемпотентного рендера (0 файлов скопировано при отсутствии изменений) ↔ надёжность checksum как единственного признака изменения | Идемпотентность экономит время на каждом повторном render'е, но целиком опирается на то, что checksum-сравнение (Алгоритм п.1a-c) не пропустит реальные изменения |
| Channel-parity — единый набор скиллов во всех каналах ↔ конфигурируемость списка дистрибуции по репо (Инварианты: «не захардкожен») | Гарантия «пилот в браузере получает тот же набор инструментов» держится только пока конфигурация списка не разошлась между пилотами/репо |

## Алгоритм (Шаг 6.7 personal-guide-render)

1. Для каждого из N скиллов в списке дистрибуции:
   a. Вычислить checksum эталонного файла из шаблона
   b. Проверить наличие файла в `.claude/skills/` репо пилота
   c. Если отсутствует или checksum отличается → скопировать
   d. Если совпадает → пропустить (idempotent)
2. Закоммитить изменения с сообщением типа `chore: refresh skills (N updated)`

## Инварианты

- Повторный вызов без изменений = 0 файлов скопировано (истинная идемпотентность)
- Список скиллов для дистрибуции определён в конфигурации рендера, не захардкожен
- Шаг 6.7 выполняется перед Шагом 6.8 (reflection-template) в рамках render

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Доверие к checksum как единственному сигналу | Внимание смещается на «checksum совпал → всё ок», недооценивая случай, когда файл в `.claude/skills/` репо пилота был вручную отредактирован самим пилотом — checksum-логика (Алгоритм п.1a-c) не различает «эталон не менялся» и «локальная копия дрейфовала» |
| Недооценка порядка Шаг 6.7 / Шаг 6.8 | При рефакторинге render-pipeline внимание съезжает на содержание самого копирования (Алгоритм), недооценивая инвариант порядка «Шаг 6.7 перед Шагом 6.8 (reflection-template)» — порядок легко случайно переставить, не заметив нарушения |

## Применимость

Паттерн применим к любому multi-channel агентному продукту с независимыми runtime-окружениями, где нужно доставить runtime-артефакты (скиллы, шаблоны) в несколько каналов.
