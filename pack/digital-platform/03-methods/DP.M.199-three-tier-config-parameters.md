# DP.M.199 — Три уровня параметров конфигурируемой системы

## Описание

Метод организации параметров сложной конфигурируемой системы в три bucket'а по частоте изменения и владельцу, вместо единого плоского config-файла.

## Три уровня

| Уровень | Примеры | Частота изменения | Владелец |
|---------|---------|-------------------|---------|
| **Ручки калибровки** (~7-8) | Курс бонусов, бюджеты, множители | Ежемесячно | Бизнес / Ops |
| **Справочники** (онтологические) | Шкала квалификации, каталог событий, группы деятельности | При изменении домена | Методолог |
| **Алгоритмические константы** | Показатель степени усилия, память сглаживания, границы редкости | При редизайне алгоритма | Инженер |

## Проблема, которую решает

Единый flat config с 25+ параметрами без классификации:
- любое изменение требует экспертизы всей математики
- бизнес-аналитик не знает, что безопасно трогать
- инженер не знает, что является доменным, а что математическим

## Ключевые свойства

- **Разные owners:** ручки = бизнес без инженера; справочники = методолог без программиста; константы = только при редизайне алгоритма
- **Разные частоты:** ручки меняются ежемесячно, справочники — при эволюции домена, константы — редко
- **Эффект разделения:** «один UPDATE ручки → пересчёт всего без рестарта»; bucket'ы не конкурируют в документации и в коде

## Применимость

- Pricing-модели и гейтинг подписок
- ML feature engineering (hyperparameters vs schema vs constants)
- Gamification-системы (points, multipliers, streaks)
- Тарифные конструкторы

## Антипаттерн

Один flat config с 25 параметрами без классификации — любое изменение требует экспертизы всей математики.
