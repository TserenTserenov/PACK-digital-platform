# DP.M.435 — Тест проводки: проверка факта и места вызова, отдельно от теста извлечённой функции

## Определение

Для критичного вызова, чья корректность зависит не только от логики функции, но и от того, что она действительно вызывается в нужном месте под нужным условием — юнит-теста извлечённой функции недостаточно. Нужен отдельный тест «проводки» (wiring test): читает исходник call site статически и проверяет факт вызова (сколько раз, где) и текст условия непосредственно перед ним.

## Проблема

Юнит-тест, проверяющий поведение функции в изоляции, остаётся зелёным, даже если реальный вызов этой функции на call site удалён, переименован или обёрнут в другое условие — риск «функцию отвязали от места вызова» тестом функции не покрывается (конкретный пример такой отвязки — `DP.FM.420`).

## IPO-паттерн

| Элемент | Описание |
|---------|----------|
| Входы | Исходный файл с предполагаемым call site; имя вызываемой функции; ожидаемое условие/guard перед вызовом |
| Обработка | Статический разбор исходника (grep/AST) — найти вызов функции, посчитать количество вхождений, извлечь условие непосредственно перед вызовом |
| Выходы | PASS, если вызов найден ровно в ожидаемом количестве и под ожидаемым условием; FAIL с указанием расхождения — иначе |

## Шаги метода

1. Определить критичный call site (обычно — обязательный побочный эффект/cleanup, для которого уже есть юнит-тест самой функции).
2. Написать отдельный тест, статически читающий исходник (не исполняющий код), утверждающий факт и условие вызова.
3. Запускать оба теста вместе: юнит-тест функции покрывает логику, тест проводки покрывает интеграцию функции с местом вызова.

## Отличие от юнит-теста

Юнит-тест доказывает «функция делает что нужно, если её вызвать». Тест проводки доказывает «функцию действительно вызывают, там где нужно, при нужном условии». Оба необходимы для критичного побочного эффекта; ни один не заменяет другой.

## Применимо к

Любой критичный побочный эффект (cleanup, обязательство, audit-запись), извлечённый в отдельную функцию — риск «отвязки от call site» существует для каждого такого случая, не только для session-guard.
