# DP.M.410 — Pull-only паттерн при разделении GitHub-организации

## Суть метода

При разделении одной GitHub-организации на несколько — новая организация самостоятельно **забирает** (pull) репозитории из старой, вместо того чтобы старая организация **отправляла** (push) их в новую. Вариант A (pull-only): новая org тянет к себе, старая org никому в новой org не выдаёт write-доступ.

## Проблема

Прямой подход (push из старой org в новую) требует выдачи write-доступа к новой организации кому-то из старой — расширение поверхности доступа именно в момент разделения, когда контроль доступа особенно важен.

## Алгоритм

1. Новая организация создаётся с собственным набором прав доступа
2. Администратор новой org использует read-доступ к старой (или публичный клон) для переноса репозиториев к себе
3. Write-доступ к новой org никому из старой org не требуется — перенос односторонний, инициируется получателем

## Тест

«Кто инициирует перенос — старая организация (push) или новая (pull)?» Pull — безопаснее, не требует расширения прав доступа.

## Связи

- Применимо к любому разделению доступов между GitHub-организациями (WP-401)
