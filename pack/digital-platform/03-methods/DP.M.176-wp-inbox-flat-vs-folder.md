# DP.M.176 — WP Inbox: Flat vs Folder (правило структурирования)

## Проблема

Двойная структура (плоские файлы + папки для одного РП) порождает navigation debt и ломает скрипты sweep/status.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Минимализм для малых РП (плоский файл без инфраструктуры) ↔ масштабируемость для крупных (папка с index.md) | Порог «<5 файлов → flat, ≥5 → папка» удерживает оба режима одним правилом: малый РП не платит за index.md и вложенность, крупный не расползается по корню inbox — но критерий прогнозируемый (при создании), и ошибка прогноза требует миграции за один коммит |
| Единообразие для скриптов (sweep читает index.md как точку входа) ↔ свобода автора РП организовать материалы под задачу | Запрет двойной структуры и требование хранить артефакты рядом с РП ограничивают автора, но убирают navigation debt: sweep/status и `bottleneck-pick --target` работают без per-РП адаптации — дисциплина структуры оплачивает автоматизацию |

## Правило

| Условие | Структура |
|---------|-----------|
| РП < 5 файлов | Плоский файл `WP-NNN-slug.md` в корне inbox |
| РП ≥ 5 файлов или наличие поддокументов | Папка `WP-NNN/` с обязательным `index.md` |

`index.md` должен содержать: frontmatter (id, status, budget) + ссылки на все вложенные файлы.

## Дополнительные правила

- Артефакты, принадлежащие РП, хранятся рядом с РП (в папке), не в корне inbox
- Скрипты sweep читают `index.md` как точку входа; flat-файлы — напрямую
- `bottleneck-pick --target WP-NNN` → пишет в `WP-NNN/bottleneck-picks/YYYY-MM-DD.yaml`
- Критерий перехода к папке — **прогнозируемый** размер при создании, не ретроактивный

## Применение

При создании нового РП — выбрать структуру исходя из прогнозируемого числа файлов.
При миграции legacy: унифицировать за один коммит (`git mv` + commit).

Stage A check: зонтичные РП (WP-250, WP-290, WP-330, WP-337, WP-353) → проверить на status=done/deferred перед нормализацией.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Текущее число файлов затмевает прогнозируемое | При создании РП практик считает то, что есть сейчас (1–2 файла → flat), хотя критерий — прогнозируемый размер; через неделю РП расползается по корню, а ретроактивная миграция откладывается, потому что «уже работает» |
| Удобство для человека затмевает контракт со скриптами | Раскладка inbox оценивается «на глаз» (читабельно ли для автора), а потребитель-скрипт — sweep читает `index.md` как точку входа, `bottleneck-pick` пишет в `WP-NNN/bottleneck-picks/` — вспоминается только когда ломается; артефакты в корне человеку почти не мешают и потому живут дольше всех |
