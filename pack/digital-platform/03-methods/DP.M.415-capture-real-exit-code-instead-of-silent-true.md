# DP.M.415 — Захват реального кода возврата вместо подавления ошибки на потенциально штатной коллизии

## Проблема

Вызов защитного шага (открытие семафора-хранителя сессии) был обёрнут в подавление любой ошибки. Реальная коллизия семафора (не инфраструктурная ошибка, а штатный кейс «другой прогон ещё держит замок», TTL 30 мин) молча проглатывалась — конвейер продолжал работу и в итоге приписал свои пути к чужому, не связанному семафору вместо явного отказа.

## IPO

- **Вход:** защитный шаг с осмысленным (не только инфраструктурным) failure-путём, обёрнутый в подавление ошибок
- **Процесс:** заменить безусловное подавление ошибки на захват реального кода возврата и текста ошибки; при штатной, но блокирующей коллизии — явно прерваться с понятным сообщением, не проваливаться дальше по конвейеру
- **Выход:** коллизия семафора либо блокирует прогон с понятным сообщением, либо (при отсутствии коллизии) конвейер продолжает как раньше — но никогда не продолжает молча поверх нераспознанной коллизии

## Паттерн

```bash
# Антипаттерн — стирает разницу между «можно проигнорировать» и «нужно остановиться»
session-guard.sh open --housekeeping 2>/dev/null || true

# Паттерн — реальный код и текст ошибки решают дальнейший путь
if ! err=$(session-guard.sh open --housekeeping 2>&1); then
  echo "session-guard collision: $err" >&2
  exit 1
fi
```

## Применимо

Любой защитный шаг конвейера с осмысленным (не чисто инфраструктурным) failure-путём — коллизия семафора, занятый лок, конфликт версий. Безусловное подавление уместно только когда ЛЮБОЙ исход шага безопасно игнорировать; если хотя бы один исход требует остановки — нужен захват реального кода.
