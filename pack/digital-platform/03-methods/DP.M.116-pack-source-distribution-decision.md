# Pack Source Distribution Decision (DP.M.116)

## 1. Контекст

При KE из нового источника (книга, статья, корпус) возникает вопрос: создать новый Pack или распределить знания по существующим?

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Целостность источника ↔ целостность предметных доменов | Вариант A (PACK-boro) сохраняет книгу как единое целое, но плодит по Pack на источник; Вариант B дробит 22 кандидата по предметной принадлежности (PACK-MIM, PACK-DP, PACK-AA), зато M << N и не остаётся orphan-сущностей |
| Скорость решения «новый Pack» ↔ стоимость владения им | Создать новый Pack быстрее, чем раскладывать captures по существующим, но каждый Pack — это lifecycle, governance и CI; порог «≥30% сущностей не вписываются» удерживает от создания Pack «на всякий случай», оставляя Вариант A только для принципиально нового домена |

## 2. Метод

**Вариант A (новый Pack):** создать PACK-{source-name}. Использовать когда:
- Источник покрывает принципиально новый домен без пересечений с существующими
- ≥30% сущностей не вписываются ни в один существующий Pack
- Источник будет единственным SoT для этого домена (активная разработка, CI нужен)

**Вариант B (распределить по существующим):** по предметной принадлежности. Использовать по умолчанию когда:
- Captures укладываются в существующие Pack-домены без orphan-сущностей
- Методы → PACK-MIM или PACK-digital-platform/03-methods/
- Паттерны платформы → PACK-digital-platform
- Различения → 01B-distinctions.md целевого Pack
- Принципы → PACK-agent-rules или FPF

## 3. Пример (WP-345 BORO)

22 кандидата из книги Chris Partridge «Business Object Reference Ontology»:
- Вариант A = PACK-boro (новый)
- Вариант B = 18 unique + 3 fold-ins: PACK-MIM (5M+1S+6D), PACK-DP (2 SOTA), PACK-AA, PACK-personal
- Выбран B: все captures укладываются в существующие домены, нет orphan-сущностей

## 4. Правило

Вариант B снижает фрагментацию Pack-экосистемы: N источников → M Pack (M << N).
Новый Pack = overhead (lifecycle, governance, CI), оправданный только при реальном новом домене.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Границы источника принимаются за границы домена | Внимание привязывается к книге/корпусу как естественной единице («раз из одной книги — значит один Pack») и не доходит до предметной проверки: укладываются ли captures в домены существующих Pack без orphan-сущностей — вопрос, который решил WP-345 в пользу Варианта B |
| Пороговое правило заменяет анализ пересечений | Фокус на критерии «≥30% не вписываются» смещает внимание от содержательной стороны — куда именно могут fold-in конкретные сущности (как 3 из 22 ушли в PACK-MIM/PACK-DP); процент считается механически, и Вариант A выбирается по числу, а не по принципиальной новизне домена |
