# DP.M.456 — Первичный артефакт и сопроводительные производные синхронизировать в одном коммите

## Описание

Когда у первичного артефакта (например, колоды слайдов) есть несколько НЕ автоматически синхронизируемых сопроводительных документов, описывающих его с других сторон (план структуры, тайминг, черновик текста), правка первичного артефакта без этих документов создаёт дрейф. При первом касании артефакта нужно выяснить, какие производные от него зависят, и дальше редактировать их вместе, одним коммитом — не докладывать о дрейфе на каждом отдельном проходе как о чужой задаче.

## IPO

**Вход:** правка первичного артефакта + известный (или ещё не выясненный) список сопроводительных документов.
**Процесс:** (1) при первом касании — выяснить, какие документы зависят от артефакта; (2) на каждой следующей правке — редактировать первичный артефакт и все выявленные производные одним изменением; (3) при несовпадении нумерации/тайминга внутри производных — пересчитать вместе с правкой, не оставлять частичным.
**Выход:** первичный артефакт и сопроводительные документы остаются взаимно согласованными на каждый коммит.

## Пример

Плановый документ (таблица слайдов, тайминг) и черновик кикоффа не совпадали с новой версией колоды слайдов после правки — на первом проходе агент честно доложил дрейф и не тронул сопроводительные документы (Drift Reporting). На следующих проходах принята модель «слайды + структура + черновик = один набор изменений»: все правки пошли одним коммитом с пересчётом нумерации и тайминга (25 слайдов, 95 минут).

## Тест применимости

«У этого артефакта есть документы, которые описывают его же с другой стороны (структура, тайминг, черновик, аннотация), но не связаны со-скриптом автосинхронизации?» Да → при правке первичного проверить и обновить их в том же коммите, не сообщать о дрейфе как о задаче для кого-то другого.

## Отличие от соседних методов

- **DP.M.301** (sync source-of-truth → derived) — односторонний АВТОМАТИЧЕСКИЙ sync между двумя копиями одного содержания через скрипт; derived read-only. Этот метод — РУЧНОЕ совместное редактирование нескольких гетерогенных документов, не являющихся копиями друг друга.
- **DP.METHOD.113** (ACL как companion-артефакт схемы) — частный случай для прав доступа к объектам БД с обязательным code review. Этот метод — общий принцип для сопроводительных документов контента.
- **DP.METHOD.149** (derived artifact reinterprets canon untouched) — обратный случай: производное расходится с каноном → канон осознанно не трогают. Этот метод — про синхронное совместное редактирование, а не про изоляцию расхождения.

## Связи

- DP.M.301, DP.METHOD.113, DP.METHOD.149 — родственные companion-artifact/drift-prevention методы, каждый на своей оси.
- Обобщает описательно упоминаемый в Pack принцип «Source-of-truth ≠ Производный» (без отдельного ID) на случай нескольких гетерогенных сопроводительных документов без автоматического sync-механизма.
