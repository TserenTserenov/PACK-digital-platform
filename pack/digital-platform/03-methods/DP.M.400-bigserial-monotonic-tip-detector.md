# DP.M.400 — BIGSERIAL-монотонность как tip-детектор без графового обхода

## Суть метода

Для поиска «последней версии» записи в цепочке событий (event-chain) с версионированием (v1/v2/pre-chain) можно использовать монотонность автоинкрементного `id` (BIGSERIAL) внутри потока вместо обхода графа связей. Поскольку `id` монотонно растёт внутри одного потока независимо от версии схемы (v1, v2, pre-chain), запись с максимальным `id` в потоке — это «наконечник» (tip) цепочки, без необходимости проходить по цепочке ссылок `parent_id` от начала до конца.

## Проблема

Графовый обход (walk по `parent_id` от корня до листа) для определения tip'а цепочки — операция с ростом стоимости по длине цепочки, требующая рекурсивных запросов или CTE. Для потоков, где версии могли меняться (v1 → v2 → pre-chain), обход дополнительно усложняется поддержкой разных схем связей.

## Алгоритм

1. В пределах одного потока (group by поток-идентификатор) выбрать запись с максимальным `id`
2. Использовать `LATERAL` join для эффективного получения «последней записи на поток» без полного графового обхода
3. `id`-монотонность работает одинаково для записей v1, v2 и pre-chain — не требует отдельной логики на версию схемы

## Тест

«Нужен ли обход графа parent-chain, чтобы найти последнюю версию, или достаточно взять максимальный id в потоке?» Если id монотонен в пределах потока — второе, обход не нужен.

## Связи

- Применимо к любой event-chain структуре с автоинкрементным id и версионированием схемы
