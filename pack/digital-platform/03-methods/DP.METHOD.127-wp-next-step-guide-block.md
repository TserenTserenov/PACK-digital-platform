# DP.METHOD.127 — Следующий шаг по активному РП как операционный блок AI-руководства

## Описание

В AI-генерируемом руководстве заменять иллюстративный блок («пример применения метода») на конкретный следующий шаг из активного рабочего продукта пилота. Руководство переходит из информационного в операционный режим.

## IPO

**Input:** активный РП пилота с полем `next_step` + тема тематической секции руководства

**Process:**
1. Для каждой секции: сопоставить тему секции с активным РП пилота
2. Извлечь `next_step` из релевантного РП
3. Вместо «пример применения X» — «Твой следующий шаг: {next_step} по {WP-NNN}»
4. `daily_guard`: если активных РП нет или `next_step` пуст → секцию не генерировать (пустой блок = шум)

**Output:** секции руководства с заземлёнными action-блоками, привязанными к реальной работе пилота

## Принцип

Каждая секция руководства должна заканчиваться принятием решения или конкретным действием. Описание метода без применения к текущей задаче = inventory, не throughput.

## Пример

WP-149 Ф3: «иллюстрация применения ТВС-матрицы» заменена на «Следующий шаг по WP-462: пройти ArchGate для sync/async решения». Пилот видит конкретное действие, а не абстрактный пример.

## Тест применимости

«Закончив читать эту секцию, пилот знает, что конкретно сделать сегодня?» Нет → применить метод.

## Guard

Нет активных РП с `next_step` → блок пропускается. Нет guard → пустой раздел «нет задач» попадает в руководство.
