# DP.METHOD.181 — Трёхуровневый вердикт проверки согласованности знаний

## Определение

При проверке согласованности записей базы знаний бинарный ответ «противоречие есть/нет»
недостаточен — нужны три состояния вердикта, отражающие судьбу эталона.

## IPO

- **Вход:** запись базы знаний + её эталон (другая запись или внешний источник)
- **Процесс:** проверка согласованности с определением текущего статуса эталона
- **Выход:** вердикт одного из трёх видов

## Три состояния вердикта

| Вердикт | Что означает | Действие |
|---------|-------------|---------|
| **clear** | Противоречие не обнаружено; эталон актуален | Proceed |
| **moved-to-cold** | Эталон перешёл в cold-хранилище (устарел, не опровергнут) | Пометить как `cold_ref`, не удалять |
| **gone** | Эталон больше не существует в базе | Обновить ссылку или пометить как orphan |

## Применение

Любая система проверки свежести и согласованности знаний:
- Детектор противоречий Pack-сущностей при коммите
- Аудит `related.see_also` ссылок
- Валидация cross-references между Pack-записями

**Тест:** «Что произошло с эталоном при сравнении?» — ответ должен быть одним из трёх,
не просто true/false.
