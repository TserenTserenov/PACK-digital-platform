# DP.M.092 — Инфраструктурный артефакт как обязательный шаг create-flow

## Описание

Важные инфраструктурные артефакты (CI guard, линтер, security scan) встраиваются в create-flow нового репо как обязательный шаг — не как отдельная задача после создания.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Системная гарантия наличия артефакта ↔ раздувание create-flow | Встраивание устраняет человеческую ошибку забвения (репо без охраны, 48+ renumber за 8-18 мая), но каждый новый обязательный шаг утяжеляет create-flow — критерий применимости («создаётся несколько раз в год, и артефакт регулярно забывается») держит границу, что достойно встраивания |
| Цена автоматической установки ↔ цена ручного забывания | Скрипт `pack-ci-install.sh` надо писать и поддерживать идемпотентным, зато ручная установка оставляет окно уязвимости «пока кто-то вспомнит», в котором peer-агенты уже порождают ID-коллизии |

## Вход

Запрос на создание нового репо определённого типа (напр. Pack via `/pack-new`)

## Выход

Репо с установленным CI guard с первого коммита

## Алгоритм

1. Create-flow skill вызывает `pack-ci-install.sh` после `git init + initial commit`
2. Скрипт добавляет `.github/workflows/pack-lint.yml` с R1-R4 проверками
3. CI guard коммитится как часть initial setup

## Критерий применимости

«Новый репо-тип создаётся несколько раз в год, и важный артефакт регулярно забывается?» → встрой в create-flow

## Bias-Annotation

_Куда систематически съезжает внимание практикующего. Epistemic stage в frontmatter не указан._

| Bias | Direction of distortion |
|------|--------------------------|
| Фокус на содержимом артефакта затмевает точку его установки | Внимание практика уходит в то, что проверяет CI guard (правила R1-R4), а главный ход метода — встраивание установки как обязательного шага create-flow сразу после initial commit — воспринимается как само собой разумеющееся |
| Встраивание новых шаблонов без проверки критерия | Увидев работающий механизм, внимание тянется «встроить ещё один артефакт» (issue-template, dependabot, CODEOWNERS) без вопроса «регулярно ли забывается», и create-flow раздувается обязательными шагами |

## Failure mode без метода

При ручной установке CI guard: каждый новый репо-тип создаётся без охраны до момента, когда кто-то вспомнит; при параллельной работе peer-агентов без CI guard возникают ID-коллизии (48+ renumber за 8-18 мая).

## Применимо к

Любые шаблонные артефакты, обязательные для каждого репо типа: линтер, security scan, issue-template, dependabot, CODEOWNERS.
