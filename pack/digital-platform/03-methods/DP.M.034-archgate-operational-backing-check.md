# [DP.M.034] ArchGate Operational Backing Check

## Суть метода

ArchGate-профиль ЭМОГССБ (✅/⚠️/❌) — **сильный**, когда каждый критерий backed операционными данными (реальный трафик, инциденты, измеренные coupling-метрики). **Слабый** — когда строится на paper comparison без данных. Слабый профиль = потенциальная пост-хок рационализация.

## Диагностические признаки слабого профиля

| Признак | Описание |
|---------|----------|
| **DDD-аргумент появился после выбора** | BC-граница определена, чтобы оправдать уже выбранный вариант, а не наоборот |
| **Бюджет взят «из головы»** | Оценка часов не вытекает из scope-декомпозиции; нет breakdown по задачам |
| **Coupling-различие декларируется, не измеряется** | «Сервисы независимы» без данных о реальных вызовах, зависимостях конфигурации, инцидентах |

## Финализирующий вопрос

Перед финализацией ArchGate — спросить для каждого критерия:

> **«Какие операционные данные обосновывают эту оценку?»**

Если ответ «нет данных, только логика» → понизить уверенность в оценке или отложить до сбора данных.

## Типы операционных данных

| Критерий ЭМОГССБ | Операционный источник |
|-----------------|----------------------|
| Эволюционируемость | История инцидентов при изменениях; частота ломающих изменений |
| Масштабируемость | Измеренный трафик; профиль нагрузки; bottleneck-данные |
| Связность (coupling) | Реальный граф вызовов; shared конфиги; зависимости деплоя |
| Безопасность | Security incidents; threat model со STRIDE на реальных данных |

## Пример: WP-305 (12 мая 2026)

ADR-IWE-015 принял вариант B (отдельный CF Worker) через ArchGate с профилем ЭМОГССБ. Independent Opus review через ~2h нашёл 5 контраргументов:
- DDD-аргумент появился POST-HOC (та же Ory JWKS, Neon, runtime, auth у обоих сервисов)
- Бюджет 16h нереалистичен — реальный scope 24-32h
- Coupling-различие между BC иллюзорно без измерений

Итог: ADR-IWE-016 A-lite (модуль внутри gateway-mcp), экономия ~22h.

## Контрмеры

1. Проводить independent review (~2h) после ~2h работы над новым архитектурным решением
2. Строить бюджет из декомпозиции задач (не от общего ощущения)
3. Фиксировать coupling-данные до ArchGate (граф вызовов, shared infra)
