# DP.METHOD.139 — Пилотный проход методологии на одном документе перед корпусом

## Описание

Перед запуском методологии извлечения на большом корпусе (N > ~50 документов) — прогнать её на одном документе. Пилотный проход выявляет классы результатов, невидимых на этапе дизайна, и обновляет сами критерии отбора до основного прогона.

Аналог canary-деплоя для knowledge-pipeline.

## IPO

**Input:** черновая методология извлечения + один репрезентативный документ из целевого корпуса

**Process:**
1. Прогнать методологию на одном документе
2. Записать все результаты, включая неожиданные классы
3. Обновить критерии отбора на основе пилота
4. Зафиксировать уточнения (дельта к исходной методологии)
5. Только после этого — прогон на полном корпусе

**Output:** уточнённая методология + пилотные результаты как валидация перед масштабированием

## Когда применять

- Методология извлечения мемов, паттернов, сущностей для большого корпуса
- Любой knowledge-pipeline, где критерии отбора могут измениться после первого контакта с материалом
- Корпус > ~50 документов (стоимость переработки высока при ошибке методологии)

## Что даёт пилот (примеры реальных находок)

- **Новый класс результата:** source-upgrade существующей записи (недостающая SOTA-ссылка к уже записанному мему) — не только добавление новых
- **Gap-детекция:** отсутствие покрытия целого паттерна в каталоге (плато мастерства — 0 мемов из 170+)

## Антипаттерн

Запустить методологию на полном корпусе, получить результаты, потом обнаружить что критерии нужно уточнить — и переработать весь корпус. Пилот на одном документе стоит 1/N от переработки корпуса.
