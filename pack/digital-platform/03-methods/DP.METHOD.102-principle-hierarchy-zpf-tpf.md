# Лестница принципов ZPF→FPF→SPF→TPF→LPF (DP.METHOD.102)

## Описание

Иерархия принципов по оси специфичности применения. Каждый уровень уточняет контекст применения принципов предыдущего.

## Уровни

| Уровень | Расшифровка | Контекст применения |
|---------|-------------|---------------------|
| **ZPF** | Zero-order Principles Framework | Любой контекст, любой домен |
| **FPF** | First-order Principles Framework | Применяется к методу IWE |
| **SPF** | Second-order Principles Framework | Применяется к конкретному домену (Pack) |
| **TPF** | Third-order Principles Framework | Применяется к конкретному инстансу (DS, операционный контекст) |
| **LPF** | Locally Particular Framework | Применяется к конкретному носителю роли (не инстанс организации, а конкретный человек/команда в роли) |

## Алгоритм поиска применимого принципа

**Направление: сверху вниз (ZPF → LPF)**

1. Начать с ZPF — есть ли универсальный принцип для ситуации?
2. Если нет → FPF (принципы метода)
3. Если нет → SPF (принципы домена из Pack)
4. Если нет → TPF (принципы конкретного инстанса)
5. Если нет → LPF (партикулярная практика конкретного носителя роли)

## Алгоритм загрузки в агента (/fpf скилл)

**Направление: снизу вверх (LPF → ZPF)**

Наиболее специфичные принципы загружаются первыми — они перевешивают общие при конфликте. Если TPF и ZPF противоречат, TPF-принцип побеждает (конкретное специфичнее общего); LPF, если применим, перевешивает и TPF.

## Инвариант

**TPF-принцип не работает без SPF-контекста.** При применении принципа нижнего уровня — проверять, удовлетворены ли условия более высоких уровней. То же для LPF относительно TPF.

**LPF — не отдельный контейнер, а тест.** В отличие от ZPF-TPF (которые размещены по репозиториям), LPF на практике классифицирует фрагменты внутри TPF-репозитория по тесту «теряет ли фрагмент смысл при замене носителя данной роли на другого носителя той же роли» (см. `memory/repo-type-rules.md`).
