# DP.M.340 — Ресурс-гуард в скилле: открыть первым, закрыть последним

## Описание

В мульти-агентной среде (Claude Code + Kimi + headless агенты) несколько агентов могут одновременно работать с одними файлами. Скилл, изменяющий файлы, должен явно резервировать и освобождать ресурс — иначе конкурентные записи создают конфликты или смазывают авторство.

**Паттерн:** resource guard открывается как **первый шаг** скилла (шаг 1.0 или аналог) — до любого Write/Edit — и закрывается как **последний шаг** (после успешного push, best-effort — ошибка закрытия не блокирует остальную работу).

## Algorithm

### Step 1.0: Открыть ресурс-гуард (перед любыми изменениями)

```bash
session-guard.sh open  # или эквивалентный механизм блокировки
```

Если гуард уже открыт другим агентом — **остановить** и сообщить пилоту. Не перезаписывать.

### Step N (основная работа): Выполнить изменения

Любые Write/Edit/commit выполняются только после успешного открытия гуарда.

### Step 4.5.x: Закрыть ресурс-гуард (после push)

```bash
session-guard.sh close  # best-effort: ошибка не блокирует
```

Вызывается **после** push, а не после последнего Edit — коммит без push не даёт пилоту результата, закрытие гуарда до push = преждевременно.

## When to use

- Скилл создаёт или изменяет файлы в разделяемом репозитории
- В том же репозитории одновременно могут работать другие агенты
- Важно, что commit-сообщение корректно атрибутирует изменения конкретному агенту/задаче

## Когда НЕ применять

- Read-only операции (поиск, чтение, анализ без записи)
- Одноразовые headless-операции, заведомо не пересекающиеся с другими агентами
- Скилл работает только в изолированном worktree

## Тест применимости

«Если два агента одновременно запустят этот скилл — они затронут одни и те же файлы?»
- Да → гуард обязателен
- Нет (разные файлы) → гуард опционален

## Инвариант

`close` вызывается **best-effort**: сбой при закрытии не означает, что работа не завершена. Файлы, созданные до фикса (без `open`), разблокируются вручную через touch + note-file.
