# DP.METHOD.245 — секрет через ссылку на переменную, не копию

## Суть метода

Передача секрета от сервиса-источника к сервису-потребителю выполняется через механизм ссылки на переменную инфраструктурной платформы (`add_reference_variable` и аналоги), а не через явное копирование значения (в конфиг, в переменную окружения, видимую агенту). Значение секрета остаётся внутри платформы управления секретами, недоступное напрямую агенту/скрипту, выполняющему настройку.

## Обоснование

Копирование значения секрета (даже временное, для передачи между конфигами) создаёт лишнюю точку экспозиции — оно может попасть в лог, историю команд, контекст LLM-агента, выполняющего операцию. Ссылка на переменную устраняет саму возможность такой утечки — секрет остаётся в контролируемом хранилище платформы на всех этапах.

## Применение

Настройка передачи любого секрета между сервисами внутри инфраструктурной платформы, поддерживающей механизм ссылок на переменные (Railway `add_reference_variable` и аналоги в других провайдерах).
