# Платформо-специфичный путь: env > params.yaml > built-in fallback

## Суть

Скрипты, вызывающие платформо-специфичные команды (osascript на macOS, notify-send на Linux), загружают путь через трёхуровневый приоритет:
1. Переменная окружения (`NOTIFY_SH_PATH`)
2. params.yaml (`notify_sh_path` поле)
3. Встроенный fallback (захардкоженный путь)

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Простота одного хардкода ↔ гибкость трёх уровней | Захардкоженный путь — одна строка, ничего не сломается «просто так»; три уровня приоритета требуют больше кода и явного порядка разрешения |
| Работает «из коробки» ↔ работает у конкретного пользователя | Built-in fallback гарантирует, что скрипт не упадёт совсем без конфигурации; но у пользователя с нестандартной установкой именно fallback может оказаться неверным путём |
| Явная конфигурация (env/params.yaml) ↔ неявный дефолт | Пользователь может не знать, что путь вообще настраиваем, и годами жить на fallback; явный уровень требует, чтобы кто-то заполнил `params.yaml` или экспортировал переменную |
| Переносимость между платформами ↔ единый скрипт | Каждая платформа (macOS/Linux) может требовать своего пути к утилите; трёхуровневая схема переносит эту вариативность в конфигурацию, а не в ветвление кода по ОС |

## Реализация (shell)

```bash
if [ -z "$NOTIFY_SH_PATH" ]; then
  NOTIFY_SH_PATH=$(grep "^notify_sh_path:" "$IWE_WORKSPACE/params.yaml" | sed 's/.*: *//')
fi
# fallback если params.yaml тоже пустой
NOTIFY_SH_PATH="${NOTIFY_SH_PATH:-/usr/local/bin/notify.sh}"
```

## Применимость

Любой IWE-скрипт с платформо-зависимыми путями: TTS, браузер, editor, системные уведомления. Условие: `params.yaml` доступен по `$IWE_WORKSPACE/params.yaml`.

## Обобщение

Паттерн «env-first, config-second, default-last» — стандарт 12-factor для платформо-специфичного конфигурирования. Не хардкодить платформенные пути в скрипты.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «У меня путь стандартный, зачем усложнять» | Разработчик пишет скрипт под свою собственную установку и хардкодит путь, который работает именно у него; трёхуровневая схема кажется избыточной инженерией, пока скрипт не запускается на другой машине |
| «params.yaml — это где-то в другом месте, разберусь потом» | Внимание концентрируется на быстром fallback-пути, который «и так работает»; явное чтение из `params.yaml` откладывается, и env/config-уровни остаются недописанными или недотестированными |
| «Один скрипт — один хардкод, это же быстро» | При добавлении нового платформо-зависимого вызова легче скопировать соседний хардкод, чем подключить существующий трёхуровневый паттерн; со временем в кодовой базе накапливаются разрозненные точки с разными путями к одной и той же утилите |
| «Fallback = достаточно надёжный дефолт» | Встроенный путь воспринимается как безопасная страховка на все случаи; реальная платформенная вариативность (разные версии ОС, разные места установки) недооценивается, пока скрипт не падает именно там, где fallback не совпал с реальностью |
