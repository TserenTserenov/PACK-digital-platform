# DP.M.283 — BYOK-First: разблокировка тира до первого платежа

## Описание

Паттерн монетизации LLM-SaaS: дать пользователю возможность подключить собственный API-ключ (BYOK — Bring Your Own Key) как промежуточный шаг разблокировки верхнего тира, до оформления платной подписки.

**Принцип:** первый шаг разблокировки ≠ первый платёж.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| COGS провайдера ↔ барьер входа пользователя | Бесплатный верхний тир дорог провайдеру; BYOK снижает COGS, но требует от пользователя управления ключом и добавляет трение |
| Конверсия в подписку ↔ потеря выручки | BYOK может привлечь пользователей, которые не конвертируют, но также снижает порог демонстрации ценности и может повысить конверсию |
| Доступ к T4 из любого канала ↔ привязка к платформе | Тир становится канал-нейтральным, что удобно пользователю, но может ослабить lock-in и влиять на unit-экономику |
| Простота «всё включено» ↔ гибкость BYOK | Подписка проще в поддержке; BYOK требует поддержки ключей, но удовлетворяет пользователей, не желающих регулярных платежей |
| Снижение риска для провайдера ↔ сложность onboarding | BYOK снижает риск бесплатных LLM-запросов, но добавляет шаг в flow и потенциальные ошибки конфигурации |

## Контекст применения

Применимо к SaaS, где операционные расходы (COGS) включают стоимость LLM-токенов:
- Провайдер несёт COGS за каждый запрос бесплатного пользователя
- Пользователь хочет верхний тир, но не готов к регулярной оплате
- BYOK позволяет пользователю убедиться в ценности до коммита на подписку

## Алгоритм

1. Определить, какие функции верхнего тира требуют высоких LLM-COGS
2. Создать `grant_llm_key`-поток: пользователь вводит свой ключ (Claude/OpenAI/другой)
3. При наличии ключа — предоставить доступ к функциям тира без платежа
4. Стандартная подписка остаётся для пользователей, не желающих управлять ключами

## Архитектурное следствие

**Канал ≠ Тир:** T4 достижим из любого клиента (claude.ai, ChatGPT, VS Code) при наличии собственного LLM-ключа. Интерфейс ортогонален технологическому тиру.

## Преимущества

- Снижает COGS провайдера при разведке верхнего тира
- Снижает барьер входа без потери выручки (конвертация → подписка после демонстрации ценности)
- Сохраняет revenue-модель для пользователей, предпочитающих «всё включено»

## Тест применимости

«Является ли LLM-COGS значимой частью операционных расходов верхнего тира?» — Да → BYOK-First применим.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «BYOK — только для power users» | Практикующий недооценивает готовность обычных пользователей управлять ключом и упускает инструмент снижения барьера |
| «Бесплатный BYOK отберёт платные подписки» | Страх каннибализации выручки блокирует предложение BYOK, хотя оно снижает COGS и может повысить конверсию |
| «Пользователи не будут заморачиваться с ключами» | Переоценка трения; часть пользователей предпочитает BYOK подписке, особенно для разведения |
| «Верхний тир должен быть только платным» | Игнорирование промежуточного шага разблокировки; пользователь не может убедиться в ценности до коммита |
| «Провайдер должен нести COGS за разведку» | Продолжение бесплатного верхнего тира без BYOK сжигает ресурсы на пользователей, которые не конвертируют |
