# DP.M.327 — Точность диагностики при многоуровневом lookup: различать причины «не найдено»

## Описание

При многоуровневом поиске (slot→area→text, id→type→content, key→category→text) единственное сообщение «не найдено» скрывает, на каком уровне произошёл сбой. Метод: формулировать отдельные WARNING для каждого уровня отказа.

## Forces

| Force | Tension |
|-------|---------|
| Простота одного warning ↔ диагностическая точность | Единое сообщение «not found» короче в коде, но не говорит разработчику, на каком уровне искать причину |
| Компактность лог-вывода ↔ полнота причинности | N отдельных веток с уникальными сообщениями увеличивают объём кода и лога; слитое сообщение компактнее, но менее информативно |
| Скорость первичной реализации lookup ↔ стоимость последующей отладки | Слитая проверка пишется быстрее при первом проходе; раздельные ветки требуют больше кода сразу, но экономят время отладки позже |
| Единообразие обработки ошибок ↔ специфика каждого уровня | Одинаковая обработка на всех уровнях проще поддерживать, но скрывает, что «нет mapping» и «mapping есть, но пусто» — разные по природе сбои |

## IPO

| Вход | Обработка | Выход |
|------|-----------|-------|
| Функция lookup с N уровнями | На каждом уровне отдельная ветка с уникальным сообщением | Отдельные WARNING по уровням: "mapping missing" / "target empty" |

## Алгоритм (для двухуровневого lookup)

```
Уровень 1: slot → area
  Нет записи slot в mapping → WARNING: "No area mapping for slot: {slot}"

Уровень 2: area → text
  Нет текста для area → WARNING: "Area mapping found for slot {slot} → area {area}, but area has no text"
```

Расширение на N уровней: каждый уровень = своя ветка + уникальный message.

## Тест корректности

«Мой warning говорит "не найдено" — он проверяет один уровень или несколько?»  
Если несколько → нарушение метода. Разбить на отдельные ветки.

## Признак нарушения

- Единственный warning «no entry» при multi-level lookup
- Разработчик получает сообщение и не знает: добавить mapping? Добавить content? Проверить оба?

## Практический пример (WP-149)

```python
# До: слитый warning
if slot not in SLOT_TO_AREA or AREA_TO_MEME.get(SLOT_TO_AREA[slot]) is None:
    logger.warning("No catalog entry for slot %s", slot)

# После: раздельные warnings
if slot not in SLOT_TO_AREA:
    logger.warning("No area mapping for slot: %s", slot)
    return None
area = SLOT_TO_AREA[slot]
if not AREA_TO_MEME.get(area):
    logger.warning("Area %s found for slot %s but has no meme text", area, slot)
    return None
```

## Bias-Annotation

| Bias | Direction of distortion |
|------|--------------------------|
| «"Не найдено" — этого достаточно, дальше разберутся по коду» | Внимание при написании lookup останавливается на факте наличия хоть какого-то сообщения, не доходит до вопроса «какой уровень конкретно отказал» |
| «Один if на всю цепочку — проще писать» | Простота реализации доминирует над тем, что читающий лог позже не сможет различить «нет записи» от «запись есть, но пуста» |
| «Отладка — забота будущего себя/коллеги» | Экономия времени при первом написании функции систематически перекладывает цену диагностики на момент реального инцидента, когда контекст уже потерян |
| «Multi-level здесь на самом деле только один уровень» | Автор недооценивает число реальных точек отказа в цепочке (slot→area→text выглядит как один шаг, хотя отказать может каждое звено) |
