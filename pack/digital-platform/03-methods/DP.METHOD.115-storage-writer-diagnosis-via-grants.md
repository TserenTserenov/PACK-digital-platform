# DP.METHOD.115 — Диагностика источника записи через авторизационный слой хранилища

## Описание

При исчерпании перебора кода (grep по репозиториям, cron, облачные сценарии — нулевой результат) — запросить у самого хранилища, кто МОЖЕТ писать в нужную таблицу. Один авторитетный запрос к системе авторизации сужает пространство кандидатов без дальнейшего перебора.

## IPO

**Input:** неизвестный источник записи + N раундов перебора кода без результата

**Process:**
1. Идентифицировать хранилище (СУБД, объектное хранилище и т.д.)
2. Запросить авторизационный слой — кто имеет право записи в таблицу/путь
3. Сопоставить результат с известными сервисами и credential-инвентарём

**Output:** суженный список кандидатов-писателей

**PostgreSQL-пример:**
```sql
SELECT grantee, privilege_type
FROM information_schema.role_table_grants
WHERE table_name = '<table>' AND privilege_type = 'INSERT';
```

## Ограничения (обязательны к учёту)

1. Права на таблицу не показывают транзитивного наследования через роли
2. Функции с `SECURITY DEFINER` обходят стандартную проверку прав таблицы
3. Метод сужает круг, но не заменяет полный аудит прав

## Тест применимости

«Исчерпан ли перебор кода после N раундов без результата?» Да → переключиться к авторизационному слою хранилища.

## Антипаттерн

Продолжать grep-перебор по коду после N раундов без результата, не спросив у хранилища напрямую.
