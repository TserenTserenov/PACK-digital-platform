# DP.M.202 — Loyalty: Community Events Dual-Cap

## Описание

Community engagement events (полученные реакции, созданный контент, рост траста) выделяются в отдельную группу с двумя независимыми ограничениями: per-action cap (антиспам) и daily total cap (суммарный предел за день).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Антиспам (per-action cap) ↔ поощрение активных участников | Строгий per-action cap блокирует массовые накрутки, но тот же лимит может искусственно тормозить легитимного активного пользователя, если граница выбрана по «спамеру», а не по «энтузиасту» |
| Защита экономики (daily total cap) ↔ стимул к community activity | Daily cap предотвращает монетизацию спам-контента, но слишком низкий предел снижает мотивацию создавать качественный контент, который приносит много реакций |
| Доверие к внешним событиям ↔ внутренний контроль | Reaction-события из внешних систем (Discourse, Slack) полезны как сигнал, но платформа не контролирует их генерацию; daily cap покрывает риск, а per-action cap применяется только к активным действиям |

## Механизм

```
Группа G4 (community events):
  Входящие:  like_received, comment_received, topic_created,
             trust_promoted, badge_granted
  Исходящие: like_created (action, а не reaction)

Per-action cap (антиспам):
  like_created: ≤ 2 раз/день считается (независимо от daily total)

Daily total cap:
  Суммарная сумма баллов из G4 ≤ daily_cap_community
```

## Ключевые свойства

- **Два ограничения ортогональны:** per-action cap по одному событию может быть исчерпан, другой — нет
- **Anti-spam через per-action:** исключает накрутку баллов массовыми likes
- **Daily total cap:** предотвращает монетизацию через спам-контент
- **Reaction events (полученные)** — пассивный сигнал (like_received), логика доверия сообщества; ограничены only daily total
- **Action events (исходящие)** — активный сигнал (like_created), дополнительный per-action cap

## Применимость

Любая платформа с community + gamification: форум, marketplace, learning community. Особенно важно при интеграции с внешними форумами (Discourse, Slack), где события генерируются вне контроля платформы.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Per-action cap выставляется по спамеру, а не по энтузиасту | Практикующий фокусируется на худшем сценарии накрутки и устанавливает лимит, который перекрывает нормальную активность легитимных пользователей |
| Reaction-события переоцениваются как «чистый» сигнал | Внимание привлекают полученные реакции (like_received, trust_promoted), и их ценность как community signal завышается относительно риска спам-контента, который покрывает daily cap |
| Уравнивание cap'ов для простоты | Практикующий склонен применить один лимит к action и reaction событиям, потому что это проще объяснить и реализовать, стирая различие по управляемости |

## Антипаттерн

Единый cap на все события — не различает «получил реакцию» и «сделал действие». Накрутчик получает те же ограничения, что и активный участник сообщества.
