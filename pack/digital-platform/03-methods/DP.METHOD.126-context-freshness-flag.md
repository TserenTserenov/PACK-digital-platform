# DP.METHOD.126 — Явный флаг свежести инжектируемого контекста (ok|missing|stale)

## Описание

При передаче контекста в LLM-промпт через инжекцию включать явный флаг состояния: `ok`, `stale` или `missing`. Без флага модель вынуждена угадывать актуальность по содержанию, что приводит к false-positive «fresh» при stale данных.

## IPO

**Input:** инжектируемый контекст + timestamp последнего обновления + порог свежести

**Process:**
1. Вычислить: `age = now - last_updated`
2. Присвоить флаг:
   - `ok` — возраст < порога (данные считаются актуальными)
   - `stale` — возраст > порога, но данные присутствуют
   - `missing` — контекст не передан или недоступен
3. Включить флаг в промпт как явный метаданный параметр (не описание): `context_status: ok|stale|missing`
4. Добавить инструкцию поведения LLM для каждого состояния в системном промпте

**Output:** промпт с явным context_status + инструкцией поведения на каждое состояние

## Инструкция поведения (шаблон)

```
- ok: используй контекст как актуальный
- stale: предупреди пользователя, что данные устарели
- missing: укажи на отсутствие и предложи запустить обновление
```

## Пример

WP-149 Ф2: стратконтекст для персонального руководства включает `strategy_context_status: ok|stale|missing`. Без флага LLM получал stale-данные и интерпретировал их как актуальные.

## Тест применимости

«Зависит ли качество вывода от свежести переданных данных?» Да → применять. «Может ли контекст отсутствовать?» Да → обязательно включить состояние `missing`.

## Антипаттерн

Передавать контекст без флага свежести — модель интерпретирует любые данные как актуальные по умолчанию.
