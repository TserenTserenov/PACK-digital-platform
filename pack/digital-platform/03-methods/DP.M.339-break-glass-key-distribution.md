# DP.M.339 — Агент как генератор и передатчик аварийного ключа

## Описание

При создании пары ключей «автоматика + аварийный (break-glass)» агент выполняет разные роли для каждого ключа:

- **Автоматический ключ** (например, @gate-bot): агент загружает приватную часть в защищённое хранилище (GitHub Secret) и сразу удаляет локальную копию.
- **Аварийный (break-glass) ключ** (security-owner): приватная часть показывается пилоту **один раз** в чате, агент удаляет локальную копию и не сохраняет её нигде.

Аварийный путь остаётся под контролем человека — агент не может воспользоваться им самостоятельно.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Удобство единого процесса генерации ↔ разделение ролей хранения | Оба ключа генерируются в одной операции ради простоты, но логика хранения после генерации должна разойтись — автоматика в защищённое хранилище, break-glass только человеку |
| Скорость передачи ↔ отсутствие следа | Показать ключ в чате быстро, но именно отсутствие сохранённого следа (файл, лог, переменная) — то, что делает аварийный путь надёжным против компрометации агента |
| Автономность агента ↔ человеческий контроль над emergency access | Агент способен сгенерировать и обработать оба ключа самостоятельно, но метод сознательно ограничивает его роль ролью «генератор+передатчик», не «хранитель» |
| Единократный показ ↔ риск потери пилотом | Показ один раз минимизирует поверхность утечки, но создаёт риск, что пилот не успеет/не сможет сохранить ключ корректно |
| Временное совмещение ролей при генерации ↔ целевое разделение после | В момент создания один агент технически держит оба ключа; метод явно называет это временным состоянием, а не конечной архитектурой |

## Algorithm

### Step 1: Сгенерировать оба ключа

```bash
gpg --batch --gen-key automation-key.conf
gpg --batch --gen-key break-glass-key.conf
```

### Step 2: Автоматический ключ — загрузить в хранилище, удалить локально

```bash
gpg --export-secret-keys automation@example.com | gh secret set GPG_PRIVATE_KEY
gpg --delete-secret-and-public-keys --batch automation@example.com
```

### Step 3: Аварийный ключ — показать пилоту один раз, удалить локально

Отобразить приватный ключ в чате (в защищённом блоке).
```bash
gpg --armor --export-secret-keys security-owner@example.com
gpg --delete-secret-and-public-keys --batch security-owner@example.com
```

### Step 4: Подтвердить, что пилот сохранил ключ

Пилот сохраняет break-glass ключ в личный менеджер паролей. После сохранения — аварийный путь полностью под контролем человека.

## Тест применимости

«Если агент скомпрометирован или потерян — может ли злоумышленник использовать аварийный ключ?»
- Нет (агент удалил копию) → паттерн применён корректно
- Да (агент сохранил копию где-либо) → нарушение инварианта

## Инвариант

Агент **никогда не хранит** приватную часть аварийного ключа после передачи пилоту. Даже временное сохранение (в файл, переменную, лог) нарушает паттерн.

## Временное ослабление

В момент генерации один агент создаёт оба ключа — разделение «автоматика vs человек» восстанавливается только когда пилот сохраняет break-glass в личный менеджер паролей и больше не показывает агентам.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Ключ уже сгенерирован — можно сохранить локально „на всякий случай“» | Привычка к промежуточным файлам/логам смещает внимание от инварианта «никогда не хранит»; временный файл кажется безопасным, потому что «временный» |
| «Оба ключа делаются одинаково, разница чисто в месте хранения» | Внимание уравнивает автоматический и аварийный ключ по процессу, упуская, что именно логика хранения после генерации — суть различия ролей |
| «Показал один раз в чате — задача выполнена» | Фокус смещается на факт показа, а не на подтверждение Step 4: сохранил ли пилот ключ в менеджер паролей реально |
| «Агент технически мог бы использовать break-glass при инциденте» | Удобство экстренного самостоятельного действия агента отвлекает от инварианта «аварийный путь остаётся под контролем человека» |
| «Временное состояние генерации — не проблема, раз потом разделим» | Внимание к «временному ослаблению» ослабевает после генерации; проверка «пилот действительно сохранил и агент действительно удалил» пропускается как формальность |
