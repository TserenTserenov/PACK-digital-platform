# DP.METHOD.220 — homes.yaml как декларативная карта маршрутизации

## Суть метода

Правила размещения артефактов по репозиториям выносятся в отдельный декларативный файл (`homes.yaml`), читаемый классификатором, вместо того чтобы жёстко прописывать пути внутри логики скриптов. Классификация происходит пофайлово, с явным дефолт-правилом для случаев, не покрытых явными записями карты.

## Обоснование

Декларативная карта отделяет знание «что куда» от кода, который это знание применяет — изменение правил маршрутизации не требует правки скрипта, только карты. Пир-ревью дизайна такой карты до реализации кода дешевле находит дефекты (двусмысленные форматы даты, конфликт с gitignore-семантикой), чем их отладка постфактум.

## Применение

Любой конвейер, принимающий решение «в какой репозиторий/директорию положить артефакт» на основе типа/содержания.
