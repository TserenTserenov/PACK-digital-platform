# DP.M.223 — Marp тёмная тема: layout-классы

## Входы

- Marp-презентация с тёмным фоном
- CSS-тема (базовая или с нуля)

## Процесс

1. **Background fix:** `tbody td` требует явного `background: #1e293b` — без него текст невидим на тёмном фоне (наследуется прозрачный фон).
2. **Контрастные метки:** класс `.big-label` (font-size: 2em, font-weight: 800) для визуального акцента в слайдах «Было/Стало».
3. **Layout-классы через `_class:`:** разделяют semantic structure от visual style. Примеры: `hook`, `split`, `cards-2`, `cards-3`, `with-eyebrow`, `center`.
4. **Audience-check:** audience-facing slides ≠ team-facing slides. Служебные подписи/метки убираются перед публикацией.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Семантическая структура ↔ визуальный стиль | Layout-классы отделяют содержание от оформления, но требуют дисциплины: легко начать добавлять inline-стили под каждый слайд, разрушая единый CSS |
| Единый CSS ↔ множество layouts | Один CSS-файл должен покрывать разные типы слайдов, что делает его сложнее; без этого каждая презентация получает собственные стили и дублирует решения |
| Audience-facing качество ↔ team-facing удобство | Служебные метки помогают команде готовить слайды, но должны исчезать перед публикацией; промежуточное состояние легко забыть проверить |

## Выходы

- CSS-тема с layout-классами
- Marp-презентация с раздельным управлением структурой и стилем

## Инвариант

`_class:` layout = semantic structure управляется отдельно от visual CSS. Один CSS → множество layouts.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Смешение служебных подписей с контентом | Практикующий добавляет метки «draft» и «team-only» прямо в слайды для собственного удобства, но забывает audience-check перед публикацией — публика видит внутренние пометки |
| Желание править CSS под каждый слайд | Вместо добавления нового layout-класса практикующий пишет inline-стили или новый CSS-файл, потому что «так быстрее» — через месяц презентации разъезжаются по версиям стилей |
| Забывание про тёмную тему | Внимание уходит в layout и типографику, а базовые вещи (`tbody td` background) остаются без проверки — таблицы становятся невидимыми на тёмном фоне |
