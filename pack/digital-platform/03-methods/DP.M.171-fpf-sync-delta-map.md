# DP.M.171: FPF-sync — delta-map синхронизации онтологии Pack с FPF

## Назначение

Метод обновления русских Pack-ов при выходе новой версии FPF или при обнаружении расхождений.
**Принцип:** не переписывать — патчить через delta-map.

## Алгоритм

1. **Собрать delta-map:** проверить каждый Pack на пробелы/расхождения с FPF (не весь словарь, только изменённые/новые концепты).
2. **Классифицировать по флагам:**
   - ✅ Чисто — каноническое определение уже присутствует.
   - ⚠️ Двузначность — термин есть, но формулировка расходится с FPF; уточнить.
   - 🔴 Пробел — понятие отсутствует; добавить явную формулировку.
3. **Патч только ⚠️ и 🔴:** обновить конкретные строки в целевых Pack-файлах.
4. **Осторожность с ⚠️:** проверить, нет ли авторского Pack-расширения, которое FPF не покрывает.

## Отличие от полного ревью

| | FPF-sync (delta-map) | Полное ревью |
|---|---|---|
| Scope | Только новые/изменённые концепты | Весь словарь Pack |
| Время | ~1–2h на Pack | ~1 день |
| Когда применять | При обновлении FPF или обнаружении drift | Раз в квартал / при major rewrite |

## Применимость

- Аудит Pack-ов после выхода FPF R{N+1}.
- On-boarding нового Pack-автора: сверка с FPF-каноном.
- Регулярный мониторинг терминологической целостности.
