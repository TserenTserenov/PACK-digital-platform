# DP.METHOD.110 — Дедупликация алертов только после появления ack-механизма

## Описание

Подавлять повторяющийся алерт без механизма подтверждения (ack) нельзя: повтор — единственный сигнал, что инцидент ещё не закрыт.

## IPO

**Input:** повторяющийся алерт (n-й раз за N дней) + решение «надоел, дедуплицировать»

**Process:**
1. Проверить: есть ли способ явно погасить алерт? (команда /ack, кнопка, статусная запись)
2. Если нет → повтор алерта = единственный рабочий сигнал «не закрыто». Дедуплицировать нельзя.
3. Если планируется дедупликация → сначала реализовать ack-механизм, потом подавлять повторы.
4. Улучшение текста (добавить номер дня повтора: «день 3», «день 7») — допустимо без ack, снижает раздражение не убирая сигнал.

**Output:** решение: доработать ack-механизм → затем дедуплицировать ИЛИ оставить повтор как есть

## Пример

WP-455: ежедневный дубль-алерт планировалось починить через дедупликацию. Анализ показал: нет команды подтверждения; подавление создало бы silent failure — инцидент продолжается, сигналов нет. Правильный путь: сначала /ack → потом подавить повторы после N дней.

## Тест применимости

«Есть ли способ явно закрыть этот алерт?» Нет → применять метод перед любой дедупликацией.

## Антипаттерн

Рефлекс «надоел повтор → убрать» без проверки, чем он будет заменён как сигнал незакрытого инцидента.
