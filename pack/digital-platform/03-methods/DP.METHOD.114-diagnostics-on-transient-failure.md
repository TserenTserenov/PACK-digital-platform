# DP.METHOD.114 — Диагностический дамп при необъяснённом транзиентном сбое

## Описание

При единичном сбое без установленной причины — сразу настроить диагностический дамп состояния на следующее падение. «Повторится — разберёмся» пассивно: следующее падение придёт без данных.

## IPO

**Input:** единичный сбой + отсутствие объяснения (чистый git log, ни одна гипотеза не подтверждена с надёжностью «подтверждено»)

**Process:**
1. Добавить сбор состояния при срабатывании: stderr, exit-code, git-status, сетевой снимок
2. Применить redaction чувствительных полей (токены, пути) до записи
3. Сохранить в durable-хранилище, не только в stdout

**Output:** готовый диагностический дамп при следующем падении

## Ограничение переноса паттерна

Паттерн из соседнего инцидента не переносится без прямого доказательства того же класса точности. При неточном сходстве — явно снижать уверенность с «подтверждено» до «наиболее вероятно».

## Тест применимости

«Если этот сбой повторится ночью — будет ли достаточно данных без повторного воспроизведения?» Нет → дамп не настроен.

## Антипаттерн

«Повторится — тогда искать» без подготовки инструментов наблюдаемости. При редком сбое это означает неограниченное время без диагноза.
