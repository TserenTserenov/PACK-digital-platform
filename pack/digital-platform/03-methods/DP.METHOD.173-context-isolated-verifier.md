# DP.METHOD.173 — Независимый верификатор с изоляцией контекста

## Определение

Верификатор читает **только уже записанные (опубликованные) артефакты** (файлы в репо, GitHub API) — не внутреннее состояние процесса-производителя. Все пункты чеклиного канона всегда присутствуют в выводе: непроверяемое кодом помечается явно (⏳), не пропускается молча.

## IPO

- **Вход:** опубликованные артефакты (файлы в репо, GitHub API, внешние эндпоинты)
- **Процесс:** сравнение с каноном; try/except изолирует падение верификатора от основного процесса
- **Выход:** чеклист `checks/<YYYY-MM-DD>.md` с PASS/⏳/FAIL на каждый пункт

## Свойства метода

1. **Context isolation:** верификатор читает внешние факты (GitHub API, файловая система), не shared state с процессом-производителем. Self-verification исключён архитектурно.
2. **Honesty-by-default:** непроверяемый пункт → ⏳, не отсутствие. N пунктов канона всегда выводятся.
3. **Process resilience:** падение верификатора не ронит основной процесс (try/except обёртка).

## Когда применять

- Ежедневные автоматические процессы, производящие артефакт (рендер руководства, экспорт данных, batch-генерация)
- Любые проверки, где source-of-truth = опубликованный файл, не переменная в памяти
- Критические автоматические процессы перед выпуском в production
