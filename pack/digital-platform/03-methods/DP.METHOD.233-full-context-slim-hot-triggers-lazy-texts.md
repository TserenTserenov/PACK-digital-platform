# DP.METHOD.233 — полный слим: hot = триггеры, lazy = тексты, метрика бюджета

## Суть метода

Архитектура контекстного каркаса разделяет содержимое на два слоя: hot-слой хранит только триггеры (когда загружать) и краткие нормы (что обязательно), полные развёрнутые тексты (правила, инструкции, протоколы) демотированы в отдельные lazy-файлы, подгружаемые по требованию. Слимирование ведётся до достижения явной количественной цели бюджета hot-слоя (например, M2 ≤12K токенов), а не произвольно.

## Обоснование

Без явной числовой цели слимирование не имеет критерия остановки и остаётся субъективным. Разделение триггер/норма (hot) от развёрнутого текста (lazy) минимизирует токены, загружаемые в каждую сессию по умолчанию, сохраняя полный контент доступным при реальной необходимости.

## Применение

Архитектурное проектирование контекстного каркаса агента с ограниченным бюджетом токенов на постоянно загружаемую часть.
