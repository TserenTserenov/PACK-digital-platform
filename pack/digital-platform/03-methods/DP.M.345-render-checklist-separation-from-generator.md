# DP.M.345 — Чеклист проверки рендера как отдельный артефакт от скрипта-генератора

## Описание

Паттерн QA для сложных generation-pipeline: скрипт-генератор и чеклист проверки — два независимых артефакта, эволюционирующих раздельно.

**Принцип разделения ответственности:**
- Скрипт знает КАК генерировать (алгоритм сборки)
- Чеклист знает ЧТО проверить (критерии качества результата)

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Удобство встроенных проверок в скрипт ↔ независимая эволюция чеклиста | Проверки внутри генератора проще запускать (один файл, один вызов); отдельный чеклист требует поддерживать два артефакта, но эволюционирует своим темпом |
| Скорость первого прогона ↔ честность диагностики | Ожидание «всё сразу зелёное» приятнее; метод явно принимает первый красный прогон как диагностику, а не как провал реализации |
| Единый источник истины (скрипт) ↔ раздельная ответственность (скрипт vs чеклист) | Держать всё знание в одном месте (скрипте) проще для навигации; разделение ЧТО/КАК снижает связность, но требует синхронизировать два файла при изменениях |
| Обновление чеклиста по мере находок ↔ стабильность критериев приёмки | Чеклист должен расти при обнаружении новых точек сбоя; частые изменения критериев затрудняют сравнение прогонов «до/после» |
| Общий (generic) паттерн для любого pipeline ↔ специфика конкретного рендера | Метод claims применимость к любому generation/render pipeline; но структура чеклиста (Части 1-2) взята из одного эталона (PD.WP.019) и может не покрывать специфику другого pipeline без адаптации |

## Структура чеклиста (эталон: PD.WP.019)

**Часть 1 — Входы генерации:**
- Снапшот знаний актуален?
- Данные пользователя получены?
- Все источники доступны (prefetch, portrait.md, etc.)?

**Часть 2 — Результат:**
- Формат соответствует спецификации?
- ВДВ-структура присутствует?
- Нужные процессы включены?
- Нет утечки из соседних секций?

## Паттерн применения

1. Создать чеклист как отдельный файл (не встраивать в скрипт)
2. Первый прогон чеклиста по новому pipeline = ожидаемо красный (диагностика, не провал)
3. Чеклист обновляется при обнаружении новых точек сбоя — независимо от изменений скрипта
4. Скрипт обновляется при изменении алгоритма генерации — независимо от чеклиста

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Скрипт написан аккуратно — значит, результат тоже будет качественным» | Внимание переносится с проверки результата на качество кода генератора; чеклист по определению проверяет результат отдельно от того, насколько «хорошо» написан скрипт |
| «Первый прогон чеклиста красный — где-то ошибка в реализации скрипта» | Красный прогон интерпретируется как провал разработчика вместо ожидаемой диагностики; метод явно называет это нормальным первым результатом |
| «Раз чеклист написан один раз — он покрывает все будущие точки сбоя» | Внимание не возвращается к чеклисту после первого создания; новые точки сбоя, обнаруженные позже, не попадают в него без сознательного усилия |
| «Изменил скрипт — надо бы обновить и чеклист заодно» | Импульс синхронно менять оба артефакта при любом изменении скрипта противоречит принципу независимой эволюции — чеклист меняется по своей причине (новая находка), не «заодно» |
| «Чеклист из одного pipeline подойдёт любому другому без изменений» | Структура (Часть 1 — входы, Часть 2 — результат) переносится на новый pipeline буквально, без проверки, совпадают ли реальные точки сбоя нового рендера с эталонными |

## Тест применимости

Применимо, если: pipeline имеет ≥3 проверяемых свойства результата И менялся за последние 3 месяца.

## Применимость

Любой сложный generation/render pipeline: персональные руководства, отчёты, презентации, конфигурации, статические сайты.

## Эталонная реализация

WP-149: `render-pilot-guides.py` (генератор) + `PD.WP.019.render-checklist.md` (чеклист). Первый прогон — 8 находок (prefetch не работает, тема дня застряла, задание протекает в guide). Все — реальные проблемы, не артефакты чеклиста.
