# DP.M.294 — Lifecycle extraction-report: applied_commit + архивация

## Описание

Метод финализации extraction-report после записи кандидатов в Pack-репо.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость применения → следующий отчёт ↔ дисциплина финализации | После записи кандидатов в Pack тянет сразу перейти к следующему отчёту; архивация — дополнительный шаг без видимого немедленного эффекта |
| История в inbox ↔ чистота очереди | Оставить файл в inbox — сохранить видимую историю обработки на месте; переместить в archive — освободить очередь от «шума» применённых записей |
| Единичная правка ↔ коммит перемещения | Изменение frontmatter (`status: applied`) можно сделать без отдельного коммита; явная фиксация перемещения коммитом — лишний шаг, но даёт трассируемость момента архивации |
| Один источник истины (`status`) ↔ два сигнала (`status` + местоположение) | Достаточно поля `status: applied`, чтобы отличить применённое; физическое перемещение в другую директорию — избыточный, но более надёжный сигнал для скриптов, которые сканируют только `inbox/` |

## Шаги

1. Добавить в frontmatter: `applied_commit: <SHA>` и обновить `status: applied`.
2. Переместить файл из `inbox/extraction-reports/` в `archive/extraction-reports/`.
3. Зафиксировать перемещение коммитом.

## Зачем

Без архивации inbox накапливает «применённые» файлы без маркера. Следующий прогон inbox-check не отличает их от новых кандидатов → ложная очередь и repeated processing. Аналог: PR merge → branch delete.

## Тест применимости

«Extraction-report находится в inbox/ и status = applied?» → применить lifecycle-метод.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Кандидаты записаны в Pack — задача решена» | Внимание останавливается на моменте применения знания; финализация самого отчёта (frontmatter + перемещение) воспринимается как второстепенная бухгалтерия, которую можно отложить |
| «Файл ведь помечен status: applied, этого достаточно» | Практикующий считает изменение одного поля достаточным сигналом; переносит фокус с реального состояния очереди (что видит следующий прогон inbox-check) на формальную метку внутри файла |
| «Архивация — это про порядок, не про корректность» | Задача воспринимается как эстетическая уборка, а не как предотвращение repeated processing; недооценивается цена пропуска для следующего агента, который читает тот же inbox |
| «applied_commit можно добавить потом, задним числом» | SHA коммита, которым были применены кандидаты, откладывается «на потом»; к моменту следующей сессии контекст коммита теряется, и applied_commit либо не заполняется, либо заполняется неточно |
