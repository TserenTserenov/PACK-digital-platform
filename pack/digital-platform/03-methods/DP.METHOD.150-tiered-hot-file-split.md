# DP.METHOD.150: 3-уровневая структура HOT-файла

## Контекст

HOT-файл IWE имеет лимит (≤150 строк / slim-core инвариант). При росте содержимого файл нарушает инвариант. Простое удаление контента ведёт к потере важных различений. Разбивка по частоте использования в сессии решает обе проблемы.

## Метод

| Уровень | Что хранит | Размер | Режим |
|---------|-----------|--------|-------|
| **Tier-A** | Полный текст наиболее критичных позиций | ≤13-15 | hot (всегда) |
| **Tier-B** | Одна строка (суть 3-5 слов) на позицию | ~20 | hot (всегда) |
| **Tier-C** | Только имена / идентификаторы | ~100+ | hot (только названия) |
| **Warm-файл** | Полные тексты для Tier-B и Tier-C | без лимита | lazy, warm horizon |

Hot-файл содержит все три уровня. Warm-файл (`memory/*-warm.md`) хранит полные тексты.
Полный текст для Tier-B/C запрашивается по `/distinction X` из warm-файла в сессии.

## Критерий распределения по уровням

- **Tier-A:** позиции, неправильное применение которых блокирует сессию (critical distinctions)
- **Tier-B:** позиции, нужные в сессии ~раз в 2-3 дня
- **Tier-C:** позиции, нужные по запросу (редко, но должны быть доступны по имени)

## Результат применения (WP-445)

distinctions.md: 136+ строк / 147 различений → hot-каркас 55K токенов (цель <60K, M1 PASS).

## Применимость

Любой HOT-файл, превышающий лимит: роли, SOTA, чеклисты, методы.
Тест: «нужен ли этот элемент в КАЖДОЙ сессии с полным текстом?»
- Да → Tier-A
- Иногда → Tier-B (одна строка hot, полный текст lazy)
- Редко, но важно знать имя → Tier-C
