# Метод: base_group вместо доменного множителя

## 1. Проблема

В gamification-схемах ценность активности кодируется двумя осями:
- `domain_mult`: множитель по домену (practice×5, learning×3, work×1)
- `base_group` G1–G5: группа по типу активности

Оба кодируют одну семантику — «насколько ценна активность» → сложная матрица → неинтуитивные результаты.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Выразительность многомерного скоринга ↔ интуитивность результата | Две оси (`domain_mult` × `base_group`) кажутся точнее одной, но кодируют одну семантику «насколько ценна активность» — результат сложной матрицы; метод жертвует измерением ради балла, который пользователь может предсказать |
| Аналитическая ценность домена ↔ простота формулы начисления | Домен нужен для фильтров и отчётов, но в формуле дублирует G1–G5; метод не удаляет домен, а понижает его до аналитического атрибута — отчёты сохраняют разрез, начисление теряет множитель |

## 2. Решение

Убрать `domain_mult` из формулы. Вся семантика ценности переносится в `base_group`:
- G1 = наименьшая ценность
- G5 = наибольшая ценность

Домен остаётся **аналитическим атрибутом** — для фильтров и отчётов, не в формуле.

## 3. Принцип переносимости

Если два атрибута кодируют одну семантику — один должен стать производным или удалиться.

**Применимо к:** любая система скоринга с многомерными множителями.

## 4. Тест

«Меняет ли удаление одного из атрибутов итоговый балл при том же намерении?» Если оба влияют на один результат → дублирование.

## 5. Прецедент

WP-327 v3 (2026-05-23): модель баллов Aisystant, переход v2→v3.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Новый множитель ощущается как рост точности | Внимание на «больше измерений = точнее оценка ценности», и проверка из теста карточки («меняет ли удаление одного атрибута итоговый балл при том же намерении?») не выполняется — дублирующая ось живёт годами |
| Правка формулы затмевает судьбу удалённой оси | При упрощении внимание фиксируется на формуле начисления, и атрибут удаляется целиком вместе с аналитической ценностью — отчёты и фильтры по домену пропадают, хотя метод требует лишь вывести его из начисления |
