# DP.M.291 — patch.object вместо строкового пути при реэкспорте через __init__.py

## Описание

Метод выбора правильного места для мокирования в Python-тестах, когда пакет реэкспортирует имя через `__init__.py`.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Краткость `patch("a.b.c")` ↔ корректность target | Строковый путь короче и привычнее, но разрешается через import location, а не source; `patch.object` требует importlib, но патчит объект там, где он живёт |
| Читаемость теста ↔ индирекция | `patch.object` с importlib менее очевиден новому читателю; зато он не ломается при изменении reexport-цепочки |
| Привычка к строковому patch ↔ реальная семантика | Разработчик привык патчить то, что импортировано в тесте, но при reexport это не то же самое, что исходный объект |
| Скорость написания теста ↔ скорость отладки | Строковый patch быстрее пишется, но приводит к «зелёным» тестам с неработающим моком; `patch.object` требует больше кода, но ошибки видны сразу |
| Поддержка reexport ↔ стабильность теста | Если `__init__.py` меняется, строковый патч может внезапно перестать мокировать; `patch.object` привязан к источнику и переживает reexport |

## Проблема

`unittest.mock.patch("a.b.c")` разрешает путь: ищет модуль `a.b`, достаёт атрибут `c`. Если `a/__init__.py` делает `from a.b import c`, тест импортирует через `from a import c` — реальный объект живёт в `a.b`, но патч ищет в `a`. Патч применяется не к источнику → мок не работает (assert_called_once() = False), тест «зелёный», но реальный код вызывает оригинал.

## Решение

```python
import importlib
_mod = importlib.import_module("a.b")
with patch.object(_mod, "c") as mock_c:
    # теперь патч применён к источнику
    ...
```

## Тест применимости

«Пакет реэкспортирует имя через `__init__.py`?» + «Мок не вызывается при assert_called_once()?» → применить `patch.object`.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «`patch("a.b.c")` — стандартный способ, его и используем» | Практикующий применяет привычный строковый патч без проверки, где реально живёт объект; reexport остаётся незамеченным |
| «Тест импортирует из `a`, значит патчим `a.c`» | Предположение, что import location совпадает с source location; патч применяется к reexport, а не к исходному объекту |
| «Тест зелёный — мок работает» | `assert_called_once()` может быть False, но тест всё равно проходит, потому что реальный код вызывает оригинал; false green не ловится без явной проверки |
| «`patch.object` слишком многословен» | Практикующий выбирает короткий строковый патч, жертвуя корректностью; экономия нескольких строк оборачивается скрытым багом |
| «Reexport через `__init__.py` — деталь реализации» | Практикующий считает, что где импортирован объект, не важно для мока; недооценивает семантику разрешения имён в `unittest.mock` |

## Связи

- Принцип: патчить там, где объект живёт, а не там, где импортируется.
