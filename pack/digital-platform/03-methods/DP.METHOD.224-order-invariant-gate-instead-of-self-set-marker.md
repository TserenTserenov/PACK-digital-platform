# DP.METHOD.224 — гейт через инвариант порядка, не через самомаркер

## Суть метода

Вместо маркера-файла (который агент технически может выставить себе сам, например через `touch`), гейт согласия строится на структурном инварианте: единственный путь создания артефакта — через выделенный скрипт (например, `create-wp.sh`), а не прямая запись файла Write-инструментом. Дополнительно — новая запись сопровождается вторым независимым структурным требованием (например, наличием записи в журнале гипотез с определённым порядком создания).

## Обоснование

Самовыставляемый маркер (флаг «согласие получено», который сам же исполнитель и устанавливает) уязвим к тому, что исполнитель обходит проверку, выставляя маркер без реального выполнения условия. Структурный инвариант («это можно создать только этим путём») не может быть подделан тем же способом — обход требует реального нарушения кода, а не простановки флага.

## Применение

Проектирование любого гейта согласия/допуска, где ранее использовался маркер-файл, устанавливаемый тем же агентом, чьё поведение он должен ограничивать.
