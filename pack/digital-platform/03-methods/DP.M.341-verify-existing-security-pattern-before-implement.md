# DP.M.341 — Верификация реального механизма защиты перед реализацией схемы доступа

## Описание

Перед реализацией схемы доступа/безопасности по абстрактному эталону — сначала прочитать 5-10 существующих миграций или примеров того же класса в репозитории, чтобы извлечь фактически применяемый механизм защиты. Проектировать поверх него.

## IPO

**Input:** новая задача на реализацию схемы доступа + абстрактный правильный паттерн (из документации, обучения, договорённостей прошлой сессии)

**Process:**
1. Найти 5-10 существующих миграций / примеров того же класса в репо (`ls migrations/` + чтение)
2. Извлечь фактически применяемый механизм защиты: роли, флаги, дисциплины кода, GRANT-паттерны
3. Сверить с абстрактным паттерном — совпадает или отличается?
4. Если отличается → проектировать поверх реального механизма, не поверх учебной абстракции

**Output:** реализация, совместимая с действующим механизмом защиты репо

## Ограничения (обязательны к учёту)

1. Существующий механизм может быть унаследованным / неоптимальным — документировать решение «проектировать поверх него» явно
2. Метод не заменяет архитектурный ревью при смене механизма защиты

## Тест применимости

«Изучал ли я, как реально защищаются данные в этом репо — или проектирую по абстрактному эталону?» По эталону → применить метод сначала.

## Антипаттерн

Реализация схемы доступа по договорённости из прошлой сессии или учебной документации без сверки с реальным кодом → появление «декоративной защиты» (код выглядит правильно, но механизм не применяется к субъекту).
