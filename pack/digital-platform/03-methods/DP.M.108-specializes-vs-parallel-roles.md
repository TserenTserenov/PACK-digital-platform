# DP.M.108 — Specializes + параметр оси вместо N отдельных ролей

## Описание

При моделировании семейства похожих ролей (Y X1, Y X2, Y X3, ...) — проверить, является ли X параметром одной роли, а не дифференциатором. Если различия только в объекте внимания, а методы/обещания/downstream идентичны — одна роль со `specializes: <parent>` + параметр оси. Если поведение тоже отличается — разные роли.

## Вход

Намерение создать N (≥2) близких по имени ролей: «Контролёр X / Контролёр Y», «Аналитик A / Аналитик B».

## Выход

- Одна роль с `specializes: <parent-role>` + параметр оси (Development / Style / Qualification / Domain)
- ИЛИ — N отдельных ролей, если тест на поведение даёт «отличается»

## Алгоритм

1. Перечислить «кандидатов на роль» (Y X1, Y X2, ...) с их предполагаемыми методами / обещаниями / downstream_consumers
2. Сравнить: совпадают ли методы? обещания? consumers? Только объект внимания различен?
3. Если только объект → одна роль + параметр оси: документировать enum в роли (e.g., `axis: [Development, Style, Qualification, Domain]`)
4. Если поведение различается → отдельные роли + общий `specializes: <parent>` если есть общая родительская абстракция
5. Записать тест в Pack: «при добавлении новой оси (5-й, 6-й) — параметризация или новая роль?»

## Критерий применимости

«Семейство близких ролей рассматривается одновременно?» Да → ОБЯЗАТЕЛЬНО применить тест. Без теста → риск Pack-bloat (N сущностей вместо 1 с параметром).

## Failure mode без метода

Pack-bloat: 4 роли «Контролёр X» вместо 1 + параметр. Onboarding пилотов: «какой Контролёр для меня?» — выбор между 4 ролями вместо одного параметра. Переиспользование методов невозможно — каждая роль дублирует методы из остальных.

## Прецедент

WP-326 (2026-05-20): DP.ROLE.046 Контролёр развития. Соблазн — 4 роли (Контролёр развития, квалификации, стиля, домена). Решение — одна роль со `specializes: DP.ROLE.022 Оркестратор` + параметр `axis: [Development, Style, Qualification, Domain]`.

## Применимо к

- DP.ROLE / MIM.R при добавлении нового семейства ролей
- DP.SC при моделировании семейства обещаний (e.g., notification-SC × N каналов = 1 SC + параметр channel)
- DP.D entities при кажущемся дублировании
