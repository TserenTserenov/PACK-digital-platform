# DP.M.305 — Frozen formula hash: версия формулы как артефакт под change-control

## 1. Принцип

Когда расчёт реализует метод из отдельного источника (Pack, РП методолога), результат обязан нести **явный хэш версии формулы** в выходе и хранилище.

```python
FORMULA_VERSION = "wp414-v1"  # меняется только через change-control РП414

def calculate_panel(user_id: int, ...) -> PanelResult:
    ...
    return PanelResult(..., formula_version=FORMULA_VERSION)
```

## 2. Инвариант разделения обязанностей

```
Кто считает (воркер)  ≠  Кто оптимизирует (методолог)  ≠  Кто проверяет (аудитор)
```

Без версионирования невозможно различить:
- «результат изменился из-за данных» vs
- «результат изменился из-за тихого рефакторинга формулы»

## 3. Процесс изменения формулы

1. Методолог создаёт новый РП (например, РП416 «обновление формулы v2»)
2. Новая версия получает идентификатор `wp416-v2`
3. Воркер обновляет `FORMULA_VERSION` через PR с явной ссылкой на РП
4. Исторические записи сохраняют старый `formula_version` — ретроспектива сопоставима

## 4. Хранение версии

- Поле `formula_version` в контрактной таблице (`<entity>_daily`)
- Поле `formula_version` в аудитной таблице (`<entity>_audit`)
- Лог воркера при каждой записи

## 5. Антипаттерн

Inline-формула без версии — рефакторинг меняет семантику молча, исторические данные несопоставимы.

## 6. Применимость

- Ночные сводки, дайджесты, панели активности с переживаемой историей
- Сертификаты достижений с формулой начисления
