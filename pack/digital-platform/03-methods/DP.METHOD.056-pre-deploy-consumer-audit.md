# DP.METHOD.056 — Pre-deploy аудит потребителей перед сменой имён MCP-инструментов

> **Применяется:** перед любым деплоем gateway или MCP-сервера с переименованием / удалением инструментов.

## §0 Назначение

При переименовании MCP-инструментов клиенты с хардкодом старого имени падают после деплоя. Метод предотвращает breaking change в проде через обязательную pre-deploy проверку.

## §1 Алгоритм

1. **Определить изменения контракта:** список переименованных / удалённых инструментов из diff
2. **Grep по всем клиентским репо:**
   ```bash
   for repo in aist_me_bot aist_pilot_bot hermes-runtime; do
     echo "=== $repo ===" && grep -rn "старое_имя_инструмента" ~/IWE/$repo/ 2>/dev/null
   done
   ```
3. **Если есть совпадения** — обновить до деплоя шлюза (атомарный PR или одновременный деплой)
4. **Если совпадений нет** — деплой чистый, продолжать

## §2 Инвариант

**Deploy нового контракта без одновременного обновления потребителей = breaking change в проде.**

Правило: gateway и его клиенты — co-deploy единица при изменении имён.

## §3 Расширение

При масштабировании (>3 клиентов): завести `consumers.yaml` с полным списком → grep автоматизировать через `scripts/pre-deploy-consumer-check.sh`.
