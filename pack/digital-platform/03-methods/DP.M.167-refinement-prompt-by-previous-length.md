# DP.M.167 — Ветвление refinement-промпта по длине предыдущего ответа

## Суть

В многоступенчатой генерации (FAQ-hit → refinement через полную LLM) промпт второго шага зависит от характера первого. Если предыдущий ответ короткий (FAQ-hit, ≤ N символов) — он мог быть off-topic; refinement-инструкция «раскрой аспекты» вырождается. Если длинный — инструкция корректна. Длина первого ответа = прокси-сигнал его источника.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Универсальность одного refinement-промпта ↔ адекватность источнику первого шага | Единый промпт «расширь незатронутые аспекты» проще, но на коротком FAQ-hit вырождается — расширять нечего, и ответ мог быть off-topic; метод платит одним if-блоком и порогом N за ветку «дай конкретный практический ответ на вопрос пользователя» |
| Точность сигнала источника ↔ его дешевизна | Metadata или confidence-score первого шага точнее, но требуют инструментария; длина ответа — грубый, но бесплатный прокси, и метод компенсирует грубость калибровкой N между распределениями (обычно 300-500 символов) |

## IPO

| | |
|---|---|
| **Вход** | Текст предыдущего ответа, текущий пользовательский запрос, пороговое значение длины N |
| **Процесс** | Если `len(previous_answer) < N` → промпт «Дай конкретный практический ответ на вопрос пользователя». Иначе → промпт «Расширь незатронутые аспекты предыдущего ответа». |
| **Выход** | Refinement-промпт, адекватный характеру предыдущего шага |

## Шаги

1. Определить N: оценить медианную длину «полного» ответа (LLM-генерация) vs «короткого» (FAQ-hit). Граница между распределениями = N (обычно 300-500 символов).
2. Вставить ветвление в генератор refinement-промпта (1 if-блок).
3. Тест: сценарий FAQ-hit → нажать «Подробнее» → ответ должен напрямую отвечать на исходный вопрос, не «расширять» generic FAQ.

## Тест применимости

«Может ли результат предыдущего шага быть off-target → промпт обязан это учитывать?» Да → нужно ветвление по прокси-сигналу источника.

## Применимость

Любая многоступенчатая LLM-система с гетерогенными источниками первого шага (FAQ-DB + полный LLM, кэш + fresh-generation, retrieval + reasoning). Прокси-сигналом может быть длина, источник в metadata, confidence-score первого шага.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Формулировки веток затмевают валидацию порога | Внимание на текстах двух промптов, а N ставится «на глаз» вместо анализа медианных длин FAQ-hit vs LLM-генерации — ветвление срабатывает не на тех ответах при безупречных формулировках |
| Тестируется счастливый путь длинного ответа | Внимание на основном сценарии (длинный ответ → «расширь аспекты»), а сценарий FAQ-hit → «Подробнее», ради которого метод и существует, остаётся непроверенным — регрессия обнаруживается от пользователя |
