# DP.METHOD.055 — Метод безопасного автоматического git push

> **see DP.D.140** (Наблюдатель-сторож ≠ Сервис доставки)

## §0 Назначение

Метод задаёт минимальный инвариант для автоматического push в неинтерактивном окружении (cron, CI/CD, серверный агент) без риска merge-конфликтов или потери контента.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Полнота инварианта (все три условия одновременно, §1) ↔ частота срабатывания автопуша | Требование одновременного clean+ahead>0+behind==0 сводит риск бесконтрольного push почти к нулю, но означает, что push массово пропускается в diverged-состояниях («при behind>0 — молча пропустить») — метод жертвует частотой доставки коммитов ради безопасности, полагаясь на отдельный pull-alert компонент, который должен ещё и не забыть сработать |
| Молчаливый skip при behind>0 (§1) ↔ видимость застревания в cron/CI-логах | «Молча пропустить» устраняет риск неконтролируемого merge/rebase в headless-режиме (§2: push при behind>0 — мутация истории без надзора), но одновременно означает, что накопление diverged-состояния не видно из самого push-шага — сигнал полностью делегирован pull-alert компоненту (DP.D.140), и если тот не настроен на конкретном сервере, diverged-состояние остаётся незамеченным сколь угодно долго |

## §1 Тройное условие (push-invariant)

Автоматический push выполняется строго при одновременном выполнении всех трёх условий:

1. **clean tree** — нет незакоммиченных изменений (`git status --porcelain` пуст)
2. **ahead > 0** — есть коммиты для доставки (`git rev-list @{u}..HEAD | wc -l > 0`)
3. **behind == 0** — нет входящих изменений, merge не потребуется (`git rev-list HEAD..@{u} | wc -l == 0`)

При behind > 0 (diverged state) — молча пропустить: за сигнализацию отвечает отдельный pull-alert компонент (см. DP.D.140).

## §2 Почему три условия

- **clean tree** — грязное дерево означает незафиксированный прогресс, push прервёт состояние на полпути
- **ahead > 0** — пустой push — холостое действие, зашумляет logs
- **behind == 0** — push при behind > 0 потребует merge/rebase: в автоматическом режиме это мутация истории без надзора

## §3 Применение

```bash
ahead=$(git rev-list @{u}..HEAD 2>/dev/null | wc -l | tr -d ' ')
behind=$(git rev-list HEAD..@{u} 2>/dev/null | wc -l | tr -d ' ')
status=$(git status --porcelain 2>/dev/null)

if [ -z "$status" ] && [ "$ahead" -gt 0 ] && [ "$behind" -eq 0 ]; then
  git push
fi
```

**Применимо:** любой CI/CD шаг «автоматический push», cron-задачи на серверах, headless git-агенты.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Фокус на числовых сравнениях без проверки предпосылки | При настройке §3 внимание сосредотачивается на корректности числовых сравнений (`ahead -gt 0`, `behind -eq 0`) и на совместимости с конкретным shell-диалектом деплоя (cron часто использует `sh`, не `bash`), но недооценивает предпосылку — настроен ли upstream (`@{u}`) вообще, без которого `git rev-list @{u}..HEAD` падает ещё до вычисления условия |
| Чтение условий вместо эмпирической проверки при отладке | Раз скрипт молча ничего не делает при провале любого из трёх условий, при отладке «почему push не случился» внимание уходит в повторное чтение трёх условий §1 вместо эмпирической проверки состояния репозитория на сервере — элегантность именованного инварианта подменяет собой пошаговый прогон `git status --porcelain`/`git rev-list` вручную |
