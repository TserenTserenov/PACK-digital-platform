# DP.M.388 Backward compat при rename ключа Digital Twin

## Определение

При переименовании ключа в структуре цифрового двойника (Digital Twin) чтение реализуется как «новый ключ первым, fallback на старый»: код сначала ищет значение под новым именем, и только при его отсутствии — под старым.

## Причина

Уже накопленные снимки (исторические записи цифрового двойника) созданы под старым именем ключа. Переименование без fallback делает их нечитаемыми задним числом — история пилота теряется в момент rename, а не в момент фактического удаления данных.

## Правило

Rename ключа в персистентной структуре с историей снимков → двухфазное чтение (новый → fallback старый), не одномоментная замена.
