# DP.M.311 — File-fallback из шаблона: graceful degradation при отсутствии Pack

## Описание

Шаблон IWE (FMT-exocortex-template) доставляет пользователю базовое поведение (языковые стили, правила, шаблоны) даже когда необязательный Pack (например, PACK-rhetoric) отсутствует. Решение — двухуровневая цепочка чтения: сначала Pack, при отсутствии — встроенный fallback в самом FMT.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Простота hard dependency ↔ устойчивость к отсутствию Pack | Требовать Pack как обязательную зависимость проще в реализации (один источник, без ветвления), но ломает setup у любого пользователя, который его не установил |
| Полнота доменной версии ↔ минимальность встроенного fallback | Pack даёт богатую, специфичную версию ресурса; встроенный в FMT fallback обязан быть достаточным, но не обязан быть полным — баланс между «достаточно» и «избыточно дублирует Pack» |
| Единый источник истины ↔ две параллельные версии ресурса | Одна версия ресурса проще поддерживать без риска расхождения, но graceful degradation по определению требует существования двух версий (Pack + FMT-embedded), которые могут разойтись |
| Скорость доставки нового поведения ↔ синхронизация fallback с Pack-версией | Обновить логику в Pack — один коммит; для полноты паттерна нужно решить, обновлять ли параллельно fallback в FMT, что удваивает работу редко используемых веток |

## Алгоритм (IPO)

**Вход:** запрос ресурса R (стиль, правило, шаблон) из шаблона или хука
**Процесс:**
1. Проверить наличие Pack-источника (`PACK-X/pack/X/...`)
2. Pack найден → загрузить из Pack (полная версия)
3. Pack отсутствует → загрузить из встроенного fallback (`FMT-exocortex-template/.claude/styles/`, `.claude/templates/` и т.п.)
**Выход:** ресурс R, доставленный в одной из двух версий, без отказа

## Применимость

| Слой | Источник fallback | Триггер |
|------|------------------|---------|
| Языковые стили | `.claude/styles/` в FMT | PACK-rhetoric отсутствует |
| Шаблоны промптов | `.claude/templates/` в FMT | Pack-домен не установлен |
| Правила формата | `.claude/rules/` в FMT | Pack-источник не клонирован |

## Принцип

Интерфейс-уровень не обязан блокироваться при отсутствии необязательного Pack. Pack даёт расширенную/доменную версию; FMT гарантирует минимальный рабочий артефакт.

## Тест применимости

«Может ли FMT доставить базовое поведение без этого Pack?» Если нет — Pack обязательный, fallback не применим. Если да — необязательный Pack, нужен fallback в FMT.

## Failure modes (антипаттерны)

- **Hard dependency:** Pack считается обязательным, шаблон ломается при его отсутствии (downgrade в новый клон → broken setup)
- **Silent divergence:** Pack-версия и FMT-fallback расходятся без changelog → пользователь видит разное поведение в зависимости от наличия Pack

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Pack всегда будет установлен у пользователя, fallback — редкий edge case» | Разработчик проектирует и тестирует только happy path с Pack; ветка fallback пишется наспех и остаётся непроверенной до первого реального пользователя без Pack |
| «Раз есть fallback, Pack можно вообще не проверять при разработке» | Внимание смещается к удобной ветке (fallback работает всегда, без внешних зависимостей), Pack-путь при локальной разработке проверяется реже |
| «Обновил Pack — значит обновил поведение для всех» | Практикующий забывает, что часть пользователей идёт по fallback-ветке в FMT, которая не подхватывает изменения Pack автоматически — нужен отдельный шаг синхронизации |
| «Fallback — это временное решение, скоро все поставят Pack» | Встроенный fallback трактуется как переходное состояние «пока не долетело», из-за чего в него не вкладывают качество наравне с Pack-версией |
