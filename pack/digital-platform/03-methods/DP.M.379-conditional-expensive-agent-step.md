# DP.M.379 — Условный запуск дорогостоящих шагов агента

## Суть метода

Агентный шаг с высокой стоимостью (токены, время, внешние API) должен иметь явные критерии запуска («когда запускать»), а не выполняться при каждом вызове протокола.

По умолчанию дорогостоящий шаг = CONDITIONAL, не ALWAYS.

## Алгоритм применения

1. Определить cost-профиль шага (токены, время, внешние вызовы).
2. Сформулировать positive trigger criteria: когда шаг имеет смысл.
3. Добавить guard в начале шага: проверить criteria, пропустить если не выполнены.
4. Логировать причину пропуска (не молча).
5. Тест: «Административная сессия без контентных правок — шаг запускается?» Нет → criteria корректны.

## Пример (KE в Quick Close)

Знание-экстракция через R23/Haiku запускается ТОЛЬКО если:
1. Сессия >30 мин
2. `git diff` непустой (есть контентные изменения)

Административные сессии (pull, status, коммит метаданных) — KE пропускает.

## Когда применять

- Любой агентный шаг с LLM-вызовом в протоколах Close/Day Close/Week Close
- Шаги с внешними API с лимитами или стоимостью
- Автоматические верификации и проверки
