# DP.METHOD.161: Процесс закрытия пишет входные данные для следующего периода

## Назначение

Устранить паттерн «открытие читает вчерашний файл / заглушку» в pipeline-системах с зависимостью Close → Open.

## Правило

**Кто закрывает период — тот инициализирует следующий.**

Close-процесс пишет инициализирующие данные в конце своего выполнения, не оставляет эту работу для Open-процесса.

## Алгоритм

1. Выполнить Close-процесс (commit, push, отчёт).
2. **В самом конце** — записать входные данные следующего периода (carry-over + приоритеты).
3. Open-процесс следующего периода читает уже инициализированный файл.

## Диагностика проблемы

Симптом: автогенератор стабильно видит «(не задано)» или заглушку, хотя данные есть.
Причина: Open-процесс читает файл, который Close не обновил.

## Антипаттерн

«Завтра при открытии соберём» → к моменту открытия контекст потерян (стейт не перенесён, приоритеты не зафиксированы, контекст переключился).

## Применимость

Любой pipeline с зависимостью «процесс A (Open) читает файл, записанный процессом B (Close)».
Примеры: Day Close → Day Open, Sprint Retro → Sprint Planning, Month Close → Month Open.
