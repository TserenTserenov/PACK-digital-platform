# DP.M.215 Resource constraint доминирует в портфеле при одном исполнителе

## Правило

Если в портфеле проектов N≥3 параллельных направлений делает один исполнитель — **resource constraint доминирует над любыми технологическими ограничениями**.

Сколь угодно правильно выбранный технический фокус («доделаем X → ускоримся») не разрешает узкое место — расширение каждого направления требует часов того же одного человека.

## Применение

При обзоре зонтичного РП в первую очередь проверить:
1. **Передача / разделение / удаление работы** (управленческое решение по resource)
2. **Только потом** технические приоритеты

Управленческое решение по resource = verdict-тип задача (~30 мин), эффект растянут на квартал (нанять, обучить, отладить).

## Антипаттерн

«Выберем технический критический путь, передачу отложим» → через месяц та же ситуация (один исполнитель делает то же количество путей).

## Тест

«У скольких параллельных направлений в портфеле один и тот же исполнитель?» ≥3 → resource = старшее ограничение.

## Применимость

- Ежемесячный review портфеля
- Стратсессия
- Момент когда DayPlan перегружен 3+ дня подряд
