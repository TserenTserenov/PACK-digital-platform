# DP.M.413 — Файловая блокировка: освобождение через trap на любом выходе

## Проблема

Первая версия защиты планового скрипта от параллельного запуска (файловая блокировка) освобождала лок только на success-ветке выполнения. При ошибке скрипт завершался, не дойдя до строки освобождения, — лок оставался висеть и блокировал все последующие запуски, включая штатные.

## IPO

- **Вход:** скрипт, защищённый файловой блокировкой от параллельного запуска
- **Процесс:** освобождение лока регистрируется через `trap ... EXIT` сразу после захвата, а не отдельной командой в конце success-пути
- **Выход:** лок освобождается при любом варианте завершения скрипта — успех, ошибка, прерывание сигналом — следующий запуск не блокируется висящим локом

## Паттерн

```bash
LOCK_FILE="/tmp/my-script.lock"
exec 200>"$LOCK_FILE"
flock -n 200 || { echo "Already running, exiting"; exit 0; }
trap 'flock -u 200' EXIT   # снимает лок на любом пути завершения, включая ошибку
# ... тело скрипта, которое может упасть на любом шаге ...
```

## Антипаттерн

```bash
flock -n 200 || exit 0
# ... тело скрипта ...
flock -u 200   # выполнится только если весь код выше не упал — при ошибке лок повиснет
```

## Применимо

Любой плановый (cron/launchd/systemd) скрипт с защитой от параллельного запуска через файловую блокировку, где тело скрипта может завершиться ошибкой до достижения явной команды освобождения.
