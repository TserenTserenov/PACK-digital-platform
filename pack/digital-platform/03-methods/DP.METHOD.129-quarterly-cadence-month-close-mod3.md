# DP.METHOD.129 — Квартальный ритм через встроенный mod-3 в Month Close

## Описание

Квартальные задачи встраиваются в существующий Month Close без отдельного launchd-задания: проверяется, кратен ли 3 номер закрываемого месяца. При кратности — выполняется дополнительный раздел чеклиста. Иначе раздел молча пропускается.

## IPO

**Input:** YYYY-MM закрываемого периода (из Month Close контекста)

**Process:**
1. Извлечь номер месяца M из YYYY-MM
2. Если `M % 3 == 0` → выполнить раздел «Quarterly» из t-checklist.md
3. Иначе → пропустить без вывода

**Output:** квартальные задачи выполнены (или молча пропущены); Month Close продолжается в обычном режиме

## Принцип

Квартальный ритм = каждый 3-й месяц. Встроить через условие кратности проще, чем создавать отдельный launchd plist (лишний lifecycle, риск дрейфа расписания). Паттерн обобщается: полугодовые задачи — `mod 6 == 0`, годовые — `mod 12 == 0`.

## Тест применимости

«Нужны ли задачи реже, чем раз в месяц, но чаще, чем раз в год?» Да + «уже есть Month Close?» Да → встроить через `month_num % N == 0`.

## Пример

WP-450 Ф6: T26 (ревизия median-ratio.conf) и T27 (ревизия порогов M1/M2 контекстного бюджета) встроены в шаг 6 Month Close с проверкой `(month % 3 == 0)`. Март (3) и Июнь (6) — выполняются; Апрель (4) и Май (5) — пропускаются.
