# DP.M.306 — Честная деградация тайла панели: статусные коды вместо дефолтных значений

## 1. Проблема

При сборке многотайловой панели метрик данные отдельных тайлов могут быть недоступны. Подстановка дефолта (0, среднее) — подделка: пользователь не отличает реальный 0 от «нет данных».

## 2. Паттерн: статусные коды тайла

| Код | Значение | Отображение |
|-----|----------|-------------|
| `not_tracked` | Поле не собирается платформой | «Не отслеживается» |
| `not_connected` | Зависимость от незавершённого РП (указать owner) | «Не подключено» |
| `no_time` | Знаменатель = 0 (нет событий за период) | «Нет данных за период» |

## 3. Инвариант

> **«Лучше явная дыра, чем правдоподобное искажение»**

Панель = trusted reference только если все тайлы честны.

## 4. Применимость

- Дашборды с частично заполненными профилями
- Агрегаты с переменным покрытием источников

## 5. Антипаттерн

Показывать точку всегда с дисклеймером «учитывайте малую выборку» — никто не учитывает, доверие к панели подрывается.

## 6. Различение

**≠ DP.M.160 (single-point degradation tracking):** DP.M.160 — про единственную точку регистрации метрики в коде. Этот паттерн — про статусные коды выходного тайла при недоступных данных (UI/API контракт).
