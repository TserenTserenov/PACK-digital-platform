# DP.M.306 — Честная деградация тайла панели: статусные коды вместо дефолтных значений

## 1. Проблема

При сборке многотайловой панели метрик данные отдельных тайлов могут быть недоступны. Подстановка дефолта (0, среднее) — подделка: пользователь не отличает реальный 0 от «нет данных».

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Полнота панели ↔ честность данных | Заполненная панель со всеми тайлами выглядит завершённо, но подмена «нет данных» на 0 создаёт ложное впечатление знания там, где его нет |
| Простота UI (число + подпись) ↔ дифференциация причин пустоты | Один нейтральный статус «нет данных» проще в вёрстке, но три разных кода (`not_tracked`/`not_connected`/`no_time`) дают пользователю разное действие в ответ на каждый |
| Скорость доставки MVP ↔ честность деградации | Быстрее подставить дефолт и отложить статусные коды на потом, но каждый день с дефолтами — это накопленное недоверие, которое позже не «чинится» одним патчем |
| Единый источник числового значения ↔ множественность причин недоступности | Тайл — это одно число на выходе, но за пустотой могут стоять три разные причины (не собирается / не подключено / нет событий), которые требуют разного статуса, а не одного «null» |

## 2. Паттерн: статусные коды тайла

| Код | Значение | Отображение |
|-----|----------|-------------|
| `not_tracked` | Поле не собирается платформой | «Не отслеживается» |
| `not_connected` | Зависимость от незавершённого РП (указать owner) | «Не подключено» |
| `no_time` | Знаменатель = 0 (нет событий за период) | «Нет данных за период» |

## 3. Инвариант

> **«Лучше явная дыра, чем правдоподобное искажение»**

Панель = trusted reference только если все тайлы честны.

## 4. Применимость

- Дашборды с частично заполненными профилями
- Агрегаты с переменным покрытием источников

## 5. Антипаттерн

Показывать точку всегда с дисклеймером «учитывайте малую выборку» — никто не учитывает, доверие к панели подрывается.

## 6. Различение

**≠ DP.M.160 (single-point degradation tracking):** DP.M.160 — про единственную точку регистрации метрики в коде. Этот паттерн — про статусные коды выходного тайла при недоступных данных (UI/API контракт).

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «0 — безопасный дефолт, никого не обманывает» | Разработчик считает 0 нейтральным значением по умолчанию, не замечая, что для пользователя 0 читается как реальный факт («у тебя ноль»), а не как «неизвестно» |
| «Один статус `no_data` покроет все случаи» | Внимание уходит от того, что разные причины пустоты требуют разных пользовательских действий (ждать / подключить источник / это не отслеживается вовсе) — сведение к одному статусу теряет эту разницу |
| «Дисклеймер рядом с числом решает проблему честности» | Практикующий подставляет предупреждающий текст вместо структурного изменения — считает, что снял с себя ответственность формулировкой, хотя пользователь текст не читает |
| «Это временная заглушка, статусные коды добавим позже» | Дефолтное значение воспринимается как placeholder «на MVP», но именно на этом этапе накапливаются данные, которые потом невозможно отличить от honest zero задним числом |
