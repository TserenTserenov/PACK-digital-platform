# DP.M.163 — Checkpoint-протокол для отложенной финализации фазы РП

## Описание

Метод фиксации промежуточного состояния фазы РП при вынужденном переносе финализации.
Применяется когда фаза выполнена, но закрытие (report.md, коммит) откладывается (контекст переключился, агент недоступен).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Цена фиксации в момент переключения ↔ цена реконструкции при возобновлении | Писать checkpoint на «уже завершённую» фазу — накладные расходы в момент, когда внимание уже переключилось; без него возобновление требует восстановления состояния по памяти и диффам, что дороже и ненадёжнее |
| Лаконичность записи ↔ точность возобновления | «Доделать фазу» пишется за секунду, но бесполезно как точка входа; метод требует конкретики («обновить строку 42 в файле X + закоммитить»), списка выполненных тестов и состояния артефактов с датой или hash |

## Когда применять

- Фаза РП выполнена содержательно, но оформление отложено
- Произошло переключение контекста (пилот переключился, peer-агент завершил сессию)
- Нужна точная реконструкция при возобновлении без потери контекста

## Отличие от handoff

Checkpoint пишется для самого себя (будущей сессии агента), не для передачи другому исполнителю.
Handoff предполагает смену исполнителя с явным получателем.

## Обязательный состав checkpoint

1. **Список выполненных тестов** — какие проверки прошли, какие нет
2. **Состояние артефактов** — путь к файлу + дата последнего изменения (или hash)
3. **«Осталось»** — конкретные незавершённые действия (не «доделать», а «обновить строку 42 в файле X + закоммитить»)

## Алгоритм

1. Зафиксировать: что сделано (список действий с результатами)
2. Зафиксировать: текущее состояние артефактов (файл + дата или hash)
3. Зафиксировать: что осталось (конкретные действия, не намерения)
4. Записать checkpoint в WP-context файл (`inbox/WP-NNN.md`) под секцией `## Checkpoint YYYY-MM-DD`
5. При возобновлении: прочитать checkpoint → продолжить с шага «Осталось»

## Инвариант

- Checkpoint создаётся в момент переключения, не позже
- Checkpoint содержит только факты (что выполнено), не намерения
- Секция «Осталось» — конкретные команды/файлы, а не «продолжить работу»

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Содержательная завершённость заслоняет неоформленность | Внимание на том, что фаза «сделана по сути», — report.md и коммит кажутся формальностью, и переключение происходит без фиксации; checkpoint не пишется именно тогда, когда он нужнее всего |
| Внимание уже в новом контексте — checkpoint пишется по остаточному принципу | При спешке переключения записываются намерения («продолжить работу») вместо фактов и конкретных шагов; при возобновлении точка входа потеряна — протокол выполнен формально, но не функционально |
