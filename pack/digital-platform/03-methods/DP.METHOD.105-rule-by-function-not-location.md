# DP.METHOD.105 — Формулировка правила по функции, а не по месту

## Описание

При обнаружении неоднозначного правила переформулировать по функции (что делает элемент), а не по месту (где он разрешён появляться).

## Детектор неоднозначности

Два независимых агента прочли одно правило по-разному без внешних изменений → правило неоднозначно, не «один ошибся».

## IPO

**Input:** правило, сформулированное через место («разрешено только в разделе X»)

**Process:**
1. Зафиксировать расхождение как сигнал неоднозначности — не ошибку агента
2. Определить функцию каждого из разошедшихся прочтений
3. Разбить на явные функциональные ограничения: «метка (разрешена везде) vs совет (только в секции Y)»
4. Убрать формулировку «в разделе X» → заменить на «при функции Y»

**Output:** функционально-разделённое правило без неоднозначности по месту

## Условия применения

- Правило сформулировано через разрешённое место, а не через цель/функцию элемента
- Детектор: расхождение двух независимых агентов за < 48 часов без изменений правила

## Антипаттерн

Считать расхождение ошибкой конкретного агента без пересмотра формулировки → правило снова породит расхождение при следующем применении.

## Лестница надёжности enforcement

1. Текстовый запрет (слабо)
2. Правило-по-функции (этот метод)
3. Структурный слот шаблона (сильно; см. DP.METHOD.107)
