# DP.METHOD.128 — Протокол самотеста детектора: синтетическое воспроизведение известного бага

## Описание

При Week Close (или ином периодическом ритуале) синтетически воспроизводить тот конкретный баг, который детектор должен ловить. Если детектор молчит при воспроизведении — он сломан. Не блокирует закрытие, но фиксирует регрессию.

## IPO

**Input:** известный баг X, который детектор обязан ловить; путь к детектору

**Process:**
1. Создать временный файл-mock без раздела/паттерна, который детектор должен требовать
2. Запустить детектор на mock
3. Ожидать ❌ (срабатывание)
4. Если ✅ — детектор снова сломан: создать issue; не блокировать Close

**Output:** подтверждение, что детектор НЕ откатился в false-green состояние

## Принцип

Детектор может откатиться при рефакторинге SKILL.md, extension или переписывании скрипта. Периодический smoke, воспроизводящий реальный инцидент = конкретная защита от регрессии детектора.

Расширяет различение «Детектор существует ≠ Детектор блокирует»: детектор может существовать и даже запускаться, но при регрессии снова перестать ловить свой класс ошибок.

## Тест применимости

«Уверены ли мы, что детектор ловит свой класс ошибок прямо сейчас, а не просто "есть в коде"?» Нет → провести самотест.

## Guard

Провал самотеста = issue для исправления, не стоп-сигнал для Week Close. Фиксировать: какой детектор, какой баг, какой тест провалился.

## Пример

day-open.checks самотест при Week Close: создаётся временный DayPlan без раздела «Мир» → запускается checks → ожидается ❌. Воспроизводит инцидент: 4 дня подряд пропускался отсутствующий раздел.
