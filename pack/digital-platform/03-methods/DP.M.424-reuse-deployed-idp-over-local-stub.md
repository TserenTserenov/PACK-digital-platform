# DP.M.424 — Переиспользовать задеплоенный IdP вместо временной локальной заглушки

## Определение

Перед проектированием новой ad-hoc проверки подлинности для узкого частного случая — проверить, не решает ли эту же задачу уже эксплуатируемый компонент платформы. Если да — переиспользовать его вместо параллельной более слабой системы доверия.

## IPO

- **Вход:** задача проверки подлинности для нового узкого случая (например, проверка легитимности экземпляра агента) + уже задеплоенный поставщик идентичности (IdP), эксплуатируемый для похожего класса задач
- **Процесс:** сравнить временную ad-hoc заглушку (например, локальную проверку по сокету) с переиспользованием существующего IdP для той же проверки подлинности
- **Выход:** решение в пользу существующего компонента — не нужно параллельно поддерживать вторую, более слабую систему доверия для частного случая

## Переносимый критерий

Перед проектированием новой ad-hoc проверки подлинности стоит спросить: не решает ли эту же задачу уже эксплуатируемый компонент платформы? Если инфраструктура доверия уже задеплоена и проверена для похожего класса задач — не нужно параллельно поддерживать вторую, более слабую.

## Прецедент

WP-469 Ф2 (АрхГейт): сравнивались временная заглушка (локальная проверка для подтверждения легитимности экземпляра агента) и переиспользование уже эксплуатируемого поставщика идентичности для той же проверки подлинности. Пир-сессия выбрала переиспользование существующего IdP.
