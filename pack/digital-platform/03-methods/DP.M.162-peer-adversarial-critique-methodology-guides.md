# DP.M.162 — Adversarial Peer Review для методологических текстов

## Описание

Метод улучшения методологических руководств через peer-сессию в режиме adversarial critique.
Один агент пишет, второй критикует по DP.SC.154 (turn-taking). Результат — v2+ с устранёнными слепыми пятнами автора.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость авторской итерации ↔ устранение слепых пятен автора | Писатель мог бы довести текст сам, но полноту аргументации, профессиональный жаргон и неприменимость для новичка он не видит по определению; метод платит вторым агентом и conversational turn-taking (DP.SC.154) за внешний взгляд |
| Острота adversarial critique ↔ управляемость процесса | Критика должна быть жёсткой, иначе слепые пятна останутся, — но напарник не вносит правки сам, а спорное уходит к пилоту через ESCALATE_TO_USER; метод удерживает остроту в рамках ролей: критик формулирует, писатель решает, пилот разрешает конфликт |

## Когда применять

- Методологический текст (руководство, методичка, инструкция) прошёл первую версию
- Нужна проверка: полнота аргументации, отсутствие профессионального жаргона, применимость для нового пользователя
- Нет независимого человека-рецензента

## Алгоритм

1. **Писатель** пишет версию v1 текста
2. **Запустить peer-сессию** (DP.SC.154): писатель + напарник-критик в conversational turn-taking
3. **Напарник** критикует adversarially: проверяет полноту аргументации, жаргон, применимость
4. **Писатель** принимает/отклоняет замечания, фиксирует разногласия
5. **При ESCALATE_TO_USER** — эскалировать спорное решение к пилоту, не автономно
6. **Результат** — текст v2+ с явными изменениями (git diff)

## Инвариант

- Финальный отчёт peer-conversation собирается из журнала реплик, не «по памяти писателя» (DP.M.NNN)
- Напарник не вносит правки самостоятельно — только формулирует замечания
- Структурная переработка (v1 монолит → v2 N-частная) = успешный исход

## Применимость

Любые методологические тексты, где важны: полнота аргументации, доступность для новичка, отсутствие профессионального жаргона. Переносимо вне зависимости от темы текста.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Принятые замечания затмевают отклонённые | Внимание писателя — на «что поправить в v2», а отклонённые замечания и разногласия выпадают из поля зрения, хотя алгоритм требует их явной фиксации, — спорные решения тихо принимаются автономно вместо эскалации пилоту |
| Видимый результат (v2, git diff) читается как устранение слепых пятен | Внимание фиксируется на структурной переработке и diff как доказательстве качества, а журнал реплик, из которого обязан собираться финальный отчёт, остаётся на периферии — итог рискует быть собран «по памяти писателя», что инвариант прямо запрещает |

## Отличие от смежных методов

| Метод | Отличие |
|-------|---------|
| DP.M.067 (two-pass review) | Самопроверка одного агента; нет внешнего критика |
| DP.M.137 (auto-trigger subagent review) | Одноразовый субагент после первого раздела; нет turn-taking |
| DP.SC.154 | Это Service Clause (обещание канала); DP.M.162 = метод использования этого канала |
