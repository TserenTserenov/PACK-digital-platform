# DP.METHOD.109 — Проверка измерительного слоя перед ожиданием новых данных

## Описание

Если аналитическая задача блокируется на «недостаточно данных», сначала проверить три условия измерительного слоя — прежде чем ждать накопления новых наблюдений.

## IPO

**Input:** аналитическая задача, заблокированная предположением «мало данных» + наличие сырых событий за период

**Process:**
1. Проверить: сырые события уже собраны в хранилище? (если нет — ожидание оправдано)
2. Проверить: пересчёт покрывает всю популяцию, а не подмножество? (ошибка: 8/51 пилотов пересчитаны)
3. Проверить: материализуются ли снимки на каждом временном срезе? (ошибка: снимки не сохранялись)
4. Если хотя бы одно условие нарушено — ретро-прогон по уже собранным событиям даёт нужный результат без ожидания

**Output:** готовая аналитика на накопленных данных ИЛИ чёткая диагностика: «данных действительно нет» vs «измеритель сломан»

## Пример

WP-290: задача стояла год на допущении «ждём когорту N≥30», при этом в хранилище уже 1.29M событий. Реальный блокер — пересчёт работал у 8/51 пилотов, снимки не материализовывались. Ретро-прогон по накопленным событиям закрыл задачу без единого нового наблюдения.

## Тест применимости

«Сырые события в хранилище уже есть?» Нет → ожидание оправдано. Да → применять метод до решения о сборе новых данных.

## Антипаттерн

Ожидание новых данных при сломанном измерительном слое — накапливает такие же непересчитанные события; проблема не уменьшается.
