# DP.M.237 — Auto-route + explicit manual override affordance

## Описание

Метод UX-проектирования: при удалении choice-point из первого входа (auto-pick по pre-check для 95% случаев) обязательно сохранить **явный** affordance для изменения выбора в ongoing-интерфейсе. Без него auto-route создаёт hidden state без self-service пути для меньшинства, которому нужен другой вариант.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Без-трения первый вход ↔ агентность пользователя | Auto-route убирает вопрос для большинства, но скрывает точку выбора; explicit override возвращает контроль, но добавляет UI и рискует запутать новичка |
| Правильность дефолта для 95% ↔ обнаруживаемость для 5% | Для большинства pre-check достаточно, но для остальных affordance должен быть виден без помощи; чем меньше доля исключений, тем легче их забыть при дизайне |
| Простота onboarding-флоу ↔ стоимость ongoing UI | Каждый override-элемент — кнопка, команда, страница — увеличивает поверхность, которую нужно поддерживать и тестировать |

## Когда применять

- Onboarding flow с явным вопросом «Какой репо?» / «Какой tenant?» / «Какой проект?» при первом входе
- Pre-check позволяет определить выбор автоматически для большинства
- Существует ненулевая доля случаев, где пользователь захочет позже сменить выбор

## Антипаттерн

«Auto-route + админ через БД» — auto-pick на первом входе + смена решения только через ручное вмешательство (psql, скрипт админа). Создаёт hidden state, ломает self-service, маскирует ошибки pre-check.

## Алгоритм

1. Pre-check определяет дефолт → auto-route без вопросов (95% сценариев)
2. На ongoing-странице (settings / status / guide) добавить **явный** элемент:
   - Кнопка «Переподключить» / «Сменить репо» / «Перевыбрать tenant»
   - Команда (`/switch`, `/reconnect`)
   - Route к settings-странице
3. Affordance должен быть **обнаруживаем** без помощи — не скрытая команда, не админ-флаг

## Инвариант

- Любая точка выбора, скрытая на первом входе, имеет явный affordance в ongoing-UI
- Self-service путь смены решения существует без обращения к админу
- Affordance виден пользователю, не зашит в скрытую страницу

## Тест применимости

«Может ли пользователь захотеть позже сменить решение, принятое автомаршрутом?» Да → нужен явный affordance, не auto-only.

## Применимо к

- Onboarding flows (выбор репо, tenant, проекта)
- Default selections (язык, тема, регион)
- Auto-pick на первом контакте (default plan, default model)
