# DP.M.279 — HELD Patch Pattern

**Назначение:** сохранить готовую доработку без деплоя и без создания нового РП, когда деплой заблокирован внешним условием.

## Проблема

Peer-сессия нашла реальные дефекты в задеплоенном артефакте. Исправление готово, но деплой невозможен: незапушенный коммит параллельного агента, merge-конфликт, замороженный прод. Создавать новый РП — overhead. Хранить в голове/backlog — потеря контекста.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Немедленный деплой фикса ↔ внешний блокер | Исправление готово, но деплой невозможен; сохранение патча позволяет не терять контекст, но требует дисциплины применения позже |
| Новый РП ↔ потеря контекста | Создание отдельного РП для небольшого заблокированного фикса — overhead; хранение в голове или backlog приводит к забвению деталей |
| Чистая история git ↔ быстрое разблокирование | HELD-патч не вливается в основную ветку; это создаёт временный артефакт, но позволяет применить фикс ровно в момент разблокировки |
| Доверие к TTL-event ↔ неопределённость | Блокер должен иметь проверяемое событие разблокировки; без чёткого TTL патч может остаться применённым никогда |

## Решение: HELD-паттерн

1. **Создать патч:** `git diff HEAD > inbox/WP-NNN/refinement-<тема>.patch`
2. **Создать инструкцию:** `inbox/WP-NNN/HELD-<тема>.md` с разделами:
   - **Что сделать:** описание доработки
   - **Чего ждать (TTL-event):** конкретное событие разблокировки (merge ветки X, пуш Y)
   - **Как применить:** `git apply inbox/WP-NNN/refinement-<тема>.patch`
   - **Что проверить:** smoke-тест после применения
3. **Задеплоить при TTL-event:** apply patch → smoke → push → удалить HELD-файлы

## Когда применять

- Доработка готова, но заблокирована внешним событием с конечным TTL
- Блокер < 24-48ч (иначе → отдельный РП или branch)
- Контекст нужно сохранить точно, не пересказом

## Инварианты

- HELD-файлы коммитить в репо (не теряются при перезапуске)
- TTL-event должен быть проверяемым (`git log --oneline | grep <commit>`)
- После применения HELD-файлы удаляются из репо (`git rm`)

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Фикс маленький, я это запомню» | Недооценка потери контекста; незафиксированный патч исчезает после переключения на другие задачи или перезапуска среды |
| «Сделаю отдельный РП, чтобы не забыть» | Для блокера <24–48ч создаётся избыточный WP; overhead превышает пользу, а HELD-файл был бы точнее и быстрее |
| «Патч потом применится чисто» | Отсутствие инструкции и smoke-теста приводит к конфликтам применения; блокер может изменить кодовую базу, и diff перестанет ложиться |
| «HELD-файлы — мусор, держать их локально» | Патч не коммитится в репо; при перезапуске/сбое среды или rebase контекст теряется безвозвратно |
| «TTL-event и так очевиден» | Блокер формулируется размыто («когда они замёрджат»); без проверяемой команды патч никогда не активируется |
