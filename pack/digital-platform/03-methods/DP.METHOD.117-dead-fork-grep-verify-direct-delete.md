# DP.METHOD.117 Мёртвый форк скрипта: верификация grep + прямое удаление

## Контекст

В репозитории существуют две версии одного инструмента: оригинал (развивается) и локальная копия (заморожена). Копия возникла как «временный форк», но стала мёртвой. Задача: безопасно устранить.

## Алгоритм

### 1. Верификация гипотезы «мёртвый форк»

```bash
# Живые вызовы по пути копии?
grep -rn "<local-path-or-script-name>" ~/IWE/ --include="*.sh" --include="*.py" --include="*.md"

# Датировка: копия заморожена, оригинал развивался?
git log --oneline -- <path-to-copy> | head -3
git log --oneline -- <path-to-original> | head -3
```

Гипотеза подтверждена если: (а) ни одной живой ссылки на локальный путь; (б) копия заморожена, оригинал продолжал развиваться.

### 2. Удаление

```bash
git rm <path-to-dead-copy>
git commit -m "chore: remove dead fork of <tool> — no callers, canonical at <location>"
```

### 3. Почему НЕ wrapper-редирект

```bash
# НЕ делать:
echo '#!/bin/bash' > dead-copy.sh
echo 'exec /path/to/original "$@"' >> dead-copy.sh
```

Wrapper-редирект принципиально отклоняется:
- **Легитимизирует мёртвую точку входа** — будущий читатель/агент думает, что путь жив.
- **Прячет факт ошибки** вместо её устранения.
- **Создаёт второй технический долг**: позже нужно удалить и wrapper тоже.

## Критерии применимости

- В репо ≥2 версии одного инструмента (оригинал + копия).
- Копия имеет другой путь или имя.
- Цель — устранение путаницы, а не версионирование.

## Связи

- P3 инженерного стиля (DP.SC.172): мёртвую ветку/код — удалять, не «для совместимости». Данный метод даёт **процедуру верификации** перед удалением.
