# DP.METHOD.247 — integrity-лог без блокировки ритуала

## Суть метода

Проверка целостности (например, R23, читающий несколько логов на предмет аномалий) фиксирует найденную аномалию явной пометкой (например, «день untrusted») в отдельном integrity-логе, но не блокирует завершение самого ритуала (day-close). Наблюдаемость аномалии (что зафиксировано) отделена от решения прервать процесс (что сделать с этим) — второе, если нужно, реализуется отдельным явным гейтом.

## Обоснование

Автоматическая блокировка ритуала при каждой обнаруженной аномалии рискует создать множество ложных остановок для аномалий разной серьёзности. Разделение «зафиксировать» и «заблокировать» позволяет накапливать сигнал (для последующего анализа паттернов) без немедленного прерывания рабочего процесса на каждый случай.

## Применение

Дизайн проверок целостности внутри регулярных ритуалов (Close-протоколы), где не каждая обнаруженная аномалия должна останавливать выполнение.
