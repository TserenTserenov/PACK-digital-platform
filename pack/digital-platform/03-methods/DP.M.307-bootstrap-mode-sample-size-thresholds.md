# DP.M.307 — Bootstrap mode метрики по истории класса: hidden / interval / point

## Проблема

Производная метрика (рычаг, множитель, средний результат, коэффициент) требует накопленной истории, чтобы быть надёжной. Показать точечную оценку при N=2 — обман: один выброс качает всё значение, доверие к панели подрывается.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Раннее удовлетворение любопытства ↔ надёжность оценки | Пользователь хочет видеть метрику сразу после первого события, но точечная оценка на N=2 статистически бессмысленна и может ввести в заблуждение |
| Простота одного режима ↔ точность отражения неопределённости | Один способ показа метрики проще в реализации и восприятии, но три режима (hidden/interval/point) честнее отражают, насколько можно доверять числу при разном N |
| Явные пороги как параметр ↔ удобство магических констант в коде | Хранить BOOTSTRAP_HIDE/POINT как версионируемый параметр метода дороже, чем захардкодить числа в воркере, но иначе смена порога станет неотслеживаемым молчаливым изменением поведения |
| Ширина интервала vs скорость перехода в point-режим | Слишком широкий интервал в режиме interval — бесполезен пользователю; слишком узкий порог перехода в point — снова точечная оценка на недостаточных данных |

## Метод

Режим показа метрики определяется размером выборки N самого слабого класса периода. Явные пороги:

| Порог | Режим | Что показывается |
|-------|-------|------------------|
| N < BOOTSTRAP_HIDE (напр. 5) | hidden | Метрика скрыта, только сырые тайлы |
| BOOTSTRAP_HIDE ≤ N < BOOTSTRAP_POINT (напр. 5..15) | interval | Интервал с шириной по дисперсии |
| N ≥ BOOTSTRAP_POINT (напр. 15) | point | Точечная оценка |

Пороги — параметр метода-источника (версионируются вместе с формулой, см. frozen formula hash), не магические константы в воркере.

## Применимость

Новые дашборды пользователей, статистика редких событий, A/B-метрики в раннем окне — любые производные метрики с накапливаемой историей.

## Антипаттерн

Единственный режим «показывать точку всегда» с дисклеймером «учитывайте малую выборку» — никто не учитывает, доверие к платформе подрывается целиком.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| «Больше данных на экране — лучше UX» | Продуктовое мышление тянет к показу числа как можно раньше; статистическая надёжность выборки отходит на второй план перед желанием «дать пользователю фидбек» |
| «Пороги 5 и 15 — это же просто числа, потом настроим» | Пороги трактуются как временные заглушки для разработки, а не как параметр метода, требующий версионирования вместе с формулой — легко забыть закрепить их как change-controlled значение |
| «N считается по всей выборке периода» | Внимание может соскользнуть на агрегированный N, упуская, что порог должен применяться к N самого слабого класса — иначе один богатый данными класс маскирует нехватку данных в другом |
| «Интервал — это просто визуальное украшение точки» | Режим interval воспринимается как декоративный элемент (полоска погрешности), а не как самостоятельный честный сигнал «оценка приблизительна» |
