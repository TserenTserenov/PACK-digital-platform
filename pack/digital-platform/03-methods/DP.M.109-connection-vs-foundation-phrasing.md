# DP.M.109 — Метод операциональной точности интеграционных терминов

## Определение

При описании системы с **опциональной интеграцией** использовать явный интерфейсный глагол («подключается к X через Y») вместо неоднозначного глагола зависимости («базируется на X»).

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Краткость формулировки ↔ операционная точность | «Базируется на X» короче, но метод требует интерфейсного глагола с протоколом («подключается к X через Y»): фраза длиннее, зато фиксирует тип отношения и заменяемость (Claude через Anthropic API — LLM-движок, заменяем) |
| Гибкость архитектуры (опциональная интеграция) ↔ честность описания | Система работает автономно, X расширяет возможности — формулировка обязана показать деградацию без X, а не поломку, иначе читатель примет интеграцию за жёсткую зависимость |

## Алгоритм

1. **Определить тип отношения:** зависимость (не работает без X) или интеграция (работает автономно, X расширяет возможности).
2. **Выбрать глагол:**
   - Зависимость → «требует», «построен на», «зависит от»
   - Интеграция → «подключается к X через Y», «использует сервисы X по протоколу Y»
   - Встроенность → «включает», «содержит», «является частью»
3. **Добавить интерфейс:** при интеграции — явно указать протокол/интерфейс (MCP Gateway, OAuth, API).

## Пример применения

| До | После |
|----|-------|
| «IWE базируется на Платформе Aisystant» | «IWE подключается к Платформе Aisystant через MCP Gateway для получения сервисов» |
| «Агент основан на Claude» | «Агент вызывает Claude через Anthropic API (LLM-движок, заменяем)» |

## Тест

«Работает ли система без X?»
- Нет → зависимость → «требует / построен на»
- Да (с деградацией) → опциональная интеграция → «подключается к X через Y»
- Да (полностью) → X является расширением → «использует X при наличии»

## Применимость

Любые текстовые описания систем: Pack-документы, ADR, README, API-документация, публичные описания продукта.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Маркетинговая сила слова затмевает тест автономности | «Базируется на Платформе Aisystant» звучит солиднее «подключается через MCP Gateway» — глагол выбирается по звучанию, и тест «работает ли система без X?» не прогоняется |
| Выбор глагола затмевает указание интерфейса | Даже перейдя на «подключается», внимание останавливается на глаголе и не доходит до шага 3 — протокол/интерфейс (MCP Gateway, OAuth, API) не указывается, и формулировка остаётся непроверяемой для читателя |
