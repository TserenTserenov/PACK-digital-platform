# DP.M.060: Атомарные ВДВ-шаги

## Определение

Методическое требование к проектированию инструментов агентов (скиллов, протоколов, чек-листов): каждый шаг должен быть **атомарным**, то есть достаточно малым, чтобы для него можно было сформулировать одну проверяемую постусловие-проверку.

**Атомарный шаг = одно решение → одна верификация.**

## Тест атомарности

> «Можно ли написать формальный post-condition на выход этого шага?»

- **Да** → шаг достаточно атомарен. Применяется [[DP.M.012]] (Machine-Check Postcondition).
- **Нет** → шаг нужно дробить. Признак: внутри шага живёт несколько независимых решений или артефактов.

## Оговорка: семантическая целостность важнее формальной мелкости

Атомарность ≠ микрошаги. Декомпозиция останавливается на уровне «одно решение → одна верификация», не мельче.

**Антипаттерн пере-декомпозиции:**

- Шаг «найти файл» + «открыть файл» + «прочитать содержимое» — это микрошаги. Единое решение здесь — «получить содержимое файла X», верификация — «содержимое получено и не пусто». Дробление не даёт ценности.
- Шаг «согласовать имя файла + создать файл + записать в реестр» — это уже **не** атомарно: три разных решения с тремя разными режимами отказа. Дробить обязательно.

**Тест семантической целостности:** «Если шаг отвалится посередине — что я понял о причине провала?» Если ответ «не знаю, где именно» — шаг слишком крупный.

## Зачем

Без атомарности — два класса дефектов агентского исполнения:

1. **Пропуски шагов в чек-листах** — длинный шаг без проверяемого выхода легко проскочить мимо или объявить выполненным без реальной работы (паттерн P5-block).
2. **Галлюцинации в open-loop задачах** — крупный шаг с размытой post-condition позволяет агенту имитировать выполнение, не делая.

Атомарные шаги предотвращают оба класса: либо post-condition прошла, либо нет; «как бы выполнено» исключено.

## Связь с другими методами

- **[[DP.M.012]] Machine-Check Postcondition** — «как проверить шаг машиной». Этот метод (DP.M.060) — «какого размера должен быть шаг, чтобы такая проверка вообще была возможна». DP.M.060 — предусловие применимости DP.M.012.
- **ВДВ (внимание-действие-верификация)** — общая методическая рамка. DP.M.060 описывает, как масштабировать единичный ВДВ-цикл (он же — атомарный шаг).
- **[[DP.M.010]] WP-lifecycle** — РП декомпозируется в фазы, фазы — в атомарные ВДВ-шаги; этот метод задаёт нижнюю границу декомпозиции.

## Когда применять

- При проектировании нового скилла или протокола (Day Open, Close, Week Close, лесон, любой ритуал).
- При расширении существующего чек-листа: каждый новый пункт проходит тест атомарности.
- При ревью провалов агента (P5-block, пропуски, snapshot без проверки): если коренная причина — крупный шаг, декомпозировать.

## Когда **не** применять

- Тривиальные задачи ≤15 мин без артефактов (отчёт чата, разовое исследование). Атомарность здесь — оверхед.
- Творческие шаги (генерация черновика, мозговой штурм), где post-condition по определению субъективна. Атомарность к ним не применима — там работает другой контроль качества (ревью человеком, ArchGate).

## Антипаттерны

- **Пере-декомпозиция.** Дробление микрошагов без независимой проверяемости («открыл файл», «прочитал», «закрыл»). Шум, не ценность.
- **«Шаг с тремя выходами».** Один пункт чек-листа создаёт три разных артефакта. Расщеплять обязательно — иначе пропуск одного из выходов остаётся незамеченным.
- **«Post-condition без проверки».** Формулировка post-condition есть, но способа машинной проверки нет. Допустимо только для творческих шагов (см. выше); для процедурных — переформулировать или дробить.

## Источник

Принцип сформулирован 6 мая 2026 в рамках замысла «Журнал решений, повтор и параллельные пути» (WP-295). Гипотеза автора: атомарные ВДВ-шаги (короткие, с явным post-condition) → меньше пропусков и галлюцинаций; крупные шаги без проверки — основной источник P5-block (853 срабатывания за апрель в 104 сессиях).

Зафиксирован как методическое требование без отдельного РП — обновление Pack силами WP-295.
