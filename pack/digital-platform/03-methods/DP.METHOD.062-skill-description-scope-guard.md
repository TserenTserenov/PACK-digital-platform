# DP.METHOD.062 — Skill description scope guard: что входит в SKILL.md, что нет

## Назначение

SKILL.md описывает контракт (обещание + алгоритм) специализированного умения агента. Этот scope guard определяет, что в SKILL.md должно быть, что не должно — и куда маршрутизировать остальное.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Полнота трёхблочной структуры (`When to use`/`Algorithm`/`Appendix`) ↔ простота skill-файла | Жёсткая структура гарантирует, что агент найдёт нужное, но для простого skill'а это может быть избыточной церемонией — пустые секции «для галочки» |
| Строгость маршрутизации по 5 строкам таблицы «Что НЕ входит» ↔ удобство держать всё под рукой в одном файле | Размазывание доменного знания/архитектурных решений/истории сессий по пяти разным местам усложняет автору skill быстрый обзор, но всё в одном SKILL.md нарушает Routing Gate и плодит второй source of truth |
| Низкий порог теста применимости («удалить блок — алгоритм всё ещё понятен?») ↔ риск потери полезного неформального контекста | Тест намеренно строг к вычищению SKILL.md, но примеры/edge cases, которые технически не входят ни в Algorithm, ни в Appendix, могут облегчать агенту решения — тест не различает «лишнее» и «неформально полезное» |

## Что входит в SKILL.md

| Блок | Назначение |
|------|-----------|
| `## When to use` | Когда использовать скилл (триггеры, scope, NOT) |
| `## Algorithm` | Пошаговый алгоритм (IPO) |
| `## Appendix` | Справочные данные (таблицы, форматы) |

## Что НЕ входит в SKILL.md (куда маршрутизировать)

| Что НЕ входит | Куда |
|---------------|------|
| Доменное знание (что такое Pack, как работает KE) | Pack-файлы (DP.D.*, DP.METHOD.*) |
| Архитектурные решения (почему так, а не иначе) | DP.ARCH.NNN или пир-сессия report.md |
| Истории сессий / changelog | sessions/*.md |
| Временные договорённости / defer-списки | inbox/extraction-reports/*.md |
| Платформенные правила (CLAUDE.md-уровень) | CLAUDE.md или PACK-agent-rules |

## Тест применимости

«Если удалить этот блок из SKILL.md — алгоритм скилла всё ещё понятен агенту без него?» Да → блок в SKILL.md не нужен, маршрутизировать в Pack / sessions.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего. Статус карточки — `draft`: пометка `tentative` по прецеденту WP-448 Ф12._

| Bias | Direction of distortion |
|------|--------------------------|
| _(tentative)_ Архитектурное обоснование смешивается с Algorithm | При написании SKILL.md автор дописывает «почему так, а не иначе» прямо внутри `## Algorithm`, потому что решение принималось только что и контекст ещё «в голове» — внимание смещается с описания шагов на обоснование выбора, хотя маршрут для этого контента — DP.ARCH.NNN (строка 2 таблицы «Что НЕ входит») |
| _(tentative)_ Appendix как «безопасное» хранилище временного | При появлении временной договорённости в процессе работы над skill'ом внимание тянется записать её прямо в `## Appendix` «чтобы не потерять», а не в inbox/extraction-reports — Appendix воспринимается как место для любого нужного-сейчас факта, хотя по scope guard туда входят только справочные форматы/таблицы |

## Связь с DP.D.147

Scope guard задаёт «минимальный содержательный барьер» (DP.D.147): SKILL.md проходит если все три обязательных секции присутствуют с содержательным наполнением. Инфраструктурная оболочка без алгоритма = не проходит.
