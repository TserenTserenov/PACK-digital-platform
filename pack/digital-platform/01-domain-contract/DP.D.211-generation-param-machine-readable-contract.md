# DP.D.211 — Параметр генерации как машиночитаемое поле-контракт ≠ инструкция только в промпте

**Различение:** параметр LLM-генерации, выраженный машиночитаемым полем в артефакте (frontmatter/YAML), ≠ тот же параметр, живущий только внутри промпта.

| Аспект | Поле-контракт в артефакте (frontmatter) | Инструкция только в промпте |
|--------|----------------------------------------|------------------------------|
| Проверяемость | Читается из канона артефакта → тест по полю | Нет способа проверить без прогона LLM |
| Изменяемость без ведома | Трудно: изменение видно в diff файла | Легко: промпт меняется незаметно |
| Поведение при сбое без наблюдателя (headless) | Параметр виден, несоответствие обнаруживается | Тихое смещение: объём/глубина меняется без теста |
| Пример | `_RUNG_DEPTH: shallow` в frontmatter руководства | `# Пиши коротко, пилот начинающий` внутри system prompt |

**Тест:** «Если параметр изменится, будет ли это зафиксировано в тесте по каноническому артефакту?»
- Да (читается из поля) → поле-контракт, тестируемо.
- Нет (живёт только в промпте) → нет теста → headless-генерация молча меняет поведение.

**Когда критично:** для задач без наблюдателя (ночной рендер, scheduled headless) поле-контракт > промпт-комментарий: иначе нет способа убедиться, что глубина/объём руководства соответствует ожиданию.

**Родственно:**
- «Подсказка показана ≠ ответ затребован (E3-prompted ≠ E3-displayed)» — та же тема «сделать невидимое проверяемым»: E3 через presence-check в артефакте, данное — через поле-контракт в frontmatter.

**Источник:** WP-149 B4, параметр `_RUNG_DEPTH` (shallow|medium|deep) → frontmatter рендеримого руководства.
