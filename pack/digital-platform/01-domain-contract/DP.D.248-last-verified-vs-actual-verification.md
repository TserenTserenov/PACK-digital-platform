# DP.D.248 — `last_verified` timestamp ≠ реальная верификация

## Различение

| Аспект | `last_verified` (поле) | Реальная верификация |
|--------|------------------------|---------------------|
| **Что отражает** | Когда скрипт/синхронизация обновил поле | Когда агент/человек фактически проверил содержимое |
| **Пример** | Sync-скрипт устанавливает `last_verified: today` при каждом прогоне | Агент прочитал запись, сравнил с источником, подтвердил корректность |
| **Риск смешения** | Отчёт показывает «зелёный» для записей, которые никто не проверял | — |
| **Тест** | «Кто именно и что проверил?» | Если ответ «скрипт синхронизации» → не верификация |

## Инвариант

Поле `last_verified` (или `*_checked`, `*_confirmed`) обновляется **только при явном
verification-шаге с конкретным результатом**: что проверено + кем + вывод.
Синхронизация без проверки содержимого не является верификацией.

## Тест

«Кто именно и что проверил при последнем обновлении `last_verified`?»
- Ответ: «скрипт синхронизации» → не верификация → поле установлено некорректно
- Ответ: «агент сравнил запись X с источником Y, вывод: актуально» → верификация

## Контекст

WP-7 D3: реестр-каталог автоматически обновлял `last_verified` при каждой синхронизации
без проверки содержимого. Отчёт о свежести показывал зелёный для всех записей.
Фикс: поле устанавливается только при явном verification-шаге.
