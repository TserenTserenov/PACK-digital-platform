# DP.D.216 — Outcome-DoD ≠ Output-DoD

| Outcome-DoD | Output-DoD |
|-------------|------------|
| Обещанный результат работает у получателя в проде | Артефакт слит в основную ветку, код зелёный |
| Verifier подтверждает + наблюдение устойчивости (7 дней без regression) | Одноразовая проверка в момент слияния |
| «Руководство реально пересобирается для ≥1 живого пилота» | «B-серия влита, тесты зелёные» |
| Изменение в метрике ценности получателя | Изменение в техническом состоянии репозитория |

**Почему важно:** Закрытие РП по output-DoD создаёт иллюзию завершённости — код слит, задача «сделана», но обещание ещё не выполнено у получателя. Output-DoD необходим, но недостаточен: код можно слить, но система не перестраивает руководство для конкретного пилота.

**Тест:** «Обещание, ради которого открывался РП, реально работает у получателя в проде?» Нет → только output-DoD, РП не закрыт.

**Связано с:** DP.D.148 (Walkthrough ≠ Smoke — методы проверки), «Inventory ≠ Progress» (слитый код ≠ доставленная ценность).
