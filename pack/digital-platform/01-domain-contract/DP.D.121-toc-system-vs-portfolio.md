# DP.D.121 ТОС-горлышко системы ≠ горлышко портфеля проектов

| Аспект | Система с единым throughput | Портфель N направлений |
|--------|----------------------------|------------------------|
| **Структура** | Один продукт через одну линию | N параллельных критических путей |
| **Throughput-метрика** | Единая (выход системы) | По одной на путь (cohort retention, monetization, и т.д.) |
| **Применимость ТОС** | Прямая — ищем одно bottleneck | Через каждый путь отдельно — N локальных bottleneck |
| **Старшее ограничение** | Технологическое звено | Часто resource (один исполнитель N путей) |

## Категориальная ошибка

Применение вопроса «где одно горлышко?» к зонтичному РП или портфелю — категориальная ошибка. Ответ «одно горлышко = WP-XXX cutover» = ловушка локального оптимума: cutover закрывает один путь, остальные N-1 продолжают терять throughput.

## Эвристика для портфеля

1. Перечислить критические пути (по бизнес-цели — retention, attraction, measurement, resource, monetization)
2. Для каждого пути назвать physical step + ограничение
3. Если у нескольких путей ограничение = один и тот же ресурс (исполнитель, бюджет, доступ) — это **resource constraint** и оно старшее (доминирует над технологическими, см. DP.M.259)

## Тест

«Есть ли в РП единый throughput-метрик?» Да → ТОС работает напрямую. Нет (несколько каналов/направлений) → ТОС применяется к каждому пути отдельно.
