# DP.D.205 — WP-ID vs PII: публичный идентификатор задачи ≠ персональные данные

## Различение

| WP-\d+ (публичный ID) | Raw profile score (PII) |
|-----------------------|------------------------|
| `WP-428`, `WP-123` | `cp.rhy=3`, `stage=2` |
| Виден в публичном реестре | Хранится только в личном профиле |
| Пользователь сам пишет его в чате | Пользователь не знает точных значений |
| Нет привязки к личности | Явная привязка к личности через telegram_id |
| Только логировать | Блокировать при распространении |

## Классификация для PII-guard

**Блокирующие (fail-closed):**
- Raw profile scores: `cp.rhy=3`, `cp.wld=2`, `stage=5`
- Email-адреса
- `telegram_id` в явном виде

**Только логируемые (логируем, не блокируем):**
- `WP-\d+` — номера задач из реестра
- Названия задач из WP-REGISTRY
- Имена файлов из публичных репо

## Тест применимости

> «Может ли пользователь сам упомянуть эту строку в публичном чате без раскрытия приватных данных?»

- **Да** → категория логируемых, не блокировать
- **Нет** → категория блокирующих

## Контекст

WP-428 Ф2: PII-guard первоначально блокировал паттерн `WP-\d+` как потенциально приватный. Solo-mode adversarial review (advokat dyavola) опроверг: WP-номера видны в публичном реестре, пользователь сам пишет их в боте. Блокирование создаёт false positive, ломает UX для легитимных вопросов («что такое WP-428?»).
