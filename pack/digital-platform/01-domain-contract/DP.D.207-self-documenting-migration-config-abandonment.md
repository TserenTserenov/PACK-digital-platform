# DP.D.207 — Самодокументирующийся «для будущей миграции» конфиг = сигнал заброшенности

**Различение:** черновик (work-in-progress, к которому вернутся) ≠ заброшенный артефакт (мёртв, но не удалён).

**Тест:** «Конфиг объясняет, почему он сам не работает?»
- Да (пишет «scheduler hardcoded, config для будущей миграции») → заброшенность: автор зафиксировал нерабочесть и ушёл, миграция не случилась.
- Нет (описывает рабочее состояние) → черновик/рабочий артефакт.

**Три независимых сигнала заброшенности (триангуляция):**
1. Артефакт попал в репозиторий случайно — `git add -A` вместо явного pathspec (его не коммитили осознанно).
2. Конфиг самодокументирует себя как «для будущей миграции» / «пока hardcoded» — некролог в комментарии.
3. Живой код питается из другого источника (другого репозитория), а этот слой — осиротевшая копия.

Один сигнал = подозрение; три независимых = уверенный диагноз заброшенности.

**Почему важно:** заброшенный артефакт, принятый за черновик, провоцирует спекулятивную работу «надо доделать» вместо удаления. Диагноз «заброшенность» → решение «удалить или явно реанимировать под задачу», не «дорабатывать вслепую».

**Связи:** AR.254 (спекулятивный анализ без binding question) — заброшенный артефакт частый триггер соблазна такого анализа.
