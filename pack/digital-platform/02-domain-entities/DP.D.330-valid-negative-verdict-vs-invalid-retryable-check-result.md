# DP.D.330 — Валидный отрицательный вердикт ≠ невалидный результат проверки

## Различение

| | Невалидный результат проверки | Валидный отрицательный вердикт |
|---|---|---|
| **Признак** | Ответ не прошёл валидацию формата | Ответ прошёл строгую валидацию и содержит `verdict=fail` |
| **Реакция раннера** | Retryable: проверку просят повторить | Терминально: запуск завершается как failed с машинным кодом причины |
| **Ошибка, если не так** | — | Корректный fail идёт по пути повтора; раннер зацикленно требует от исполнителя положительный ответ |

## Механизм

Шаг проверки принимал `verdict=pass|fail` как контракт формата, но общий postcondition требовал `pass`. Из-за этого корректный `fail` попадал в тот же путь, что и невалидный вывод, и раннер зацикленно просил повторить проверку до получения `pass`. Исправление вводит отдельный терминальный путь: строго провалидированный `verdict=fail` завершает запуск как failed с машинным кодом причины, а прочие невалидные ответы остаются retryable. Итоговая формулировка источника: корректный отрицательный результат — это завершённая проверка с ошибкой, а не повод требовать от исполнителя ложный положительный ответ.

## Тест различения

«Раннер различает „ответ не прошёл валидацию формата“ и „ответ валиден и говорит fail“? Валидный fail завершает запуск терминально с кодом причины, а повтор запрашивается только для невалидного ответа?» Нет → воспроизведена ошибка: цикл повторов до появления pass.

## Границы

Различение применимо там, где формат ответа проверки задан контрактом (`verdict=pass|fail`) и есть общий postcondition. Терминальность fail опирается на строгую валидацию ответа: ответ, не прошедший валидацию, остаётся retryable.
