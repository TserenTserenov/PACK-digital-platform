# DP.D.111 Триаж ≠ Исполнение

**Источник:** session-close 2026-05-29 (peer-session 06 operational-triage-night)
**Тип:** distinction (операционное различение)

## Определения

- **Триаж (decision-support):** фаза принятия решений о каждом пункте списка — без немедленного исполнения. Результат = решение зафиксировано, файл/состояние ещё не изменены.
- **Исполнение (execution):** фаза изменения состояния — файлы редактируются, коммиты делаются, статусы обновляются.

## Тест

«Принято ли решение или уже меняется файл?»
- Только принято → триаж
- Файл изменяется → уже исполнение

## Анти-паттерн

Смешение triage + execution в одной фазе = WIP inflation: начинается параллельно много задач (dirty-файлы, незакрытые сессии, просроченные РП), ни одна не доводится до конца.

## Правильный паттерн

**Фаза А (triage):** пройти по каждому пункту, вынести решение, зафиксировать. Сами пункты — не трогать.
**Фаза Б (execution):** исполнить принятые решения по очереди.

## Применимость

- Операционный триаж (dirty-файлы, незакрытые сессии, просроченные РП)
- Inbox-разбор (task triage до task execution)
- Любой список неопределённых элементов перед рабочей сессией
