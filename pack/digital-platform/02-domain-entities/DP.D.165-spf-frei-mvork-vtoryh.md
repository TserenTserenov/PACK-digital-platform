# DP.D.165: SPF (фреймворк вторых/доменных принципов) ≠ Pack (результат применения SPF)

| SPF | Pack |
|-----|------|
| Фреймворк: требования + процесс | Результат применения фреймворка |
| Задаёт форму и критерии домена | Наполненный инженерный ядро-учебник домена |
| Один на платформу (`~/IWE/SPF/`) | Много инстансов (по одному на домен) |
| «Как можно собрать учебник» | «Собранный учебник конкретной области» |

**Почему важно**: `SPF/README.md` явно: «Pack — результат применения SPF». Путать фреймворк с его инстансом — то же, что путать форму с отливкой. Это специализация A.7 (Method ≠ Tool, Object ≠ Description) для платформенной терминологии.

**Соответствие первоисточнику (Левенчук, слайды 28.06.2026, перепроверено; поправка 08.07.2026 — прямая сверка `~/IWE/FPF/FPF-Spec.md`):** Левенчук-«DPF» («учебник предметной области», «вторые принципы») это наполненное СОДЕРЖАНИЕ домена, которое он генерирует одним запросом. Это = IWE-«Pack». То есть **Pack = DPF**.

**Поправка 08.07.2026:** утверждение «у Левенчука отдельного имени для станка нет» — устарело. Прямая проверка `FPF-Spec.md` (строка 270) показала: паттерн `E.4.DPF` («Domain Principle Framework Authoring and Publication-or-Access Carrier Assembly») — это и есть имя станка: конвейер сборки доменного учебника (SoTA-пакеты источников, решения по архитектуре паттернов, маршрут именования, тела зрелых паттернов, реестр связей и редакций, каналы публикации, цикл качества, маршрут актуальности). То есть **`E.4.DPF` ≈ наш «SPF»** (станок, не содержание). Прежний вывод «имени нет» — следствие недостаточно глубокой сверки на момент 28.06, не эволюция терминологии Левенчука после этой даты.

Асимметрия сохраняется: IWE держит «SPF» отдельным словом для методологии/процесса, у Левенчука это подпаттерн `E.4.DPF` внутри общей архитектуры `E.4` (FPF Ecosystem Family Architecture). Переименование не требуется — только уточнение соответствия.

**Асимметрия фреймворк/содержание:** `FPF` = фреймворк + содержание (формат-апарат E.8 плюс наполненные первые принципы). `SPF` = только фреймворк (форма + процесс, без доменного содержания). `Pack` = только содержание (наполненные доменные принципы по форме SPF). «Вторые принципы» = «доменные принципы» (синонимы); отказываться от термина не нужно, нужно держать соответствие Pack=DPF.
