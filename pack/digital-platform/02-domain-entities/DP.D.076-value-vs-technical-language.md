# DP.D.076: Ценностный язык ≠ Технический язык в user-facing копии

> **Применять на границе внутреннего домена и пользовательского интерфейса.** Технический язык корректен в Pack, документации для разработчиков, промптах агентов. Ценностный язык обязателен в боте, онбординге, хелпдеск-текстах, email-шаблонах.

## Различение

| Аспект | Технический язык | Ценностный язык |
|--------|-----------------|-----------------|
| **Аудитория** | Разработчик системы | Конечный пользователь |
| **Ссылки** | ID схемы, имена таблиц, номера правил (FORM.089, DP.SC.105) | Выгода для пользователя (что получу, зачем, как меняет жизнь) |
| **Пример «до»** | «Aisystant отправляет события в Activity Hub через DP.SC.105» | — |
| **Пример «после»** | — | «Система отслеживает ваш прогресс автоматически» |
| **Тест** | Точность описания механизма | Понимание пользователем своей выгоды |

## Тест

«Если убрать этот термин — потеряет ли пользователь понимание своей **выгоды**?» Нет → убрать (технический язык). Да → переформулировать через ценность или оставить.

## Применение

- Боты и чат-интерфейсы
- Онбординг-сообщения и welcome-тексты
- Хелпдеск-инструкции для пользователей
- Email-шаблоны и push-уведомления
- Любой текст, где разработчик говорит с конечным пользователем

## Failure mode (нарушение)

Упоминание в user-facing копии: FORM.NNN, имён таблиц, DP.IDs, DP.SC.NNN, GDPR-терминологии, технических идентификаторов ролей (Аттестатор, Проектировщик).
