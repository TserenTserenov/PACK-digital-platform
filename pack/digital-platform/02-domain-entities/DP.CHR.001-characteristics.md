# Характеристики платформы IWE

## 1. Концепция

По аналогии с характеристиками созидателя (PACK-personal/pack/personal-development/02-domain-entities/characteristics/PD.CHR.001-characteristics.md), но субъект измерения — сама платформа, не пользователь:

```
Характеристика → Показатель → Значение → Состояние
     (CHR)         (Metric)    (Value)    (State)
```

## 2. Различение: характеристика платформы ≠ архитектурная характеристика (DP.ARCH.001 §4)

[DP.ARCH.001](DP.ARCH.001-platform-architecture.md) §4 (ЭМОГССБ + L2) — критерии оценки **архитектурного решения** в момент принятия (используются АрхГейтом, разово на решение). Эта карточка — **непрерывно измеряемые состояния** уже работающей платформы (аналог vitals/дашборда, значение меняется во времени). Имена могут совпадать («Экономичность», «Безопасность») — это родственные, но не тождественные оси: одна оценивает решение один раз, другая наблюдает состояние платформы постоянно.

## 4. Границы (по аналогии с WP-151 § Границы и термины)

- Не дублирует WP-212 (security audit cadence — источник данных для DP.CHR.001.3, не переизобретается).

## 5. Осталось (для Ф1+, вне узкого объёма Ф0)

- Свести per-call данные DP.SC.145 (cost/tokens) в накопительный ряд по DP.CHR.001.2 — источник есть, ряда нет.
- Свести обещанный RPO/RTO (DP.SC.131, DP.SC.008) в фактический ряд по DP.CHR.001.4 — обещание есть, факт-ряда нет.
- Интеграция с кодом/дашбордом/Neon-хранением — по триггеру, не в Ф0.
- Решить, нужны ли отдельные файлы DP.CHR.002+ на каждую характеристику (по образцу PD.CHR.002+) — пока все 4 умещаются в одной карточке.
