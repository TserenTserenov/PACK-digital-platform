# DP.D.189: no ≠ conditional-no ≠ defer (три статуса готовности системы к охвату)

При оценке готовности компонента к включению в систему ярлык «нет» скрывает три принципиально разных состояния с разными путями разблокировки:

| Статус | Смысл | Что нужно для разблокировки |
|--------|-------|----------------------------|
| **no** | Нет ни роли, ни моста, ни кода — не планируется | Стратегическое решение начать |
| **conditional-no** | Условие гипотетическое, в работе нет | Конкретное решение о реализации условия |
| **defer** | Работа уже начата, ждёт конкретного блокера | Устранение одного названного блокера |

**Почему важно**: одинаковый ярлык «нет» для разного уровня готовности вводит в заблуждение при планировании бэклога — создаётся иллюзия одинакового расстояния до готовности. `defer` намного ближе к `yes`, чем `no`.

**Тест:** «есть ли уже начатая работа, ведущая к этому состоянию?» Да → defer. «Есть гипотетическое условие, но оно не в работе?» → conditional-no. «Ничего нет и не планируется?» → no.

**Контекст:** WP-457 Ф10 (State-Transition Gate), статусы охвата осей Включённость и Забота (2026-07-05).
