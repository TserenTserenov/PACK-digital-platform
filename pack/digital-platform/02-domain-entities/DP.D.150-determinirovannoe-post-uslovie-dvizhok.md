# DP.D.150: Детерминированное пост-условие (в движок) ≠ Семантическое пост-условие (в Haiku)

| Детерминированное | Семантическое / Качественное |
|-------------------|------------------------------|
| bash-проверки: grep / git / test | LLM-оценка: Haiku R23 |
| Объективный результат: 0 или 1 | Нюансированный результат: шкала / обоснование |
| Живёт в rule-engine.sh на событии Close | Вызывается после детерминированного прохода |
| Ноль токенов, полностью детерминирован | Небольшой LLM-вызов, ненулевые токены |
| Рефлекс (lookup в реестре AR) | Делиберация (LLM для граничных случаев) |

**Принцип (WP-295 Ф5, вариант A):** детерминированные post-conditions — ВНУТРЬ движка правил; семантические/качественные — делегировать Haiku. Это делегирование, а не дублирование.

**Тест:** «Можно ли проверить это условие grep/git/test без LLM?» Да → детерминированное (в движок). Нет → семантическое (в Haiku R23).

**Граница:** совпадает с [[Рефлекс ≠ интеллект]] (distinctions.md). Post-condition = рефлекс если lookup в реестре; остальное — делегирование Haiku.
