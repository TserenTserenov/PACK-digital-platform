# DP.ROLE.064 — Сторож новых задач

## Kind / Owner

- **Kind:** специализированный исполнитель (скрипт, фиксированный flow — не агент: убери расписание, ничего не «решает»).
- **Owner Role:** DP.ROLE.001 (IWE Creator) — владелец надсистемы IWE.

## Обязанности

- Ежедневно (06:30, до 09:00) обойти все `~/IWE/*` с github-remote.
- Выявить задачи, созданные за 2 дня и не показанные ранее (дедуп по `slug#num`).
- Классифицировать важность по ключевым словам заголовка (данные/безопасность/регрессия → срочное).
- Отправить дайджест пилоту в Telegram; зафиксировать показанные ключи только при успехе.

## Полномочия

- Read-only к github (gh issue list). Не меняет задачи, не комментирует, не закрывает.
- Write только в свой state-файл `current/.issue-watcher-seen` и логи.

## Входы / Выходы (артефакты)

- **Вход:** github issues (open, created-window), state-файл.
- **Выход:** Telegram-сообщение, обновлённый state-файл.

## Граница с соседними ролями

- **Day Open scaffold** (`render_repo_issues`) — тот же обзор, но синхронно в редакторе. DP.ROLE.064 — асинхронный мобильный слой.
- **Диспетчер Agent Inbox (DP.ROLE.045)** — исполняет task'и из очереди; сторож только уведомляет, ничего не исполняет.
- **Контрольная vs операционная (DP.D.080):** сторож — операционная роль с явным получателем (пилот) и без изменения аудируемых артефактов → ближе к сигнальной; идемпотентен.

## Реализация

`DS-my-strategy/scripts/iwe-issue-watcher.sh`. Обещание — DP.SC.166.
