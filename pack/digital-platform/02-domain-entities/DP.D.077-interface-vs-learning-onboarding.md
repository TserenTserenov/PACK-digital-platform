# DP.D.077: Interface Onboarding ≠ Learning Onboarding

> **Не путать с «туром по продукту».** Тур по продукту — это маркетинговый формат ознакомления. Interface Onboarding — технический слой подсказок при первом использовании команды; Learning Onboarding — содержательный слой первого урока или первого slot.

## Различение

| Аспект | Interface Onboarding | Learning Onboarding |
|--------|---------------------|---------------------|
| **Объект обучения** | Как работает интерфейс (нажать, подключить, запустить команду) | Что делать с содержанием (первый урок, первый slot, первая неудовлетворённость) |
| **Триггер** | Первое использование конкретной команды/канала (`first_use_{command}` флаг) | Первый вход в контент (lesson_started, slot_logged) |
| **Повторяемость** | После первого раза — краткий вариант или отсутствует (progressive disclosure) | Контент всегда полный, но уровень адаптируется к ступени |
| **Канал** | Специфичен для канала (Bot: inline; Browser: MCP intro; VS Code: day-open hint) | Единый контент через разные каналы |
| **Cognitive load** | Снижает friction при работе с интерфейсом | Вводит в предметную область |

## Тест применимости

«Пользователь не понимает, *как* запустить действие или *что* оно сделает с интерфейсом?» → Interface Onboarding.
«Пользователь не знает, *зачем* и *что изучать* в системе?» → Learning Onboarding.

## Антипаттерн

Смешение двух слоёв: новый пользователь одновременно изучает «как нажать кнопку» и «что делать дальше» → cognitive overload. Признак: один экран онбординга пытается и объяснить интерфейс, и ввести в содержание.

## Техническая реализация (пример)

- Флаги `first_use_{command}` в user state → при первом вызове команды показывается expanded hint, при повторном — краткий или пропускается.
- Каждый канал (бот, браузер, git-secret, git-explicit, VS Code) имеет свой набор interface-подсказок.
- Learning Onboarding живёт в отдельном потоке (первый урок, первый slot).
