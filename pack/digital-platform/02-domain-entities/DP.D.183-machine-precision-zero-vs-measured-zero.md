# DP.D.183 Машинный ноль в измеренном поле ≠ результат измерения «ноль»

| Аспект | Машинный ноль (0.0 точно) | Результат измерения «ноль» |
|--------|--------------------------|--------------------------|
| **Семантика** | Writer не читал источник данных / использовал default-значение | Измерение выполнено, за период ничего не нашлось |
| **Диагноз** | Сломан парсер / нет доступа к источнику | Пилот действительно не был активен |
| **Смежные поля** | Другие поля тоже равны нулю с машинной точностью | Соседние счётчики могут быть ненулевыми |
| **Реакция** | Проверить pipeline: запустился ли парсер, было ли чтение источника | Принять как факт |

## Инвариант

Машинная точность (`0.0` без дроби) в поле, измеряющем непрерывную величину, — сигнал отсутствия реального замера, не результата «ноль». При реальном нуле из измерения появится объяснение в смежных полях или дробная часть.

## Применение

При диагностике аномалий в measurement pipeline: если видишь точный ноль в поле `active_hours`, `duration_sec`, `event_count` — сначала проверить, запустился ли парсер и было ли чтение источника данных (WakaTime, DB, лог) до вывода «пилот был неактивен».

## Тест

«`human_active_h = 0.0` — результат или default?»
- Все смежные поля тоже равны 0.0 с машинной точностью → скорее всего default (writer не читал данные)
- Только это поле равно нулю при ненулевых соседях → возможен реальный нулевой результат
