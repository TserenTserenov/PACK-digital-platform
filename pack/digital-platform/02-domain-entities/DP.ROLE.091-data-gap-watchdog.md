# DP.ROLE.091 — Сторож данных (data-gap watchdog)

## Kind / Owner

- **Kind:** специализированный исполнитель (скрипт, фиксированный flow, cron/launchd — не агент: убери расписание, ничего не «решает»).
- **Owner Role:** DP.ROLE.001 (IWE Creator) — владелец надсистемы IWE (прецедент — DP.ROLE.064 Сторож новых задач).

## Обязанности

- Периодически (интервал = наименьший `freshness_sla` среди зарегистрированных потоков) читать timestamp последней записи каждого потока из реестра конвейеров (WP-476 Ф3): health.db, WakaTime — стартовый набор.
- Сравнить разрыв с числовым порогом потока; превышение → Telegram-алерт с указанием потока и длительности разрыва.
- На Week Close — запустить self-test: внести детерминированный canary-факт (искусственный разрыв, который no-op-чекер физически не может пройти зелёным) и подтвердить, что детектор его ловит; провал — зарегистрировать инцидент, не тихий warning.
- Различать «источник молчит» (infrastructure error — невалидный ключ, недоступна БД) от «реально ноль» — не писать ложный ноль вместо алерта.

## Полномочия

- Read-only к домам данных (health.db, WakaTime API). Не мутирует дома данных, только читает last-timestamp.
- Write только в свой state-файл (дедуп/cooldown алертов, по образцу `date-watchdog.sh`) и логи.

## Входы / Выходы (артефакты)

- **Вход:** health.db (`~/Library/IWE/health-data/health.db`), ответ WakaTime REST API, числовые пороги из реестра конвейеров WP-476 Ф3.
- **Выход:** Telegram-алерт (реальный разрыв), self-test verdict PASS/FAIL (Week Close), запись в state-файл.

## Граница с соседними ролями

- **Process-watchdog слой** (`date-watchdog.sh`, `day-open-pipeline-watchdog.sh`, `alerter.py` — без собственной Pack-регистрации на 16.07) — следит, запустился ли процесс-производитель по расписанию. Сторож данных следит за содержимым результата этого процесса: процесс может отработать «успешно» и не записать ни одной актуальной строки (ровно так был пропущен разрыв 45ч в WP-470) — два разных слоя одного риска, не дублирование.
- **WP-429 Layer 1/3 checkers** (`f5_hot_diff_guard.py`, `layer3_registry_checker.py`) — тот же архитектурный паттерн (периодический батч с self-test/canary), применённый к Pack-контенту и реестрам, не к персональным данным пилота. Сторож данных — тот же класс механизма («semantic gate»/П3), другой домен.
- **DP.ROLE.064 (Сторож новых задач)** — тот же Kind (специализированный скрипт-исполнитель, владелец DP.ROLE.001), другой домен (github issues, не данные пилота).
