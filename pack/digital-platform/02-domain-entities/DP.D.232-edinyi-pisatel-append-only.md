# DP.D.232: Единый писатель append-only журнала (один writer-модуль) ≠ N независимых писателей

Append-only журнал решений/событий должен иметь РОВНО одного писателя — единую функцию-writer в одном модуле (`classify_and_log(inp, source)`). При N независимых писателях: (1) дрейф формы записи между ними; (2) каждый новый исполнитель, пишущий своим `printf`/`puts`, воспроизводит обход централизованной двери (gate) без изменения кода двери.

**Следствие для gate-enforcement:** поле `source` в каждой записи позволяет различать исполнителей — на нём держится критерий приёмки «хотя бы одна запись от каждого обязательного исполнителя».

**Тест:** «Могу ли я добавить нового исполнителя, не зарегистрировав его через единственную функцию-writer?» Да → писателей N, обход возможен. Нет → единственный writer.

**Связано с:** «Дедуп-гейт отправителя ≠ приватная защёлка» (там — readers журнала; здесь — writers), «Детектор существует ≠ детектор блокирует» (смежный класс: enforcement через единственную точку vs. множество), DP.D.049 (Лог ≠ Инцидент ≠ State file — тип артефакта; данный — целостность через единственного writer). Смежно: DP.FM.186 (Append-only phantom early-writer — другой механизм отказа: не множественность писателей, а неавторизованный ранний писатель).
