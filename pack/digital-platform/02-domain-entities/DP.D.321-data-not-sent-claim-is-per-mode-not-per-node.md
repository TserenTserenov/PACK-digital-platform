# DP.D.321 — «Данные не отправляются» верно per-режим, не для всего узла целиком

## Различение

| | Один режим узла | Узел в целом (несколько режимов) |
|---|---|---|
| **Когда заявление корректно** | Если проверено именно для этого режима использования | Только если ВСЕ режимы узла ведут себя одинаково по отношению к данным |
| **Ошибка, если не так** | — | Одна строка таблицы документации утверждает свойство, верное лишь для части режимов, как будто оно верно для узла целиком |
| **Пример** | Aisystant MCP в режиме «поиск по платформе»: данные не уходят | Aisystant MCP в режиме «подключённый личный репозиторий на индексацию»: контент чанкуется, эмбеддится через OpenRouter, хранится на платформе |

## Механизм

`SETUP-GUIDE.md` описывал приватность MCP-сервера Aisystant одной строкой на весь узел («Данные пользователя не отправляются»), хотя узел работает в двух разных режимах с разным обращением с данными: поиск по платформе (данные не уходят) и подключённый личный репозиторий на индексацию (контент чанкуется, эмбеддится через OpenRouter, хранится на платформе). Строка была верна для одного режима и ложна для другого — таблица документации не различала режимы использования одного и того же узла, поэтому одно заявление молчаливо распространялось на оба.

## Тест различения

«Узел работает в нескольких различимых режимах использования, и заявление о данных проверено для каждого из них по отдельности?» Нет → заявление, верное для одного режима, рискует быть ложным для другого, будучи представленным как свойство узла в целом.

## Границы

Различение применимо к узлам/интеграциям с несколькими явно различимыми режимами использования (разные user-facing функции одного технического компонента), где обращение с данными между режимами отличается. Не применимо там, где узел имеет ровно один режим использования — там заявление по конструкции относится ко всему узлу.
