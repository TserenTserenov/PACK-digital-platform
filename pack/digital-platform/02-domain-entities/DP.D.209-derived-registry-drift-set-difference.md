# DP.D.209 — Дрейф производного реестра = разность множеств, не regex «найден ID»

**Различение:** обнаружение orphan-ID (`set(derived) − set(source) ≠ ∅`) ≠ обнаружение ID как таковых в производном файле.

| Подход | Что детектирует | Применимость |
|--------|----------------|-------------|
| Regex «найден ID в файле» | Наличие паттерна `WP-\d+` | 100% ложных срабатываний: производный по дизайну содержит ID из исходника |
| Разность множеств `set(derived) − set(source)` | Orphan-ID (в производном, но не в исходнике) | Реальный сигнал дрейфа |

**Тест:** «Появился ли в производном файле ID, которого нет в исходнике?»
- Да (`set(derived) − set(source) ≠ ∅`) → дрейф: исходник был обновлён, производный не пересгенерирован или пересгенерирован неверно.
- Нет → производный синхронен с исходником.

**Предпосылка:** детектор дрейфа должен знать `sot_path` (путь исходника) в конфигурации — иначе невозможно вычислить разность множеств.

**Почему regex даёт 100% ложных срабатываний:** файл `active-wp.md` — производная таблица из `WP-REGISTRY.md`; строки вида `| WP-001 |` находятся там по назначению. Regex на «нашёл ID» = обнаружение нормы, не аномалии.

**Связи:**
- «Source-of-truth ≠ Производный» — базовое различение; данное добавляет операционализацию «как именно проверять дрейф».
- DP.D.064 (same vs different promise) — родственное: оба про инварианты производных артефактов.
