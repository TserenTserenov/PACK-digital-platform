# DP.D.126 — Интерфейс ≠ Тир

## Различение

Канал доставки (интерфейс: бот, браузер claude.ai, ChatGPT, Кими, VS Code) и технологический тир (T0-T4, оснащение LLM + memory + MCP-tools + lifelong storage) — независимы. Любой канал может хостить любой тир.

## Контекст

При проектировании оснащения (T0-T4) возникает соблазн жёстко привязать тиры к каналам: «T0=бот, T1=браузер, T2=VS Code, T3=GPT, T4=кастом». Это удобно для маркетинга, но архитектурно неверно.

## Корректная модель

| Ось | Что определяет |
|-----|---------------|
| Канал (интерфейс) | Surface, через который пилот общается с системой |
| Тир | Функциональная конфигурация: LLM + memory + MCP-tools + lifelong storage |

**Достижимость T4 из разных каналов:**
- claude.ai → Aisystant MCP + своя LLM-подписка → T4
- ChatGPT → MCP → T4
- Кими → MCP → T4
- Telegram-бот → MCP → T4
- VS Code → Local Gateway + MCP → T4

## Тест

«Может ли пользователь достичь функционала X из канала Y?» Если ответ требует пересмотра по каналу — coupling.

## Антипаттерн

Матрица «канал × тир» с пустыми ячейками («тут T3 невозможен») — рождает ложные ограничения. Канал = иллюстративный (для удобства объяснения); тир = функциональная конфигурация.

## Применение

В sales-материалах и описаниях продукта: «выбери канал» отдельно от «выбери оснащение». В архитектурных решениях: считать coupling канал↔тир red flag, требующим обоснования.
