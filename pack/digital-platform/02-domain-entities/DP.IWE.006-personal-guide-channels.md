# DP.IWE.006 — Personal Guide Channels

## Описание

Архитектура доступа к персональному руководству пилота из разных клиентских сред. **Два трека доставки:**
- **Sovereign-трек** (явный Гит) — пилот владеет репо `personal-guide` на своём GitHub-аккаунте
- **Managed-трек** (тайный Гит) — платформа хранит руководство в системном репо `pg-{uuid8}` на org-аккаунте, пилот видит дайджест без GitHub-аккаунта

## Двухтрековая модель: T3a vs T3b

| | **T3a — Тайный Гит (Managed)** | **T3b — Явный Гит (Sovereign)** |
|---|---|---|
| **GitHub-аккаунт** | Не нужен | Нужен |
| **Репо** | `aisystant/pg-{uuid8}` (private org) | `username/personal-guide` |
| **Владелец** | Платформа (org-App) | Пилот |
| **Что видит пилот** | Дайджест в боте + веб-страница `guide.system-school.ru` | Полное репо на GitHub + дайджест |
| **Редактирование** | Нельзя (только чтение) | Можно (все файлы) |
| **Миграция** | T3a → T3b: возможна по запросу (WP-309 Ф9) | Обратная: не предусмотрена |
| **GDPR удаление** | Удаление org-репо + purge indexes | Uninstall App + delete repo + purge |

## Матрица: 4 канала × 4 операции

| Операция | Бот (Telegram) | Браузер (Web) | VS Code | Managed (Web-ридер) |
|----------|:--------------:|:-------------:|:-------:|:-------------------:|
| Create репо | ✅ | ✅ | ✅ | ✅ (автоматически системой) |
| Read руководство | ✅ (дайджест) | ✅ | ✅ | ✅ (веб-страница) |
| Commit reflection | ✅ | ❌ | ✅ | ❌ (read-only) |
| Refresh on RCS change | ❌ | ❌ | ✅ | ✅ (автоматически) |

## Сценарии по тирам

| Тир | Трек | Сценарий | Каналы |
|-----|------|----------|--------|
| T1 | — | Только бот: `/slot`, `/points`, марафон | Бот |
| T2 | — | Бот + браузер: Навигатор, Диагност | Бот + Браузер |
| **T3a** | Тайный Гит | «Платформа ведёт» — нет GitHub, дайджест в боте | Бот + Managed-ридер |
| **T3b** | Явный Гит | «Веду сам» — свой GitHub, полное репо | Бот + Браузер + VS Code |
| T4 | Явный Гит (реком.) | Полный IWE: ритуалы, стратегия, все агенты | Бот + Браузер + VS Code |

## Инварианты

1. **Sovereign-трек** — репо `personal-guide` функционирует одинаково из всех трёх каналов для операций, поддерживаемых данным каналом.
2. **Managed-трек** — read-only доставка через org-App. Пилот не имеет прямого доступа к GitHub.
3. **Миграция T3a→T3b** — пилот может в любой момент перейти с managed на sovereign (создать GitHub-аккаунт → `/personal-guide-start` → система переносит содержимое).
4. **Матрица — SoT** для проектирования клиентских интерфейсов.

## Применимость

Паттерн «один артефакт — несколько каналов» применим к любому персональному артефакту (workbook, portfolio, roadmap), требующему доступа из разных клиентских окружений. Двухтрековая модель (managed + sovereign) применима когда барьер входа (GitHub-аккаунт) отсекает часть аудитории.
