# DP.D.306: Атомарность лока (внутри инструмента) ≠ Общий namespace лока (между инструментами)

| Атомарность лока (mkdir/flock/ln) | Общий namespace лока |
|---|---|
| Решает гонку ВНУТРИ одного инструмента (повторный самозапуск) | Решает гонку МЕЖДУ разными инструментами на одном ресурсе |
| У каждого инструмента может быть свой лок-файл | Несколько инструментов обязаны использовать ОДИН И ТОТ ЖЕ лок-файл/директорию |
| Корректна сама по себе | Без неё — у каждого инструмента корректный, но бесполезный (для взаимного исключения) замок |

**Пример:** три независимых скрипта (`canon-refresh.sh`, `git-dirty-guard.sh`, `canon-reconcile.sh`) читают и правят один и тот же git checkout. Каждый уже был защищён от повторного самозапуска атомарным `mkdir`-локом — но лок каждого инструмента жил в своей директории. Третий скрипт взял тот же `$GIT_DIR/dirty-guard.lock`, что и первые два, вместо отдельного namespace — только тогда mkdir одного инструмента стал блокировать mkdir остальных на этом же ресурсе.

**Тест:** «Несколько РАЗНЫХ инструментов трогают один общий ресурс?» Да → они обязаны использовать один и тот же namespace лока, а не только собственную атомарную защиту от самозапуска.
