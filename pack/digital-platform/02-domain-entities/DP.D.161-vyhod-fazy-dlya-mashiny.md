# DP.D.161: Выход фазы для машины-потребителя = структура в БД (VIEW) ≠ человекочитаемый отчёт

Выбор формата выхода фазы определяется **типом потребителя**, а не удобством автора.

| Машина-потребитель (следующая стадия конвейера) | Человек-потребитель |
|------------------------------------------------|---------------------|
| Запрашиваемая структура в БД: VIEW, таблица, materialized view | Markdown-отчёт, документ |
| Читается программой напрямую через SQL/API | Читается человеком визуально |
| Отчёт для машины = лишний слой парсинга + не запрашиваемый | Структура для человека = избыточный SQL-overhead |
| Фаза имеет самостоятельный артефакт (VIEW) | Фаза «схлопывается» в отчёт |

**Тест:** «Кто потребитель выхода этой фазы — человек или следующая стадия конвейера?»
- Машина → структура (VIEW/таблица).
- Человек → отчёт.

**Следствие:** если выход потребляет машина, фаза не схлопывается в отчёт — её самостоятельный продукт = витрина в БД. Это меняет DoD фазы.

**Применение в WP-439 Ф2:** выход Ф2 (тип-подсказка для перевода) потребляет Ф3 (машинный конвейер) → созданы два VIEW: `concept_kind_context` (1043 строки) и `concept_translation_orphans` (2710 строк). Без VIEW Ф3 требовала бы парсинга markdown.

**Связано с:** DP.D.018 (Model ≠ View — ортогональное различение, о паттерне проектирования); DP.D.003 (Данные ≠ Представление). Не заменяет их, дополняет по оси «для кого».
