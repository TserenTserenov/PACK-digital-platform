# DP.D.318 — Идентичность сессии ≠ полномочие писателя ≠ доказательство завершения

## Различение

| Сигнал | Отвечает на вопрос | НЕ отвечает на вопрос |
|---|---|---|
| UUID / session_uid | О какой сессии идёт речь | Кто вправе писать; завершено ли |
| Аренда с монотонным fencing-token | Кто вправе писать прямо сейчас | Кто это; завершено ли |
| Квитанция конкретной попытки (attempt receipt) | Завершена ли именно эта попытка | Кто это; вправе ли ещё писать |
| PID, возраст процесса, читаемое имя, heartbeat, `exit 0` | Только наблюдения за процессом | Ничего из вышеперечисленного напрямую |

## Механизм

Три разных вопроса о сессии/процессе — «кто это» (идентичность), «кто вправе действовать» (полномочие) и «что уже сделано» (завершение) — требуют трёх разных видов свидетельств. Смерть PID или отсутствие heartbeat доказывают только отсутствие прежнего наблюдаемого поведения, не отсутствие владения, не факт завершения и не право третьей стороны публиковать/удалять/закрывать за него. Один сигнал не может ответить на все три вопроса сразу.

## Границы

Обработчик осиротевших сессий без отдельного terminal proof (квитанции завершения) имеет право только на обратимый карантин (заморозка данных) — не на признание успеха, не на освобождение полномочия, не на создание нового поколения. Локальное завершение — один постоянный per-session lock и монотонные стадии (PREPARED → PUBLISHED → CLEANED → terminal), привязанные к одному attempt_id; retry после терминального исхода получает новый UID, recovery незавершённой попытки сохраняет UID/attempt и повышает generation. Отвергнутые альтернативы: owner-file + PID-reaper (повторное использование PID, гонки ABA), бесшовный смешанный rollout без cutover (неустранимая гонка со старым писателем).

## Тест

«Этот сигнал говорит, кто это, кому можно писать, или что уже сделано?» — один сигнал не может отвечать за все три; если наблюдение используют не для того вопроса, на который оно отвечает — это ошибка классификации свидетельства.
