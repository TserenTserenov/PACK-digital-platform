# DP.ROLE.074: Диспетчер стилей

## 1. Определение

**Диспетчер стилей** — операционная роль, превращающая сырой контекст хода в полный композитный ключ и инъектирующая фрагмент стиля в промпт.

Граница ответственности — **маршрутизация, не данные**: Диспетчер не хранит правила стиля (это Хранитель, DP.ROLE.073). Диспетчер вычисляет, какой ключ нужен, и зовёт Хранителя.

**Зависимость A9 — явная:** детектор канала (разговорный/технический, A9 из L1 разговорного стиля) — входной артефакт Диспетчера, не скрытая деталь. При смене реализации A9 контракт Диспетчера остаётся прежним (меняется источник классификации канала, не интерфейс).

---

## 2. Входы (inputs)

| Вход | Источник | Данные | Триггер |
|------|----------|--------|---------|
| Сырой контекст хода | рантайм / хук | сообщение пилота, репо, тип артефакта, жанр | Начало хода (UserPromptSubmit / PreToolUse) |
| Классификация канала | A9 детектор (зависимость) | технический / «на пальцах» | Вычисление ключа |
| Режим точности | контракт принимающего использования | `wide` / `explanatory` / `engineering` | Вычисление ключа |
| Фрагмент стиля | DP.ROLE.073 Хранитель | текст правил по ключу | После вычисления ключа |

## 3. Обязанности

- Определить мета-класс читателя (человек/агент) и роль (пилот/новичок/ученик/напарник/исполнитель) из контекста хода.
- Прогнать детектор канала A9 (технический vs «на пальцах»).
- Принять режим точности из контракта материала; если он не указан, передать `wide` и пометить допущение.
- Собрать `context_key` = (мета-класс, роль, канал, домен, режим точности), сложить полный ключ с хэшами каскада.
- Запросить фрагмент у Хранителя и инъектировать в промпт до первого токена.
- При неоднозначном контексте — дефолтный регистр + пометка.

## 4. Полномочия и границы

- **Владеет:** логикой вычисления ключа и точкой инъекции.
- **Зависит от:** A9 детектор канала (явная зависимость), DP.ROLE.073 Хранитель (источник фрагментов).
- **Не владеет:** данными стиля, каскадом (это Хранитель).
- **Не делает:** не хранит правила, не пишет оверрайды пользователя, не определяет истинность утверждений и не подменяет онтологическую проверку выбором стиля.

## 5. Выходы (outputs)

| Выход | Получатель | Артефакт |
|-------|-----------|----------|
| Полный ключ | DP.ROLE.073 Хранитель | `(context_key, precision_mode, user_override_hash, platform_layer_hash)` |
| Инъекция фрагмента | промпт агента | системный промпт с правилами стиля |
| Лог инъекции / пометка неоднозначности | наблюдаемость | какой ключ вычислен, был ли дефолт |
