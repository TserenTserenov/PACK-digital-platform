# DP.D.166: Ось происхождения (Base/Pack/DS) ≠ Ось охвата (FPF/DPF/LPF)

| Base/Pack/DS (IWE) | FPF/DPF/LPF (Левенчук) |
|--------------------|------------------------|
| Режет по происхождению и владельцу | Режет по уровню общности |
| Куда течёт изменение (fallback chain DS→Pack→Base) | Насколько знание универсально |
| Тип репозитория / юрисдикция | Тип набора принципов / охват |

**Почему важно**: это две карты одной территории, совпадают НЕ клеточка-в-клеточку. `Base` ⊇ {ZP (основания), FPF (первые принципы), SPF (фреймворк доменных принципов), FMT-* (форматы)} — шире одного уровня Левенчука. `Pack` ≈ DPF. `PACK-agent-rules` + инструкции установки ≈ LPF (при этом `PACK-agent-rules` помечен `type: pack`, хотя по смыслу LPF → переклассифицировать до промоции). Решение IWE: не заменять свою ось, а совместить обе (происхождение + охват).

**Тест:** «про владельца и направление изменения или про охват знания?» Происхождение → Base/Pack/DS. Охват → FPF/DPF/LPF.

**Связано с:** [DP.D.165] (SPF ≠ Pack). Источник: WP-451, семинар Левенчука 28.06.2026.
