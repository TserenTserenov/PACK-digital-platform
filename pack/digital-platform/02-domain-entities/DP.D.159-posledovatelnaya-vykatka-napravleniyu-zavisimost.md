# DP.D.159: Последовательная выкатка по направлению зависимости ≠ Параллельная выкатка (аддитивная фича через слои в разных репо)

Когда новая фича добавляется несколькими слоями в РАЗНЫХ репозиториях/ветках (схема БД + код-писатель + пользовательский триггер-текст), атомарный co-deploy невозможен. Выкатывать строго по направлению зависимости: сначала производитель зависимости, затем потребитель, затем инициатор записи.

| Последовательно по зависимости | Параллельно |
|--------------------------------|-------------|
| (1) таблица БД (migration) → (2) код-писатель → (3) пользовательский триггер | все слои разом |
| у каждого слоя при выкатке уже поднята его зависимость | слой стреляет в ещё-не-существующую зависимость |
| безопасно при cross-repo (нет атомарной транзакции деплоя) | код пишет в отсутствующую таблицу; бот собирает согласие на захват, которого ещё нет |

**Тест:** «Если выкатить только этот слой, есть ли у него уже поднятая зависимость?» Нет → не выкатывать первым.

**Граница:** forward/аддитивный комплемент к [DP.M.222] (3-компонентный **атомарный** co-deploy — когда всё умещается в один PR) и к [[Авто-деплойный прокси нельзя пушить раньше нового бэкенда]] (distinctions.md). Зеркало удаления — [[Снять секрет ≠ снять код, который его требует]] (там потребитель снимается ПЕРЕД зависимостью). Ось: добавление → производитель первым; удаление → потребитель первым.
