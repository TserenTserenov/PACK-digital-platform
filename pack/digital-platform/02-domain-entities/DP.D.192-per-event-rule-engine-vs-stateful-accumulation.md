# DP.D.192 — Per-event rule engine ≠ Stateful accumulation

| Аспект | Per-event rule engine | Stateful accumulation |
|--------|-----------------------|----------------------|
| **Единица обработки** | Одно событие → одно обновление поля | Множество событий → агрегированный результат |
| **Состояние между событиями** | Нет (stateless между вызовами) | Есть (история накапливается) |
| **Операция** | `UPSERT` / `MERGE` одного поля | `SUM`, `COUNT`, `WINDOW` по истории |
| **Контракт** | Идемпотентное правило: «если это событие — делай X» | Накопительная логика: «учти все события за период» |
| **Ошибка смешения** | Попытка агрегировать внутри rule engine нарушает его контракт → смешивание двух вычислительных моделей в одном компоненте | — |

## Инвариант

Воркер проекций = per-event rule engine (правило на событие). Компонент агрегации истории = отдельный сервис с собственным storage. Смешивать нельзя: расширение ALLOWED_TARGETS воркера для aggregation destination = нарушение архитектурного контракта.

## Применение

При проектировании нового aggregation-компонента: первый вопрос — «хочу встроить агрегацию в существующий воркер?» Если воркер = per-event rule engine → нет, создать отдельный компонент. Проверка: есть ли нужная таблица в ALLOWED_TARGETS воркера? Нет → отдельный компонент, не расширение.

## Тест

«Нужный результат = функция от одного события или от истории событий?»
- Одно событие → per-event rule engine (воркер проекций)
- История событий → stateful accumulation (отдельный компонент)
