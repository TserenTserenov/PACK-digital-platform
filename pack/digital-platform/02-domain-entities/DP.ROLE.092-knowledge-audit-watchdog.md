# DP.ROLE.092 — Аудитор знаний (knowledge-audit watchdog)

## Kind / Owner

- **Kind:** гибрид. Расписание-триггер — специализированный исполнитель (launchd-таймер, фиксированный flow: убери расписание — ничего не запустится). Сама проверка внутри — LLM-агент (R2 Экстрактор в режиме аудита, `DS-ai-systems/extractor/prompts/knowledge-audit.md`): структурная и контентная оценка (полнота, дубликаты, семантическое пересечение >70%) требует суждения, не заменяется детерминированным чекером — убери LLM, проверка сломается (различение «Скрипт ≠ Агент», `distinctions.md`).
- **Owner Role:** DP.ROLE.001 (IWE Creator) — владелец надсистемы IWE (прецедент — DP.ROLE.064, DP.ROLE.091).

## Обязанности

- Ежемесячно (launchd) запустить Claude CLI headless с промптом `knowledge-audit.md` на текущий scope ротации (один Pack за проход — полный цикл по числу Pack'ов).
- Дождаться Audit Report (формат уже определён в промпте, Шаг 4) и отправить сводку (Pack'ов проверено, критичных проблем, общая оценка 🟢/🟡/🔴) пилоту в Telegram — по образцу `data-gap-watchdog`.
- При критичной оценке (🔴) — не тихая запись в лог, явный сигнал с готовым текстом исправления (уже спроектировано промптом Шаг 5, эта роль не меняет логику самого аудита).
- Не исправлять находки самостоятельно — только доставить отчёт; исправление = отдельное решение пилота (промпт явно: «Не исправляй без одобрения»).

## Полномочия

- Read-only к Pack-репозиториям (`PACK-*`) в scope ротации.
- Write только в свой state-файл (учёт ротации — какой Pack проверен когда) и логи.
- Не пишет напрямую в Pack — исправления идут через штатный KE/R15-конвейер, не в обход `/apply-captures`.

## Входы / Выходы (артефакты)

- **Вход:** Pack-репозитории в scope текущей ротации, `feedback-log.md` (единый дом, WP-476 Ф5) — не предлагать уже отклонённые паттерны.
- **Выход:** Telegram-сводка (пилоту), полный Audit Report (файл/лог), обновлённый state-файл ротации.

## Граница с соседними ролями

- **DP.ROLE.091 (Сторож данных)** — тот же архитектурный класс (периодический сторож с Telegram-алертом), другой предмет: содержимое персональных данных (health/WakaTime) vs структура и полнота базы знаний (Pack-контент). Не дублирует — соседствует.
- **R2 Экстрактор (AISYS.013, `DS-ai-systems/extractor/`)** — эта роль не подменяет Экстрактора, а добавляет ему регулярный триггер `launchd_3h`→ теперь и `launchd_monthly` для сценария Knowledge Audit, который раньше запускался только по прямому запросу пользователя (`system.yaml` сценарий «Session-Close Extraction»/«Inbox-Check» уже имели триггеры; Knowledge Audit — нет).
- **R15 Валидатор** — не заменяется: находки аудита (в т.ч. предложенные исправления) проходят тот же R15-гейт, что и обычные extraction-кандидаты, не применяются автоматически.
