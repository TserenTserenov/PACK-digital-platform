# DP.D.220: Режим отказа lazy-компонента = деградация (capability недоступна в сессии) ≠ блокировка работы

Условно-загружаемый каркасный компонент (скилл, формат-правило, роль, style-guide) может не загрузиться: advance-signal не пришёл, триггер не отработал, хук не вызвался. Контракт отказа: агент **продолжает работу без этого компонента** (деградация изолирована), а не падает.

| Деградация (правильно) | Блокировка (анти-паттерн) |
|------------------------|---------------------------|
| Lazy-компонент не загрузился → capability недоступна в этой сессии | Lazy-компонент не загрузился → работа останавливается |
| Отказ изолирован, основная работа идёт | Отказ каскадирует в остановку |
| Lazy сохраняет смысл (eager-стоимость не возвращается) | Lazy теряет смысл: всё равно надо было грузить eager |

**Тест:** «Если lazy-компонент не загрузился — система падает или продолжает?»
- Падает → lazy сломан по дизайну (надо было грузить eager).
- Продолжает (деградация) → контракт корректен.

**Граница с DP.D.158.** DP.D.158 — про *write-path* (сторонний best-effort захват данных деградирует без отката основной транзакции). DP.D.220 — про *read-path* (загрузка опциональной capability в контекст деградирует без блокировки сессии). Разные стороны различения «Read-path ≠ Write-path (side effects)».

**Связано с:** DP.D.158 (write-path сиблинг: best-effort захват ≠ основное событие); DP.METHOD.146 (activate-on-prefix — режим отказа = этот контракт); DP.FM.235 (eager bloat — проблема, которую lazy лечит при условии этого контракта).
