# DP.D.071: Декларированный bounded context ≠ Фактический bounded context

| Аспект | Декларированный | Фактический |
|--------|-----------------|-------------|
| **Носитель** | Frontmatter (`mastery_node`, `domain`, `pack-id`) | Тело документа (упоминаемые сущности, инструменты, понятия) |
| **Кто пишет** | Автор при создании | Накапливается при правках |
| **Темп изменения** | Редко, осознанно | Часто, неявно |
| **Виден кому** | Routing-инструментам, диспетчерам | Читателю при reading |

**Правило.** Заявленный frontmatter и реальное содержание тела дрейфуют — пишутся в разное время и разными слоями внимания. Заявление о принадлежности к bounded context — гипотеза, проверяется аудитом тела.

**Тест.** Для подраздела ≥500 строк: grep'нуть упомянутые сущности → классифицировать через карту mastery_node → расхождение >20% контента = bounded context violation. Эффективен в cold context (peer-агент), не самопроверка автора.

**Failure modes:**
- Дублирование контента между артефактами (тот же материал в Guide 1 S3 и Guide 3).
- Routing-агент (Портной, Навигатор) направляет запрос про X к артефакту, который на 50% про Y.
- Потребитель видит «обещали Y, дали X».

**Различение с Routing Gate** (DP.D.057, DP.KR.001 §5): Routing Gate — «куда положить новый файл». DP.D.071 — «соответствует ли уже-положенный файл своему frontmatter-обещанию».

**Применимо к:** руководства Pack, спецификации, методы Pack, описания ролей, любые артефакты с frontmatter-декларацией домена и существенным объёмом тела.

**Контр-pattern:** «mastery_node правильный, значит и тело подразумеваемо правильное» — frontmatter и тело пишутся в разное время, дрейфуют.
