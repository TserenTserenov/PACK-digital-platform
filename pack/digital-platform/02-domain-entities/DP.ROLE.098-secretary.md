# Секретарь (DP.ROLE.098)

<!-- see DP.SC.067, WP-389 -->

> **Kind:** Функциональная роль (FPF A.2), Grade 0 на этапе MVP — детерминированная программа (диспетчер задач + скрипты чтения), без вызова языковой модели на первом шаге. Суждение (какую роль формулировать, что важно) закладывается позже, MVP отвечает по фиксированному шаблону.
> **Owner Role:** Пилот (владелец обязательств и вопросов); техническая поддержка — R6 Кодировщик.

## 1. Миссия

Быть одним адресуемым собеседником для двух вещей: доставки созревших обязательств и ответа на прямой вопрос о состоянии дел — без создания нового хранилища. Снимает архитектурное противоречие, зафиксированное в карточке WP-389 03.07.2026 («единый календарь для всех» против «у каждого агента своё расписание»): решение не про хранилище, а про адресата — хранилища остаются раздельными, роль одна.

Не путать с «Секретарём очереди решений» (WP-503, ночная актуализация РП на цехе-1) — та роль работает только с портфелем РП пилота на одной машине; эта — с обязательствами и вопросами шире портфеля РП, рассчитана на доставку многим пользователям шаблона IWE.

## 2. Обязанности

1. Периодически (раз в 6-12 часов) проверять источники на созревшие обязательства (`hypotheses_due.py due`, журнал событий).
2. Доставлять созревшее обязательство с идентификатором для отмены через существующий канал (Телеграм на MVP, канал не зашит намертво).
3. Принимать отмену: до отправки — снять тихо; после отправки — зафиксировать событие «отменено», не удалять запись.
4. На прямой вопрос пилота синтезировать ответ по фиксированному шаблону (просроченное → зависшее → конфликты, по возрасту) из существующих источников, без нового суждения на MVP.
5. Сигнализировать, если сам простаивал дольше полутора суток (защита от повторения находки 15.08: диспетчер спал три месяца незамеченным).

## 3. Полномочия

- Читать журнал гипотез, журнал событий, портфель РП — только чтение, не пишет в эти источники напрямую.
- Писать событие отмены/доставки в отдельный журнал обязательств (не в источники, из которых читает).
- НЕ принимает решений по содержанию обязательств — не переформулирует гипотезы, не меняет приоритеты РП.
- НЕ становится единственным источником истины ни по одному из источников, которые читает (принцип платформы №6, отчуждаемость).

## 4. Связи

- `DP.SC.067` — обещание, которое роль реализует.
- `DP.SC.192` (Диспетчер отложенного запуска, `DP.ROLE.086`) — используемый паттерн предохранителей и одноразовых задач для доставки.
- `hypotheses_due.py` (`DS-my-strategy/scripts/`) — источник созревших обязательств.
- `iwe-agent-dispatcher.py --mode batch` (`DS-my-strategy/scripts/`) — исполнитель, на котором держится периодическая проверка.
- `DP.SC.064` (Секретарь очереди решений, `DP.ROLE.NNN` не оформлен отдельно, живёт внутри WP-503) — смежная, но не тождественная роль; граница описана в DP.SC.067 §«Границы с сопутствующими обещаниями».

## 5. Входы/выходы (артефакты)

| Вход | Выход |
|------|-------|
| Срабатывание периодической проверки (раз в 6-12 часов) | Сообщение о созревшем обязательстве с id для отмены |
| `cancel <id>` (до или после доставки) | Событие «отменено» в журнале обязательств |
| Прямой вопрос пилота («что просрочено», «что зависло») | Синтезированный ответ по шаблону |
| Возраст последнего прогона > 36 часов | Сигнал о простое |

## 6. Режим отказа

См. `DP.SC.067` «Режим отказа»: источник недоступен → явное сообщение, не тихий частичный ответ; диспетчер простаивает дольше полутора суток → отдельный сигнал; канал доставки недоступен → обязательство остаётся непогашенным, повторная попытка без нового вызова модели.

## 7. Путь до множества пользователей

MVP реализуется в `DS-my-strategy` (авторский экземпляр). Доставка в шаблон (`FMT-exocortex-template`) — отдельный, не-MVP критерий готовности WP-389: рецепт «шаблон + облачная задача + свой ключ модели + свой канал доставки», без нашей инфраструктуры на каждого пользователя (см. `DP.SC.019` — тот же принцип самостоятельного развёртывания уже принят платформой для ночной автоматики).
