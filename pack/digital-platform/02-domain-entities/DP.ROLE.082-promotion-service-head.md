# Руководитель продвижения (DP.ROLE.082)

> **Kind:** Domain Owner Role (владелец домена без архитектурных полномочий) — первый такой прецедент в этом Pack. Проверено grep по `memory/roles.md` и каталогу `PACK-digital-platform/02-domain-entities/` (сессия `2026-07-10-10-ds-my-strategy-inbox`): совпадений нет, ближайший кандидат «Владелец продукта» не подходит по объёму полномочий. Шаблона для копирования нет.
> **Owner Role:** Алёна Чайковская — исполнитель роли и владелец домена.
> **Связи:** R1 Стратег (приоритизация РП конвейера продвижения внутри общего плана недели) — Руководитель продвижения не приоритизирует сам, приносит содержание для приоритизации; R5 Архитектор — архитектурные решения по типам/структуре Pack (новая сущность ECO.SYS/PIPE, изменение каркаса) остаются за R5, Руководитель продвижения инициирует изменение содержания, не структуры.

## 1. Миссия

Владеть доменным содержанием 5 систем службы продвижения (Лид, Сообщество, Конвейер продвижения, Участник сообщества, Конвейер продюсирования — источник: доклад Алёны 19 апр 2026, WP-233) после того, как онтологический каркас этих систем формализован в PACK-ecosystem (Ф1 WP-251). Цель WP-251 Ф4 — передать эту роль Алёне полностью, без утечки архитектурных решений в операционку.

**Граница:** Руководитель продвижения работает с содержанием типов (какие состояния у Лида, какие шаги в конвейере) — не с формой Pack (SPF-структура, новые типы файлов, каркас `ECO.SYS`/`ECO.PIPE`). Изменение формы — только через R5 Архитектор.

## 2. Обязанности

| Обязанность | Метод | Триггер |
|-------------|-------|---------|
| Наполнять содержание 5 систем (типы Лидов, состояния Сообщества, шаги конвейеров) | Правка content-полей в `ECO.SYS.*`/`ECO.PIPE.*` (после Ф1 WP-251) | По мере накопления доменного знания |
| Инициировать изменение доменного содержания | Предложение через governance-протокол (Ф4 WP-251, `promotion-service-governance.md`) | Новое наблюдение о Лиде/Сообществе |
| Прогонять материалы конвейера через контроль качества коммуникации | Метод `ECO.M.NNN-lead-persona-verification` (см. ECO.SC.003, `may`) | Перед публикацией поста/письма/1:1-сообщения |
| Проводить сессию разбора модели | 1 сессия ~1.5ч (Ф4 WP-251) | При передаче владения |

## 3. Полномочия

- **Предлагает** изменения доменного содержания (типы, состояния, методы) — через review-протокол Ф4.
- **Не создаёт** новые `ECO.SYS`/`ECO.PIPE` сущности и не меняет SPF-каркас без ревью R5 Архитектор.
- **Не приоритизирует** РП конвейера продвижения в общем плане недели (это R1 Стратег) — приносит содержание, не порядок работ.
- **Владеет** решением pass/fail по находкам метода `lead-persona-verification` для собственных материалов (рекомендация, не гейт — см. ECO.SC.003).

## 4. Границы роли

| Делает | НЕ делает |
|--------|-----------|
| Наполняет типы конкретным доменным содержанием | Не меняет структуру Pack / SPF-каркас |
| Инициирует изменения через review-протокол | Не мержит изменения в обход R5 |
| Прогоняет материалы через банк персон | Не формализует сам метод как Pack-артефакт (Ф1, разово) |
| Владеет операционными решениями по 5 системам | Архитектурные решения по типу/новой сущности — только с ревью R5 |

## 5. Открытые пункты (Ф4 WP-251)

- Полный протокол передачи владения и review-цикл — `PACK-ecosystem/docs/promotion-service-governance.md` (Ф4, не создан).
- Формальное подтверждение Алёны: «Моя модель корректно записана, я готова ей владеть» — критерий готовности WP-251.
