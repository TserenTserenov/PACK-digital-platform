# DP.D.072: Спецификация формата ≠ Чеклист приёмки формата

| Аспект | Спецификация формата (pipeline-doc) | Чеклист приёмки |
|--------|--------------------------------------|-----------------|
| **Когда обновляется** | Постоянно (при каждой итерации формата) | Редко (открывается только при верификации) |
| **Темп дрейфа** | Догоняет реальность | Отстаёт от реальности на 1+ итерацию |
| **Кто читает** | Исполнитель при создании артефакта | Верификатор при приёмке |
| **Риск** | Артефакт получает текущий формат | Верификация по устаревшему чеклисту = false-positive «дефект» |

**Правило (расширение OwnerIntegrity на формат).** Один SoT для формата артефакта. Либо: (a) чеклист = SoT, pipeline ссылается на чеклист; либо (b) pipeline = SoT, чеклист generate'ится из pipeline скриптом. Оба независимо = drift гарантирован.

**Тест.** «При изменении формата артефакта какой документ обновляется первым?» Если один — он SoT, второй должен ссылаться. Если оба независимо — drift.

**Failure mode без правила (зафиксирован WP-300 F4).** Верификатор по чеклисту нашёл «дефект структуры подраздела» во ВСЕХ файлах — не дефект, а устаревший чеклист (структура «Теория/Метод/Через IWE» vs актуальная «Сигнатура/Объяснение/Степени мастерства»).

**Применимо к:** спецификации формата артефактов, чеклисты приёмки, рубрики верификации, frontmatter-схемы.
