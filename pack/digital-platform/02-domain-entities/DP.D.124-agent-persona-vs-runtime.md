# DP.D.124 — Агент-персонаж ≠ Агент-рантайм

## Различение

UX-персонаж (имя, личность, стиль) и backend LLM + memory — разные вещи. Одно имя может покрывать разные реализации по тиру.

| Аспект | Агент-персонаж | Агент-рантайм |
|--------|---------------|--------------|
| Что это | UX-идентичность для пользователя | LLM + memory stack за кулисами |
| Меняется по тиру? | Нет (единое имя) | Да (Haiku T0 → Hermes T3) |
| Определяется | Брендом / продуктом | Техническими COGS и фичами тира |
| Пример | «Гермес» как персонаж | T0: Haiku узкий промпт; T3: Hermes-рантайм |

## Паттерн: Persona-over-Runtime

Один персонаж для всех тиров, backend подменяется по тиру:
- **T0/T1:** дешёвый помощник (Haiku, узкий промпт) — free/starter
- **T3:** полный рантайм (Nous Research Hermes, ~17K токенов/ответ) — premium

Альтернатива (Name-ties-to-Runtime pattern): разные имена на разных тирах — менее удобно для UX, но честнее для разработчиков.

## Почему важно фиксировать

Без явного различения разработчик смешивает: «сделаем поведение Гермеса» (персонаж) и «добавим Hermes-рантайм» (backend). Это два разных решения с разным COGS, разными гейтами (IntegrationGate при смене обещания), разным degrade-behavior.

## LLM COGS аргумент

Hermes-рантайм ~17K токенов/ответ → чистый free-tier невозможен. T0/T1 требует дешёвого backend'а (Haiku) под тем же персонажем.

## Тест

«Если заменить backend с Haiku на GPT-4 — изменится ли персонаж для пользователя?» Нет → персонаж ≠ рантайм.
