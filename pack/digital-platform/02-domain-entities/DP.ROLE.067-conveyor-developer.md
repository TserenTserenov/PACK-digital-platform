# DP.ROLE.067 — Разработчик-исполнитель IWE

> **Kind:** Human-agent hybrid role (человек T4+ усиливается агентами).
> **Owner Role:** R14 Заказчик (пилот) — назначает в команду разработки.
> **Текущий исполнитель:** члены команды T4+ (TD1).

---

## 1. Миссия

Провести задачу разработки IWE через весь конвейер от Открытия до Закрытия с инвариантом двойного выхода. Каждая станция пройдена → артефакт проверен → знание захвачено.

**Граница:** DP.ROLE.067 активируется только при наличии формальной карточки задачи с `wp:` в frontmatter. Без карточки — работа идёт в режиме R6 Кодировщик (hotfix, рутинный патч).

---

## 2. Обязанности

| Обязанность | Как выполняется | Станция |
|-------------|-----------------|---------|
| Пройти WP Gate | Объявить роль, работу, класс, оценку, модель | Открытие |
| Пройти IntegrationGate/ArchGate | Обещание → сценарии → роль → код | Проектирование |
| Реализовать код/артефакт | Соблюдать CLAUDE.md репо, минимальные изменения | Работа |
| Захватить знание одновременно | Capture-to-Pack: различения, уроки, обновления Pack/шаблона | Работа |
| Проверить по классу верификации | Чеклист / сверка с эталоном / peer-review | Проверка |
| Закрыть РП | Коммит, обновление реестра, разводка знания | Закрытие |

---

## 3. Границы

- **Не** берёт задачи без оформленной карточки (тег маршрутизации, класс верификации, критерий приёмки).
- **Не** пропускает станцию Проверки ради скорости.
- **Не** вливает код без peer-review (если верификация V3+) или согласования Ведущего (TD1+TA4).
- **Не** является архитектором для сложных решений — эскалирует к DP.ROLE.069.

---

## 4. Входы / Выходы

**Входы:**
- Оформленная задача от DP.ROLE.068 (карточка с frontmatter: wp, verification_class, acceptance_criteria).
- Архитектура от DP.ROLE.069 (для сложных задач).
- Среда: репо, агенты, гайд разработчика.

**Выходы:**
- Работающий код/артефакт (PR в репо).
- Зафиксированное знание (Pack, шаблон, AGENTS.md/CLAUDE.md, memory).
- Закрытый РП в реестре.

---

## 5. Ограничения (инварианты роли)

1. **Двойной выход обязателен.** Ничто не покидает станцию без пары: код + знание.
2. **WP Gate перед работой.** Нет формального открытия — нет конвейера.
3. **Проверка перед закрытием.** Верификатор ≠ автор. Самопроверка не считается.
4. **WIP-лимит.** Не более 8–15 активных РП одновременно (правило S-47).

---

## 6. Связи с другими ролями

| Роль | Отношение |
|------|-----------|
| DP.ROLE.068 Постановщик | Получает оформленную задачу |
| DP.ROLE.069 Архитектор | Эскалирует сложные архитектурные решения |
| DP.ROLE.070 Верификатор | Проходит проверку перед закрытием |
| DP.ROLE.071 Ведущий разработчик | Создаёт PR, получает merge или reject |
| DP.ROLE.045 Диспетчер | Получает задачу из очереди (при команде >1) |
| DP.ROLE.039 Peer Agent | Использует агента для усиления (не делегирует ответственность) |
| R6 Кодировщик | Базовая роль, которую специализирует DP.ROLE.067 в режиме конвейера |

---

## 7. Точки входа (интерфейсы)

### Начало задачи (для разработчика)

```bash
# 1. Получить задачу из очереди (Диспетчер) или напрямую от Постановщика
# 2. Открыть сессию, ритуал WP Gate
# 3. Пройти станции конвейера
# 4. Закрытие: PR, peer-review, merge
```
