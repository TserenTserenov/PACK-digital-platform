# DP.D.226: Уровень принципов (степень общности: ZPF/FPF/SPF/TPF) ≠ Слой репозиториев (место хранения: Base/Pack/DS)

Две ортогональные оси, которые слипаются в одну строку и читаются как тождество.

**Ось 1: Уровень принципов** — степень специфичности правила (ZPF самый общий → TPF самый специфичный). Один принцип может «жить» на любой оси 2.

**Ось 2: Слой репозиториев** — место хранения (Base = ZPF+FPF+SPF = платформа → Pack = доменные знания → DS = реализации). Один репо может содержать принципы разных уровней.

| | ZPF/FPF/SPF/TPF (ось 1) | Base/Pack/DS (ось 2) |
|--|--|--|
| **Что описывает** | Степень общности принципа | Место хранения артефакта |
| **Вопрос** | «Насколько специфично это правило?» | «В каком репо это лежит?» |
| **Пример: «правило IWE»** | TPF (самое специфичное) | DS или Pack (зависит от природы) |
| **Пример: «форматирование»** | FPF (универсальный формат) | Base (платформенное хранилище) |

**Тест:** «Это про степень общности правила или про то, в каком репозитории оно лежит?» Разные вопросы → две разные оси.

**Почему слипаются:** цепочка «чем специфичнее принцип, тем ниже по иерархии хранилищ» верна как тенденция, но не как тождество. TPF-принцип может жить в Pack (если он доменный); FPF-принцип может жить в DS (если он реализационный). Смешение ведёт к «TPF — это DS», что бессмысленно.
