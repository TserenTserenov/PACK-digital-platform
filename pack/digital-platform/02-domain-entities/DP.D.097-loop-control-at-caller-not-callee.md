# DP.D.097 — Loop control у вызывающей роли, не у вызываемой

> В цепочке агентов downstream-роль возвращает результат вызывающей, **не** инициирует следующий вызов сама. Контроль над timeout / retry / cancellation остаётся в одной точке (вызывающая роль).

## Различение

| Аспект | (а) Loop control у callee (downstream) | (б) Loop control у caller (вызывающая) |
|--------|----------------------------------------|----------------------------------------|
| **Кто решает «дальше»** | Downstream-роль вызывает следующего исполнителя сама | Downstream возвращает результат, caller решает |
| **Где timeout** | Размазан по цепочке (каждая роль ждёт свою) | В одной точке (caller-loop) |
| **Где cancellation** | Каждая роль должна реализовать | Только в caller |
| **Кто прервёт бесконечный цикл** | Никто гарантированно (zigzag через N ролей) | Caller — owner итераций |

## Антипаттерн

Артефактор-Постановщик, получив запрос от Маршрутизатора, **сам** вызывает исполнителя (например, Subagent X). Subagent X возвращает результат Артефактору. Артефактор передаёт его обратно Маршрутизатору. Loop control размазан: timeout у кого? Retry-policy у кого? Cancellation propagates вверх или вниз? Сквозной observability невозможен.

## Правильный паттерн

```
Маршрутизатор → Артефактор → return → Маршрутизатор → Subagent X → return → Маршрутизатор
```

Маршрутизатор — единственный owner итерации. Артефактор просто структурирует ввод и возвращает. Subagent X выполняет работу и возвращает. Timeout, retry, cancellation — все на уровне Маршрутизатора.

## Аналог в других системах

- **HTTP middleware:** handler возвращает response, middleware решает retry. Handler сам не дёргает следующий endpoint.
- **Saga pattern:** orchestrator вызывает шаги последовательно. Шаги не вызывают друг друга напрямую (это уже choreography — другой паттерн).
- **Event loop:** callback возвращает результат в loop. Callback не запускает другой callback напрямую.

## Тест

Перед утверждением «downstream-роль сама вызовет следующего исполнителя» ответить:
1. Кто гарантированно прервёт бесконечный цикл при сбое?
2. Где находится единая точка timeout / retry / cancellation?
3. Может ли вызывающий полностью отменить операцию одним вызовом?

Нет однозначного ответа на любой → loop control размазан → антипаттерн.

## Применимость

- Цепочки agentic-ролей (Маршрутизатор → Артефактор → Subagent → ...).
- Pipeline-обработка с маршрутизацией (classifier → handler → processor).
- Любая N-уровневая делегация с потребностью сквозного контроля выполнения.
