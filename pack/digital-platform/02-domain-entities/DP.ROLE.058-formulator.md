# DP.ROLE.058 — R?? Артефактор-Постановщик

## Описание

Агентная роль, структурирующая сырой запрос пользователя в оформленный РП с routing-тегом.
Вызывается Маршрутизатором (DP.ROLE.059) когда входящий запрос не содержит routing-tag.
Результат возвращается обратно в Маршрутизатор — не передаётся исполнителю напрямую.

Автоматизирует WP Gate Ritual (CLAUDE.md §2): классификацию задачи по 4 классам
(trivial / closed-loop / open-loop / problem-framing) и определение артефакта.

## Вход → Выход

- **Вход:** сырой запрос — текст любой длины и структуры, без routing-tag
- **Выход:** structured request `{task_type, class, artifact, budget_estimate, confidence, routing_tag}`
  → возвращается в Маршрутизатор (DP.ROLE.059) для lookup

## Обязанности

1. **Определить task_type** из содержания запроса (статический lookup по ключевым словам,
   Haiku при неоднозначности)
2. **Присвоить class** по критериям WP Gate: trivial / closed-loop / open-loop / problem-framing;
   при сомнении — более широкий класс (open-loop, не closed-loop)
3. **Описать artifact** — одна строка: что является результатом задачи
4. **Оценить budget_estimate** — грубая оценка (~Xh) для WP Gate Ritual
5. **Проставить confidence** (high / low) — `low` если task_type определён через LLM
6. **Вернуть structured request** → Маршрутизатор; **не вызывать исполнителя самостоятельно**
7. **При INSUFFICIENT_INPUT** (< 5 слов, пустой ввод) → вернуть `INSUFFICIENT_INPUT`,
   не запускать LLM

## Полномочия

- Вызывать Haiku для классификации неоднозначных запросов
- Применять статические правила классификации (ключевые слова → task_type)
- Возвращать `confidence=low` без уведомления пилота
- Выбирать более широкий class при неопределённости

## Место в цепочке

```
Маршрутизатор (DP.ROLE.059)
  │ нет routing-tag
  ▼
Артефактор-Постановщик (DP.ROLE.058)
  │ structured request с routing-tag
  ▼
Маршрутизатор (DP.ROLE.059) — повторный lookup
```

**Инвариант:** Артефактор — downstream-исполнитель Маршрутизатора, не предшественник.
Loop ограничен 1 итерацией (контролирует Маршрутизатор).

## Связь с WP Gate Ritual

Артефактор-Постановщик формализует шаги 1–2 WP Gate Ritual:
- Шаг 1 WP Gate: «объявить роль, работу, РП, класс верификации» → Артефактор определяет `class`
- Шаг 2 WP Gate: «дождаться согласования» → Артефактор проставляет `confidence`; при `low`
  Маршрутизатор передаёт сигнал для уточнения пилотом

Артефактор **не заменяет** согласование пилота при создании нового РП — он структурирует
вход для ускорения Ritual, не обходит его.

## Надсистема

Экзокортекс (DP.ARCH.001). Подсистема «Система исполнения задач IWE» (WP-350).

## Исполнитель

Inline-логика в Opening-протоколе + Haiku LLM для классификации.
Статический keyword-lookup реализуется в Ф12 WP-350 как часть `route-task.sh`.

## Триггер

Вызов от Маршрутизатора (DP.ROLE.059) при отсутствии routing-tag во входящем запросе.
