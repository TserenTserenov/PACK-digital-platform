# DP.D.250: Владелец домена с архитектурными полномочиями ≠ Владелец домена без архитектурных полномочий

> Первый прецедент в Pack — роль «Руководитель продвижения» (WP-251).

| С архитектурными полномочиями | Без архитектурных полномочий |
|-------------------------------|------------------------------|
| Вводит новые типы сущностей | Только операционные решения в рамках существующих типов |
| Меняет структуру домена (схема, тип, архитектура) | Работает внутри существующей структуры |
| Аналог: Product Owner / Architect | Аналог: доменный эксперт с делегированными операционными правами |
| Инициирует ArchGate | Не инициирует ArchGate; при нужде в изменении типа — эскалирует к R1/R2 |

**Практический признак:** «Ты можешь добавить персону в банк (операция — разрешено), но не можешь добавить новый тип персоны без архитектурного ревью (тип — эскалация к R1/R2)».

**Паттерн делегирования:** изменение типа/структуры → ArchGate (R1/R2); операция в рамках существующего типа → domain owner без arch-полномочий.

**Связано с:** [DP.D.033] (Role-Centric Architecture — роль независима от исполнителя; смежно), [DP.D.034] (Three-Axis Access Control — оси авторизации; на каком уровне принимать решения).

> Источник: WP-251 Ф0 пир-сессия claude+kimi (2026-07-10, commit a3699fcae). Прецедент: Алёна как «Руководитель продвижения» — права на 5 систем (банк персон, реестр мемов, editorial calendar и др.), без права менять тип сущности или вводить новую архитектуру.
