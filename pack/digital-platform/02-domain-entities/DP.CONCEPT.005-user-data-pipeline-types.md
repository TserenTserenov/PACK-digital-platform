# Концепт: 4 типа конвейеров личных данных пользователя

## 1. Определение

Таксономия данных личной AI-платформы по источнику и назначению. Применима к любой персональной AI-платформе: разные конвейеры требуют разных политик хранения, согласия пользователя и data residency.

## 2. Четыре типа

| # | Тип | Источник | Примеры |
|---|-----|---------|---------|
| **2.1** | Биометрика и активность с устройств | Apple Health, iCloud Drive, wearables | resting_heart_rate, sleep stages, steps |
| **2.2** | Поведенческие следы внутри платформы | События бота, прогресс обучения, feedback | lesson_completed, check-in events, quiz answers |
| **2.3** | Агентские следы и знания | Сессии агентов, captures, commit-история | session transcripts, KE reports, git log |
| **2.4** | Персональный контекст для агентских решений | Профиль, состояние, декларации | Strategy.md, PD.FORM.*, pilot reflections |

## 3. Ключевые различия

| Параметр | 2.1 Биометрика | 2.2 Поведение | 2.3 Агентские следы | 2.4 Контекст |
|----------|---------------|---------------|---------------------|-------------|
| **Источник** | Внешнее устройство | Платформа (push) | Платформа (pull) | Пилот (декларация) |
| **Частота** | Непрерывно | По событию | По сессии | По изменению |
| **PII-уровень** | Высокий | Средний | Средний | Высокий |
| **Согласие** | Явное (HealthKit) | Неявное (usage) | Требует disclosure | Явное |

## 4. Применение в проектировании

При проектировании нового сервиса, работающего с данными пользователя:
1. Определить, к какому типу конвейера относятся данные
2. Применить политику residency этого типа (DP.METHOD.168 — ResidencyGate)
3. Учесть частоту, PII-уровень и модель согласия
