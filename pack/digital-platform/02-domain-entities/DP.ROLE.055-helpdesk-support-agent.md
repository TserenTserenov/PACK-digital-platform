# Агент поддержки IWE — DP.ROLE.055

> # see DP.SC.150, DP.ROLE.055
>
> **Kind:** Operational Role — обрабатывает входящий поток обращений по понятным сценариям. Не аналитическая (не Аналитик ограничений DP.ROLE.054), не архитектурная (не R6).
> **Owner Role:** IWE Platform — носитель: люди (Ильшат — диспетчер, Дима — разработчик-эскалация, Кими — методист руководств, Наталья — UX-вопросы). Chatwoot-аккаунты управляются администратором (Дмитрий, на MVP).

---

## 1. Миссия

Дать пилоту IWE короткую обратную связь по любым проблемам в течение SLA-окна (≤24ч на первый ответ, ≤48ч на резолюцию), не заставляя его искать «куда писать» и не теряя контекст между чатами.

Аналогия: первая линия техподдержки в SaaS-продукте — но с встроенным экзокортексным контекстом (агент сразу видит профиль пользователя, последние действия, статус подписки).

**Граница:** Агент поддержки НЕ:
- разрабатывает фиксы багов (передаёт R6 Кодировщику через Linear с тегом).
- принимает решения о фичах (передаёт Стратегу через еженедельный отчёт).
- меняет учебный контент (передаёт Методисту R4).
- модерирует клуб (это отдельная роль).

---

## 2. Обязанности (носимы)

1. **Первичная маршрутизация:** при появлении нового тикета — проверка автоназначения по теме, корректировка если автомат ошибся.
2. **Ответ в пределах SLA:** первый ответ ≤24ч, даже если это «принял, разбираемся, отвечу до X».
3. **Контекст-чтение:** ДО ответа открыть карточку пилота в Chatwoot (custom_attributes: ory_uuid, subscription, current_stage, recent_events).
4. **FAQ-обогащение:** если вопрос повторяется в ≥3 тикетах — создать FAQ-статью (Saved Reply в Chatwoot + запись в `chatwoot_articles`).
5. **Эскалация:** подтверждённые баги → Linear через кнопку. Фичреквесты → еженедельный дайджест для Стратега.
6. **Закрытие с CSAT:** resolve в Chatwoot триггерит CSAT-опрос пилоту. Низкие оценки (≤2) — личный follow-up.

---

## 3. Полномочия

- **Read:** карточка пилота в Chatwoot (всё custom_attributes + activity_log).
- **Write:** только в `conversations` и `articles` Chatwoot. Не имеет прав на `learning`, `persona`, `subscription` Neon DB.
- **Escalate:** создание Linear issue через готовый workflow. Не имеет прав напрямую коммитить в репо.
- **No PII export:** запрет выгружать переписку наружу (Chatwoot ↔ Linear передаёт только описание + теги, не транскрипт).

## 5. Носитель

- **Ильшат** — диспетчер первой линии, темы: общее, баллы, навигация.
- **Дима** — техническая эскалация, темы: баг, performance, доступность.
- **Кими** — методическая экспертиза, темы: руководство, контент, методы.
- **Наталья** — UX, темы: бот-UI, лендинг, навигация.

MVP: один-двое онлайн в рабочее время. Ночные тикеты — обрабатываются утром, FAQ-перехват и автотикеты работают круглосуточно.

## 6. Метрики

| Метрика | Цель MVP |
|---------|----------|
| First Response Time (avg) | ≤4ч в рабочее время, ≤24ч ночью |
| Resolution Time (avg) | ≤48ч |
| FAQ-hit rate | ≥30% обращений закрываются без участия агента |
| CSAT (avg) | ≥4.0 из 5 |
