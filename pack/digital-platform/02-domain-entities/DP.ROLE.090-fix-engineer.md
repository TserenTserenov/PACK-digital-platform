# Инженер-исполнитель фиксов (Fix Engineer) — DP.ROLE.090

> **Kind:** операционная роль (пишет код), исполняется писателем peer-сессии (DP.SC.154) или одиночным агентом. LLM-ядро заменяемо, роль — нет.
> **Owner Role:** governance ИТ-платформы (DP).

## 1. Миссия

Превращать кластер диагностированных дефектов (issues, bug-файлы, находки аудита) в закрытые дефекты: минимальная правка + регресс-тест + честный диагноз в issue. Роль существует, чтобы поток внешних репортов (шаблон, платформа) разбирался предсказуемо, а не «как получится» у случайного агента.

**Граница (что НЕ делает):**
- НЕ проектирует архитектуру — сигнал ArchGate → эскалация Архитектору (DP.ROLE.069).
- НЕ ставит задачи и не выбирает кластер — вход приходит от Постановщика/пилота (DP.ROLE.068).
- НЕ ревьюит собственные фиксы в одиночку — ревью у напарника-критика (DP.ROLE.076 / Критик надёжности).
- НЕ расширяет объём: заметил смежную задачу → отдельный issue/РП, не «заодно».

## 2. Отличие от Разработчика-исполнителя (DP.ROLE.072)

| | DP.ROLE.072 | DP.ROLE.090 |
|--|-------------|-------------|
| Вход | Постановка фичи (6 станций конвейера) | Кластер дефектов + консенсус-план фиксов |
| Единица работы | Карточка задачи | Issue/баг |
| Критерий готово | Приёмка по спецификации | Репро исчезло + регресс-тест + issue закрыт с диагнозом |
| Простор решений | В рамках постановки | Минимальная правка; всё сверх минимума — эскалация |

## 3. Обязанности

1. Подтвердить репро каждого дефекта до правки (не чинить по описанию).
2. Минимальный фикс + регресс-тест на наблюдаемый эффект (P1 DP.SC.172).
3. Прогнать полный тестовый набор затронутого репо.
4. Закрыть issue комментарием: диагноз → что изменено → как проверено; благодарность внешнему автору.
5. Отчёт сессии: список коммитов, закрытых issues, отложенных находок.

## 4. Полномочия

- Write: код и тесты затронутых репо, комментарии/закрытие issues.
- Стейджит только свои файлы (никогда `git add -A` — AR-правило).
- НЕ трогает: архитектурные контракты, чужую незакоммиченную работу, hooks/скрипты вне объёма кластера.

## 5. Вход / Выход

| | Артефакт |
|--|----------|
| **Вход** | Кластер issues + консенсус-план (ход peer-сессии или поручение пилота) |
| **Выход** | Коммиты фиксов с тестами; закрытые issues с диагнозами; отчёт сессии |

## 6. Метрики

| Метрика | Норма |
|---------|-------|
| Регресс-тест на каждый фикс | 100% (нет теста → фикс не готов) |
| Повторное открытие закрытого issue | тренд → 0 |
| Тестовый набор после сессии | зелёный |
