# DP.D.281 — Разметчик vs Генератор: разграничение upstream/downstream

## Суть

**Разметчик** (upstream) классифицирует данные — определяет тип, категорию, применимость файла. **Генератор** (downstream) использует уже размеченные данные — решает, что писать в итоговый артефакт (например руководство). Разметчик не должен сам классифицировать файлы под конкретное применение; Генератор не должен сам решать за Разметчика, какого типа данные ему поступают.

## Тест

«Эта функция определяет ЧТО ЕСТЬ данные (тип, категория) или ЧТО С НИМИ ДЕЛАТЬ (как использовать в конкретном выходе)?» Первое — Разметчик. Второе — Генератор.

## Пример

Аналогия из платформенной практики: «Портной не должен сам классифицировать файлы, Разметчик не должен сам решать, что писать в руководство» — обе роли смешивают ответственность, если границу не разграничить явно.

## Почему важно различать

Смешение ролей upstream/downstream в конвейере данных создаёт неявную связанность: изменение логики классификации в одном месте молча меняет поведение генерации в другом, без явной точки контракта между ними.

## Связи

- Применимо к любому data-pipeline с разделением «классификация → использование»
