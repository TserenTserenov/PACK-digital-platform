# DP.ROLE.071 — Ведущий разработчик IWE

> **Kind:** Human role (человек TD1+TA4).
> **Owner Role:** R14 Заказчик (пилот).
> **Текущий исполнитель:** член команды с уровнем TD1+TA4 (текущий: Ильшат + пилот).

---

## 1. Миссия

Быть **merge gate** и **архитектурным арбитром** для команды разработки IWE. Только Ведущий разработчик вливает код в main (или делегирует это право явно).

**Граница:** Ведущий разработчик не пишет код в рутинных задачах и не проверяет работу вместо Верификатора.

---

## 2. Обязанности

| Обязанность | Как выполняется |
|-------------|-----------------|
| Согласовать merge PR | Проверить: верификация пройдена, двойной выход есть, конфликтов нет |
| Принимать архитектурные решения | При эскалации от Архитектора или при конфликте подходов |
| Подписывать рост в команде | Решение о повышении T4→TD1, вводе нового разработчика в команду |
| Контролировать WIP | Правило S-47: 8–15 активных РП, не больше |
| Эскалировать к пилоту | Стратегические решения, выходящие за рамки команды |

---

## 3. Границы

- **Не** пишет код в рутинных задачах (это работа DP.ROLE.072).
- **Не** проверяет работу вместо Верификатора (проверяет, что проверка была, а не заменяет её).
- **Не** ставит задачи вместо Постановщика (может инициировать, но оформление — DP.ROLE.068).
- **Не** принимает архитектурные решения в конфликте с платформенной архитектурой без согласования с R5 / пилотом.

---

## 4. Входы / Выходы

**Входы:**
- PR от Разработчика-исполнителя (код + знание + вердикт Верификатора).
- Эскалации от Архитектора конвейера.
- Запросы на рост в команде.

**Выходы:**
- Решение merge / request changes / reject.
- Архитектурное решение по эскалации.
- Подпись о росте (T4→TD1, новый разработчик).
- Контроль WIP: приостановка/возобновление задач.

---

## 5. Ограничения (инварианты роли)

1. **Merge gate.** Только Ведущий (или его явный делегат) вливает в main.
2. **WIP-лимит.** Превышение 15 активных РП — стоп и пересмотр бэклога.
3. **Не замена проверки.** Ведущий проверяет факт проверки, не содержание.
4. **Эскалация стратегии.** Решения об изменении конвейера в целом — к пилоту.

---

| Метрика | Норма | Где брать |

| Медиана времени merge-решения | ≤4ч для V2, ≤1 дня для V3/V4 | GitHub PR stats |

| Активных РП (WIP) | 8–15 | WP-реестр |
| Решений по росту в команде | По запросу | Ручной учёт |
