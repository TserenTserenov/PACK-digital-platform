# DP.D.240 — Доменное событие ≠ интерпретация факта

## Различение

| Аспект | Доменное событие (факт) | Интерпретация (маппинг) |
|--------|------------------------|------------------------|
| **Что это** | Что произошло в системе | Что это значит (тип-события → ось) |
| **Где хранится** | Неизменяемый журнал событий | Отдельная таблица соответствия |
| **Меняется ли** | Нет — защита неизменяемостью | Да — правится при исправлении бага |
| **Кто читает** | Все подписчики журнала | Читающая сторона (агрегаты, проекции) |

## Инвариант

В неизменяемый журнал пишется **только сам факт** (что произошло), не его интерпретация (что это значит).

Если «каноническое» событие содержит маппинг (тип → ось) — баг в коде маппинга становится неизменяемым: ошибку нельзя тихо исправить.

## Правило размещения

Интерпретация (таблица соответствия тип-события → ось) живёт на **читающей стороне**: в агрегате, проекции, сервисе аналитики. Не в журнале событий.

## Тест

«Если в коде нормализации найден баг — можно ли исправить результат без изменения журнала?»
- Да (интерпретация на читающей стороне) → правильно
- Нет (интерпретация записана в журнал) → журнал содержит ошибку, исправление требует backfill

## Контекст

WP-457 Ф10: предложение писать «каноническое» событие поверх доменного (паттерн двойной записи) оказалось внутренне противоречивым — неизменяемость защищает факт, но баг в нормализации тоже становится неизменяемым. Решение: маппинг тип-события → ось живёт в отдельной таблице соответствия на читающей стороне.
