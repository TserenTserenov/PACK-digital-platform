# DP.D.096: Парламент-модель памяти агентов — 5 элементов и инварианты

## Определение

Архитектурный паттерн мульти-агентной памяти: **N доменных агентов + тонкий координатор + платформенный замок + верификатор + окно команд**, при котором ни один агент в одиночку не может прочитать данные чужого домена.

## 5 элементов

1. **Координатор** — знает только имена доменных агентов; маршрутизирует запрос, не читая содержимого. Аналогия: телефонный коммутатор.
2. **Доменные агенты (N штук)** — каждый знает только свой домен, физически изолирован (отдельная схема БД / scope токена).
3. **Платформенный замок** — токены / OAuth scope на уровне API, не промпта. Принудительная изоляция на инфраструктурном уровне.
4. **Верификатор** — контрольная роль, read-only, независима от Координатора и доменных агентов.
5. **Окно команд** — три класса по обратимости: безопасные / обратимые-в-доме / необратимые-от-имени.

## Инвариант

> «Может ли один агент в одиночку прочитать данные не своего домена?»
>
> - **Да** → не Парламент (Президент-модель), независимо от именования
> - **Нет** → Парламент-инвариант соблюдён

## Границы домена

Многодоменная запись (событие касается нескольких доменов) разрезается на карточки при создании — пилот определяет границу домена.
