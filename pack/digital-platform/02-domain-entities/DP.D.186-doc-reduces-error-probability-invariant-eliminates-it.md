# DP.D.186 Документация снижает вероятность ошибки ≠ инвариант в коде устраняет её физически

| Аспект | Документация | Инвариант в коде |
|--------|-------------|------------------|
| **Носитель защиты** | Текст для человека | Исполняемый код |
| **Условие срабатывания** | Человек прочёл и помнит | Каждый запуск, независимо от читателя |
| **Результат** | Снижает вероятность ошибки | Физически предотвращает ошибку |
| **Уязвимость** | Copy-paste из старой заметки; новый агент без контекста | Отсутствует (пока инвариант не удалён) |
| **Пример** | `# Замени {{HOME_DIR}} перед запуском` | `[[ "$path" == *"{{"* ]] && die "placeholder not substituted"` |

## Тест различения

> «Если все тексты об ошибке исчезнут, система всё ещё не даст её совершить?»

- **Нет** → документальный фикс. Продавать как «устранение причины» нельзя.
- **Да** → код содержит инвариант; защита не зависит от текста.

## Применение

При предложении фикса-через-текст (README, комментарий, правило) называть явно:

> «Это **doc-fix**: снижает вероятность ошибки, но не устраняет её физически. Для устранения нужен инвариант: [ранняя проверка / assert / guard].»

Затем решить: doc-fix + инвариант — или только инвариант (если текст дублирует то, что код уже проверяет).

## Связи

- Смежная ось: «Containment ≠ root-cause fix» — носитель временный vs постоянный.
- AR-нарушение: предлагать doc-fix как «решение» без явной оговорки = P5 (дезориентация пилота).
