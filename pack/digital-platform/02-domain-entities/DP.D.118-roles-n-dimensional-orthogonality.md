# DP.D.118 — N-мерная ортогональность ролей в peer-сессии

## Различение

Все роли в peer-сессии ортогональны друг другу — каждая роль = отдельная независимая ось в N-мерном пространстве. Один агент в одной сессии = точка с координатами по N осям; агент может играть N ролей одновременно, если они не конфликтуют по типу.

## Ошибочная упрощённая модель

В DP.SC.154 (peer-conversation) роли организованы по двум осям: доменная (Стратег/Инженер/...) × протокольная (writer/peer). Двумерная свёртка скрывает реальную множественность.

## Корректная модель

Каждая роль (Стратег DP.ROLE.012, Менеджер, Инженер, Методолог, писатель, критик) — отдельное независимое измерение. Агент в сессии = `roles: [...]` (множественное число), не `role: writer-стратег` (одиночное двумерное).

## Единственное жёсткое ограничение

DP.D.080: контрольная ≠ операционная — независимость аудита требует, чтобы одна роль не совмещала эти два типа в одной сессии.

## Тест

«Можно ли иметь все 2^N комбинаций включения/выключения ролей?»
- Да → ортогональные оси, использовать множественную модель.
- Нет → одно измерение со специализациями, использовать одиночную модель.

## Применение

При проектировании ролевых каталогов и frontmatter реплик в peer-сессиях:
- frontmatter реплики: `roles: [writer, DP.ROLE.012]` вместо `role: writer-стратег`.
- meta сессии: `roles: [DP.ROLE.NNN, ...]` — все играемые роли.
- структурная роль (writer/peer) указывается per-turn, см. DP.D.119.
