# DP.D.273: Стратегическая доменная роль ≠ infrastructure-agent

> **Перенумеровано при разрешении коллизии (2026-07-19, РП170 Ф3): DP.D.125 → DP.D.273.** Номер 125 оставлен за одноимённым файлом (решение по анализу контекстов ссылок — превосходство за файлом; реестр: `DS-my-strategy/inbox/bugs/drift-2026-07-18-dpd-numbering-collisions.md`). Ссылки на «DP.D.125» до 2026-07-19 могли означать эту сущность.

**Конвенция Pack: тип `infrastructure-agent`**

| Стратегическая доменная роль | infrastructure-agent |
|------------------------------|----------------------|
| Принимает доменные решения (что, когда, кому) | Исполняет технические операции над состоянием |
| Знает о доменной онтологии (пользователи, роли, характеристики) | Знает о техническом состоянии (FSM, feature flags, маршруты) |
| Изменяется при изменении доменной логики | Изменяется при изменении технической механики |
| Пример: Онбордер, Навигатор, Контролёр, Диагност | Пример: DP.ROLE.013 Проводник (FSM-executor) |

**Тест**: «Если изменится бизнес-логика онбординга — нужно ли менять этот компонент?» Нет → это `infrastructure-agent`. Да → стратегическая роль.

**Нотация:** `type: infrastructure-agent`, `kind: <специализация>`. Допустимые kind:
- `FSM-executor` — управляет FSM состоянием (feature flags, кнопки, команды)
- `notification-dispatcher` — доставляет уведомления
- `event-router` — маршрутизирует события

**Размещение:** в `02-domain-entities/` как архитектурный концепт (progressive disclosure паттерн), но явно помечен как `type: infrastructure-agent` — не позиционируется как стратегический актор.
