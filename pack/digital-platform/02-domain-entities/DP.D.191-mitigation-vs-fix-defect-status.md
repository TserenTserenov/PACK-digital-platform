# DP.D.191 — Mitigation ≠ Fix

| Аспект | Mitigation (снижение риска) | Fix (устранение причины) |
|--------|---------------------------|------------------------|
| **Что делает** | Снижает вероятность или масштаб проявления | Устраняет первопричину дефекта |
| **Статус дефекта** | Остаётся **открытым** («риск снижен, не устранён») | Закрывается |
| **Тест** | При воспроизведении исходного условия дефект проявится снова? | При воспроизведении — не проявится |
| **Пример** | retry+backoff при fail-closed согласии: window уязвимости при сбое остаётся | Переработка механизма согласия без window уязвимости |
| **Ошибка смешения** | Маркировать mitigation как «done/closed» → скрытый residual risk | — |

## Инвариант

Mitigation не закрывает дефект в security audit. Запись «риск снижен» — это отдельный статус, не «fixed». Следующий аудит должен видеть дефект открытым с пометкой о принятом mitigation.

## Применение

При security review: каждый дефект явно маркируется:
- `closed: fix` — первопричина устранена, при воспроизведении условий дефект не проявится
- `open: mitigated` — риск снижен (retry, rate limiting, circuit breaker), первопричина остаётся

Смешение → накопление residual risk, невидимого при следующем аудите.

## Тест

«При намеренном воспроизведении исходного условия — дефект проявится снова?»
- Да → mitigation, не fix → статус открытый
- Нет → fix → статус закрытый
