# DP.D.092 — Rate limit ≠ Value: частотный потолок и ценность — две оси, две колонки

## Суть

В дизайне reward-системы две независимых оси активности:
1. **Value (`base`)** — сколько одно событие стоит. Uniform per group.
2. **Rate limit (`max_per_day`)** — сколько событий в сутки засчитывается.

Лумпинг = склеить в одну колонку. Анти-паттерн.

## Тест

«Если число можно поделить на (количество × ценность) — это композитное; разделить ДО реализации.» Например, «5 помодоро по 10 баллов = 50» — это уже композитное.

## Failure mode при лумпинге

- Невозможно изменить лимит без переопределения веса.
- Невозможно объяснить экономику пользователю («почему вчера 50, сегодня 30?»).
- Первый день засчитывается полностью, второй — теряется молча.

## Применимость

- Rate limits API.
- Бонусные программы.
- Лицензии с количественным потолком.
